# ADR-0002：知识单元必须记录级溯源 + 内容指纹

- 状态：`proposed`
- 日期：2026-09-16
- 决策者：Owner（周健）
- 依赖：ADR-0001（双账本）

## 背景

会议明确定了一个交付物：「落地审核**留存**及反馈机制」。
法务侧的框架文档也把「可追踪」「可留痕」列为核心诉求。

但实测现状是：**目前没有任何一条知识单元能回答「你是从哪来的」。**

### 实测证据

**证据 1：规则表的「依据来源」不是来源**

21 条规则的 `依据来源` 字段，取值只有 3 种，且**全部是文件名**：

| 取值 | 条数 |
|---|---:|
| `吸奶器广告文案审计_红绿灯.xlsx 规则库` | 13 |
| `W1卖点表达边界（品线反馈2026-09-10 T4）+ 吸奶器广告文案审计_红绿灯.xlsx 规则库` | 7 |
| `W1利益点边界表(SWMYUF)刷新 + 吸奶器广告文案审计_红绿灯.xlsx 规则库` | 1 |

没有链接、没有版本号、没有条款号、没有生效日期。
**「H07 禁止 pain-free」这条规则，依据是哪份文件、哪一版、哪一条？答不出来。**

**证据 2：记录引用不存在的规则**

291 条记录里，2 条引用了规则编号 `EMPTY` —— 规则表里没有这个编号。

**证据 3：无法回答「上周和这周规则变了什么」**

昨天（09-15）调研时快照的规则表，与今天（09-16）实测的规则表，
`适用产品` 字段 21/21 全部填同一个常量 `[W1, M5, M6, M9, Air1]`。
而设计文档 §3.6 已经指出这是错的（把 21 条规则写死成同一组产品）。
**但没有任何机制记录这个字段何时被谁改过。**

## 决策

**每一个进入知识库的知识单元，必须携带四元溯源信息，缺一不可。**

```yaml
# 知识单元最小溯源块
id: RULE-H07                     # 稳定 ID，永不变
source:
  kind: feishu-bitable           # 来源类型
  app_token: Lk3Qb8y2QaVyZns6gprcVNE9nA0
  table_id: tblD1MiUK1v5fdjD
  record_id: recXXXXXX           # ★ 记录级，不是表级
snapshot_sha256: 2a1a219a7e76…   # ★ 拉取时的整表内容指纹
captured_at: 2026-09-16T05:08:45Z
authority: human                 # human | machine | derived
```

**四条硬规则：**

1. **溯源到记录，不到表。** 「来自规则库表」不算溯源；必须能定位到 `record_id`。
2. **必须带快照指纹。** 没有 `snapshot_sha256` 的知识单元**不得进入任何报告或 Agent 的判定依据**。
3. **稳定 ID 与来源解耦。** `RULE-H07` 这个 ID 属于我们，不属于飞书。
   飞书那条记录被删了，ID 仍然存在，只是状态变成 `orphaned`。
4. **`authority` 必须显式。** 人写的、机器生成的、从别处推导出来的，三者不能混。

## 为什么是记录级而不是表级

表级溯源只能回答「这数据来自规则库」，而我们要回答的是：

- H07 这条规则，**是谁**在**什么时候**写的？
- 它**改过几次**？每次**改了什么**？
- 现在 Agent 用的 H07，和人工判定时用的 H07，**是同一版吗**？

最后一个问题尤其关键：**Agent 判定与人工判定必须能对齐到同一版规则**，
否则「Agent 复现率」这个指标算出来是没有意义的。

## 后果

**正面**
- 任何数字都能追溯到「哪一版数据的第几条」
- 规则变更可 diff、可回滚
- Agent 判定可回放（规则 + 输入都有指纹）
- 对话里出现的引用不实问题，从机制上被消除

**负面 / 代价**
- 飞书表每次改动都会改变整表指纹 → 需要区分「内容变了」与「元数据动了」
  （已在 `tools/live_snapshot.py` 中处理：指纹只取 `record_id + fields`，排除时间戳）
- 需要维护 ID 映射表，且映射表本身要进 git
- 一旦飞书记录被删，本地会出现 `orphaned` 单元 —— 需要显式清理流程，不能默认忽略

## 待 Owner 确认的问题

1. 稳定 ID 的命名规则由谁定？（建议：`<域>-<族><序号>`，如 `RULE-H07`、`CLAIM-BP-001`）
2. 飞书记录被删除时，本地单元应标记 `orphaned` 保留，还是直接归档？
3. 是否接受「无指纹的数字不得进报告」这条硬规则（它会拖慢临时性的口头回答）？
