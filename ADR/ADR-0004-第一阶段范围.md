## 未采纳的建议（存档）

> 建议收窄到吸奶器单点闭环。理由：
> 1. 会议自己定的调子「第一阶段仅聚焦底线风险拦截」「不可能一口气吃大胖子」
> 2. 三个品线并行 = 三倍人工投料 + 一套管道，而现在两份投料是空的
> 3. 单点闭环能回答唯一重要的问题：管道**能不能通**
> 4. 失败成本：三线各做 60% 时，无法判断是「方法不对」还是「人手不够」

## 三品线并行必须配套的三个前提（否则本决策的代价会失控）

既然三线并行，为了不重演「三个半成品」，以下三条**建议立即落实**：

1. **管道只建一次，品线只提供数据。**
   规则库结构、字段设计、判定流程**不得**因品线而分叉。
   分叉一旦发生，就等于做了三个项目。

2. **每条品线必须有人指定的对接人，且在 2 周内投出第一批料。**
   没有投料的品线，其进度**按 0 计**，不按「正在进行」计。

3. **进度汇报按「闭环跑通次数」计，不按「完成百分比」计。**
   例：吸奶器 3 次、baby monitor 0 次、bottle washer 0 次。
   百分比会掩盖「什么都没跑通」，次数不会。

## 后果

**正面（决策带来的）**
- 不需要向会议相关方解释范围变更 —— 省掉政治成本
- 三条品线的对接人被保留在项目内，不会因范围收窄而退出
- 若两条品线能快速投料，可提前发现「跨品线通用规则」（如绝对化用语在三条线都适用）

**负面（必须监控的）**
- **规则工作量为原估的 3 倍**（另两条品线要从零写规则）
- **第一阶段交付物大概率变成三份半成品** —— 需靠上面三个前提缓解
- 若 2 周内两条品线未投料，实质等同于单点闭环，但**失去了单点闭环的专注度**
  → **触发条件**：2 周后若仍无投料，本 ADR 必须重开

## 复审触发条件

满足任一条即重开本 ADR：

- 2 周后 baby monitor / bottle washer 仍无任何投料
- 任一品线出现「进度无法用闭环次数表达」的情况
- 三条品线开始要求规则库结构分叉
