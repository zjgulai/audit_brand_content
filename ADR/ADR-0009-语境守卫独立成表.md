# ADR-0009：语境守卫独立成表 —— 机制分离的第二处，与所有权分离

- 状态：`accepted`（Owner 决策 4：「需要成独立的表」）
- 日期：2026-09-16
- 决策者：Owner（是否独立成表）；开发者（表结构、不变量、实施与度量）
- 依赖：ADR-0008（机制分离 · 白名单独立成表）
- 触发：ADR-0008 §六 遗留待决 #1

## 一、决策

`豁免词` 字段里的语境守卫词**移出规则库，独立成表**。

这与决策 3 不是两件事，是**同一个病的第二处**：

| # | 位置 | 通道由什么决定 | 后果 |
|---|---|---|---|
| 1 | `安全词` 那一行 | `边界类型` 字符串 | 任何 `SELECT 检测关键词` 都取到白名单词 |
| 2 | **`豁免词` 字段** | **无 —— 两类词混放** | **84 守卫 / 10 白名单词，靠词义区分** |
| 3 | `downgrade_band` | `effect` 箭头右侧字符串 | 一个字段承担放行与降级两条通道 |

决策 3（ADR-0008）只解决了 #1。本 ADR 解决 #2。**#3 仍未解决**（见 §七）。

## 二、先厘清机制：`豁免词` 里到底装了什么

ADR-0008 §2.1 把语境守卫描述为「否定/免责 → 降级」。**实施中发现这个定义偏窄**，
按它分类会把一半的词判成「未归类」。按现网 94 个条目实测，实际有四种形态：

| 形态 | 数量 | 例 |
|---|---|---|
| 否定 | 26 | `does not treat` · `cannot cure` · `不能治疗` · `无法治疗` |
| 弱化/替代表述 | 25 | `comfort` · `gentle` · `relieve engorgement` · `放松` |
| 溯源/同源表述 | 14 | `inspired by` · `参考自然哺乳` · `借鉴` · `自然奶阵` |
| 风险降低表述 | 7 | `reduce the risk of clogged` · `risk of plugged ducts` |
| 免责声明 | 6 | `not a medical device` · `不是乳腺炎治疗设备` |
| 未归类 | 11 | 需法务裁定 |

**统一的定义**（不再举例式描述）：

> **语境守卫 = 出现该词，表明该规则所指的主张并未被作出（否定 / 免责 / 溯源 / 弱化替代），
> 从而把该规则降级，而不是放行。**

## 三、拆分：94 = 84 + 10

现网 `豁免词` 共 94 个条目。与白名单表逐词比对后：

| 项 | 数量 |
|---|---|
| 现网 `豁免词` 条目 | 94 |
| − 白名单词的**重复登记**（见 §3.1） | 10 |
| = 语境守卫 | **84** |
| ＋ 骨架独有、现网未登记（见 §3.2） | 5 |
| = 语境守卫表 | **89** |

### 3.1 那 10 个「守卫」其实是白名单词

`FDA cleared` / `FDA-cleared` / `FDA registered` / `low noise` / `quiet mode` /
`low-decibel` / `suction level` / `adjustable suction` / `comfort` / `gentle`

它们是白名单表已有的词，被人手抄进了 `豁免词`。**不是守卫。**

**但判据不是「它在不在白名单表里」，而是它走的通道**：

| 词 | 所在带 | 通道落点 | 机制 |
|---|---|---|---|
| `FDA cleared` 等 8 词 | T6.1 / M01 / M02 的带 | `auto_pass` | **放行** → 白名单的活 |
| `comfort` / `gentle` | T2.1.2.pain-relief 的带 | `manual_review` | **降级** → 守卫的活 |

`comfort` / `gentle` 因此是**跨表的**：它们登记在白名单表（`status: quarantined`，
未通过「第三方可复核」准入），却作用在降级通道上。
这正是 ADR-0008 §2.5 记下的边界 —— **放行 ≠ 降级**：

> 隔离的含义是「这个词不给疼痛主张放行」，不是「这个词什么都不做」。

所以装载层（`vocab.py`）的组装规则是：

```
降级带 = 语境守卫表(downgrades)  ∪  白名单表中 status=quarantined 且目标为降级带的词
```

### 3.2 5 个词只在骨架里，现网没有

`cannot prevent` · `risk of clogged` · `缓解涨奶` · `may help` · `supports your natural`

反向的缺口：**骨架已接线，现网 `豁免词` 未登记**。
若只从现网侧建表，这 5 词会静默消失。两来源必须合并。

## 四、为什么不能靠「已接线」当准入开关

第一版实现把 84 个守卫**全部**接入运行时，等价性验证立刻报出行为变更：

```
T1.1.medical-cure    丢失 [] ／ 多出 29 个词
T1.2.medical-prevent 丢失 [] ／ 多出 10 个词
```

**这是对的，验证挡住了它。** 那 39 个词是现网登记了、骨架重写时剔除的
（`REWRITE_NOTES.md` 里没有记录原因 —— 本身就说明剔除是无记录的）。

按 ADR-0008 §三，「一条语境规则该不该存在」是**法务**的决定，开发者不得自行增删。
所以表用**三态登记**（与白名单表同构）：

| 状态 | 数量 | 含义 | 是否参与运行时 |
|---|---|---|---|
| `active` 已接线 | 46 | 骨架降级带原有 | ✅ |
| `pending` 待法务定性 | 39 | 现网登记，骨架未收录 | ❌ |
| `misrouted` 走错通道 | 4 | 落在放行带（见 §五） | ❌ |

**共 89 词 = 46 + 39 + 4。** 与搬迁前的带**逐词相同**。

### 等价性验证（搬迁不得改变行为）

`wire_context_guards.py` 在搬迁后立即回算 `vocab.down_bands`，与搬迁前逐词比对：

```
✅ T1.1.medical-cure      12 词，逐词一致      ✅ T2.1.1.milk-supply   6 词，逐词一致
✅ T1.2.medical-prevent    5 词，逐词一致      ✅ T2.1.2.pain-relief  14 词，逐词一致
✅ T1.5.duct-unclog        3 词，逐词一致      ✅ T2.2.mimic-claim     8 词，逐词一致
```

并通过端到端 A/B（旧：从规则文件读带 ｜ 新：从独立表组装）：
`score.py --json` 输出 **2762 字节逐字节完全一致**。

> 从没验证过等价的重构，等于没有重构。

## 五、★ G3：4 个词走错了通道（需 Owner / 法务裁定）

| 词 | 现网来源 | 实际占据 |
|---|---|---|
| `FDA 注册` | H06 | `T6.1.regulatory-status` 的 **auto_pass** 带 |
| `silent mode` | M01 | `T2.2.quiet-claim` 的 **auto_pass** 带 |
| `静音模式` | M01 | `T2.2.quiet-claim` 的 **auto_pass** 带 |
| `suction settings` | M02 | `T2.2.suction-claim` 的 **auto_pass** 带 |

这 4 个词**证成主张**（客观事实 / 产品参数），属白名单机制，却被登记在 `豁免词` 里。
其中 `silent mode` / `静音模式` 尤其需要看：M01 规则判的就是 `silent` / `静音`，
而含 `静音` 的 `静音模式` 直接落到 `auto_pass` —— 这是**同一类词同时判险又放行**，
与 `reduces pain`（EB-R011）是同一种结构。

**本 ADR 只记录，不裁定。** `wire_context_guards.py` 明确不动这 4 个词 ——
语义裁定不是开发者的权限（ADR-0008 §三分工表）。

## 六、实施：把「读另一个文件」做成结构

| 动作 | 产物 |
|---|---|
| 语境守卫抽为独立表，每词声明 `downgrades` | `research/governance/skeleton/context-guards-v1.json` |
| 从规则库取出守卫词（6 条规则 48 词 → 0） | `rules-v1.json` |
| **唯一装载入口**，三来源物理分离 | `research/governance/skeleton/vocab.py` |
| 五项不变量机检（退出码区分结构/政策） | `lint_context_guards.py` |
| 搬迁 + 等价性验证 | `wire_context_guards.py` |
| `score.py` 拒绝从规则文件读词表 | `score.py`（`vocab is None` 即 `SystemExit`） |

**关键改动**：`rules-v1.json` 现在**不持有任何词表** ——
它只有 `match.keywords`（判险词，唯一产生命中的来源）与 `effect`（通道声明）。
降级词从独立表组装，放行词从另一张独立表组装。**结构上不可能混。**

`vocab.assert_channels()` 在**每次装载**时跑 W1/W3/G1/G3/G4，违反即 `exit 3`，
不降级为警告 —— 从没触发过的守卫等于没有守卫。

## 七、所有权分离：一个实测出来的架构结论

ADR-0008 §六 遗留 #3 记「守衡 app 对该 Base 只有读权限」。本次把读写对照测全了：

| 操作 | 对**用户拥有的**主 Base | 对 **app 自己创建的** Base |
|---|---|---|
| 读 tables / fields / records | `code 0` ✅ | ✅ |
| 建表 / 建记录 / 删记录 / 删表 | `HTTP 403 · 91403 Forbidden` ❌ | ✅ |
| Base 改名 | — | ✅（`PUT /bitable/v1/apps/{token}`） |
| 设链接分享为组织内可编辑 | — | ✅ |
| 加周健为 full_access 协作者 | — | ✅ |

**这带来一个比「权限不够」更好的结论：机制分离可以做成所有权分离。**

```
人写规则      → 主 Base「吸奶器广告文案·品线内容边界风控」（app 只读，物理上改不了）
app 维护词表  → 「品线内容边界-机器词表」（人可读可编辑，词是程序产出的）
```

app 改不了人的规则库，人也不靠手抄维护词表 —— 这正是 ADR-0008 想要的，
而且**不需要任何开关或约定来维持**。

## 八、后果

**正面**
- `豁免词` 这个「一个字段装两种机制」的字段**被结构消灭**（词表不在规则文件里了）
- 89 个守卫词有了可机检的接线状态；39 个未接线词此前**完全不可见**
- G3 违反可机检，`silent mode` 这类「判险词同时放行」不再靠人眼看
- `score.py` 无法再从规则文件读词表 —— 读取路径错了会直接 `exit 3`

**负面 / 代价**
- 语境守卫表与原 Base **不在同一个 Base**（因 app 无写权限），管理面分成两处
- 39 词待法务定性、4 词待裁定，未接线期间它们的降级效果与现网一致（即：不生效）
  > ★ **2026-09-17 更正（ADR-0014 §二）：本行「（即：不生效）」是错的，方向反了。**
  > 旧 `豁免词` 的语义是**放行**，不是「不生效」——同批次天然对照实测：
  > `Savannah-20260825` 的 `i=265` 含豁免词 → 源表 0 命中·绿，同批 `i=270/271`
  > 不含 → 命中 `H07,U04`·红。所以未接线期间的真实差异是
  > **放行 → 满档 `auto_reject`**，是一处回归，不是等价。
  > 本行的措辞把一个回归读成了等价，39 个词因此停在这里没有被追。
  > 决策结论不变，只更正这句事实断言。
- `downgrade_band` 这个名字仍在（第三处同病），改名会让 `score.py` 失效，
  属独立变更，本 ADR 只标注不动手
- ADR-0008 §2.1 对语境守卫的定义偏窄，本 ADR §二已更正

## 九、遗留待决

1. **4 个 G3 违反词**（`FDA 注册` / `silent mode` / `静音模式` / `suction settings`）：
   移入白名单表，还是从词表删除？—— 需 Owner / 法务裁定
2. **39 个待法务定性的守卫词**：删除，还是补一条规则？
3. **39 词的成因未记录**：骨架重写时剔除它们，`REWRITE_NOTES.md` 无任何说明。
   需确认是「有意剔除」还是「抄漏」—— 两者处置完全不同
4. **决策 3 步骤 B（删规则库 `安全词` 行）仍受阻**：app 对主 Base 无写权限，
   需有编辑权限的人执行，或把 `守衡` 应用加为**可编辑**协作者
5. ADR-0006 第 1、2 条的落地排期
6. `downgrade_band` 是否改名以让通道显式化
