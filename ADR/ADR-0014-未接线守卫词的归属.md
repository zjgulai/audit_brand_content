## 一、这件事的形状：不是「漏了几个词」

D15 立案时的表述是「源表漏放 3 条」。逐行对账推翻了它：源表那次放行是**对的**，
错的是迁移把 `treat yourself` 从**放行**搬成了**降级**。

但真正的问题不在那 3 条。把旧规则 94 个豁免词逐词喂给引擎实测之后：

| 实测带 | 条数 | 含义 |
|---|---:|---|
| `pass`（仍放行） | **2** | `silent mode` / `静音模式`（D3 法务定案的成果） |
| `downgrade`（降级） | 13 | 含 `treat yourself` —— 已造成 3 条误拦 |
| **无带** | **21** | 词在守卫表里，但 `wired=false` → 对引擎零影响 → 规则按满档判险 |

而守卫表里 `wired=false` 的词一共 **39 个**，不是 21 个 —— 21 只是其中
「自身就会命中本规则」的那部分（会自我命中的词，其接线状态才在引擎里有可观测差异）。

**39 个词的状态是同一个：挂了 `status_note="待法务定性"`，然后什么也没发生。**

## 二、更正 ADR-0009 §八 的一句事实断言

ADR-0009 §八「负面 / 代价」写着：

> 39 词待法务定性、4 词待裁定，**未接线期间它们的降级效果与现网一致（即：不生效）**

**括号里的那句是错的，而且方向反了。** 旧 `豁免词` 的语义是**放行**，不是「不生效」。
这不是从文档抄来的推论 —— `audit_migration_fidelity.py` 轴 0 每次运行都实测一次
同批次天然对照：`Savannah-20260825` 的 `i=265` 含豁免词 `treat yourself` → 源表
**0 命中·绿**；同批 `i=270/271` 不含 → 源表 **命中 H07,U04·红**。同一次扫描，
含的绿、不含的红。

所以那句话的实际意思是：「新系统里它不生效」= 「旧系统里它也不生效」。
**前一半对，后一半错。** 旧系统里它做了一件事：放行。

| | 旧系统（`豁免词`） | 新系统（`wired=false`） |
|---|---|---|
| 词对引擎的作用 | **放行**（不命中） | **无** |
| 规则最终处置 | 不判险 | **满档 `auto_reject`** |

这句断言造成的后果是具体的：它把一个**回归**（放行 → 满档判险）读成了**等价**。
读起来像结论，所以没有人再去查。39 个词因此停在这里。

> 本 ADR 依 `ADR/README.md` 规则 1 新开，不改写 ADR-0009 的结论；
> 只在 ADR-0009 §八 那一行加一条指向本节的更正指针。

## 三、实测：39 个未接线词的真实暴露面

判据不建在任何分类字段上，只建在**引擎自己的输出**上。

**能力测量**（把词单独喂给引擎，看它拿到什么带）：36 个旧豁免词会自我命中，
三桶 2/13/21（守恒 2+13+21=36）。

**发生测量**（在 291 条存量语料上数实例）：

| 量 | 值 |
|---|---:|
| 94 个旧豁免词里，在本语料**出现过**的 | **13** |
| 94 个旧豁免词里，**零实例**的 | **81** |
| 39 个未接线词里，零实例的 | **38** |
| 39 个未接线词里，有实例的 | **1** —— `soulage les engorgements` |

**那唯一一个有实例的词，没有引入分歧。** 它出现在 4 条记录
（`#136/#166/#168/#169`，广告名 `w1-卖点图` / `w1-卖点视频`），
源表判 `H07,M01 · 高危·红`，引擎判 `auto_reject / L4 / H07,M01` ——
**两者逐条一致**（它要降的是 H01，而这 4 条 H01 未命中）。

结论要写全，两个数都要给：

- **暴露面 21**（词在未接线状态下按满档判险，其中 8 个是中文否定式）
- **本语料实际分歧 0 条** —— 其中 38 个零实例、1 个与源表一致
- 已发生的 3 条误拦来自 `treat yourself`，它**是接线的**（走了错的通道），不属于这 39 个

> ★ 本节更正了 2026-09-17 早先一句过头的话：「只有自我触发的 36 个词，
> 豁免才真正生效过」。自我触发是**能力**测量（合成输入上能否观测到差异），
> 语料实例是**发生**测量，两者不能互相代替。36 与 13 说的不是同一件事。

## 四、根因：断在「已识别」与「已登记」之间

D12 把「未决事项写在哪」收敛成一处：`$decision_queue`。该处的 `$decision_queue_note`
自己写着判据：

> 每一项必须是**可选的题**……并且写明 `default_if_unanswered` ——
> 「沉默等于哪个选项」必须答得出来。**没有默认值的未决项不是未决，是遗忘。**

查账结果：**队列 22 项，全部 `answered`，`open` 项 0 条。**

也就是说，这 39 个词**从来没有进入过唯一该写的位置**。它们的「待法务定性」
写在一个词表字段里（`status_note`），而那个字段没有 `options`、没有
`recommended`、没有 `default_if_unanswered` —— 按 D12 自己的判据，那不是未决项，
是遗忘。

断链的形状是这样的：

```
ADR-0009 §二  已识别：guard_type=未归类「需法务裁定」        ✅ 识别到了
ADR-0009 §八  已读错：把它读成「与现网一致（即：不生效）」    ❌ 于是不必急着裁定
词表 status_note 已写下：「待法务定性」                       ⚠ 写了，但没有题的形状
$decision_queue 已登记：0 条                                  ❌ 唯一该写的位置是空的
```

**「已识别」不等于「已登记」。** 中间那一环没有制品、没有闸门，
所以少了一环也不需要任何人做错什么。

## 五、本次最重的一条：`乳腺炎治疗设备` 是旧表的一个假阴孔

H02（医疗功效 · 预防/治疗乳腺炎）的 `exceptions` 里有两条并列的词：

```
"不是乳腺炎治疗设备", "乳腺炎治疗设备"
```

第二条**不是免责声明 —— 它就是 H02 要抓的那个主张本身**。实测确认：
`乳腺炎治疗设备` 不在 H02 的 `keywords` 里，但 `乳腺炎` 在；
而旧 `exceptions` 的语义是**放行**。

也就是说：**旧系统对写着「乳腺炎治疗设备」的文案是放行的。**
按同口径（子串）判定，一句话只要带上这个词，H02 就不再拦它。

现在它 `wired=false`，所以实测 `judge("乳腺炎治疗设备")` → `auto_reject`
（同时命中 T1.1.medical-cure 与 T1.2.medical-prevent）——
**这个洞是被意外关上的，不是被决定关上的**。

这条要单独拎出来，不能混在批量接线里：**它不是「这个词该不该降级」的问题，
是「旧表里有一条写反的词」的问题。** 忠实迁移会把这个洞原样搬进新系统。
（未逐条互查的还有同一 `豁免词` 字段在另外 20 条规则里的内容 —— 见 §十 遗留。）

## 六、「非主张」没有归宿：两个通道的判据合起来容不下它

两处判据都是制品里写死的：

| 表 | 判据（原文） |
|---|---|
| `whitelist-v1.json` · `admission_criterion` | 能否被第三方独立复核为**真/假**（R5-E） |
| `context-guards-v1.json` · `mechanism.semantics` | 出现在文案中时，表明该规则所指的主张**并未被作出**（否定 / 免责 / 溯源 / 弱化替代） |

`treat yourself`（犒劳自己）两条都不满足：它不是可证真假的**主张**，
也不是对某个主张的**取消** —— 它是**另一个**主张（自我照护建议）。
实测中它落在 `guard_type=未归类`，被接成**降级**，而旧系统对它是**放行**。

`guard_type=未归类` 全表 7 个：`or cure` `or treat` `soulage les engorgements`
`soulager les engorgements` `treat yourself` `乳腺炎治疗设备` `gently`。

**「未归类」不是一条通道，是表层词素推导留下的残渣桶。** 词掉进去之后，
处置由默认值决定，而不是由任何人为它做的决定。

> ★ **撤回一条我自己提过的说法。** 我在 2026-09-17 的提案里写过
> 「旧系统的 `exceptions` 里本来有『非主张』这一档，新设计把它弄丢了」。
> **这句不成立**：`rules_raw.json` 里 H01/H02/H07 的 `exceptions` 都是
> **扁平的字符串数组，没有任何档位**；新表的 `guard_type` 值域里也没有这一档。
> 「非主张」从来没有被显式建立过，所以谈不上弄丢。
> 真实情况比那句话轻、也比那句话难：**旧系统用「一个字段装两种机制」把它兜住了，
> 新设计把放行与降级正确地拆成两个通道之后，这一类词就没有位置了。**
> 这不是迁移丢了一档，是**分离之后空出来的一格还没被填**。
> 记录留在这里而不是删掉 —— 免得下一版又有人从「旧表里本来有」推起。

## 七、决策：四道题，只写在一个地方

| 题 | 覆盖的未接线词 | 问的是什么 |
|---|---:|---|
| `Q23` | 18（否定 16 + 免责 2） | 语义档明确、同族已接线的这批，接不接 |
| `Q24` | 1（`乳腺炎治疗设备`） | 假阴孔：迁移、剔除，还是当成普通降级词 |
| `Q25` | 2（`or cure` `or treat`）+ 已接线的 `treat yourself` | 「非主张」走通道还是走准入 |
| `Q26` | 18（弱化 10 / 风险降低 5 / 溯源 1 / 未归类 2） | 不自我命中的那批，接不接 |

**守恒（`V45d` 每跑一次都验）**：18 + 1 + 2 + 18 = **39** = 未接线集合，
无缺口、无多余、无重复认领。认领写在各题的 `covers_unwired_guards` 字段里。

四道题的可选项、代价、推荐、沉默后果，见
`research/governance/skeleton/legal-decisions-v1.json` 的 `$decision_queue`。
本 ADR 不复制。

## 八、机器闸门：`V45d`

```
V45d  每个未接线的守卫词都指向一条可决策的未决项
      （被 ≥1 条 open 认领，或词条点名一条已答的 Q/D）；
      认领并集恰好等于未接线集合；未接线 ≤ 39（棘轮）
```

判据与 `V43a` 同形 —— 空缺本身允许存在，但**空缺必须指向一个可决策的未决项**：
不指向 = 遗忘（红），指向 = 待决（绿）。两者在制品上看不出差别，只有查得出。

- **反向对照**在门内，不是靠人记得跑：从队列里真抽掉一条认领，判据必须变红。
- **棘轮**：接线之后 `未接线 < 39`，本门转红并要求收紧阈值 —— 否则它守的是一个过期的现状。

## 九、开发者异议与本次自陈

依 `ADR/README.md` 规则 5，建议与异议一并留档。

1. **我不建议把 Q23/Q26 合成一道题。** 它们看起来都是「接不接」，
   但判据不同：Q23 的词会自我命中（接线与否在引擎里有可观测差异），
   Q26 的词不会（要靠「别的词命中时把它降级」才生效）。
   合成一题会让后者的证据被前者的实测掩盖。
2. **我在本次工作中撤回了两条自己的结论**，两条都写进制品而不是删掉：
   - 「甲/乙分类（14/14）」—— 建立在 `guard_type` 这个自带「待法务确认」标注的
     启发式上，且把源表写明的三层设计压成两层。撤回记录在
     `audit_migration_fidelity.py` 轴 1b 段。
   - 「旧系统本来有『非主张』这一档」—— 见 §六 的撤回框。
3. **Q24 的选项 B（忠实迁移）我认为不该被选**，但它必须留在选项里 ——
   因为「与现网一致」是这个项目里**最容易被当成正确性证明**的一句话，
   而 ADR-0009 §八 已经证明它可以是错的。

## 十、后果与遗留

**正面**
- 39 个未接线词从「不可见地停着」变成「逐词可决策」，且由 `V45d` 持续守着
- ADR-0009 §八 那句方向反了的断言被更正并留档，不再被后续 ADR 引用
- 判据从「分类 + 措辞」换成「把词喂给引擎看它拿到什么带」，不再依赖任何待确认字段

**负面 / 代价**
- 四道题会占用一次法务档期；在作答之前，39 个词的降级效果仍然不生效
- 本语料分歧 0 条 → **本次不产生任何投放侧移交，也不触发复扫**（与 D15 的结论一致）
- `V45d` 的棘轮阈值 `39` 在校准之前是硬编码的现状值

**遗留待决（不写在这里，按 D12 落入 `$decision_queue`）**
- 另外 20 条规则的 `豁免词` 字段尚未逐条互查「有没有第二条 `乳腺炎治疗设备`」
  —— 这是 Q24 的执行前置，不是独立的新问题
- 39 个词若经裁定**不接线**，守卫表的 G2 不变量（每个守卫词至少声明一条
  `downgrades`，否则是死重）需要补一条「已裁定不接线」的合法态
