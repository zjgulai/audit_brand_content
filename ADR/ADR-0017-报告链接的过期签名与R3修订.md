# ADR-0017：报告链接的过期签名（R3 修订）

- 状态：`accepted`（2026-10-25 委托方裁定「T-403 走 A：真做签名 URL」）
- 日期：2026-10-26
- 编号属主：`audit-multi-content-1d`
- 关联：Playbook §8.8（D-2 落地规格）· `base/report_store.py` 的 R3 · T-403
- 前置：本 ADR **修订** R3，不推翻 R1/R2

---

## 一 · 要解决的问题

Playbook §8.8 对报告的链接有三条要求：

| 要求 | 现状 |
|---|---|
| 链接带**过期签名** | ❌ 无。`ReportStore._url()` 恒返回 `static_base/reports/<id>.md` |
| **过期不等于失效** —— 过期后可重签，**文件不删** | ❌ 无过期概念 |
| ACL 按案件参与人 | ✅ `can_read_content` 已在用 |

`skeleton`/`api` 里 `hmac` / `itsdangerous` / `?sig=` **0 命中**，
`_valid_url()` 还要求 URL `endswith(".md")` —— 带查询串必然判 `bad_url`。

所以「重签返回新 url」这句话，在改之前**产不出真东西**。

## 二 · R3 原文与本次修订

**原文**：

> **R3**：URL 只由静态 base 拼出，必须是 `.../reports/<id>.md`。

**它真正防的是什么**（读 `_check_static_base` 与 `_valid_url` 的注释可知）：
链接不许指向**渲染服务**、不许是 `/api/` 端点。也就是「链接指向文件本体」。

**`endswith(".md")` 只是那件事的实现手段**，不是目的。加了 `?exp=&sig=` 之后
链接仍然指向 `reports/<id>.md` 本体，只是多了一个可验证的时效凭据 ——
**目的达成了，手段要改**。

**修订后的 R3**：

> **R3（2026-10-26 修订）**：URL 必须指向静态 base 下的 `reports/<id>.md` 本体，
> 允许且仅允许一个查询串，键集合恒为 `{exp, sig}`。
> 仍然**禁止**指向渲染服务或 `/api/` 端点（`/api/`、`render`、`renderer`
> 三个子串照旧拒绝）。

★ **不变的**：不许指向渲染服务；不许落在 `/api/`；文件名必须与 `report_id` 一致。
★ **变了的**：尾部允许 `?exp=<unix>&sig=<hex>`。

## 三 · 三态语义：有签名 / 无签名 / 坏签名

这是本 ADR 最关键的一节。三种情形**必须分开**，否则「打不开」会有二义。

| 情形 | 判定 | 理由 |
|---|---|---|
| **无 `exp`/`sig`** | 走**原有**路径：session + `can_read_content` | 兼容已发布报告（索引里存的就是无签名的 URL）；内部页面用这条 |
| **有 `exp` 与 `sig`，且签名有效、未过期** | 走**原有**路径 **+** 签名校验 | ★ §8.8 两行同时成立：链接带签名 **且** 按参与人 ACL。签名不是「免登录通行证」 |
| **有其一或签名无效或已过期** | **403**，即使请求者是参与人 | 过期的意义就是「这扇门关了」。若参与者仍能读，过期就只是装饰 |

★ **为什么签名不替代 ACL**：§8.8 的 ACL 那一行写的是「未参与人打不开」。
如果签名能替代 ACL，任何拿到链接的人都能读客户素材 —— 而签名的对象是
「链接」不是「人」。两条同时成立才既满足「可分享」又满足「最小可见」。

★ **为什么无签名仍然放行**：已发布报告的索引记录里存的是无签名 URL
（`report_id` 内容寻址、不可变）。若强制所有 URL 必须带签名，
**存量报告全部打不开**，而这与「文件长期保留」直接冲突。
所以签名是**追加的一层**，不是替换。

## 四 · 密钥从哪里来、怎么轮换、丢了怎么办

| 问题 | 决定 | 依据 |
|---|---|---|
| 从哪来 | 环境变量 `REVIEW_REPORT_LINK_SECRET`，**生产必须显式给** | 与其它 `REVIEW_*` 一致；不许有默认值 |
| 没给会怎样 | `ReportStore` 照常构造、照常发布与读取；**只有 `resign` 返回 503** | 签名缺失不该让整个报告系统不可用；但**不许**降级成「发一个无签名的『新链接』」—— 那正是「读数变绿代替能力建成」 |
| 多长 | ≥ 32 字节（64 hex）。短于此直接拒 | HMAC-SHA256 的密钥短于 32 字节会明显削弱强度 |
| 怎么轮换 | **双密钥窗口**：`REVIEW_REPORT_LINK_SECRET`（新，用于签）+ `REVIEW_REPORT_LINK_SECRET_PREV`（旧，只用于验）。验证时两个都试 | 轮换时旧链接在 TTL 内仍然打得开，不会一夜之间全断 |
| 丢了怎么办 | 已发出且未过期的链接**立即全部失效**（这是**正确**行为，不是事故）：无密钥即无法验证，只能重签 | 与 TS-32「session 库不备份、故障后重登」同一条思路：一个无法证明的凭据不该被信任 |
| 存哪 | 只在进程环境里，**不落盘、不入仓、不进索引** | `.gitignore` 已挡 `*.pem` / `*credential*` / `*secret*`；本 ADR 不新增任何落盘 |

## 五 · TTL

默认 **3600 秒（1 小时）**，可用 `REVIEW_REPORT_LINK_TTL` 覆盖。

依据：报告链接是「给人打开看一眼」的，不是长期外链。1 小时足够一次评审会；
`exp` 写在 URL 里，所以 TTL 只影响「新签出来的有多长命」，
不影响已经发出去的（它们各自带着自己的 `exp`）。

**上限**：允许配置为 30 天（2592000s）。超过上限直接拒 ——
一个「永不过期」的签名链接等于没有过期语义，而这个端点存在的理由就是过期。

## 六 · 签名算法（要能跨语言复算）

```
canonical = report_id + "\n" + str(exp)          # UTF-8
sig       = HMAC-SHA256(secret, canonical).hexdigest()   # 64 hex
url       = static_base + "/reports/" + report_id + ".md?exp=" + exp + "&sig=" + sig
```

- **只签 `report_id` 与 `exp`**，不签 ACL、不签租户：签名回答的是
  「这个链接是不是我们发的、发到什么时候」，不是「谁能看」。
- **比较用 `hmac.compare_digest`**，不用 `==`。
- **`exp` 用整数秒（UTC）**，不用浮点、不用本地时区。
- **参数顺序固定** `exp` 在前 `sig` 在后；解析时按集合比，不按顺序。

## 七 · 本 ADR 自己也要能被证伪

执行点：`tools/verify_report_resign.py`。判据清单见 §八，每条都带反向对照。

**若本 ADR 是错的，最先红的会是**：把 `_valid_url` 的签名分支删掉 →
「签名 URL 能打开」红；把 `exp` 检查去掉 → 「过期 URL 打不开」红；
把 `sig` 比较改成恒 True → 「篡改 URL 打不开」红。

## 八 · 判据（交给 T-403 的实现）

| # | 判据 | 为什么 |
|---|---|---|
| R-1 | `resign` 返回 200，且 `url` 带 `exp` 与 `sig` | 票面① |
| R-2 | **旧文件 sha256 未变** | 票面②（重签不碰正文） |
| R-3 | 旧报告仍在权威 `state["reports"]` 且索引记录未变 | 票面③ |
| R-4 | 签名 URL **能打开**（参与人 + 有效签名） | Q1-1 |
| R-5 | **过期** URL 打不开（即使参与人） | Q1-2 |
| R-6 | **篡改** `sig` 一位 → 打不开 | Q1-3 |
| R-7 | 篡改 `report_id`（换一个真存在的报告）→ 打不开 | 防「签名跨报告复用」 |
| R-8 | 无签名 URL 仍能读（兼容） | 存量报告不许坏 |
| R-9 | 密钥缺失 → `resign` 503，且**不返回无签名的新 URL** | 不许把「没密钥」做成「看起来成功」 |
| R-10 | TTL 超上限（30d）→ 构造期拒 | 上限要有执行点 |
| R-11 | 轮换窗口：旧密钥签的链接，配上 `..._PREV` 仍可验证 | 轮换不断链 |

## 九 · 明确不做

- **不改报告正文的任何字节**（R2 仍然成立：IR 版本变才产生新 report_id）。
- **不做「撤销单个链接」**（没有黑名单）：过期即撤销，重签即新。要立即作废
  就换密钥（那会让全部链接失效 —— 这是有意的代价）。
- **不在索引里存签名**：签名是**链接的属性**，不是报告的属性。
  存进去会让「同一报告的两个有效期」变成两条索引记录，而索引是只追加的。
