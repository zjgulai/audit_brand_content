## 〇 · 一句话

**委托方给的方向与盘上的事实不一致，本 ADR 以实测为准，并把「不一致」本身记下来。**

三处实测否决/更正（详见 §一）：tokenhub **没有** gemini；`gemini-3.8-flash` **现在可用**
（早上的 429 是瞬时限流）；vod 可用的 gemini 有 6 个且都通。

结论：**vod 仍是音画对齐的唯一落点**（tokenhub 一家的 `audio` 输入是 0 家），
但**必须加多模型回落 + 429 重试**，不能把可用性押在单个模型上。

## 一 · 三处实测（都可复现）

### 1.1 tokenhub 里没有 gemini —— 委托方的方向与事实不符

```
tokenhub: 共 123 个，gemini 0 个
  （无）
vod: 共 73 个，gemini 13 个
  ['gemini-3.7-flash', 'gemini-3-flash-preview', 'gemini-3.1-flash-lite', 'gemini-3.8-flash',
   'gemini-robotics-er-2-preview', 'gemini-2.5-flash', 'gemini-3.5-flash-lite',
   'gemini-3.1-flash-lite-preview', 'gemini-4-argon', 'gemini-2.5-pro', 'gemini-3.6-flash',
   'gemini-3.5-flash', 'gemini-3.1-pro-preview']
```

复现：`GET {base}/models`（两个网关各一次，只读，不烧 token）。见
`tools/multimodal_client.py --models`（本票新增）。

★ **本地缓存也印证同一结论**：`~/.cache/magpie/models/tokenhub.json`（fetched 2026-10-21）
里 `gemini` 命中 **0**。缓存与实时两侧一致，所以这不是缓存过期。

**所以「增加 tokenhub 中的 gemini-3.8-flash」在盘上做不到。** 三种可能，都不该由我猜：

| 可能 | 怎么验证 | 处置 |
|---|---|---|
| tokenhub 有但我们这个 key 看不到 | 换 key 或查租户配额 | 需要委托方在控制台确认 |
| 模型名不同（如走别名/路由） | 列出 tokenhub 全部 123 个 id 逐个核 | 已做：无 gemini 字样 |
| 需要单独开通 | 网关侧申请 | 委托方决定是否要开 |

**本 ADR 不因此阻塞**：vod 侧已有 6 个可用 gemini，方案按 §二 落地。

### 1.2 `gemini-3.8-flash` **现在可用** —— 早上那条读数是瞬时故障

| 模型（vod） | 结果 |
|---|---|
| `gemini-3.8-flash` | **ok** |
| `gemini-3.7-flash` | ok |
| `gemini-3.6-flash` | ok |
| `gemini-3.5-flash` | ok |
| `gemini-3.1-flash-lite` | ok |
| `gemini-4-argon` | **error / HTTP 429 `request is limited`** |

```
gemini-3.8-flash             → ok
gemini-3.7-flash             → ok
gemini-3.6-flash             → ok
gemini-3.5-flash             → ok
gemini-3.1-flash-lite        → ok
gemini-4-argon               → error  网关返回 HTTP 429：{"error":{"code":"limited",...
```

★ **必须更正 T-432 那次提交里写死的一句话**：`LIVE_PROBE_20261026` 把
`vod:gemini-3.8-flash` 记成 `error(429 rate_limited)`，并据此说「T-435 的音画对齐
默认落 gemini-3.1-flash-lite，不是 3.8」。**那句话把「某时某刻的一次 429」
写成了「这个模型不能用」** —— 而 429 是**限流**，不是**不可用**，两者完全不同：
前者重试就好，后者要换模型。这正是 §2.4.1 第 5 行「一个会过期的读数没有任何东西
在它过期时变红」的形状。

改法两条，缺一条都还会重犯：
① 读数带**时刻**且**标明它是一次探测**（`probed_at` + `attempts`）；
② 判据断言「429 必须落 `retryable`，不许落 `unavailable`」——由 §三 的重试机制执行。

### 1.3 vod 的 429 是真问题，但它有解

`gemini-4-argon` 仍然 429，说明**限流是模型级的、会轮转的**，不是坏掉。
所以不可用的形态不是「换一个固定的模型」，而是：

> **多模型回落 + 429 重试（带退避）+ 每次调用记录「实际用了哪个模型」。**

单模型固定会周期性地被打到 429，而那时整个媒体线停摆 —— 这是把可用性押在一处。

## 二 · 网关策略（本 ADR 的正面决定）

### 2.1 分工不变，但每侧都是**一组**不是**一个**

| 任务 | 必需介质 | 主选 | 回落链（按序） | 依据 |
|---|---|---|---|---|
| `scene_semantics` | image | tokenhub `glm-5.3-flash` | vod `gemini-3.8-flash` → `gemini-3.7-flash` → `gemini-3.5-flash` → `gemini-3.1-flash-lite` | 画面语义两侧都能做；tokenhub 为主（委托方 2026-10-26） |
| `mark_symbol` | image | 同上 | 同上 | 同上 |
| `av_alignment` | **video + audio** | vod `gemini-3.8-flash` | vod `gemini-3.7-flash` → `gemini-3.6-flash` → `gemini-3.5-flash` → `gemini-3.1-flash-lite` | **只有 vod 的 gemini 家族声明 `audio`**；tokenhub 的 glm 家族 `audio` 为 0 家 |

⚠️ **回落链里不许出现 tokenhub 做 `av_alignment`** —— 它会返回一个「看起来分析过了」
的结果而根本没看音轨。这条由 `base/multimodal_provider.py` 的 `required_media`
闸门在调用**之前**拒，`gateway_supports()` 是它的第二道。

### 2.2 429 / 超时 / 5xx 的处置：重试，不换语义

```
429 → 指数退避重试同一模型（最多 3 次，1s/2s/4s）
      ↓ 仍 429
      落到下一个模型（同一网关）
      ↓ 整条链都失败
      status = "error"，且 reason 里带「整条链都失败 + 每个模型的最后一次读数」
```

**三条不许**：
1. **不许**把 429 落成 `ok` 或 `untested` —— 它是 `error`（测了但失败），
   与 `untested`（没测）不同档。
2. **不许**为了「跑通」把 `av_alignment` 降级成 `scene_semantics`
   —— 那会把「没听音轨」说成「听了没问题」。
3. **不许**在回落成功时静默换模型：结果里必须带 `model_used` 与 `fallback_from`，
   否则「这次结论是哪一版模型给的」在报告里查不出来。

### 2.3 为什么不做「按价格自动选」

委托方 2026-10-26 的决定是**质量优先于 ROI**（方案 §〇 第 1 条）。
按价格自动选会让同一张图在不同时刻被不同模型看，**报告不可复现**。
回落顺序是**写死的**、可审计的，价格只作为排序时的次要理由记录在案。

### 2.4 出境面不因回落而变大

回落链跨了两个网关 ⇒ 出境面是**两侧的并集**。这不是自动成立的，必须有断言：
`egress_manifest(task)` 必须列出回落链上**每一个**接收方；`registration_for()`
只登记**这次真会用到**的那几条。判据在 `verify_multimodal_client`（现 65 条）。

## 三 · 「留多久」与「送什么」已在 T-438 落地，本 ADR 只补一处

`base/multimodal_egress.py` 已做：快照 + 到期时刻（算出来的）+ append-only 落盘 +
读不出的文件不删 + fail-closed 到期判定。

**本 ADR 补的一处**：回落链让「送出去给谁」变成**动态**的（取决于哪一次回落成功）。
所以快照必须能回答「这一次实际用了哪个网关」——
落在 `analyze()` 返回的 `model_used` / `gateway_used` 上，随 L1 观察进权威。
**不许**只记在日志里（日志会轮转，而审计要的是可重放的证据）。

## 六 · 这份 ADR 自己的可证伪性

| 断言 | 怎么复核 | 若它错了会怎样 |
|---|---|---|
| tokenhub 无 gemini | `python3 tools/multimodal_client.py --models` | 委托方开通后此表变红 → 本 ADR 需改 |
| `gemini-3.8-flash` 可用 | 同上（含一次真调用探针） | 若长期 429，回落链第一条就该让位 |
| vod 是 av_alignment 唯一落点 | `python3 -c "from base.multimodal_provider import ...; print(glm 家族 audio)"` | 若 tokenhub 某模型声明 audio，§2.1 表要改 |
| 未接能力落 untested | `verify_multimodal_provider --controls` / `verify_video_ingest` 退 2 | 若某处落成 ok，e11 就不成立了 |

**已知盲区（明着留着）**：
1. **网关的模型清单会变**（本轮就抓到一个：早上 3.8-flash 429、现在 ok）。
   本 ADR 里的模型名是**某时某刻的读数**，不是常量。判据是「回落链**非空且按序尝试**」，
   不是「链上每个模型永远可用」。
2. **`e10` 今天一条都不成立**。本的 ADR 不声称它成立，只给出使它成立的最短路径。
3. **装 ffmpeg 不解决容器侧**。本机装了只让开发期能验，生产仍要 ADR-0018 §六 的四件事。

## 七 · 决定

1. **不把 gemini 加到 tokenhub**（盘上没有；要加需委托方在网关侧开通）。
   vod 侧 gemini 仍是音画对齐的唯一落点。
2. **每侧改成一组模型 + 429 重试 + 回落记录**（§2.1/§2.2），
   而不是把可用性押在单模型上。
3. **`gemini-3.8-flash` 恢复为主选**，并把「429 是 retryable，不是 unavailable」
   变成判据（§1.2）。
