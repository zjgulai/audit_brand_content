# AGENTS.md 预算读数：真实大小 vs stat（填充态）· 2026-10-21

> 问题：`verify_agents_budget.py` 用 `os.path.getsize` 读大小。
> 若注入方按**外部 stat**（填充态下多 4096）判断 65536 预算，两个读数会差 4096 ——
> 正好是一条教训的量级，而检查器会一直报「余量够」。
>
> **结论先行**：填充态在本环境**可复现**；`os.path.getsize` 返回真实值，外部 `stat` 返回 +4096。
> 检查器已改成 `max(real, stat)`，结论行同时报两个数。
> **注入方按哪个数判断：未测**（仓内无任何记录，见 §2）。

## 3. 改成了什么

`tools/verify_agents_budget.py`：

- 新增 `_stat_size(path)`：**外部** `stat`（darwin `-f %z` / 其他 `-c %s`）；取不到返回 `None`。
- 新增 `sizes(path)` 与 `effective_size(real, stat)`：判定用 **`max(real, stat)`**。
- `check()` 的 B1：
  - 结论行同时报两个数：
    `AGENTS.md 60835B（stat 60835B）· 余量：按 real 4701 / 按 stat 4701（判定用 4701）`
  - stat 读不到 → **退 2（未测）**，不落绿。
- `--controls` 新增**填充态对照**：
  - Python 写一个 10000 字节的 `.md` → 断言 `stat == real + 4096` 且判定用 `stat`；
  - **造不出填充态 → 明说「未测」并退 2**，不假装验过。
- 原有行为级对照（`.txt` 造超预算文件）保持不变。

## 6. ★ 改 AGENTS.md 的固定流程：每次写入都先红一次

**2026-10-21 实测，同一天内连撞三次**（都在加 §2.4.8 那一条时）：

| 操作 | real | stat | 预算判定 |
|---|---:|---:|---|
| Edit 写入新章节 | 62235 | 66331 | **红**（stat 越线 678） |
| Python 压缩重写 | 61919 | 66015 | **红** |
| 再 Edit 改一行 | 62143 | 66239 | **红** |

三次都不是内容超预算，而是**写文件这个动作本身进了填充态**。
`verify_agents_budget` 现在按 `max(real, stat)` 判 —— 这是对的（保守），
但它带来一个必然后果：

> **任何一次写 `AGENTS.md`，改完立刻跑预算检查都会红一次**，
> 除非改完马上做一次去填充（`cp` 往返 + sha256 相等断言）。

### 所以流程是三步，不是两步

```bash
# 1. 改（Edit / Python / 任何写盘方式都可能触发填充）
# 2. 去填充 —— 必须做，否则下一次检查一定红
before=$(python3 -c "import hashlib;print(hashlib.sha256(open('AGENTS.md','rb').read()).hexdigest())")
cp AGENTS.md AGENTS.md.depad.tmp && mv AGENTS.md.depad.tmp AGENTS.md
after=$(python3 -c "import hashlib;print(hashlib.sha256(open('AGENTS.md','rb').read()).hexdigest())")
[ "$before" = "$after" ] && echo "内容未变 ✅" || echo "❌ 内容被改动"
# 3. 再跑预算
python3 tools/verify_agents_budget.py
```

### 怎么分辨「真超预算」和「只是填充」

看两个数：

```
real 62143 / stat 66239   → 差 4096，是填充；去填充后再判
real 66239 / stat 66239   → 差 0，是真超预算；必须搬内容
```

**判据是「real 与 stat 是否相同」，不是「数字大不大」。** 只看一个数的话，
填充态会让一个 62KB 的文件看起来已经超了 65KB 上限。

### 为什么要写在这里而不是 AGENTS.md

写进 `AGENTS.md` 要再花约 100 字节，而当时余量只剩 105 —— 加完只剩 5 字节，
等于把这个文件锁死在边缘。**这条规矩放在这里，因为本文件不受 65536 预算约束**
（它不是注入文件）。`AGENTS.md` 的 §2.4.8 已经写了「两个口径都要报」的原则，
细节留在这里。
