#### series ↔ collection 的不匹配:已实测(2026-10-17)

> 以下是页面快照实测,不是预测。**这是 v1.1 方案里最重要的一节,不读它直接写代码会跑出错的 mapping**。

| 维度 | support 站 `Breast Pump` 系列页(12 个产品) | 主站 `hospital-grade-breast-pump` collection(7 个商品) |
|---|---|---|
| 产品 handle 形态 | `wellness-1 / m-9 / m-6 / m-5-smart / s-12-pro-quick / s-9-pro / v-2-pro / v-1-pro / s-12-pro / m-5 / bpv-3 / air-1` | `v1-pro-hospital-grade-wearable-breast-pump / v2pro-hands-free-breast-pump-ultra-light-potent / v1pro-v2pro-wearable-breast-pump-replacement-parts / momcozy-wearable-milk-standard-collection-cup... / v1-pro-bra-bundle-...-warm / v3-double-electric-breast-pump / v3-double-electric-breast-pump-replacement-parts` |
| 覆盖范围 | 主站 A **全集**(含 M/S/Air/Wellness/V) | 主站 B **窄化**(只 Hospital-Grade:V1 Pro / V2 Pro / V3 + 配件/替换/打包) |
| 同一款产品的 handle 在两边 | support `v-1-pro` vs 主站 `v1-pro-hospital-grade-wearable-breast-pump` | — |

**坐实三件事**:

1. **主站 collection ≠ support series**(系列名同叫 "Breast Pump",但口径不同)——方案 §六"不做的事"原本默认主站 collection 和 support series 是 1:1,**现在证实不是**。
2. **同一款产品在两个站的 handle 写法不一样**(support 站叫 `v-1-pro`,主站叫 `v1-pro-hospital-grade-wearable-breast-pump`)。mapping 必须有 **`{support_handle, main_handle, sku}` 三键索引**,单键对不上。
3. **同一 series 在主站可能没有 1:1 的 collection。** "Hospital Grade" 在主站是单独 collection,但它**只是** support "Breast Pump" 中的两个 SKU(V1 Pro / V2 Pro / V3)。**所以本任务真正要回答的对账问题是**:`"Breast Pump" 在主站**是否还有第二个 collection`** 装 M/S/Air/Wellness——这是 v1.2 调研项,试点阶段不必解决,但方案里要标"未结清"。

> **那 mapping 该怎么搭**?现在的口径是:**产品为粒度**,每个产品一件 `products/<sku>/product.json`,
> `mapping.json` 不再做 1:1,而是:
>
> ```
> support_series "breast-pump" ─┬─ support_handle "v-1-pro" ─── main_handle "v1-pro-hospital-grade-wearable-breast-pump" ── sku "BP252-NR10BA-A"
>                              ├─ support_handle "m-9"        ── ❌ 未在主站现有 collection 中(可能需要第二个 collection)
>                              ├─ support_handle "wellness-1"  ── ❌
>                              └─ ... 9 个未映射
> ```
>
> 试点阶段接受 `unmapped_products ≥ 5`(也就是 support 12 个里至少 5 个暂时无主站对账),**不视为失败**;
> 后续 v1.2 通过 `browse_store()` 用 M/S/Air/Wellness 关键词反查第二主站 collection 来补。

## 三、采集分两支

### 支 1:主站 momcozy.com(走 webmcp + 单抠 description)

| 步 | 工具 | 拿到什么 |
|---|---|---|
| a | `browse_store(collection=<slug>)` | 该系列下商品清单:title/handle/id/price_range/image_url/available/variant_count/product_type/tags |
| b | `get_product(handle=<h>)` | 全字段:**price/list_price/variants[].sku/availability/images[]** 等 |
| c | Playwright 访问 `/products/<h>` 页面,提取 `.product__description`(或对应 selector)块 | **description_html + description_text + specs/spec(如有)** + rating/review_count(如有) |
| d | 拼装 `product.json`(b + c),images 按 sha256 下载到 `products/<sku>/images/` | 一份完整商品 |

2. 主站 `browse_store()` 的 `collection_title` 反查关键词("Breast Pump" → 7 商品)

## 五、风险点(写到这一份的桩子)

1. **rsc/html 双层** — momcozy.com 是 Shopify Hydrogen,大概率 React Server Components,初次渲染看不到价格/SKU,必须**模拟滚动 + 等 hydration**,否则采到的是占位符。先用一个商品试通。
2. **CDN 反爬** — `cdn.shopify.com` 商品图,大量并发必触发限流。需要**串行 + 退避**,且 README 里要标明下载次序的速度。
3. **support 站文章分页** — 现在看主页是 slider 形态,**真分页要在系列页里找**。先抓首页内容,真有分页再加。
4. **图片版权** — 用户选了下到本地。要在 `manifest.json` 里**标注"内部使用,如需外发需走法务复核"**,作为提示,不作为阻断。
5. **+4096 填充(本项目 §2.1)** — 所有写入的图片文件,**写完做字节级校验**(sha256),再用 `verify_depad.py` 兜底。
6. **陈旧字节码(本项目 §2.1.1)** — 如果写 python 校验脚本,**改完任何被 import 的 .py 立即清 `~/Library/Caches/com.apple.python` 对应子树**,否则会出现"源码改了脚本却用旧值"的怪事。

## 六、不做的事(明确划界)

- 不接增量 diff(用户选一次性)
- 不下载用户头像/客服头像/品牌 logo(版权不确定)
- 不爬评论区/评测(合规风险 + 价值密度低)
- 不动 `support.momcozy.com` 上的隐私/账号型 URL(发现即停)
- 不跨站爬任何支持站 `*.pdf`(如果文章里链了 PDF,只记 URL,**不下** —— 同红线 §2.6 第 1 项精神:"能不能下得下来"不是要问的问题)
