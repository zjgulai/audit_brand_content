## 二、仍未解决的 critical（7 条）

### C1 · `superseded` 被自己的白名单挡死

| 项 | 内容 |
|---|---|
| **位置** | 白名单（三列 candidate/confirmed/rejected） vs append-only 要求旧条标 `superseded` |
| **后果** | **每次确认/驳回/撤销都会产出 `(任意 produced_by, superseded)`，正好在表外 → 被拒收** |
| **另一条路也不通** | 不标 `superseded` → `has_candidate` 仍为真 → 内容永远停在 REVIEW |
| **性质** | **死锁**，两条路都不通 |
| **修法** | 白名单加 `superseded` 列；或明确 `superseded` 不属于 `produced_by × status` 白名单管辖 |

### C2 · 空三族：`not_applicable` 与「必然 UNASSESSED」互斥

| 项 | 内容 |
|---|---|
| **位置** | §3.3.8.0「无 control_point 的族 not_applicable」 vs §5.3「空族下内容必然落 UNASSESSED」 |
| **后果** | 同一份干净文本：按前者 → coverage full → **PASS**；按后者 → coverage partial → **REVIEW** |
| **更深的问题** | `not_applicable` 把「待做」当成了「不适用」，与 L1-0c「忘了做 vs 决定不做要长得不同」直接冲突 |
| **修法** | **需要你定**：空族算「不适用」还是「未做」。这决定了第一阶段能不能出 PASS |

### C3 · P0–Pn 与 L0–L5 两套刻度没有映射

| 项 | 内容 |
|---|---|
| **位置** | Finding 的 `severity` 是 L0–L5；原则三 / L2-4 / §6 指标 / §8 第 8 项全用 P0–P3 |

| **实际断点** | 实现者判断一条 H01 命中是 L4 还是 L5 只能自己编 —— 编 L3 → REVIEW，编 L4 → BLOCK。**同一条规则两种终局** |

### C4 · `authority_state` 不是 Finding 字段

## 五、我不再自己改的理由

这一轮已经出现「改一处、冒出三处」的迹象：
修了判定链 → 暴露 `authority_state` 没字段 → 加字段又牵出 P0/L 刻度 → 刻度又牵出控制点主表缺 severity。

**再往下改，是在补一个还没想清楚的数据模型。** 建议先把下面三件事定掉，再回来改文档：

1. **P0–P3 到底是什么**（检测层 or 严重度）—— 决定 severity 字段的设计
2. **空三族算不算「不适用」** —— 决定第一阶段能否出 PASS
3. **验收表要不要对全部判据负责** —— 决定 §8 是 22 行还是 80 行

---

**核验方式的可复现性**：三路 agent 互不通信，各自独立读同一份冻结文件。
它们**共同指出**的 `authority_state` 缺失与 P0/L 刻度问题，可信度最高；
只出现在单路的条目（如 C7 的具体格子），需人工复核。
