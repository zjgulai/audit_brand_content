## 三、问题 2：与 `web/design-baseline.json` 对拍（漂移实证与成因）

### 3.1 对拍发现的「103 vs 95」漂移及那 8 条差额的来龙去脉

在本次执行 `--rebase-baseline` 之前，`web/design-baseline.json` 有 **`103` 条**，而当前 `parseCss("web/src/styles.css")` 有 **`95` 条**。为什么少了 **8 条**？用以下命令可直接复现 `2e59ca8` 基线与当前 `parseCss` 的 8 条差集：

```bash
git show 2e59ca8:web/design-baseline.json | node -e '
const fs = require("node:fs");
const oldBase = JSON.parse(fs.readFileSync(0, "utf8"));
// 跑 check_design_tokens.mjs 的当前解析
const { execFileSync } = require("node:child_process");
const curBase = JSON.parse(fs.readFileSync("web/design-baseline.json", "utf8"));
const keyOf = e => `${e.file}|${e.selector}|${e.prop}|${e.value}`;
const curSet = new Set(curBase.tokens.map(keyOf));
const diff = oldBase.tokens.filter(e => !curSet.has(keyOf(e)));
console.log("Removed 8 entries:", JSON.stringify(diff, null, 2));
'
```

**这 8 条差额的真实成因（在 Wave A 修 `DT-3` 时曾发生过一次手改 `design-baseline.json`）**：

1. **2 条是真的在代码里改成了 `transparent`**：
   - `.btn--primary { border-color: hsl(var(--brand)) }` → 改成了 `border-color: transparent`（`styles.css:186`）
   - `.btn--primary:hover:not(:disabled) { border-color: hsl(var(--brand-hover)) }` → 改成了 `border-color: transparent`（`styles.css:193`）
2. **4 条是因为属性名根本不在 `BARE_PROPS` 里（当时手写进 `design-baseline.json`，而 `parseCss` 从来不会产出它们）**：
   - `outline-offset: 2px`（2 处：`a:focus-visible...` 与 `.skip-link:focus`）—— `outline-offset` 不在 `BARE_PROPS`
   - `.queue__row[aria-current="true"] { border-left-color: hsl(var(--brand)) }` —— `border-left-color` 不在 `BARE_PROPS`
   - `.state--forbidden { border-width: 2px }` —— `border-width` 不在 `BARE_PROPS`
3. **2 条是因为 `check_design_tokens.mjs:127` `parseCss()` 的 `@import` 缓冲小缺陷**：
   - `styles.css:15` 顶部有一行 `@import "./styles/tokens.css";`（以 `;` 结尾而非 `{}`），`parseCss()` 只在遇到 `{` 或 `}` 时清空 `buf`，导致紧随其后的第一个规则块 `html { color: hsl(var(--foreground)); background: hsl(var(--background)); }` 的 selector 被拼成了 `@import "./styles/tokens.css"; html`（以 `@` 开头），进而被第 141 行 `if (selector.startsWith("@")) continue;` 跳过了！当时手改 `design-baseline.json` 把 `:root` 替换成了 `html`，所以 `design-baseline.json` 里多出了这两条 `selector: "html"`。

> **结论**：`103` 是当时手改 `design-baseline.json` 留下的虚高数字；按 `check_design_tokens.mjs` 机器生成器的确定性产出，今天实数是 **`95` 条**。现已通过 `node web/scripts/check_design_tokens.mjs --rebase-baseline` 将 `web/design-baseline.json` 同步校准为 **`95` 条**（`基线 95 条 · 当前 95 条 · 新增 0 · 已删除 0`）。

## 四、问题 3：区分「真裸值」与「假裸值」—— `95` 这个数字到底有没有意义？

用下面这条命令可以把 `web/design-baseline.json` 里的 `95` 条逐条归入 3 个互不重叠的桶：

```bash
node -e '
const tokens = JSON.parse(require("node:fs").readFileSync("web/design-baseline.json", "utf8")).tokens;
const onlyHslVar = tokens.filter(e => /^hsl\(var\(--[a-z0-9-]+\)\)$/.test(e.value));
const pxWithHslVar = tokens.filter(e => /\b\d+px\b/.test(e.value) && /hsl\(var\(--[a-z0-9-]+\)\)/.test(e.value));
const pxWithKeyword = tokens.filter(e => /\b\d+px\b/.test(e.value) && !/hsl\(var\(--[a-z0-9-]+\)\)/.test(e.value));
const trueBare = tokens.filter(e => !onlyHslVar.includes(e) && !pxWithHslVar.includes(e) && !pxWithKeyword.includes(e));
console.log(JSON.stringify({
  total_dt3: tokens.length,
  bucket1_pure_hsl_var_wrapper: onlyHslVar.length,
  bucket2_border_or_outline_px_with_hsl_var: pxWithHslVar.length,
  bucket3_border_px_with_keyword: pxWithKeyword.length,
  bucket4_true_bare_hex_or_font_or_spacing: trueBare.length
}, null, 2));
'
```

**实跑输出**：

```json

  "bucket2_border_or_outline_px_with_hsl_var": 26,
  "bucket3_border_px_with_keyword": 2,
  "bucket4_true_bare_hex_or_font_or_spacing": 0
```

### 对两个关键判据问题的正面回答：

1. **`hsl(var(--...))` 里那个 `hsl` 是函数名还是裸值？**
   - **它是 CSS 颜色空间函数名（包装器），不是裸值。**
   - 因为 `web/src/styles/tokens.css` 按 shadcn/Tailwind 惯例把 L1 色值定义为裸通道三元组（如 `--brand: 346.5 41.3% 29.4%;`），在 CSS 里引用它**语法上必须写 `hsl(var(--brand))`**。
   - `check_design_tokens.mjs:117` 写的是 `if (/\b(?:rgba?|hsla?)\(/.test(v)) return true;`，没有排除 `hsl(var(--...))`，导致 **67 条完全合规的语义 Token 引用被误判成了「裸值」**。
2. **`1px solid` 的 `1px` 是边框宽度还是间距？**
   - **全部 28 条含 `px` 的 DT-3 条目都是边框/焦点环/阴影的物理线宽（`1px` 21 条、`2px` 3 条、`3px` 4 条），0 条是间距（`margin/padding/gap`）或字号（`font-size`）。**
3. **这对 `#111` 意味着什么？**
   - 如果按「是否违背设计系统 Token 纪律（写死 `#hex`、写死非 var `hsl(...)`、写死 `font-size: 13px`、写死 `padding: 12px`）」来衡量，`web/src/styles.css` 里的**真裸值今天已经是 `0` 处**；
   - 剩下的 `95` 处之所以还在 `design-baseline.json` 里，是因为 `DT-3` 把 `hsl(var(--*))` 函数壳（67 处）和 `1px/2px/3px` 边框线宽（28 处）也算了进来。
