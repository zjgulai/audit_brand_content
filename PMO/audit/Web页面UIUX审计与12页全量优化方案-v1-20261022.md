## 三、分页面 UI/UX 详细设计与交互规范（P-01 至 P-12）

### 3.1 P-01 内容提交单（`/submit` & 顶栏全局抽屉）

* **设计目标**：解决 PRD v2.0 §7.2 第 2 条「机器只补不强猜，一次提交 = 一张提交单，三个必填」的入口约束。
* **布局与交互**：
  1. **三必填前置栏（Segmented / Select）**：
     * `内容阶段 (content_stage)`：`发布前完整内容 (final_content)`（默认）｜`生产中间物 (brief/script)`（选中时立即弹出黄色预警：「第一阶段不审生产中间物，提交将被路由至 `rejected_unsupported`」）。
     * `产品线 (product_line)`：`吸奶器 (breast_pump)`｜`Baby Monitor`｜`Bottle Washer / 喂养`｜`其他`。
     * `投放渠道 (entry_channel)`：`Amazon`｜`独立站 (Shopify/PDP)`｜`TikTok / 社媒`｜`EDM / PR`。
  2. **内容形态与多通道输入区（Tabs）**：
     * **文字/文案（`ad_text` / `free_text`）**：带字数与 UTF-8 字节实时统计的多行文本框 + 实时计算客户端预览 `text_sha256`。
     * **落地页/链接（`landing_page` / `uri`）**：URL 输入框（支持飞书云文档 docx/wiki 链接、独立站 URL）。
     * **图片/视频/文档（`image` / `video` / `structured_json`）**：明确显示当前阶段能力档位提示——图片/视频自动标注 **「浅档审查：将执行 OCR/ASR 与基础视觉候选，不做区域级像素审计，结论将携带 partial 覆盖声明」**（对齐 PRD v2.0 §6.3 浅档地板条款）。
  3. **提交反馈与幂等保护**：
     * 自动生成 UUID 作为 `Idempotency-Key`；点击提交后原地展示 **受理回执卡（Attempt Receipt）**：显示 `submission_id`、`attempt_id`、`status (accepted / rejected_unsupported / failed)`，并提供「查看案件进度 →」直达链接。

### 3.2 P-02 收件箱与我的内容（`/inbox` & `/my-cases`）

* **设计目标**：打通 UJ-7（失效/自动重审仅 Web In-App 通知）与 DP1 文案提交人的自决闭环。
* **核心分区**：
  1. **In-App 通知中心（消费 `GET /api/v1/notifications`）**：
     * 展示 `invalidation`（签名因规则/正文/依据变化自动失效）与 `auto_rereview`（全量重审已入队/已完成）两类通知。
     * 每条通知含 **「标记已读（`POST /notifications/{id}/read`）」** 与 **「确认知悉（`POST /notifications/{id}/ack`）」** 按钮，底部嚴格遵守 UIUX §2 UJ-7 文案纪律：显示「工作台内通知记录」，绝不显示「外部消息已送达」。
  2. **待自决专区（DP1 专属）**：
     * 高亮列出状态为 `待自决` 的本人提交案件。提供两个明确动作：**「修改后重新提交」**（预填原案件元数据拉起 P-01 抽屉）与 **「附说明接受当前建议」**。

### 3.3 P-03 案件总览列表（`/cases`）

* **设计目标**：消费后端已有的 `GET /api/v1/cases`，让统筹、法务、审核员能全局检索所有可读案件（含已 `BLOCK`、`PASS`、`未审查` 的终态案件，区别于只含待办的 `/queue`）。
* **筛选与展示**：
  * **多维筛选条**：五标签多选（`BLOCK` / `REVIEW` / `待自决` / `未审查` / `PASS`）、放行状态（`待放行` / `已签发` / `已拒绝` / `已撤回` / `已失效`）、产品线、负责人（含「未指派」）、是否样例数据（`sample`）。
  * **列表字段**：案件 ID、五标签徽标（带专属图标）、处置层（`DP0`–`DP4`）、覆盖状态徽标（`full` / `partial` / `not_evaluated`）、放行状态、品线、负责人、创建时间、操作（「深审」/「报告」）。
