# 前端校验的三个假绿形状（2026-10-24）

> 起因：2026-10-23 全站视觉刷新时，我加的三条 DOM 几何断言**连续三次全部通过，但验的不是我以为的东西**。
> 三次都不是「断言写错了逻辑」，而是**断言看起来在验、实际什么都没验** ——
> 与 `AGENTS.md` §2.4.4「自证有副作用」、§2.4.8「同一个量两个口径」是同一族。
>
> 这份文件只记**形状**与**判据**，不重复 AGENTS.md 里的规矩。

---

## 形状一：`Runtime.evaluate` 默认 `awaitPromise: false` —— **等待函数恒为真**

### 发生了什么

`check_pages.mjs` 要给 SPA 页面做「等元素出现再量」：

```js
// ❌ 第一版：看起来在等，实际没等
const found = await evalValue(`new Promise((res) => {
  if (document.querySelector(selector)) return res(true);
  const t = setInterval(() => {
    if (document.querySelector(selector)) { clearInterval(t); res(true); }
  }, 100);
  setTimeout(() => { clearInterval(t); res(false); }, 15000);
})`);
```

`evalValue` 内部是 `Runtime.evaluate({ expression, returnByValue: true })`。
**CDP 的 `awaitPromise` 默认 `false`** —— 它不会等 Promise 兑现，
而是把 Promise 对象本身作为结果返回。`returnByValue: true` 下，
一个 Promise 序列化成 `{}`。

于是 `found` 恒为 `{}`（truthy），**循环一次都不跑**，
立刻去量一个还没渲染的 DOM —— 量到 `table.found = false`，
而页面其实完全正常。

### 判据

**在 CDP 里等待，必须满足两条之一：**

1. 显式传 `awaitPromise: true`；或
2. **在 Node 侧轮询**（推荐 —— 不依赖 CDP 的序列化语义）：

```js
// ✅ 第二版
const end = Date.now() + 15000;
let found = false;
while (Date.now() < end) {
  found = Boolean(
    await evalValue(`Boolean(document.querySelector(${JSON.stringify(selector)}))`),
  );
  if (found) break;
  await sleep(100);
}
```

### 这个形状的识别特征

- 断言**从来没有失败过**（连一次都没有），而你确信它应该偶尔失败；
- 加 `console.log` 一看，等待函数返回的是对象不是布尔；
- 把被测元素**故意删掉**，断言**还是绿的**。

最后一条是最快的判别法 —— **每次写等待，先故意让它等一个不存在的东西，
确认它会超时**。

## 形状二：`rem` 的基数是 13px，不是浏览器的 16px

### 发生了什么

`styles.css` 里：

```css
html {
  font-size: var(--text-base);   /* --text-base: 13px */
}
```

所以 `22rem = 22 × 13 = 286px`，**不是 352px**。

我写判据时按浏览器默认 16px 算：

```js
const MIN_CARD_PX = 352;          // ❌ 22rem 按 16px 算
```

结果 4 列 × 294.9px 的**正确布局被判红**。更坏的是：
若阈值写反方向（写小），错误布局会被判绿 —— **同一个常数错了两个方向都会骗人**。

### 判据

**任何 `rem` 相关的像素阈值，必须从 CSS 里把根字号读出来，不能假设 16px。**

```js
// ✅ 把常量与来源写在一起
const ROOT_FONT_PX = 13;          // styles.css: html { font-size: var(--text-base) }
const MIN_CARD_REM = 22;          // styles.css: minmax(22rem, 1fr)
const MIN_CARD_PX = MIN_CARD_REM * ROOT_FONT_PX;
```

**更好的做法**：不断言绝对像素，而是**读实际的计算样式**与 CSS 里的值对拍。
本条之所以还能用常数，是因为 `--text-base` 是 L1 token 且被 DT-5 锁着，
不会悄悄变。**一旦那个 token 没被锁，就必须改成从 DOM 读。**

## 形状三：`Page.navigate` 会丢掉前端内存态

### 发生了什么

要量 `/cases` 的表格容器，我写：

```js
await cdp.send("Page.navigate", { url: `${base}/cases` });   // ❌
```

`Page.navigate` 是**整页重载**。而本项目的开发身份存在 `IdentitySwitcher` 的
React state 里（由 `enable()` 之后才有值），**不在 cookie 或 localStorage**。
重载之后 `current === null`，于是：

```tsx
// CasesPage.tsx
if (devEnabled && current === null) { setRows(null); return; }   // 不渲染表格
```

页面渲染出一个只有标题的空壳，`table.found = false`。
**看起来像「表格没被容器包住」，实际是「表格根本没渲染」。**

### 判据

**在 SPA 里量数据区，导航必须走 SPA 内跳转，不能整页重载：**

```js
// ✅ 点导航链接或 pushState + popstate
await evalValue(`(() => {
  const a = [...document.querySelectorAll('a')]
    .find((x) => x.getAttribute('href') === ${JSON.stringify(href)});
  if (a) { a.click(); return true; }
  window.history.pushState({}, '', ${JSON.stringify(href)});
  window.dispatchEvent(new PopStateEvent('popstate'));
  return true;
})()`);
```

**例外**：量「登录页未登录态」时必须整页导航（`/login` 在 dev 下会重定向到
`/queue`）。那种场合要**换一个不依赖内存态的入口** ——
本次用的是「起一个静态服务托管 `dist`，把 `/me` 返回 401」，
走真实生产构建 + 真实未登录态。

## 三者的共同点

| | 表面现象 | 真因 | 若不去查的后果 |
|---|---|---|---|
| 一 | 断言全绿 | 等待恒为真，量到未渲染的 DOM | 判据形同虚设，且**永远不会红** |
| 二 | 正确布局被判红 | 常数按 16px 算，实际 13px | 会去改**正确的 CSS** 迁就错误的判据 |
| 三 | 表格「没有容器」 | 整页重载丢了身份，表格没渲染 | 会给正确的 CSS 加一个多余的面板类 |

**三者的共同点是：报出来的现象指向一个无关的方向。**

这与 `PMO/填充态-环境特性-实测史.md` 里 +4096 那条、以及
`AGENTS.md` §2.1.1 的陈旧字节码是同一种病 —— **读数没有对准它要描述的东西**。

---

## 可操作结论

1. **写等待，先让它等一个不存在的东西，确认会超时。**
2. **写 `rem` 阈值，先 grep 根字号，不要假设 16px。**
3. **量 SPA 数据区，先确认导航方式不会丢内存态**；
   拿不准就先用 `document.body.innerText` 看一眼渲染结果对不对。
4. 三条都满足时再写断言 —— **否则你写的不是判据，是一段恒真的散文。**
