## 1. 一句话结论 + 关键决策表

**一句话：先把会假绿的前端断言改成会红的门，再把依赖治理做成可执行检查器，然后按真实消费者引入成熟库；shadcn 只复制源码、Nova 只借结构与紧凑间距、`web/DESIGN.md` 的 token 仍是唯一设计语言；Motion、react-resizable-panels、Zustand、dnd-kit 当前零消费者，暂不安装；Table 是否随 Query 一起落由 D-K 单独拍板。**

用户原文用的是「譬如」——六项是示例，不是强制清单。方案按「有没有消费者、有没有执行点」逐项裁定，而不是按清单一次装齐。

#### shadcn/ui Nova

- **shadcn 不是运行时组件包。** 当前官方 CLI 包名是 `shadcn` 4.22.1（MIT，`engines.node >= 20.18.1`），组件由 CLI 从 registry 复制进项目，导入路径是项目别名 **`@/ui/<component>`**（本方案统一别名 `@/* -> web/src/*`，源码落在 `web/src/ui/`）。`shadcn-ui@0.9.5` 已 deprecated；`@shadcn/ui@0.0.4` 是 2023 年旧包，不是当前官方 CLI。不存在 `shadcn/ui` 这个包。
- **Nova 是 style preset，不是独立 npm 主题包。** 官方 `components.json` schema 的 style enum 包含 `radix-nova` / `base-nova` / `aria-nova`（以及 vega/maia/lyra/mira 等）。裸 `nova` 是 preset 名，不是合法 style 值。Nova 默认：Geist 字体、neutral 色、0.625rem 圆角、紧凑 padding/margin、Lucide 图标。
- **Vite 项目不能直接用 `--defaults`。** CLI 4.22.1 的 `-d/--defaults` 固定为 `--template=next --preset=base-nova`；本仓应按 `-t vite -b radix -p nova` 生成 `radix-nova`，且必须在临时副本先跑。`init` 没有 dry-run，直接在本仓跑会改 `vite.config.ts`、`tsconfig`、CSS。`add` 有 `--dry-run/--diff/--view/--overwrite`。
- **radix-nova 的隐式依赖：** dependencies = `class-variance-authority`、`cn`、`lucide-react`、`radix-ui`；devDependencies = `tw-animate-css`、`shadcn`；CSS 引入 `tw-animate-css` 与 `shadcn/tailwind.css`；registry 的 `utils` 内容为 `export { cn } from "cn"`。用户列出的 `clsx`/`tailwind-merge` 在 2026 版已被 `cn` 取代；「Radix 各包」已合并为单个 `radix-ui`。
- **按需组件的额外依赖：** command→`cmdk`；drawer→`vaul`；sonner→`sonner` + `next-themes`；chart→`recharts`；calendar→`react-day-picker` + `date-fns`；carousel→`embla-carousel-react`；input-otp→`input-otp`；resizable→`react-resizable-panels`。**未用的组件不应提前安装。**
- **registry 原始文件不能手抄。** dialog/sonner 等文件含 `@/app/(create)/components/icon-placeholder` 和 `next-themes`；必须走 CLI 的 `iconLibrary`/transform，或复制后替换为本地 Lucide 图标与自有 theme hook。
- **form registry item 在 radix-nova 下为空。** UIUX 要求的 React Hook Form + Zod 不能被「form 组件」直接满足，需要 `field` + RHF 或自写表单层。
- **Nova 默认与现有 DESIGN 冲突：** DESIGN 是 Inter Tight / JetBrains Mono、13px 基准、28px 行高、0.25rem 圆角、品牌酒红 #6A2C3A；Nova 是 Geist、neutral、10px 级紧凑间距、0.625rem 圆角。全量 Nova 会改写字体/间距/圆角，必须显式裁定谁优先。

**判定：** TS-8 允许「借 shadcn 组织」，但禁止「依赖其生成模板」；验收表 #111 把后者具体化为「直接 import shadcn 生成组件必须红」，并要求颜色/间距/字号全部来自 token、样式层出现裸值即红。**这两条不是逐字矛盾：复制后改写 import、只 import Radix + 自有模块，是可以通过的；保留 `cva`/`cn` 等第三方 import 需要明确白名单（本方案把 `cva`/`clsx`/`tailwind-merge` 收在 `@/lib/utils`）。** 所以这是「条件一致」，不是「合同自相矛盾」。

#### Lucide

- `lucide-react` 1.60.0（ISC，`sideEffects:false`，peer React `^16.5.1||^17||^18||^19`）。正确导入是 `import { Check } from "lucide-react"`；每个图标是独立 ESM 模块（单图标源码约 0.5KB），tree-shakable。
- **无障碍默认值是「装饰性」：** 没有 `aria-*`/`role`/`title` 时自动输出 `aria-hidden="true"`。要表达语义必须显式给 `aria-label`/`role`/`title`，否则读屏会跳过。
- **全量 barrel 的 bundlephobia 读数 780,885 B min / 198,235 B gzip 不是实际成本**，前提是只 import 具名图标、禁止 `import * as Icons`。CI 需要一个「全量 import」坏样本做反向对照。
- 适合替换 U+2190/U+26A0/U+2193 这类动作提示，但必须保留文字标签，不替代正文里的语义文案，尤其不能替代五标签的文字。

#### Motion

- 包名 `motion` 14.4.0（MIT，`sideEffects:false`，peer React `^18||^19`，依赖 `framer-motion` 14.4.0）；React 导入路径是 `import { motion } from "motion/react"`。`framer-motion` 仍是同版本旧包，二者不要同时安装/导入。
- bundlephobia 对 `motion` 包入口读数为 166,220 B min / 55,862 B gzip；`motion/react` 子入口需单独实测，不能直接把 55.9KB 当作 React 子集成本。
- **reduced-motion 不是自动生效：** MotionConfigContext 默认 `reducedMotion: "never"`。`<MotionConfig reducedMotion="user">` 只关闭 transform/layout 动画，保留 opacity/backgroundColor 动画。DESIGN 要求「prefers-reduced-motion 下全部关闭」，现有 `* { animation: none !important; transition: none !important; }` 拦不住 Motion 的 JS 内联动画。必须每个自定义动画用 `useReducedMotion()` 把 opacity/backgroundColor 也降为静态。
- React 19 的 `MotionStyle` 类型冲突（issue #3422）已在 12.23.28 修复，14.4.0 已包含；本仓未实测。

#### react-resizable-panels

- `react-resizable-panels` 4.14.7（MIT，peer React `^18||^19`，无第三方依赖）。v4 API 是 `Group/Panel/Separator`（类型 `GroupProps/SeparatorProps`），v3 的 `PanelGroup/PanelResizeHandle` 已移除；v4 是破坏性重写（`direction`→`orientation`）。**更正：**「size 需显式单位」不准确——数字按像素解释、无单位字符串按百分比解释，显式单位（px/%/em/rem/vh/vw）是可选的。
- Separator 渲染 WAI-ARIA separator 角色与键盘可 resize；README 未列出具体键位，需在引入时实测。已知 issue #714 是 Vite 7 SSR + React Router 7 下 `defaultSize` 的 flex-basis 不清理；当前是 SPA，理论不触发，但若引入 SSR/框架模式要回归。
- shadcn 的 Resizable 已包裹这个库，不要再单独实现一套。

#### dnd-kit

- 稳定包 `@dnd-kit/core` 6.3.1（MIT，peer React `>=16.8`）已被官方 docs 标为 legacy；新包 `@dnd-kit/react` 0.5.1（0.x，peer React `^18||^19`）使用 `DragDropProvider/DragOverlay` 与 `useDraggable/useDroppable/useSortable`。**两者不要同时安装。**
- 内置 keyboard sensor、屏幕阅读器指令/实时播报、默认 ARIA；但默认播报文案是英文，中文界面需自定义 `announcements`。WCAG 2.5.7/AX-7 仍要求拖拽有单指针/按钮替代；dnd-kit 的键盘 sensor 不会自动生成「上移/下移/移入某组」这类按钮。
- `@dnd-kit/core` bundlephobia 43,700 B min / 14,237 B gzip；React 19 SSR 下动态 ID 可能导致 hydration #418，当前 SPA 不涉及，引入时需验证。

#### Zustand

- `zustand` 5.0.15（MIT，peer React `>=18`，immer/use-sync-external-store 为 optional peers）；导入 `import { create } from "zustand"`；bundlephobia 核心入口 856 B min / 489 B gzip；无 a11y 面。
- 与 TanStack Query 正常互补：Query 管服务端缓存（cases/queue/reports，key 按 tenant+resource+id+filters），Zustand 只放跨页面瞬时 UI 状态（多选、面板尺寸、未提交草稿缓冲）。**禁止把服务端数据复制进 Zustand。** 只有 Zustand 也缓存服务端数据或复制 Query cache 时才重叠。

#### TanStack（合同/决策相关）

- `@tanstack/react-query` 5.104.5（peer React `^18||^19`）、`@tanstack/react-router` 1.170.45（peer React `>=18||>=19`）、`@tanstack/react-table` 9.3.1（peer React `>=18`）。React 19 的 peer 范围成立，但本仓未装未测。
- TS-7 已授权要求 Router；D-085 直接选择 Query+Table。TS-25/26 是 TS-20+，未授权，**不得称为「合同条款」**。若方案要 Query，应引用 D-085，而不是 TS-25。
- Table 当前没有消费者：队列是 `Link` 列表、报告是 `ul`，没有排序、分页、虚拟化。D-085 选了 Table，但落点由 D-K 决定；UIUX §7.2 已写「500 行表格启用 virtualization；服务端权威排序字段不得仅客户端排序」，当前页面不满足触发条件。

## 5. 统一设计语言

### 5.1 三层模型与唯一权威

```
L1 token 层    web/src/styles/tokens.css      唯一色/字号/间距/圆角/动效来源
L2 原语层      web/src/ui/**                  复制进仓、可改、有 provenance
L3 业务层      web/src/components/** + pages/**  只写业务，不写视觉值
```

- **唯一 alias：** `@/* -> web/src/*`。因此 `@/ui/* -> web/src/ui/*`，`@/lib/utils -> web/src/lib/utils.ts`。`vite.config.ts` 的 `resolve.alias` 与 `tsconfig.app.json` 的 `baseUrl`/`paths` 必须写同一个映射；全稿只允许这一套，禁止 `@/components/ui/*` 与 `@/ui/*` 并存。
- **单一 token 源：** `web/DESIGN.md` 是设计语言与 token 的权威；`tokens.css` 是它的机器可读落点。UIUX §6.2 只保留语义分类（severity/coverage/authority/workflow），不另立一套色值。
- **DESIGN.md 与 tokens.css 的等式：** DESIGN.md 内放一个稳定的机器块 `<!-- TOKENS:BEGIN -->` … `<!-- TOKENS:END -->`（JSON code fence）；`web/scripts/gen_tokens.mjs --write` 从该块生成 `tokens.css`，`--check` 逐 token 比对名字与值；不一致 → 红。没有机器块 → 未测（退 2）。
- **单一组件层：** 所有可复用 UI 原语进 `web/src/ui/`；页面只组合组件，不写一次性样式。
- **单一图标层：** 业务层只有 `web/src/components/icon.tsx` 直接 import `lucide-react`；`web/src/ui/**` 允许具名 import Lucide（shadcn 组件需要），但禁止 `import * as`。业务组件通过 `icon.tsx` 取图标，禁止散落 import 与 Unicode 符号。
- **单一动效语言：** CSS 过渡优先；Motion 只作为实现手段，不改变 120ms/600ms/无入场/reduced-motion 全关的既定语言。
- **一个角色只许一个库：** 路由、服务端状态、客户端状态、图标、动画、拖拽、可调布局、表格、表单/校验，各一行 allowlist；新增库必须改策略文件并留下消费者。
- **源码可控的定义：** shadcn 复制进仓的 UI 层是真正可改源码（MIT）；Radix、CVA、clsx、tailwind-merge、Lucide、Tailwind、Motion、panels、dnd-kit、Zustand 都是 npm 运行时依赖，只能靠精确版本 + lockfile + provenance + 许可证审查控制。若委托方要求「所有 UI 源码进仓」，只有 shadcn 层满足；把 Radix 也 vendor 会与 TS-8 的 Radix 原语方向重复，且安全更新成本高。

### 5.4 Tailwind v4 接入与层叠顺序

现有 703 行 CSS 是**无层（unlayered）**的。Tailwind v4 把 utilities 放进 `@layer utilities`。**CSS 层叠里「无层」优先于「有层」**——如果直接把 703 行原样保留，所有 Tailwind 工具类都会被旧 CSS 压掉，表现为「组件长得完全没变」。

正确做法是分段导入并显式声明层序：

```css
/* web/src/styles/index.css */
@layer theme, base, legacy, components, utilities;

@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "./tokens.css" layer(base);
@import "./base.css" layer(base);
@import "./legacy.css" layer(legacy);
@import "tailwindcss/utilities.css" layer(utilities);
```

- `legacy` 排在 `components`/`utilities` 之前 → 新组件能覆盖旧样式；旧样式仍在，逐页删除。
- **legacy.css 里不得保留 `:root` 或任何 token 声明。** 迁移时把 `web/src/styles.css:19-43` 的 17 个自定义属性全部搬进 `tokens.css`，legacy 只保留选择器与布局规则。否则 legacy 在 base 之后，会覆盖 `tokens.css` 的同名 token，后续改 `tokens.css` 不生效。
- 如果使用一体化的 `@import "tailwindcss"`，无法把 `legacy` 插在 `utilities` 之前；所以本方案采用分段导入。
- Tailwind preflight 会重置 `margin`/`border-style`/标题字号。首版按标准 preflight 接入，先用视觉基线判定冲突；若冲突超阈值，再改为 `theme + utilities` 两段导入并保留自有 8 行 base reset。**不要同时保留两套 reset。**
- `@theme inline` 映射必须写全，否则 `bg-background`、`bg-ok`、`p-2`、`font-mono` 这类类名生成不出来：

**源码放置规则：**

1. **shadcn 源码只进 `web/src/ui/`。** 业务代码从 `@/ui/*` 取；`shadcn` 只保留为 devDependency（codegen），不得出现在运行时 import。`vite.config.ts` 与 `tsconfig.app.json` 只写一套 alias：`@/* -> src/*`。
2. **`cn()` 只用 `clsx + tailwind-merge`，不用 `cn` 包。** `class-variance-authority@0.7.1` 自己仍 `dependencies: {clsx: ^2.1.1}`；装了 `cn` 而不做 alias，树里就同时有 `cn` 和 `clsx` 两套类名拼接实现。`web/src/lib/utils.ts` 同时 re-export `cn` 与 `cva`，UI 层只从 `@/lib/utils` 取，形成单一第三方边界。
3. **每个 `web/src/ui/*.tsx` 必须在 `provenance.json` 有登记：** registry URL、style、CLI 版本、抓取日期、上游 sha256、`local_diff`、`normalized`、owner、reason。`upstream_sha256` 与本地文件不一致时，`local_diff` 必须非空。
4. **`ui-normalize.mjs` 统一改写 import 与剥掉入场动画类：** 把 `@/components/ui/*` 一律改成 `@/ui/*`，把 `cn` 的 import 统一到 `@/lib/utils`；剥掉 `animate-in`、`animate-out`、`fade-in-0`、`fade-out-0`、`zoom-in-95`、`zoom-out-95`、`slide-in-from-*`、`slide-out-to-*`、`duration-100/200`；保留 `transition-colors`/`transition-opacity`，时长统一为 `duration-[120ms]`（结构常量白名单外，但这是动效 token 的显式例外，需登记）。每个文件都会被规范化，所以 provenance 记 `normalized` 版本，而不是逐处手改。
5. **`shadcn/tailwind.css` 只抄必要片段：** `@custom-variant` 块 + accordion 两个 keyframes（约 2KB）；**不抄** `shimmer`、`scroll-fade-*`，因为 DESIGN 明确拒绝 shimmer。
6. **不手抄 registry 原始文件：** dialog/sonner 等含 `@/app/(create)/components/icon-placeholder` 和 `next-themes`；必须走 CLI transform，或复制后替换为本地 Lucide 图标与自有 theme hook。
7. **图标只有一个业务入口：** `components/icon.tsx` 具名导入 `lucide-react`；装饰性图标默认 `aria-hidden="true"`；有语义时传 `aria-label`/`role`/`title`。禁止 `import * as Icons`。`web/src/ui/**` 允许具名 import Lucide，但同样禁止全量 import。
8. **开发身份切换器保留原生 `<select>`。** 它是 dev-only 控件，且 `check_identity_switch.mjs` 已为 `HTMLSelectElement` 的 value setter + change 事件写好真实交互断言。换 Radix Select 只会增加一个门禁断裂点；如果产品要求统一，必须在同一变更里把门禁改成 Radix 的可访问交互并加反向对照。外观可以用 Tailwind 重做。
9. **`#review-note` 保留为原生 `<textarea>`。** shadcn Textarea 仍是原生元素，保留 `id="review-note"` 即可让 `check_review_actions.mjs` 的 `HTMLTextAreaElement` setter 继续工作；若改用 Radix/自定义控件，必须在同一提交把门改成可访问交互断言。

| **F13** | 裸值棘轮 | `web/src/styles/**/*.css`（除 `tokens.css`）+ `style={{}}` | 调用 `check_design_tokens.mjs --check --json`；出现**基线之外**的裸值 → 红；删除允许（shrink-only）；Node 不可用 → 未测（2） |
| **F14** | 上游漂移 | `--online` 时重取 `registryItem` 的 sha256；本地假 registry 可注入 | 上游变、本地有改动 → 需人工三方复核（红，1）；网络取不到 → **未测（2）**；**无每周触发者时一律报未测** |
| **F15** | 结论行不许撒谎 | 自身 | 有红时必须同时报出未测/延后条数；未测文案里不许出现「没问题」「通过」「全绿」；未知退出码（137 被杀）必须落进「未测」；结论行由纯函数 `verdict(n_pass,n_fail,n_untested,n_waived,n_deferred)` 生成 |
| **F16** | 相邻 manifest 重复声明 | `tools/package.json` 与 `tools/agent/package.json`（以及任何相邻 scope） | 同一依赖在两个相邻 manifest 重复声明且没有独立 lock → 红；合并或给独立 lock → 绿。`tools/agent` 本批 **DEFERRED**，控制样本在临时目录证明会红/会绿 |

> **F15 是给这个检查器自己写的**——`prd_baseline.mjs` 第一次运行就把 `--offline` 报成了「✅ 16 项全过」，这个坑不能重踩。

### 6.6 退出码与结论行

| 码 | 含义 |
|---|---|
| `0` | 全绿（**且 0 条未测、0 条延后、0 条豁免未过期**） |
| `1` | 有红（**即使同时有未测/延后，也先退 1**，但报告里必须同时列出未测与延后） |
| `2` | 只有未测/延后（lockfile 读不出 / `dist` 或 manifest 不存在 / 网络取不到 registry / selftest 跑不了 / Node 不可用） |

**未测、延后、豁免、通过、红必须长得不一样。** 结论行必须区分五者；有红时也要报出未测与延后；未测的文案里不许出现「没问题」「通过」「全绿」。`DEFERRED`（如 tools/agent）计入未测，不计入通过。不能把「命令存在」当成「有人在跑」；每个门必须指出调用点（`gate.sh` 或 `dev-up.sh` 的哪一阶段）。

### 6.8 waiver 模型（怎么处理「现在就是违规」）

没有 waiver，检查器第一天就全红，然后没人看报告（AGENTS §2.1.1：会误报的检查器比没有更糟）。所以：

```json
"waivers": [
  { "id": "W-001", "scope": "web", "rule": "F12",
    "reason": "本机无 pnpm/corepack，TS-6 偏差已登记 deployment-plan §147",
    "owner": "web owner（待编排方指派）", "expires": "2026-12-31", "ticket": "T-WEB-01" }
]
```

规则：

- waiver **必须**有 `owner` + `expires` + `ticket`；缺一即红。
- 过期 waiver → **红**（不是警告）。这是防止 waiver 变成永久豁免的唯一手段。
- 生效中的 waiver 打印为 `WAIVED`，**不计入通过数**，结论行单独报「N 条豁免」。
- **禁止**用 waiver 绕过 `F5`（互斥）、`F8`（provenance）、`F9`（ui import 闭包）、`F15`（结论行）—— policy 里 `unwaivable: ["F5","F8","F9","F15"]`。

当前需要的 waiver（示例，实施时按实际读数填）：

| ID | scope | rule | 原因 | owner | expires |
|---|---|---|---|---|---|
| W-001 | web | F12 | npm 代替 pnpm；本机 pnpm/corepack 不可用 | web owner（待指派） | 2026-12-31 |
| W-002 | web/tools | F4 | `@types/node` 24.19.2 vs 26.5.1（dev-only） | web owner（待指派） | 2026-12-31 |
| W-003 | web/tools | F4t | `undici-types` 7.24.6 vs 8.9.0（随 `@types/node` 传递） | web owner（待指派） | 2026-12-31 |

### 6.11 自证无副作用

- 所有 selftest 只在 `mktemp -d` 临时目录或注入的 root 上跑，不得写真实 `package.json`/lockfile；检查器不得改状态文件。
- 文件发现只用 `git ls-files`（与 `verify_download_governance.py` 同一条纪律）。`git ls-files` 跑不了 → **未测（退 2）**，不是「没有文件」。
- 每次主检查都真跑反向对照，不是只跑 `--selftest`；反向对照跑不了 → 退 2。
- `--selftest` 指向真实仓库必须被拒绝；这条本身要有反向对照（C20）。
- 不写 `PMO/shouheng-state/`、不启动/重启守衡；本方案不涉及守护进程。

### 6.12 检查器的单一实现

计划自己要求「单一实现」，所以不能出现两套重复检查：

- **DT/F13：** `web/scripts/check_design_tokens.mjs` 是唯一实现；`verify_frontend_deps.py` 的 F13 用 `subprocess` 调 `node ... --check --json` 并解析 `ok/reds/untested`。Node 不可用 → 未测（2），不在 Python 里重写一套正则。

- **样例数据：** `web/scripts/check_sample_data.mjs` 是唯一实现；`check_pages.mjs` 不重复写样例规则。
- **视觉：** `web/scripts/check_visual.mjs` 是唯一实现；不把截图比较塞进 `check_pages.mjs`。
- 每个脚本都输出 `--json`，字段固定为 `{ok, reds[], untested[], waived[], details[]}`，供 gate 与 Python 共同消费。

- 1280×720 与 400% reflow 在真实 Chrome 的读数（阶段 0 才测）。
- 读屏（VoiceOver/NVDA）、真实键盘全流程、真实用户测试。
- Query 在真实后端下的轮询/可见性/终态行为（阶段 4 才测）。
- Router 迁移后的直接 URL、刷新、404、深链。
- 生产认证 SSO、真实写面（ADR-0015 D5 之外的 action）不在本方案范围。
- **F14 的每周触发尚未建成；在此之前它一律报「未测」。**
- **F8 的 provenance 只是本地记录；F14 未测时，不能声称「已与上游核对」。**

## 10. 不做什么

1. **不把 Motion、react-resizable-panels、Zustand、dnd-kit、TanStack Table 预装。** 没有消费者就不装；有真实用例再按阶段 6 逐个立项；Table 需 D-K 拍板。
2. **不采用 Nova 默认主题**（Geist/neutral/0.625rem），除非委托方明确选择并承担 DESIGN/A6/对比度表重写。
3. **不引入 shadcn 运行时依赖**；不手抄 registry 原始文件；`shadcn` 只做 devDependency。
4. **不引入 `cn` 包**；不做 `resolve.alias` 魔法；类名合并只用 `clsx + tailwind-merge`，收在 `web/src/lib/utils.ts`。
5. **不启用 `tw-animate-css` / 入场动画**；shadcn 生成物里的 `animate-in` 类由 normalizer 剥掉。
6. **不安装 `next-themes`、`sonner`**（除非替换 theme hook 并重新评审）；不装 chart/calendar/carousel/command/drawer/input-otp。
7. **不在本批迁 pnpm**；不与 UI 迁移耦合；pnpm 另开票。
8. **不新起前端项目/脚手架**；改造现有 `web/`。
9. **不自行改写合同文本、Playbook、AGENTS.md 或 PMO 决策**；合同变更走委托方决策记录。
10. **不做生产 SSO、真实写面、12 页全量生产化**；遵守 ADR-0015 D5 的首批写面。
11. **不做深色主题**；token 结构允许后续加，但本批不写 `.dark`。
12. **不做独立 metrics dashboard / chart**；依据 UIUX §7.2 与 §11 `/metrics` 内部接口，不引用未授权的 TS-26。
13. **不把截图/PNG/媒体提交进公开仓**；视觉基线用 JSON 结构快照。
14. **不跑全量 `depad --fix`**；不 `git add -A`；不重启守衡。
15. **不把 axe 0 违规当成 WCAG 通过**；人工证据必须签收。
16. **不把「检查器绿」当成「生产可用」**；生产边界门必须在 hostile build 上跑。
17. **不碰 `tools/agent/`**；不修改它的 manifest/lock；不要求重启守衡；T-SH-01 交 8a。
18. **不把 woff2 直接入库**；字体默认 system-ui，自托管必须走 T-WEB-02f + `asset_baseline.json` + DG-3。
19. **不在 D-K 拍板前装 Table**；500 行 virtualization 与服务端排序没有落点时，不假装已满足 UIUX §7.2。
20. **不把「F14 未测」写成「源码可控已验证」**；F8 只报「本地记录完整（未与上游核对）」。
