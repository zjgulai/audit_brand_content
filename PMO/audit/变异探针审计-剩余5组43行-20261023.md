| 问题 | 读代码 | 变异 |

## 二、★ 这批抓出的最重要一件事：我的工具自己有个假 killed 缺陷

`mutprobe` 第一版的判据是「崩溃点落在**被变异的文件**里 → untested；落在别处 → killed」。
这个判据有个漏洞，由探针 agent 当场报出来，我复现确认：

`tools/verify_decision_table.py:311`

```python
T("F2 五标签都可达", seen == FIVE_STATES, str(sorted(seen)))
```

`base/decision_table.py` 的 `_error()` 在 `NO_CHAIN` 时返回 `"state": None`，
于是 `sorted({None, "待自决"})` 抛 `TypeError`。

**验收器自己有一个与变异无关的崩溃点。** 任何把输入推进 `NO_CHAIN` 的变异都会让它崩，
而我的判据会把「帧落在验收器一侧」记成 killed —— **假 killed**。

> **假 killed 比假绿更坏。** 假绿会被审计抓出来；假 killed 会让一条没验的判据
> 心安理得地留在 `passed` 里，而且没有任何东西会再去看它。

**修法**：判据改成看**异常类型**，不看崩溃点在哪。

| 异常 | 判定 | 理由 |
|---|---|---|
| 无 Traceback + 退非零 | killed | 验收器「打印 ✗ 再 return 1」，最常见的形态 |
| `AssertionError` / `SystemExit` | killed | 有人写了断言，它不成立 |
| `NameError`/`TypeError`/`KeyError`/`SyntaxError` | **untested** | 改崩了，不是抓住 |

自证加到 8 项，新增**成对**的两条（缺一条修法就会走向反面）：
S7 验收器自身有无关崩溃点时**不许**记 killed；
S8 验收器的 `AssertionError` **必须**算 killed（防止把不误报的检查器修成哑巴）。

复现：`python3 tools/mutprobe.py --selftest` → 8/8。
