## 二、为什么要单独记这一条

这件事**不是一次普通的代码提交**。它分三步走完，每一步都留下了一条可查的记录：

1. **权限闸门两次拦截（本会话）**
   编排会话两次尝试提交该文件，均被自动权限分类器拦下，理由是
   「引用了外部 GitHub Actions，**用户没有逐个点名这些外部仓库**」。
   **拦截是对的**——「引用了外部代码源」这件事该由人确认，不该由 agent 顺手带进去。

2. **授权发生在另一个会话（`ea`）**
   委托方在 `ea` 会话里逐字输入了授权原话，点名了全部五个仓库与「均已 pin SHA」。
   `ea` 据此提交了 `2af496e`，并在提交信息里注明「（委托方授权入库）」。

3. **编排会话要求可独立复核的依据，而不是采信复述**
   编排会话看到提交信息后**没有直接采信**，要求 `ea` 给出**可独立复核的指针**（而非复述）。

   ★ **那一步核验没有完成**：逐行读取另一个会话的转录被权限闸门拦了两次
   （一次「读另一个 Claude 会话的转录未经授权」，一次 PII 分类器误拦），
   **编排会话没有绕过**。因此当时**没能**独立确认那句授权的归属。

   > **本记录只写到这里为止。** 另一个会话的转录内容不复制、不摘录进本仓 ——
   > 它属于那个会话，不属于这个仓库。核验没做完就是没做完。

4. **委托方在本会话当场确认**
   委托方在本会话明确回话：「**确认授权成立**」。

   → 本条据此收口：授权由**委托方本人**在本会话给出，依据是本会话的一手对话，
   而不是另一个会话的转录。

## 四、这条记录的边界

* **不证明这份 YAML 在真实 GitHub runner 上跑得通。** 本机无 `gh`、离线，
  触发不了一次真实 workflow run。**第一次真实 push 是它的首次实战。**
* **不证明远端分支保护拦得住合并。** 本机读不到（无 `gh`、带凭据详情 401），
  `--scope ci` 刻意不判它。
* **不构成本仓对外部 Action 的长期安全承诺。** pin SHA 只保证「不会悄悄换代码」，
  不保证「这份 SHA 的代码没有漏洞」。升级需要人工改 SHA。

## 五、留给以后的规矩

**「授权」是这件事里唯一不能靠推断的一类** —— 它决定外部代码能不能进仓库。
所以本项目对被授权事项的要求是两句话：

> **授权必须指得出原话，不能是「我记得」或「pin 了 SHA 应该就算」。**
> 而 agent 一侧给出的证据必须是**别人能独立复核的指针**，不是复述。

`ea` 这次给了转录路径（可复核），编排会话要求它给（而不是采信），
两条合起来才让这件事收口。**缺任何一条，都应该继续问。**
