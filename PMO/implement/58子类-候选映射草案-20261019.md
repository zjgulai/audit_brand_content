## 1. 计数口径（先说清，再列候选）

### 1.1 规则级（本文主口径）

现有 26 条规则中，25 条能通过 `parent_rule` 落到一个控制点、再落到一个族；
1 条是 `安全词`（`T9.objective-parameter`），**不是控制点码**，不归入七族候选。

- 宣称：18 条规则
- 事实：4 条规则
- 披露：3 条规则
- 场景/权利/渠道/品牌：0 条
- 合计：**25 条**（active 24 + `U02` deprecated 1）

这与 `research/governance/README.md` 的既有约束一致：
**一个 `subclass_code` 最多映射一条规则；冲突时以 `rule_key` 为准。**
所以本文给每条规则一个候选 `subclass_code`，不把多条规则塞进同一个 subclass。

### 1.2 topic 级（辅助口径，只用于说明归并）

同一 `topic` 下可以有多个 `topic_label`：

- `T2.2`：`机器性能声明 · 适体性` / `机器性能声明 · 智能仿生`
- `T2.2.2`：`噪音 / 吸力` / `吸力夸大`
- `T3.2`：`专家 / 个人背书` / `专家 / 个人背书 · 头衔`

按 topic 归并后是 **22 条**（宣称 15 / 事实 4 / 披露 3）。
**但 topic 归并会少算规则级差异**，所以主口径仍是 25；
22 只用于回答「如果产品按主题而不是按规则建子类，会是多少」。

### 1.3 复现命令（读数不是手写的）

```bash
python3 - <<'PY'
import json
from collections import defaultdict
cp = json.load(open("research/governance/control-points-v1.json"))
family = {r["control_code"]: r["family"] for r in cp["control_points"]}
rules = json.load(open("research/governance/skeleton/rules-v1.json"))["rules"]
by = defaultdict(list)
for r in rules:
    f = family.get(r["parent_rule"])
    if f:
        by[f].append((r["topic"], r["topic_label"], r["rule_key"], r["parent_rule"]))
for f in cp["families"]:
    print(f, "rules=", len(by[f]),
          "topics=", len({x[0] for x in by[f]}))
print("total rule-level=", sum(len(v) for v in by.values()))
print("unmapped=", [r["rule_key"] for r in rules if r["parent_rule"] not in family])
PY
```

## 2. 建议的 `subclass_code` 命名规则

**提案（待产品确认后才可分配）：**

```
<族前缀>-<两位序号>
```

| 族 | 建议前缀 | 示例 |
|---|---|---|
| 宣称控制 | `CLAIM` | `CLAIM-01` |
| 事实控制 | `FACT` | `FACT-01` |
| 披露控制 | `DISC` | `DISC-01` |
| 场景控制 | `SCENE` | `SCENE-01` |
| 权利控制 | `RIGHT` | `RIGHT-01` |
| 渠道控制 | `CHAN` | `CHAN-01` |
| 品牌控制 | `BRAND` | `BRAND-01` |

约束：

- 序号只在族内递增；**码一经分配不复用、不改号**（与 `control_code` 同一条纪律）。
- 前缀只表达**展示分组**，不表达严重度、判定确定性或控制点语义。
- `subclass_code` **不是控制点码**，不能替代 `control_code`；
  也不能拿它当控制点数量分母（数量口径只读控制点主表）。
- **`rule_key` 是唯一机器键**：所有机器连接、判定、报告去重都以 `rule_key` 为准；
  `subclass_code` 只是可选展示属性，冲突时以 `rule_key` 为准。
- 本草案**不把 `subclass_code` 写进 `rules-v1.json`**；这里只是候选命名，不是分配记录。

## 7. 与 `rule_key` / `control_code` 的关系（一句话版）

```
rule_key        唯一机器键：判定、连接、报告去重都用它
control_code    控制点键：归属、路由、版本、依据挂在它上面
subclass_code   可选展示属性：只影响报告分组/排序，不参与判定与连接
```

- 当前 `rules-v1.json` 里 `subclass_code` 为 **0 条**；本文**不写入**。
- 一个 `subclass_code` 最多映射一条规则（现有 V61 约束）；冲突时以 `rule_key` 为准。
- 58 是**分类确认视图的二级条目数**，不是控制点全集，也不是判定分母。
  控制点数量口径仍只读 `control-points-v1.json` 主表（行 78 已接的执行点）。
