## 一、读数

样本 65 条（分层抽样，`/tmp/llm_eval_sample.json`），模型 `deepseek-flash`（仓库既有 `tools/agent/llm.mjs`，OpenAI 兼容协议）。

| 轮次 | axis_exact | unknown | 解析失败 | 结论 |
|---|---:|---:|---:|---|
| 纯文本分类器（拆泄漏后基线） | **22.07%** | 57.42% | — | 不可用 |
| LLM · 含子类名（run2） | **78.13%**（50/64） | 0.00% | 1/65 | 未达标（门槛 95%） |
| LLM · 隐藏子类名（盲测） | **77.05%**（47/61） | 0.00% | 4/65 | 未达标 |
| LLM · 补 DSC11/12 分界后（run3） | **76.92%**（50/65） | 0.00% | 0/65 | 未达标 |
| LLM · 同 prompt 复跑（run4） | **79.69%**（51/64） | 0.00% | 1/65 | 未达标 |

**两轮差 1.08pp（含子类名 vs 盲测）。** 这一项本来是最该担心的地方 —— 契约 §6 风险 2 写着「子类名 → 多数轴 56/56 与 gold 相同，模型若靠子类名猜，等于换了一种泄漏」。
现在读数说明：**它没靠子类名**。这是本轮唯一一条可以放心记为「已排除」的风险。

`UNKNOWN` 各轮都是 0 —— 模型对每条都给得出答案，从不弃权。这一点在下一节会变成问题（弃权本可以救回几条）。

> ⚠️ **先看噪声，再看任何"改进"。** run3 与 run4 用的是**逐字相同的 prompt**（temperature=0），
> 结果差 **3/65**，且翻转的正是两条边界样本（`r-6f2500…` 在 FACT↔DISC 之间来回、
> `r-d576de…` 同理）。也就是说：**±3 条以内的差异不可解释**，
> 把它记成"提示词改好了"或"改坏了"都是把噪声当信号。
> 后文对 DSC11/12 那次修改的评估，一律按这个噪声带读。

## 二、错例不是噪声

两轮各有 15 / 18 条错，**交集 14 条**。也就是说错误是**系统性的**，不是采样抖动：

| 方向 | 条数 |
|---|---:|
| FACT → DISC | 4 |
| DISC → FACT | 3 |
| FACT → SCENE / SCENE → DISC / FACT → CLAIM / FACT → BRAND / CLAIM → FACT / CLAIM → DISC / RIGHT → DISC | 各 1 |

九种方向，只有两个方向（FACT↔DISC 双向）占了 7/14。**其余七种各 1 条，是散点。**

## 四、剩下的 7 条里，4 条撞在同一个规范空洞上

| rule_id | gold | 模型 | 规则正文的关键改写 |
|---|---|---|---|
| `r-6f2500bc187d8fae` | FACT | DISC | `修订为：补充：该姿势的优点是视野开阔…` |
| `r-b2530a099df678b3` | FACT | DISC | `修订为：补充说明：短期内使用的母乳优先直接冷藏…` |
| `r-640dfb910ee7c32b` | FACT | DISC | `修订为：补充说明：上班初期不建议同时安排断夜奶…` |
| `r-c12133ccfd10080b` | FACT | DISC | `修订为：补充说明：体重增长趋势应符合 WHO 生长曲线…` |

**四条全是「修订为：补充（说明）……」，模型的错法完全一样。**

规范没有判据能分开这两种情况：

- **DISC 读法**：谓词是「补充」，宾语是一串受众可见的信息 → 命中 DSC1。
- **FACT 读法**：这是修订元语言，动作是把缺失的事实补全 → 命中 FCT8（知识不完整）。

现有 DSC1 的谓词表写的是「需明确/应说明/必须标注/加注/提示/披露/告知」，
**「补充」不在里面，但也不在排除项里**；DSC8 说「去掉 X 后基础事实仍独立成立则不命中 DISC」，
而这四条去掉 X 之后，「描述不完整」这个问题**正好也不存在了** —— 两头都能自圆其说。

这不是模型的问题，是**规范缺一条分界测试**。它是我写 §2.8 时该一并处理而漏掉的那一类。

### 已补：DSC11/DSC12 + FCT10，但收益落在噪声带里

我当天就补了判据（规范 §3.4 DSC11–DSC12、§3.6 FCT10、§4.21 四条样本 + 一条反例配对，
提示词同步加入「拿掉 X 之后原句还成不成立」这道测试）。效果要**分开读**：

| 观察 | 读数 | 能不能算数 |
|---|---|---|
| 四条里翻正 | 2/4（`r-b2530a…`、`r-c12133…`） | ✅ 有 `reason` 引用了新判据，是判据在起作用 |
| 四条里仍错 | 2/4（`r-6f2500…`、`r-640dfb…`） | 模型引用了 DSC12 且推理**站得住**（「拿掉后原句仍成立 → 披露」） |
| `r-39b29b5…`（同形、此前不稳定） | 稳定判 FACT 并引用 FCT10 | ✅ 判据把它钉住了 |
| 反向回归 | 3 条原本对的翻错 | ❌ **但同 prompt 复跑也翻 3 条** |

所以诚实的结论是：**新判据让「为什么这么判」可复核了，还没让读数动。**
76.92% vs 78.13% vs 79.69% 三个数在同一个噪声带里，**不能拿其中任何一对做 A/B**。

剩下那 2 条不是判据不清，是**判据的输入不够**：
`r-6f2500…` 补的是「该姿势的优点」，`r-640dfb…` 补的是「返岗初期别同时断夜奶」——
两者都可以读成「一句独立建议」，也都可以读成「主命题缺少的成分」。
**这类样本的真值只能由人定，不能由判据定**（见 §五：它们本来就没被复核过）。

> 附带证据：`r-39b29b57103f9888`（同样含「补入…处理方式」）在盲测里也翻成了 DISC，
> 在含子类名那轮是 FACT —— 连模型自己在这条上都不稳定，正好落在同一个空洞里。

## 五、基准的真实成色

| 项 | 读数 |
|---|---:|
| 512 分母中有人工复核痕迹（`review_note`/`review_raw` 非空，或 `primary_reviewed ≠ primary_initial`） | **16 / 512 = 3.1%** |
| 即：gold 就是初始自动分类、没人看过的 | **496 / 512 = 96.9%** |

**这就是本轮最该报的一件事。** 「LLM 78% vs 门槛 95%」读起来像模型不行；
真实情况是：**我们拿一个未经复核的自动分类结果当考官，去判另一个分类器的分。**

这一条同样解释了为什么纯文本分类器当初能「做到 83%」—— 不是它好，是它和目标同源。

## 六、下一步（按性价比排）

1. **先给 65 条样本定噪声带，再谈任何改进。** 同 prompt 复跑差 3 条，
   意味着任何"改了提示词涨了 2 条"的说法都没有依据。
   做法：把 `r-6f2500…`、`r-d576de…`、`r-46e00e…` 这类翻转样本单独标成 `unstable`，
   后面**不拿它们算达标率**，单独报「稳定答对 / 稳定答错 / 抖动」三档。
2. **人工仲裁 14 条系统性错例**（7 条规范已指明方向，另外 7 条需要人看）。
   仲裁完 benchmark 变成「已复核子集」，读数才有意义。0e 的
   `披露模板重抽-40条` 已经示范过做法：逐条读原文 + 附证据指针。
3. **不要在 512 全量上重跑**。65 条的错例已经收敛（14/15 共有），
   先修判据、再扩样本，否则是在测噪声。
4. **`temperature=0` 不等于确定性。** 本机 `deepseek-flash` 在 65 条上有 3 条翻转，
   其中两条正是边界样本 —— 这不是 bug，是「边界样本本来就在判据边缘」的物理表现。
   评测器要把这一点报出来，而不是给它抹平。
5. `r-dd43e1afe7ec11e1` 在 run2 解析失败（模型输出了 `code` 字段而不是 `primary`），
   run3/run4 恢复 —— 属于输出契约偶发不遵守，`parseVerdict` 已经把它记成 PARSE_FAIL 而不是答错。
   但**门槛只算解析成功的分母**这件事必须在报告里显式说明，否则解析失败会被悄悄吃掉。

## 七、这份评测自己怎么被验

`node tools/llm_rule_axis_eval.mjs --selftest` —— 22 项，全部是纯函数，不联网。

| 组 | 验什么 |
|---|---|
| 输入白名单（3 项） | 禁用字段 `primary_initial`/`primary_reviewed`/`quality_tag`/`policy_fragment` 填成 `ZZZ_FORBIDDEN` 后 prompt 里必须找不到；正反各一次 |
| 盲测遮罩（3 项） | 盲测里**没有**子类名，且**非盲测里必须有** —— 两条成对，只验一边的话构造器恒返回空串也能过 |
| 输出契约（7 项） | 集合外的 primary 不收；同时给 primary 与 unknown 不收；围栏 JSON 收；纯文本不收 |
| 计分（6 项） | 分母只算解析成功；空输入 → `tested=false`（未测，不是 0%）；全对 → pass |
| 结论行（2 项） | 三态（达标/未达标/未测）文案互异；未测文案里不许出现「达标」 |
| 白名单源码（1 项） | 构造器源码不引用禁用字段 |

**为什么「空输入 = 未测」要单独成一条**：如果 0 条结果算 0%，下一轮看到 0% 的人会去调提示词，
而真因是没跑成。这与 `AGENTS.md` §2.4.2 的 L3、§2.7 的 E1 是同一条纪律。
