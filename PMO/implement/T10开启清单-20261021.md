## 四、可开启的通用判据（每条都要满足）

一个规则从「否」变「是」，必须同时满足以下全部条件，缺一不可：

1. **引擎口径**：`base/rule_judge.py` 已执行 `exclude_patterns` 与 `require_context`；`keywords` 与 `patterns` 的关系已定；有行为级反向对照（断开排除式 → 断言红）。
2. **正向样本**：至少 **20 条**真实第一方广告文案（不是规则/法规/台账、不是引用/用户原话），其中**至少 5 条**是该规则的真目标。
3. **precision**：双人独立标注后，**precision ≥ 0.80**；分歧已裁决并留档。
4. **负向样本**：同一批测试里，**误报率 ≤ 0.20**（或 precision 的补数），且没有「只能误报」的规则。
5. **规则变更**：本清单建议的 pattern/排除式变更须经 owner 复核并落地；本清单**不直接改** `rules-v1.json`。

> 这五条里第 2 条是当前所有 10 条的共同缺口：8a 的 11 条命中全是误报，**没有任何一条规则被证明能命中真目标**。第 1 条是全局阻塞：引擎不执行排除/上下文，开了也不是清单里量到的行为。

## 七、T10.2.village-naming 的 `require_context` 装反了（doublefit 同形）

### 7.1 出处：谁加的、按什么依据

- `require_context` 不是 1d 导入时新写的：`0d8b98d`（fa，「品牌判据审计 + 第 1 批 10 条发布期用词规则」）的候选 JSON 里，`T10.2.village-naming` 与 `T10.2.doublefit-naming` 已经有这两个 `require_context`。
- `164768a`（1d，「T10 规则导入」）把它原样导入 `rules-v1.json`；`git blame` 指向 `164768a`，是因为那才是入库提交。`164768a` 对候选 JSON 的改动里，**对这两条规则只改了 `context_note`**（补「术语解释 / 技术定义」），没有改 `require_context`。
- `source_legacy` 写的是 `momcozy_ai_brand_knowledge_base.md §L8`。但品牌文档原文只说：
  - KB:42「Momcozy Village: 官方社群的名称，严禁说成“user group”。」
  - KB:39「DoubleFit™ Flange: 严禁说“suction cup”或“plastic part”，必须强调“双层密封法兰”。」
  - 它**没有**说「只有正确名称在场才算命中」。所以 `require_context` 是规则作者的推断，**指得出提交与文件，指不出原文依据**。

### 7.2 为什么是反装，而不是收窄

`require_context` 的语义是「文本必须至少出现其中一个词，否则整条规则不产生命中」。而这两条规则要抓的是「用了错误叫法」：

- 真违规：「Join our user group to meet other moms.」→ 没有 `Momcozy Village` → **被挡**。
- 不该抓：「Momcozy Village: 官方社群的名称，严禁说成“user group”。」→ 有 `Momcozy Village` → **放行**，随后 pattern 命中 `user group` → **报出这条术语说明**（误报）。

允许语料里的真实反例只有品牌文档这一侧；台账 1,161 条与 MECE 638 条里 `user group / user community / 用户群 / 用户社群` 命中 **0**，`suction cup / plastic part / 吸盘 / 塑料件` 也是 **0**。所以：

- **真实反例（误报侧）**：KB:42 与 KB:39，都是「正确名称 + 错误叫法」同时出现的**术语说明/禁止说法**。
- **真违规侧**：允许语料里 **0 条**；候选 JSON 的 `Join our user group…` 是 constructed，不是实测。

### 7.3 village 的正确判据建议

**删除 `require_context`**（它把正确名称当成命中前提，方向反了），改为**排除式**。建议（不写入 `rules-v1.json`）：

```python
NEG  = r'(?:严禁|禁止|不要|不应|不能|不许|避免|别)(?:说|叫|称为|使用|用)'
TERM = r'(?i)(?:名称|术语|叫法|定义|指的是|又称|即|called|known as|generic|term|definition|technical)'
COMP = r'(?i)(?:竞品|其他品牌|competitor|other brands?)'
# 可选：引号内术语；可能误伤“把 user group 加引号引用”的真违规，需 owner 决定
QUOTED = r'[「『“\"][^」』”\"]{0,80}[」』”\"]'
```

把这几个加进 `match.exclude_patterns`；`patterns` 保持 `user group|user community|用户群|用户社群`。

在真实品牌文档与 constructed 样本上跑（排除式只看是否命中，不替代人工判读）：

| 文本 | 现 `require_context` | 建议排除式 | 判断 |
|---|---|---|---|
| KB:42 真实术语说明 | 通过 → 会报 | NEG + TERM 命中 → 排除 | 正确（不报术语说明） |
| `Join our user group...`（constructed） | 无正确名称 → 被挡 | 不命中排除式 → 会报 | 正确（若是真违规） |
| `The competitor's user group...`（constructed） | 无正确名称 → 被挡 | COMP 命中 → 排除 | 正确（竞品语境） |

结论：**village 按现在的写法根本开不了**。删掉 `require_context` + 排除术语/否定/竞品，才有可能让真违规通过、让术语说明不通过；但「真违规」一侧在允许语料里仍是 0 条，precision 还无法计算，必须补真实广告正例。

### 7.4 doublefit 是不是同类

**是同类，但不是完全互斥。** `require_context` 是 `DoubleFit / 法兰 / flange / 泵 / pump`，patterns 抓 `suction cup / plastic part / 吸盘 / 塑料件`：

- 真实反例：KB:39「DoubleFit™ Flange: 严禁说“suction cup”或“plastic part”…」有 `DoubleFit`/`法兰` → 通过 require_context → pattern 命中 → **报出术语说明**（误报）。
- 真违规：「The suction cup keeps the flange in place.」也含 `flange` → 通过 require_context；所以这条**不会**像 village 那样把所有真违规挡掉，但它是同一种**机制错误**：用「正确名称在场」当命中前提，无法排除「术语定义/否定/竞品」。
- 另一个误报：`The suction cup is a generic term for the flange.` 含 `flange` → 通过；`generic term` 没有排除式 → 会报。

建议同样：**删除 require_context**，加 `NEG` / `TERM` / `COMP` 排除式；`TERM` 里的 `generic|term|definition|technical` 正好覆盖「术语定义」。真违规侧同样 0 条真实语料，需补正例。

### 7.5 这是多大的类别问题

- 全仓 36 条规则里，带 `require_context` 的只有 **3 条**：`T10.1.weight-loss`、`T10.2.village-naming`、`T10.2.doublefit-naming`。
- 其中 **2 条**（village、doublefit）属于「把正确名称当上下文」的同一毛病；`weight-loss` 的 `require_context` 是**产品/场景上下文**（产后/收腹带/belly band），是合法的收窄，不是同类。
- 所以比例是 **2/10 T10 = 20%**、**2/3 带 require_context 的规则 = 67%**。不是 36 条规则普遍都有，但命中率很高，而且是一个**schema 陷阱**：
  - `require_context` 同时被用来表达两种完全不同的意思：①「场景/品类上下文」（合法）；②「正确名称在场」（会把规则装反）。
  - 建议给规则 schema 加 `require_context_kind: scenario | correct_term`，或在 verifier 里拒绝「`require_context` 的值等于该规则的 correct/replacement term」；至少要求这类规则同时有 `exclude_patterns` 覆盖否定/术语解释/竞品语境，并加行为级反向对照。
- 这条不是 village 个例，而是「正确名称当上下文」这一类；当前快照里 2 条，未来任何新规则照这个写法都会复发。

### 7.6 结论

- `T10.2.village-naming` 按现在的写法**根本开不了**：`require_context` 挡真违规、放术语说明。
- `T10.2.doublefit-naming` 同形、同结论；它只是没有 village 那么完全互斥。
- 两条都需要：删除 `require_context`、改为否定/术语/竞品排除式、补真实广告正例（各 ≥5 条真命中）、双人标注 precision ≥0.80；在这些完成前保持 `enabled: false`。
