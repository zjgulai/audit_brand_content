## 六之补 · 冻结回归集里有一条样本与法务决定相反（2026-10-26 发现）

做 T-407 的签署申请时捞出来的，**与 T-400 段的八票无关，但比它们重要**：

| | |
|---|---|
| 样本 | `GS-011`：`FDA cleared medical device for home use` |
| 该样本的期望 | `expected.kind = should_hit`（**该拦**） |
| `rules-v1.json` 的实际规则 | `FDA cleared` 在 `downgrade_band.keywords` 里 → 落 **auto_pass** |
| 规则里的依据 | `$decision: "D2 · 法务 2026-09-16：**放行**"`，并引 21 CFR 807.97：「禁止把 cleared 说成 approved，不禁止说 cleared」 |

**所以引擎不拦它是按法务的意思，错的是样本的期望值**，不是引擎漏了。
样本建集于 2026-10-22，比那条法务决定晚 36 天 —— 建集时没有对照
`legal-decisions-v1.json` 做一次对账。

★ 为什么必须写进这份报告而不是只留在申请文档里：**签反了会把合规表述变成违规**。
  一家如实声明「FDA 510(k) cleared」的厂商，会因为这个样本被拦。
  这不是「保守一点没坏处」的场景 —— 两个方向都会造成实质损害。

★ 顺带一条方法上的结论：**「其余 82 条期望值与引擎一致」不代表标签对，
  只代表引擎按标签在做。** 两者不一致的地方才是能捞到问题的入口，
  而它只有 1 条（`GS-011`）—— 也就是说**靠一致性检查发现不了这类错**，
  必须逐条对着法务决定看。

## 七之补 · 两处台账读数的核对结果（2026-10-26）

做收尾时发现的两处「数字对不上」，都核过了，**一处是真缺陷、一处不是**：

### 7.1 `acceptance-ratchet.json`：地板高于当次读数（**真缺陷，已修**）

| 字段 | 改前 | 说明 |
|---|---|---|
| `passed_floor` | 126 | 只许上调 |
| `recorded_reading.passed` | **124** | ← 与 floor 矛盾 |

`how_to_raise` 自己写的是「把 `passed_floor` 改成当前 `passed`」。
两者应当**永远相等**（floor 就是那一刻的读数）。124 与 126 并存意味着：
「抬地板那次，读数没跟着更新」。

**修法**：补 `recorded_reading`（126），**不动 floor** —— floor 下调是倒退，
而这里的事实是「读数当时就已经是 126，只是没记」。并加 `recorded_note` 写明这次更正。

### 7.2 `waiver-v1.json` WV-07：`收回原因` 里写「8 项断言」（**不是缺陷**）

实测 `verify_regression_set.py` 现在是 **11 项**。看起来像台账漂移，
但读完整条：WV-07 状态是 `closed`，`收回原因` 写「2026-10-23 已交付：T-85 建了冻结回归集
（83 条）+ `verify_regression_set.py`（8 项断言）」—— 那是**交付当天的读数**。

★ 判断：**不改**。改它等于改写一条历史记录（「当时交付的是什么」），
而这正是 ADR 收录异议时的同一条规矩。若将来要表达「现在是多少项」，
应当新增一条记录，不是覆盖旧的。
