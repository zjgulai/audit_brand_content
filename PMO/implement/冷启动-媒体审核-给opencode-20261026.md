### T-430 的具体内容（第一票，写细一点）

`base/orchestrator.py` 的 `_coverage_ir()`（79–87 行）用白名单重建 coverage，
**漏了 `does_not_cover`**。复现：

```bash
python3 -c "
from base.orchestrator import _coverage_ir
out = _coverage_ir({'coverage': {'coverage_state':'partial','modalities_evaluated':['image'],
    'rules_version':{'version':'r'},'control_points_applied':['H01'],
    'does_not_cover':['画面语义']}, 'coverage_state':'partial'}, {'control_points':['H01']}, {})
print('还在吗:', 'does_not_cover' in out)"   # → False
```

`contract.from_media()` 刻意不给 `covers`/`does_not_cover` 默认值（默认值会让
「只做了 OCR」看起来像「图片已审」），结果那个声明在最后一跳被**静默丢弃**。
文本上无害（文本该字段本来就空），**一开媒体就等于把没审的部分伪装成审过**。

改法：加进重建白名单，并从 `unit.textification.does_not_cover` 兜底（两条路都要）。
判据：`verify_orchestrator.py` 新增一条断言（非空 `does_not_cover` → IR 里逐字相等）；
**变异「删掉那一行」→ 必须红**。

### 多模态结果怎么落（这条最容易做错）

finding 有三要素，**缺一即拒**：

```python
# base/finding_store.py:69
ADMISSION_KEYS = ("control_code", "authority_ref", "location")
```

`location` VLM 能给；`control_code` 与 `authority_ref` **都是知识库产物**。
所以「先打通 + 落 candidate finding + 知识库慢慢建」三条**不能同时成立**。

**分两级**：
- **L1 观察** → `case.context.multimodal_observations`，进权威、报告单独成节、
  标「候选 · 待人工确认」。**今天就能跑，不需要 control_code。**
- **L2 候选** → 现有 finding 表，`produced_by="multimodal"`、`status="candidate"`。
  等一批 control_code。

**L1 不是降级。** 一条没有 `control_code` 的「画面语义」今天就不是 finding，是观察。
把观察伪装成 finding，后果是复核时**无法申诉**——没有 control_code 就无法对照规则。

加 `multimodal` 到 `finding_store.ALLOWED` 时**必须不含 `confirmed`**：
多模态不能自己确认。目前是 `{'human','rule','semantic'}`。

### 已经踩过的坑（别再踩）

- **陈旧字节码**：本机 `sys.pycache_prefix` 指向 `~/Library/Caches/com.apple.python`，
  **不是**仓库里的 `__pycache__`。改了被 verifier import 的 `.py` 后结果与源码对不上，先删：
  `rm -rf ~/Library/Caches/com.apple.python/Users/lute/Project/audit_multi_content`
  现象是「源码明显对、运行行为明显旧」。**第一动作是删缓存，不是怀疑框架。**
- **跨平台断言可能只在某一侧有效**：SQLite WAL 在 Linux 上 `close()` 自动清、macOS 不清，
  同一个判据两侧结论相反（已修）。**一个只在目标平台上才可能红的断言，
  在开发平台上永远绿，等于没有。** 写断言前先问：这条在另一侧有没有可能红？
- **`+4096` 填充态**：某些写盘方式会让文件尾部被填充，`read` 打不开、`tail` 出乱码。
  判据 `python3 tools/verify_depad.py`（仅 macOS 宿主有效）。
- **macOS 没有 `timeout`**：缺失时输出为空、`rc=127`，和「扫完了没命中」长得一样。
- **`$?` 在管道后取的是最后一个命令的状态**。要真值：`cmd >/dev/null 2>&1; rc=$?`。
