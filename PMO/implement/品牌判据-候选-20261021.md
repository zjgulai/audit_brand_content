## 一、口径与方法

### 1.1 什么叫「可判」

一条断言算「可判」，必须同时满足：

- **输入明确**：文案 / 图片 / OCR / 元数据 / 音频 / 视频帧，至少一种能拿到；
- **判据明确**：精确字符串、词边界、阈值、或可复算的度量；
- **输出明确**：命中/不命中，或一个可比较的分数；
- **不依赖当场判断**：不是「读起来像不像 Momcozy」。

不满足的，按缺什么分成三档：

| 档 | 含义 | 本表标记 |
|---|---|---|
| 可判 | 今天就能写成确定性断言 | `可判` |
| 半可判 | 需要视觉/音频分类器，或需要先做人工校准 | `半可判` |
| 不可判 | 主观、策略、法律判断；没有可复算的判据 | `不可判` |
| 生成期 | 原文明确约束的是 Prompt / 模型参数 / 生成流程，不是已发布资产 | `生成期` |
| 缺口 | 文档承诺了检查，代码没有实现 | `缺口` |

### 1.2 计数单位

按「一条可独立判断的品牌要求」切分，不按句子数：

- 一个句子里有多个可独立判断的项，拆开（如 Clinical 与 Machine 是同一条，
  但 Weight Loss 是另一条）；
- 纯流程、工具用法、模型选择、时间估算不计入；
- 29 个禁用词作为**一条**生成期约束计入（不是 29 条），因为它们的判据和归属是同一个；
- 色彩按「一组色值/一组阈值」计入，不按每个 hex 计入。

### 8.2 关键读数

- **核心 3 色完全一致**：`#E30022` / `#A8B8A0` / `#FDFBF7`。三份没有分歧。
- `design_tokens` 的另外 3 个是 **UI 文本/反白色**，不是品牌主张色。
- `semantic` 的另外 3 个是 **实测主色**（`measured_dominant`），不是定义 token。
- `controls` 的另外 3 个也是 **实测主导色**，但与 semantic 的实测值**只有 1 个相同**
  （`#B47C80`）；另外 2 个互相不同：

- `BRAND_CONFIG` 的 4 个 = 核心 3 + `#B47C80`；它是 `controls` 实测色块的一个子集。
- **唯一性计数**：全部出现过的 hex 去重后 **11 个**：
  3 核心 + 3 文本/反白 + 5 实测色（`#B47C80` 共享，另有 4 个不同实测值）。
  其中只有 **3 个是已定义的品牌色**；3 个是 UI 角色色；5 个是实测候选。

### 8.3 裁定建议

| 层 | 权威 | 理由 |
|---|---|---|
| **已定义品牌色 / UI token** | `momcozy_design_tokens.json` | 它是唯一机器可读、被 CSS/UI 消费的 token 文件；6 个值里 3 个是品牌色、3 个是 UI 角色色，角色清楚 |
| **AIGC Prompt 色彩语言** | `semantic_library.md §2.1` | 它有 `prompt_phrase`、HSV、usage，是给生成模型的语义；但 `measured_dominant` 只能标 `measured_non_canonical` |
| **实测暖色** | **暂无权威** | `semantic` 与 `controls` 各测了一套，互相不一致；在两套都未被同一次测量验证前，不能任选一套当硬规则 |
| **BRAND_CONFIG 的 4 色** | **派生** | 从核心 3 + 实测 `#B47C80` 派生；不应手工维护成第四套权威 |
