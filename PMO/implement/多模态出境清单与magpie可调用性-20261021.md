## 一 magpie 可调用性（问题 ①）

### 1.1 只做了两次本机读数，没有发任何 HTTP 请求

```bash
# ① 本机 TCP connect（不构造、不发送任何 HTTP 请求）
python3 - <<'PY'
import socket
s = socket.socket(); s.settimeout(1.5)
try:
    s.connect(("127.0.0.1", 3425)); print("LISTENING")
except Exception as e: print("NOT LISTENING", type(e).__name__, e)
finally: s.close()
PY
# → LISTENING

# ② 谁在监听（lsof 代替 ps：ps 在本环境会被拒，见 AGENTS.md §2.2 第 7 条）
lsof -nP -iTCP:3425 -sTCP:LISTEN
# → magpie  3245  lute  6u  IPv4 ... TCP 127.0.0.1:3425 (LISTEN)
```

**这两条能证的和不能证的，必须分开说：**

| 能证明 | 不能证明 |
|---|---|
| 有个叫 `magpie` 的进程在 `127.0.0.1:3425` 上接受连接 | 它**愿意**代理哪个上游、用哪个账号 |
| 端口是通的 | 哪个 provider 的**凭据已配置** |
| —— | 发出去的数据**实际去了哪** |

★ 这正是 `AGENTS.md` §2.4.1 第 4 行那句话：**开关是声明，条数是证据**。
端口在听是「开关」，能回一条真实响应才是「条数」—— 而本任务禁止真实外呼，
所以**「可调用」这个词在本文里只能读到「端口活着」这一层**，不许往下延伸。

### 1.2 为什么这仍然是有意义的结论

它排除了一种失败：**「magpie 根本没跑」**。如果端口不通，后面所有选型讨论都是空中楼阁。
现在至少知道：**接线时的失败不会是「连不上」，而会落在「鉴权 / 配额 / 模型不支持」那一层。**
这个区分在排期上是「先装东西」vs「先申请东西」的差别。

## 二 三条模型核对的逐条结果（问题 ②③④）

数据源：`~/.cache/magpie/models.json`（5.9 MB，读取时间 2026-10-21），
结构为 `{provider: {models: {model_id: meta}}}`，共 **232 provider / 9087 行 / 4118 唯一 id**。

### 2.1 ★ 点 1 —— 确认，而且比 05 说的更强

**`glm-5.3-flash` 在 27 家 provider 上，`audio` 是 0 家。**

| 模态组合 | provider 数 |
|---|---:|
| `image + pdf + text + video` | 14 |
| `image + text` | 6 |
| `image + text + video` | 4 |
| `text`（连图都不吃） | 3 |
| **任意含 `audio`** | **0** |

复现：

```bash
python3 - <<'PY'
import json, os
from collections import Counter
g = json.load(open(os.path.expanduser('~/.cache/magpie/models.json')))
c = Counter()
for prov, blob in g.items():
    meta = (blob.get('models') or {}).get('glm-5.3-flash')
    if meta: c[tuple(sorted(meta['modalities']['input']))] += 1
print('total:', sum(c.values()), 'with_audio:',
      sum(n for m, n in c.items() if 'audio' in m))
for m, n in c.most_common(): print(f'  {n:>2}  {list(m)}')
PY
```

**05 的警告成立**：拿它做 `av_alignment`，视频轨读得到、音轨读不到 ——
而且**不会报错**，只会返回一个「看起来分析过了」的结果。这是最坏的那种失败。

### 2.2 点 2 —— 部分确认，**05 给的 id 要更正**

**不是「只有 1 家」，是 2 个不同 id 各 1 家 —— 而且它们的模态不一样。**

| id | provider 数 | input modalities |
|---|---:|---|
| `doubao-seed-2-1-pro`（连字符） | **0** | —— 这个 id 不存在 |
| `bytedance/doubao-seed-2.1-pro`（点号） | 1 | `['text']` ← **纯文本，不是 VLM** |
| `volcengine/doubao-seed-2.1-pro`（点号） | 1 | `['image', 'text', 'video']` ← **这才是 VLM** |

**这条更正有实际后果**：如果按 `bytedance/` 那条接线，会得到一个纯文本模型，
而它面对图片的行为与「模态不支持」不完全一样 —— 可能报错，也可能把图当文本吞掉。
**按 `volcengine/` 那条接，才是 05 想指的那个模型。**

> 这不是挑字眼。同一个模型在两家 provider 上模态不同，是 magpie 这类聚合网关的常态：
> `bytedance/` 走的是原生 API（只出文本），`volcengine/` 走的是火山引擎的多模态端点。
> **模型 id 相同不代表能力相同 —— 能力挂在 provider 上，不在模型名上。**

### 2.3 ★ 点 3 —— 确认，且比 05 提醒的更彻底

两个网关的清单**不是能力清单，是名字清单**：

| 文件 | 条目 | `ID` | `Name` | `Provider` | `Released` | `Efforts` | `Temperature` | `Price` |
|---|---:|---|---:|---:|---:|---:|---:|---:|
| `vod.json` | 71 | 71/71 | 71/71 | **0/71** | **0/71** | **0/71** | **0/71** | **0/71** |
| `tokenhub.json` | 116 | 116/116 | 116/116 | **0/116** | **0/116** | **0/116** | **0/116** | **0/116** |

字段全集就是：`ID / Name / Provider / Released / Efforts / Temperature / Price`。
**没有任何 `modality` / `input` / `capability` 类字段**（`grep -i modalit` 对两个文件都是 0 命中）。

样例行，可以看到空得有多彻底：

```json
{"ID": "gemini-3.1-flash-lite-preview", "Name": "gemini-3.1-flash-lite-preview",
 "Provider": "", "Released": "", "Efforts": null, "Temperature": null, "Price": null}
```

**所以：从这两份清单推能力，必然产出假数据。** 05 的判断是对的。
要拿模态，唯一合法路径是回 `models.json` 按 id 对 —— 而对不上的那部分**模态未知**，
必须写成 `untested`，不许猜。

## 三 ★ 我的契约有缺口（05 点 1 引发的，需 05 授权才能改）

这是本次核对**唯一需要改代码**的地方，按 05 的要求「报给我，不要自己改」，所以只报不改。

### 3.1 缺口是什么

```bash
$ grep -niE "modalit|input_modalities|capabilit" base/multimodal_provider.py
（0 命中）

$ grep -n "kind" base/multimodal_provider.py
241:    kind: Optional[str] = None          # ← 自由字符串
254:        if self.kind is not None:
255:            object.__setattr__(self, "kind", _require_text(self.kind, "MediaRef.kind"))
```

**`MediaRef.kind` 是自由字符串，不是枚举。** 后果按 05 的原话就是这个形状：

> 调用方可以给 `glm-5.3-flash` 传一个 `av_alignment` 任务 + 一个含音轨的视频，
> 而契约层**没有任何东西会红** —— 它只记一笔 `kind="video/mp4"`，
> 至于这个 provider 到底吃不吃音轨，**本层不知道也不问**。

### 3.2 为什么这不是「实现方自己管好就行」

因为 `ProviderRegistration.required_authorizations` 是**逐任务**的，
而 `egress_items` 是**逐 provider**的：

```python
# 现状：出境项挂在 provider 上，任务挂在 required_authorizations 上
"egress_items": [...],                    # 这一家会送出什么（不分任务）
"required_authorizations": {              # 每个任务要哪些授权
    "scene_semantics": [...], "av_alignment": [...],
}
```

于是「音轨这个数据项只对 `av_alignment` 有意义」这件事**在清单里表达不出来** ——
一个只跑静图的部署，清单里也会挂着 `audio_track`，审计读到的出境面比实际大。
反过来说，如果实现方偷懒不登记音轨，**也没有东西会红**。

### 3.3 三处候选改法（要 05 选一个，我不自己定）

| 选项 | 改什么 | 代价 |
|---|---|---|
| **A（我倾向）** | `EgressItem` 加 `tasks: Tuple[str, ...]`（空 = 适用于全部任务）；`egress_manifest` 按任务展开 | 改 dataclass + 清单结构，`digest` 会变一次；要更新 5 条现有断言 |
| **B** | `MultimodalTask` 枚举加 `required_media`（如 `AV_ALIGNMENT → {"video","audio"}`），`analyze()` 在调用前校验 `MediaRef.kind` | 改动小，但 `kind` 是自由字符串，校验只能做「声明了 audio 就必须有音轨」这种弱形式 |
| **C** | 不改契约，在 `ProviderRegistration.note` 里写清 | **不推荐**：这正是 `AGENTS.md` §2.4 说的「注释不是约束」 |

**A + B 一起做**才是完整的：A 管「出境面按任务收窄」，B 管「调之前就知道模态不够」。
但这是两个改动，建议分开授权。

## 四 数据出境清单（按现状，零外呼）

### 4.1 本层能声明的边界

`base/multimodal_provider.py` 的 `_policy_boundary()` 对 `actual_egress_status`
**只接受 `none` 与 `untested` 两个值**（D7 断言守着它）：

| 值 | 含义 | 什么时候出现 |
|---|---|---|
| `none` | **本层没有发起出境**（没调 provider，或调用前就被拒） | 空注册表、任务不支持、未授权 |
| `untested` | **调用过 provider，但本层零网络，无法观测实际发了什么** | provider 抛异常、provider 返回后被归一化 |

★ **没有第三个值，特别没有「已经确认只送到了 X」** ——
因为本层零网络，说出那句话就比输入大了（§2.4.1 第 4 行）。

### 4.2 三类任务的出境面（**若启用**会送出什么）

| 任务 | 出境数据项 | 数据分级 | 为什么是这一级 |
|---|---|---|---|
| `scene_semantics` | 抽帧画面 | `confidential` | 客户商品素材，含未上市包装与卖点文案 |
| `mark_symbol` | 图标/认证标志区域裁图 | `confidential` | 同属客户素材；且认证徽章本身可反推供应链 |
| `av_alignment` | 视频帧 **+ 音轨** | `confidential` | **音轨可能含人声**，按 `pii` 复核（见 4.3） |

**依据不是猜的**：仓内 `tools/download_callers.json` 已登记的三个下载点，
`data_class` **全部是 `confidential`**：

```
tools/gold_pilot_fetch.py:1   media_tmp_url        confidential  gold_pilot_fetch（审查结论 gold 试点）
tools/agent/feishu.mjs:1      im_message_resource  confidential  agent.mjs（守衡群附件入站）
tools/momcozy/lib/image.mjs:1 external_http        confidential  Momcozy 商品图
```

**没有一条登记成 `pii`。** 这不代表音轨里没有人声 —— 只代表**没人测过**。
所以 4.3 把它单列。

### 4.3 一条必须承认的未测

> **「音轨里有没有人声」本单未测。**

本任务禁止读客户素材（`~/audit-data/gold/pilot/` 读取被安全策略拦下，这是对的），
所以我不可能知道任何一条音轨的内容。**但这恰好是 `pii` 判定的唯一依据。**

因此正确的写法不是「音轨是 confidential」，而是：

| 数据项 | 已确定的 | 未测的 | 处置 |
|---|---|---|---|
| 视频帧 | 客户素材 → `confidential` | —— | 按 `confidential` 走 |
| **音轨** | 含语音的可能性未排除 | **是否含可识别人声** | **按 `pii` 从严处理，直到有人测过** |

★ 「从严」在这里不是保守，是**成本对称**：标成 `confidential` 而已、实际含人声，
代价是一次合规事故；标成 `pii` 而实际没有，代价只是一行多写的授权项。

### 4.4 出境清单的机器可读形式

契约层已经是可执行的（不是一份文档）：

```bash
python3 - <<'PY'
import sys; sys.path.insert(0, '.')
from base import multimodal_provider as M

reg = M.ProviderRegistration(
    provider_id="<provider>",
    recipient="<可指认的接收方，不许写「云端」>",
    egress_items=(
        M.EgressItem(item_id="frames", description="抽帧画面", data_class="confidential"),
        M.EgressItem(item_id="audio_track", description="视频音轨", data_class="pii"),
    ),
    required_authorizations={
        "scene_semantics": ("egress:frames",),
        "av_alignment": ("egress:frames", "egress:audio"),
    },
    authorized={"scene_semantics": False, "av_alignment": False},
)
r = M.ProviderRegistry(); r.register(reg, <实现>)
print(r.egress_manifest_report()["digest_sha256"])
PY
```

**两个刻意的设计**：

1. **`authorized` 没有默认值**，且键集合必须与 `required_authorizations` 完全相等
   （C2 断言，M3 变异对照）。缺键 = 构造期报错，**不许默认成已授权**。
2. **`egress_manifest` 描述的是「若启用会送出什么」**，`would_egress` 才是
   「当前有没有授权出去」。两者分开，审计才不会把「计划」读成「已经发生」。
