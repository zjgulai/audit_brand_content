## 一 · 先说一个结构性矛盾（必须先解决，不能绕）

委托方选了「**落成 candidate finding**」。但 finding 有三要素，缺一即拒：

```python
# base/finding_store.py:69
ADMISSION_KEYS = ("control_code", "authority_ref", "location")
```

| 要素 | 多模态能给吗 | 说明 |
|---|---|---|
| `location` | ✅ | VLM 可给归一化 bbox / timecode |
| `control_code` | ❌ | **知识库产物**。画面语义对应的控制点码今天不存在 |
| `authority_ref` | ❌ | **知识库产物**。依据引用今天不存在 |

所以「先打通功能 + 落 candidate finding + 知识库慢慢建」三条**同时成立有困难**：
没有 control_code 就进不了 finding 表。

### 处置：两级落地，都保留委托方意图

| 级别 | 落点 | 今天可做？ | 需要知识库？ |
|---|---|---|---|
| **L1 观察** | `case.context.multimodal_observations`（进权威 state，报告单独成节，标「候选·待人工」） | ✅ | ❌ |
| **L2 候选** | 现有 finding 表，`produced_by="multimodal"`、`status="candidate"` | 等一批 control_code | ✅ |

**L1 不是降级，是照实说。** 一条没有 `control_code` 的「画面语义」，
它今天就不是一条 finding —— 它是一条**观察**。把观察伪装成 finding，
后果是报告里有 convincing 的行、复核时无法申诉（没有 control_code 无法对照规则）。

**L1 → L2 的升级路径**：知识库每补一批画面语义控制点，就把已积累的观察按
`control_code` 映射成 finding。**观察数据不丢，L2 是重放而不是重跑。**

## 二 · claude-video 怎么适配（第 2 条决定）

读完全仓 README，它的设计与我们**不同但可借用**：

| 它的做法 | 我们直接可用吗 | 适配 |
|---|---|---|
| **双引擎**：Gemini 整段直判 / local ffmpeg 抽帧 | ✅ **正好对上**「先打通功能」 | 我们的双轨：`engine=direct`（整段送 VLM）/ `engine=frames`（抽帧） |
| `--detail` 四档（transcript / efficient / balanced / token-burner） | ✅ 帧预算的工程化 | 抄口径，见 §三 |
| **16×16 RGB 缩略图去重**（mean channel difference） | ✅ 成本控制关键，且**不用模型** | 直接抄算法：16×16 RGB、均值通道差、阈值可配 |
| 原生字幕优先 → WhisperX / Groq / OpenAI 兜底 | ⚠️ 部分 | 中文广告要 ASR，但**字幕优先**这条对（平台原生字幕最准、免费） |
| 场景切变抽帧 + 均匀采样兜底 | ✅ | `balanced` 档就是「场景切变，几乎静止时回落均匀」 |
| yt-dlp 下载 + cookies + 浏览器会话 | ❌ | 我们素材来自业务方导出，不走公开站点 |
| CLI / skill 形态，给人用 | ❌ | 我们要**服务内被调用的库**，批量、可重放、可审计 |
| `WATCH_GEMINI_MODEL` 自由字符串 | ✅ | 正好接 magpie：改 base URL + model id，不锁版本 |

**结论：抄它的引擎分层与帧预算，不抄它的分发形态。**
它服务「agent 看一段视频」，我们服务「批量审核 + 可申诉 + 可重建」。

### 2.1 一个要特别注意的差异

claude-video 的 `gemini` 引擎把**整段视频**传到 Google Files API，
「上传后删除，删不掉 48 小时内过期」。

我们这边这条要额外一层：`base/multimodal_provider.py` 是**授权闸门**，
它明确规定「本层一行网络实现都不许有」，出境必须逐任务声明。
所以我们的 `engine=direct` **不能绕开 `require_authorization()`**。

```
claude-video:  CLI 直接调 → Google
我们:          CLI/服务 → multimodal_provider.analyze()
                            → require_authorization(provider, task)   ← 闸门
                            → 实现方发请求（唯一有网络的地方）
```

## 三 · 帧策略（第 3 条决定：抄 balanced）

委托方选定 `balanced`。逐参数落定，全部可配：

| 参数 | 取值 | 依据 |
|---|---|---|
| 抽帧方式 | **场景切变优先，几乎静止时回落均匀采样** | claude-video 的 `balanced` |
| 帧上限 | **100** | 同上 |
| 去重 | **16×16 RGB 缩略图 + 均值通道差**，默认开，可 `--no-dedup` | 同上；关键是不用模型 |
| 帧宽 | 默认 **512px**；含屏上文字时 1024 | 同上 |
| 时间戳 | **源相对**（含区间与分数秒） | 同上；审核要能定位到秒 |
| 每帧元数据 | `{ts, w, h, sha256, source_uri}` | 我们要可复现，它只给人看 |

**与 claude-video 的一处刻意不同**：它按「帧数」控预算，我们还要控**token**。
同一段 30s 广告，100 帧 @512px 与 20 帧 @1024px 的信息量不同，
但前者 token 可能是后者 5 倍。**我们记录实际的帧数 × 尺寸 × 模型 token 用量**，
作为下一轮调参的依据 —— 它不管 ROI，我们管（虽然排在质量之后）。

## 四 · 架构：三处改动，一处新增

```
POST /api/v1/submissions (content_type=图片|视频)
   │
   ├─ ① 进件解包        base/media_ingest.py  【新增】
   │     图片 → 原样 + 尺寸/EXIF
   │     视频 → ffprobe(时长/分辨率/音轨) + 抽帧(balanced) + 可选 ASR
   │
   ├─ ② 多模态分析      base/multimodal_provider.py  【已有，接真实 provider】
   │     analyze(MediaRef, tasks) → 授权闸门 → 实现方发请求
   │     实现方 = tools/multimodal_client.py  【新增】OpenAI 兼容，走 magpie
   │
   ├─ ③ 结果落库        base/review_reducer.py  【改】
   │     L1: case.context.multimodal_observations
   │     L2: finding 表，produced_by="multimodal"（白名单要加）
   │
   └─ ④ 报告            base/judge_entry.py → report_snapshot  【改】
         画面语义单独成节，措辞「候选 · 待人工确认」
```

### 4.1 为什么实现方是新的 `tools/multimodal_client.py` 而不是改 `multimodal_provider.py`

后者文件头写死了：「**本文件只做纯内存判断：没有 HTTP、没有 URL、没有 socket、没有凭据读取。**」
理由是「一个需要联网才能验证的权限层，在断网时最先失效」。

所以：
- `multimodal_provider.py` = **闸门 + 契约**（不改）
- `tools/multimodal_client.py` = **唯一有网络的地方**（新增）

判据要能证明这条边界：**`multimodal_provider.py` 里出现 `requests`/`httpx`/`urllib`/`socket` 即红。**

### T-431 · 图片进件打通（宿主，不碰引擎）（2d · 依赖 T-430）

**范围**：`POST /api/v1/submissions` 收 `content_type=图片` + `source.kind=image`，
用**现有**宿主 Vision OCR（`.tools/bin/ocr`，本机可用）→ `judge_unit` → 权威。

**为什么先用宿主 OCR**：委托方要「先打通功能」。宿主 OCR 今天就能跑，
不需要装容器引擎、不需要等镜像。代价：**`host_only`，不进生产镜像**。

**判据**：
1. 端到端：提交一张真实广告图 → `GET /api/v1/cases` 出现案件，`modalities_evaluated==["image"]`。
2. `does_not_cover` 含「画面语义」（依赖 T-430）。
3. **反例**：OCR 失败 → `parse_status=failed` 且 `failure_kind` 落四类之一，
   **不许产出一个「审过了」的 REVIEW**。
4. `verify_media_portability` 宿主原生命中数**仍是 3**（本票不减少它）。

### T-432 · 多模态客户端 + 闸门接通（3d · 依赖 T-431）

**做**：

1. 新增 `tools/multimodal_client.py`：OpenAI 兼容 `/chat/completions`，
   base URL 与 model 从配置读（**不读凭据文件，从环境变量**）。
2. 注册一个 `MultimodalProvider` 实现，`analyze()` 内部调 client。
3. `require_authorization` 逐任务登记：`scene_semantics` / `mark_symbol` / `av_alignment`。
4. **出境清单**落盘：送什么、送给谁、留多久。

**判据**：
1. 一张图 → `analyze(..., [SCENE_SEMANTICS])` 返回 `status="ok"` 且含结构化观察。
2. **未授权时一次都不许调**：变异「跳过 require_authorization」→ 红。
3. **provider 缺失 → `untested`**，不是 `[]`、不是 `None`、不是 `ok`。
4. **网络隔离（判据要精确，否则是假红）**：只查 **import 语句**，不查全文 ——

   ```bash
   grep -cE "^\s*(import|from)\s+(requests|httpx|urllib|socket|aiohttp|openai|anyio)" \
       base/multimodal_provider.py
   # → 0
   ```

   实测：全文 `grep -cE "requests|httpx|urllib|socket"` 命中 **3** 处，
   全部落在文档注释（第 24 / 83 / 84 行），**代码里一处都没有**。
   一条把注释当违规的判据，会让下一个人去改注释而不是改代码。
5. 无 audio 的 provider 请求 `av_alignment` → **拒绝**，不是返回空。

### T-434 · L2 candidate finding（2d · 依赖 T-433 + 一批 control_code）

**做**：

1. `finding_store.ALLOWED` 加 `"multimodal": frozenset({"candidate", "rejected", "superseded"})`
   —— **刻意不含 `confirmed`**：多模态不能自己确认，必须人复核。
2. 观察 → finding 的映射器：`control_code` 由配置表给（初始为空 → 全部落 L1）。
3. `authority_ref` 指向知识库条目；没有就**不许升级成 finding**。

**判据**：
1. `produced_by="multimodal"` × `status="confirmed"` → **必须拒**（白名单）。
2. 缺 `control_code` 的观察 → 留在 L1，**不许**降级塞进 finding。
3. 人复核后 `candidate → confirmed` 正常走现有 `adjudicate_finding`。
4. 变异：把 `confirmed` 加进 multimodal 白名单 → 红。

### T-435 · 视频抽帧（balanced）+ 音画对齐（5d · 依赖 T-432）

**做**：

1. `base/media_ingest.py` 的 `extract_frames()`：场景切变 + 均匀兜底 + 16×16 去重 + 上限 100。
2. `ffprobe` 拿时长/分辨率/有无音轨。
3. `engine=direct` 分支：整段视频走 `av_alignment`（前提：provider 声明 `audio+video`）。
4. `engine=frames` 分支：帧序列走 `scene_semantics`。

**判据**：
1. 一段 30s 广告 → 帧数 ≤ 100、每帧有时戳、`sha256` 可复现（同输入同输出）。
2. **去重有效**：一段静止画面 → 去重后帧数显著少于去重前（给具体阈值）。
3. `av_alignment` 的请求体里**必须同时含 video 与 audio**；只有 video → 拒。
4. **无音轨的视频**：`covers` 里「音轨」必须是 `not_applicable`，不许写「已评」。
5. 变异：去掉去重 → 帧数暴涨，判据 2 红。
