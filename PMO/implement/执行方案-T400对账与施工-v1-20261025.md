## 二 · 方案：每票重定 scope 与判据

### 2.1 T-401 · 申诉三条 → 两段，不可合并

**实测（`POST` 已放行、重启后读不回）**：

```
open            = 200
GET /appeals    = []          ← 权威里明明有那条（state_appeals = [("appeal-…","withdrawn")]）
find_appeal_case(appeal_id)   = None → /withdraw 返回 404
```

根因是**两个真独立的原因**，票面只提了第一个：

| # | 原因 | 位置 | 后果 |
|---|---|---|---|
| 1 | 三条不在 `PRODUCTION_WRITE_PATHS` | `api/production_app.py:36` | `POST` 501 |
| 2 | **`GET /api/v1/appeals` 只读 frozen `appeals.json`** | `api/review_api.py:850` | 写完读不回 → 前端 P-06「提交成功、列表空白」 |

第 2 条不是新发现 —— `T-311-施工单` §一 第 8 行就记过「读的是 frozen，与写侧是两个真相源」，
**但 T-401 的判据②「重启后仍可读」正落在这一条上，而 T-311 没有关掉它**。
`T-311` 关掉的是 `reports` / `signer-grants` / `takedown-grants` 三处同形状的读侧
（`review_api.py:732` / `:915` 都有注释），**唯独漏了 appeals**。

第三条根因（`find_appeal_case` 返回 None）在**走真实 submit 链路时不存在** ——
它是我用「手造 frozen case」做夹具时，那个夹具缺 `tenant` 造成的假象。
**这条记下来是因为它差点变成一条错误的施工项**：如果不换真实链路复跑，
我会去改 `find_appeal_case`，而它是对的。§2.4.1 第 5 行同一个形状。

**第三个发现（施工中撞到，不在票面上）**：`appeal_pause` 在 reducer 里有
（`review_reducer.py:409`），但**全仓没有任何 HTTP 入口能发出它**
（`grep -rn "appeal_pause" api/` → 0）。于是 `migrate` 在生产装配下**不可达**：
`migrate` 只接受 `paused`，而 `pause` 发不出去。所以「迁移」这个能力是**结构性缺失**，
不是「路由没通」。本票只把路由接上并锁住「领域规则没被绕过」（`open → 409 not_paused`），
**不假装迁移能用** —— 那需要先有 pause 入口（记入 T-401b）。

**scope 拆成两段，按顺序做**：

- **T-401a（本批做）**：三条进 `PRODUCTION_WRITE_PATHS` + `GET /appeals` 改读权威
  （`ReviewCommandService.list_appeals(tenant=...)`，与 `list_published_reports` 同位置、同分工：
  服务层给数据，API 层判可见性）+ 冻结回落。
- **T-401b（不做，登记）**：申诉列表的分页/索引。上千案件时 `find_appeal_case` 是线性扫，
  T-311c 已记，本次不夹带。

**判据（四条，缺一条不算完成）**：

| # | 判据 | 为什么要这一条 |
|---|---|---|
| J1 | 三条各 `200`，且响应里 `appeal_id` 是**内容派生 ID**（`appeal-` + 16 hex） | 防「200 但返回案件状态」（我实测第一版响应体前 300 字符全是 case 字段） |
| J2 | `GET /appeals` 立刻读得到刚开的那条，**且 `state` 跟着 `withdraw` 变成 `withdrawn`** | 这一条是 T-401a 的核心；不写它，票面判据②永远绿不了 |
| J3 | **新进程、同一数据根**：重启后 `GET /appeals` 仍返回同一条、同 `state` | 「重启后仍可读」按字面执行 |
| J4 | **反向对照**：把三条从集合里摘掉 → 三条各 `501` | 证明 J1 的 200 来自这次改动，不是本来就通 |

**必须翻转的既有断言（否则本票做不完）**：
`tools/verify_production_app.py:489` 的 **C14「appeal capability 关闭」断言它返 501**。

### 2.3 T-403 · 报告重签 → 停下来问，不自作主张

**为什么不能按票面 1d 做完**。票面判据是：

> ① 重签返回新 url；② 旧文件 sha256 未变；③ 旧报告仍在 `state["reports"]`

而 Playbook §8.8 对这一条的定义是「**链接带过期签名 + 按 report_id 鉴权**；
过期不等于失效 —— 过期后可重签，**文件不删**」。

盘上实际有什么：

| 需要的 | 盘上有吗 |
|---|---|
| 报告不可变、内容寻址 | ✅ `ReportStore.publish`（`reports/<id>.md`，已存在只许字节相同） |
| 从 IR 重建 | ✅ `rebuild()` |
| **URL 过期** | ❌ 无。`_url()` 恒返回 `static_base/reports/<id>.md`，无时间参数 |
| **URL 签名** | ❌ 无。全仓 `hmac` / `itsdangerous` / `?sig=` **0 命中** |
| 带查询串的 URL 能通过校验 | ❌ **不能**。`_valid_url()` 要求 `endswith(".md")`，`?sig=…` 必判 `bad_url` |

所以「重签返回新 url」这句话，在当前实现下只有三种落地方式，**代价差一个数量级**：

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A**（票面字面） | 每次 resign 生成带 TTL 的 HMAC 签名 URL；`_valid_url` 放宽到允许 querystring；`/static/reports/{id}.md` 校验签名 | 2–3d | 动 `ReportStore` 的 R3 契约，`verify_report_store` 的多条断言要跟着改 |
| **B**（最小诚实） | resign 只**延长会话内可读性**，返回同一个静态 URL + `expires_at` 元数据，明确「本部署不做签名 URL」 | 0.5d | 与 Playbook §8.8 不符，属于**能力缺口**，必须进 waiver 或差距表 |
| **C**（拒绝） | 端点保留 501，票降为 `blocked`，理由写清「缺签名链接基础设施」 | 0d | 生产 P-09 按钮仍不可用 |

**我的判断**：A 是对的长期形态，但它是一次**契约改动**（`R3`：URL 只由静态 base 拼出），
而 `R3` 是有 ADR 背书的。所以这一票**不能由我按偏好选**。

### 4.1 Q1 落地时必须同时满足的四条（否则 A 方案不算做成）

选定 A 之后，「签名 URL」这句话要能被证伪，否则它就退化成一句注释（§2.4）：

1. **签名 URL 能打开**：带合法 `?exp=&sig=` 的 URL 经静态路由返回正文；
2. **过期 URL 打不开**：把 `exp` 改成过去 → 拒（不是「还能读」）；
3. **篡改 URL 打不开**：改任意一个字符 → 拒；
4. **旧文件一个字节没变**：resign 前后 `reports/<id>.md` 的 sha256 相同。

另有一条**必须写进交付说明**：签名密钥从哪来、怎么轮换、丢了怎么办。
没有这一段，A 方案就是一个「密钥写死在代码里」的实现 —— 而那是把签名做成装饰。
