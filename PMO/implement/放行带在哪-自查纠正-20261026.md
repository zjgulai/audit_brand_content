# 放行带在哪儿：一次自查把「已生效」改成「从未生效」（2026-10-26）

> 这份文件记的是一次**自我推翻**。
> 触发点很小：改完 GS-011 的标签后，我要在 `changelog` 里写一句「引擎不需要改，实测放行带已生效」。
> 落笔前我想把那个读数复现一遍。复现不出来 —— 而且真相与那句话**方向相反**。

---

## 一 · 我原来写的是什么，为什么写错了

改 GS-011 时我跑过（当时看起来是对的）：

```
$ python3 -c "…judge_unit(text='FDA cleared medical device for home use')…"
findings: []          ← 没命中
label: REVIEW / DP3
```

我从 `findings == []` 推出「`downgrade_band` 把 `FDA cleared` 放行了」，
进而写进三处文档：「放行带已生效」。

**这个推断缺了一环**：`findings == []` 有**两个**可能的原因 ——

1. 命中了，但被放行带降级成不命中；
2. **根本就没命中** —— 那个词不在这条规则的 `match.keywords` 里。

实测是第 2 种。

```
$ python3 -c "…rules[10]['match']['keywords']…"
['FDA approved', 'FDA certified', 'FDA 认证', 'FDA 批准', 'FDA 通过']
$ python3 -c "…'FDA cleared' in rules[10]['match']['keywords']…"
False
$ python3 -c "…rules[10]['downgrade_band']['keywords']…"
['FDA cleared', 'FDA-cleared', 'FDA registered', 'FDA 注册']
```

`FDA cleared` **只在带里，不在 match 里**。所以生产引擎不命中它，与放行带没有关系。

> 这与 AGENTS.md §2.4.1 第 4 行是同一个形状：
> **「查无此人」的正确输入不是「我采的那条通道里没有」，而是「所有通道都采过且都活着」。**
> 这里是：「这个词不命中」的正确输入不是「findings 为空」，而是「它在 match 里，且带没有放行它」。

---

## 二 · 真相：放行带只在**分析引擎**里

`grep` 计数，两个引擎：

```
$ grep -c "downgrade" base/rule_judge.py
0
$ grep -c "downgrade" research/governance/skeleton/score.py
13
```

而 ADR-0016 §三 定的是（委托方 2026-10-20）：

> `skeleton/judge.py` 降级为**分析工具**（benchmark / 抽样 / 人工复核辅助），
> 不再参与生产判定。`rule_judge`（`rules-v1.json`）为**唯一判定引擎**。

`base/judge_entry.py` 第 5 行也这么写：

> ADR-0016 的唯一生产判定引擎是 base/rule_judge.py；旧 skeleton/judge.py 只作分析。

也就是说：**放行带留在了已经不作生产判定的那一侧。**

---

## 三 · 后果：两个引擎对同一句话给出相反判定

```
$ python3 - <<'EOF'   # 生产引擎 = base.rule_judge；分析引擎 = skeleton.judge
EOF

文本                                           生产引擎       分析引擎
----------------------------------------------------------------------------
FDA approved breast pump.                    命中1        auto_reject
FDA approved breast pump. FDA cleared.       命中1        auto_pass     ← 分歧
FDA cleared medical device for home use      命中0        catch_all
FDA registered facility.                     命中0        catch_all
```

`rules-v1.json` 的 `$decision`（D2 · 法务 2026-09-16）明文写着：

> 带是文本级的 —— 带词出现在同段文本的**任何位置**即生效，因此
> `FDA approved breast pump. FDA cleared.` 判 auto_pass。

**分析引擎按 D2 做了；生产引擎没有。** 同一句法务已经裁过的文本，
系统今天在生产上判 `REVIEW`（拦），而法务说该放。

这一条比原票面写的严重：不是「带太宽放过了违规」，是「**带从未在生产里跑过**」。

## 四 · 为什么没有任何检查发现它

三层都查过，各自都没有覆盖这一格：

| 检查 | 它查什么 | 为什么没红 |
|---|---|---|
| `verify_engine_contract.py` 的 **V22c** | 「裸主张 auto_reject / 同现 auto_pass」 | 它调的是 `J.judge(...)`，`J` 是 `skeleton.judge` —— **分析引擎**。它在自己的世界里全对 |
| `verify_rule_change_regression.py` | 规则变更前后行为差分 | 子进程 `import judge as J`，同样只跑分析引擎 |
| `verify_regression_set.py` | 集合规模 / 指纹 / 变更记录 | 文档头明写「**不证明样本语义正确**」；`expected.kind` 它只用来数陷阱负样本，从不与引擎输出比对 |

最后一条是根子：

```
$ grep -rn "expected" tools/*.py | grep "kind" | grep -v verify_regression
(空)
```

**全仓没有任何一行代码把 83 条的 `expected.kind` 与引擎输出比对过。**
所以「样本说该拦、引擎说放行」这种矛盾，永远不会有东西红。

### 4.1 顺手量了一下：这格空着有多大

把 83 条全喂给生产引擎、只挑 `should_hit` 与 `correctly_exempted` 两层比对：

```
$ python3 - <<'EOF'   # 见下方复现脚本
EOF
should_hit 却不命中 / correctly_exempted 却命中 的条数: 3
  ('GS-006', 'should_hit', 0, 'Our formula prevents allergies in infant')
  ('GS-012', 'should_hit', 0, 'Doctors recommend this bottle above all ')
  ('GS-013', 'should_hit', 0, 'Reduces SIDS risk by 80 percent')
```

> ★ **这三条不是新发现。** 它们是 `PMO/implement/T-407-样本签署申请-v1-20261026.md`
> §「已知规则缺口」里已经逐条写明的（`GS-006` 缺 `prevents allergies`、
> `GS-012` 缺 `Doctors recommend` 这个语序、`GS-013` 缺 SIDS 宣称）。
> 两个引擎对它们都 `catch_all`／不命中 —— 所以它们是**规则缺口**，不是引擎分歧。
>
> 记在这里只为一件事：**这个数字以前是人工看出来的，不是任何断言算出来的。**
> 同一格空着，`should_hit` 与引擎不符可以累积到 3 条而无人知 —— 换一天它可以是 30 条。

## 五 · 我改了什么、没改什么

### 改了的（三处文字，都是把错误归因改对）

| 位置 | 原文 | 改后 |
|---|---|---|
| `signoff["GS-011"]["basis"]` | 「实测该句在生产链上 findings=[] / REVIEW/DP3（放行带已生效）」 | 「findings=[]，但**这不能归因于放行带** —— 该引擎里 `downgrade` 出现 0 次，`FDA cleared` 从未进 `match.keywords`」 |
| `signoff_meta.待裁定[GS-011]["引擎是否需要改"]` | 「不需要 —— D2 本来就让它放行；实测 findings=[]」 | 「不需要改，但**理由与我最初写的不一样**：不是放行，是不命中」 |
| `signoff_meta.待裁定[GS-011]["遗留"]` | 「downgrade_band 是文本级生效，`FDA approved … FDA cleared.` 会被整体放行」 | 「**放行带在生产引擎里没有消费者**；实测两引擎对同一句给相反判定」 |

**GS-011 的 `expected.kind` 改判本身不变** —— 它依据的是「D2 是逐条裁定过的事实」
与「`FDA cleared` 不在 `match.keywords` 里」，这两条都**不依赖**引擎行为。
去掉我那条错证据，理由仍然成立。我在 `signoff_meta` 里补了这句，免得下一个人以为改判建立在假前提上。

### 没改的

- **没有**把 `FDA cleared` 塞进 `match.keywords` 让差异「消失」。那会把 D2 的两个词
  变成同一条违禁，与 21 CFR 807.97 相反。
- **没有**把放行带移植进 `base/rule_judge.py`。那是改判定主链语义，属于 T-390 那一类
  需要裁定的范围 —— 而且我此刻不知道「该移植」还是「该裁定生产不实现它」。
- **没有**改 V22c。它守的是分析引擎的一致性，那个断言是对的，只是**它守的不是生产**。

## 七 · 这条教训值一句话

> **`findings == []` 不是「放行」的证据。**
> 「该拦而没拦」与「压根不匹配」在输出上完全一样 ——
> 要区分它们，必须去看**输入是怎么进匹配的**，不是看输出。

同一句话在本项目的另一个化身（AGENTS.md §2.4.1 第 4 行）：
**否定结论的输入不能小于否定结论本身。**
