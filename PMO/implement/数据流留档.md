# 数据流留档（C-44 / IN-2）

> **第一阶段：人工验收。** 本文件是验收人沿主链路核对「每个判定输入从哪来、谁写、谁读」的留档；
> 不是自动生成的架构图，也不替代各模块自己的自证。
>
> 验收方式：按下面的逐段指针打开文件与行号，确认「输出字段 → 下游消费者」没有第二条生产者；
> 发现指针失效（行号漂移/函数改名）时先改本文件，再改代码。

## 一条主链路

```
submission_router
  → normalizer（ContentUnit v1）
  → rule_judge / semantic_judge
  → evidence_sync（ValidatedFinding）
  → coverage_composer（coverage_state）
  → decision_table（state / layer / obligations）
  → disposition_router（owner / due / release_status）
  → orchestrator（ReviewIR + receipt）
  → report_renderer（md / 群消息）
  → report_store（静态 md + index + URL）
  → send_gateway（形态决策 / 发送）
```

## 判定函数只读哪些字段

`base/decision_table.py:180 decide()` 的输入只应来自以下五类；任何第六类字段被读取，
都应视为「判定输入来源不可追溯」：

| 字段 | 唯一生产者 | 指针 |
|---|---|---|
| `parse_status` / `failure_kind` | normalizer | `base/normalizer.py:330` |
| `coverage_state` | coverage_composer | `base/coverage_composer.py:263` |
| `findings`（含 `status`/`severity`） | rule_judge / semantic_judge | `base/rule_judge.py:131`、`base/semantic_judge.py:260` |
| `authority_state` / `rule_conflict` | evidence_sync | `base/evidence_sync.py:189` |
| `max_sev` / gaps / candidate 派生量 | decision_table 自身从 findings 计算 | `base/decision_table.py:180` |
