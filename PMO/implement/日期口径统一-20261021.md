## 唯一来源

`tools/bj_time.py`：

- `BJ = timezone(timedelta(hours=8))`
- `bj_now()` → 带 `+08:00` 的当前时刻
- `bj_today()` → 北京日历日
- `bj_today_iso()` → `YYYY-MM-DD`

其他文件只允许两种写法：直接 `from bj_time import bj_today`，或保留一个
**只做委托**的薄包装（`kb_gap_ledger.today_bj()`、`load.today()`），不再自己算。

## 怎么证明统一

```bash
python3 tools/bj_time.py --selftest
```

它做两件事，都是行为级：

1. **AST 扫调用点**：扫 `tools/`、`research/kb/`、`base/` 里所有
   `date.today` / `datetime.today` / `datetime.utcnow` / **裸 `datetime.now()`**；
   除 `tools/bj_time.py` 外必须为 0。显式 `now(UTC)` / `now(+08:00)` 是时刻戳，不算本地今天。
2. **同一性 + TZ 子进程**：
   - 导入 10 个消费者，断言 `bj_today` / `bj_now` 是**同一个函数对象**，不是文本同名；
   - 在 `TZ=UTC`、`TZ=Pacific/Kiritimati`（UTC+14）、`TZ=Etc/GMT+12` 三个子进程里
     各打印全部消费者的读数，必须都等于北京日期 `2026-10-21`。

`Pacific/Kiritimati` 是关键的反向对照：当时 UTC 约 14:xx，+14 区已经是 `10-22`；
如果还有谁用本机 `date.today()`，这一条会立刻露出 `10-22`。实测三者全部 `10-21`。

## TZ 实测读数

```text
TZ=UTC                → 全部 = 2026-10-21
TZ=Pacific/Kiritimati → 全部 = 2026-10-21   ← 本机日期会是 10-22
TZ=Etc/GMT+12         → 全部 = 2026-10-21
```

> 以上是 **2026-10-21** 的读数；2026-10-22 复跑同一命令，三处均为 **2026-10-22**。
> 关键是三种 TZ 读数一致且等于北京日历日，不是某个固定日期。

`TZ=UTC python3 tools/verify_pending.py --json` → rc1，`RC-03` 到期 `2026-10-02`，
`过期天数=19`；`TZ=UTC python3 tools/kb_gaps.py --check` → rc2，同一到期日、同一「逾期 19 天」。
`TZ=Pacific/Kiritimati` 下两处读数相同。
