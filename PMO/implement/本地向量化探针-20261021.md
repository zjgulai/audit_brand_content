### 4.2 检索近似

- **≥3 字**：字符 trigram 的 BM25（k1=1.2, b=0.75），近似 FTS5 `trigram`；
- **2 字**：退化为「精确子串次数 + 标题命中加权 + 短文本微加分」，近似生产
  `positional`/`like` 回退；
- **多词查询**：每个词单独打分，按各词最大值归一后相加；这是本地近似，不是生产的
  单字符串 FTS 查询；
- **topK=10**；排序先按分数，再按文本长度、id。

> 生产 `kb_client.mjs` 的代码注释写明：`q=吸奶器`（3 字）→ `bm25`；
> `q=无痛`（2 字）→ `positional` + `fallback:'like'`。
> 本轮本地复现的就是这个门槛，不是另立一套。

### 4.3 638 条规则落在哪一层（05 问）

| 项 | 读数 |
|---|---|
| 文件 | `research/governance/rules-mece-migration-v1.json` |
| 大小 | **685,042 B** |
| 顶层 | `schema` / `date` / `count` / `note` / `assignments` |

### 6.1 10 组同义对

**读数**：

- 10 组里 **7 组可测**（3 组语料没有 B，是语料覆盖问题，不是检索失败）。
- 7 组里 **7 组的 top10 命中 ≤1**：5 组为 0（胀奶、漏奶、无痛、收腹带、温奶器），
  2 组为 1（防溢、母乳）。
- 反向也不对称：`无痛 → 疼痛缓解` 的 top10 命中 0，但 `疼痛缓解 → 无痛` 命中 4。
  这说明**词频/标题偏向**在起作用，不是单纯「词不在」。
- **oracle 同义扩展**（把已知的 B 加进查询）能把 7/7 组全部补回。
  **这是上界，不是 reranker 实测**：它用了我们手工知道的同义词；真实场景里你不知道用户会用哪个词。

### 6.2 这说明什么

- **缺的确实是同义词桥**：字面检索对 `胀奶/漏奶/无痛/温奶器` 这类词召回差；
- **但不等于「必须上向量」**：一个受控的同义词表 / 查询规范化就能补掉这 7 组；
- **也不等于「同义词表够用」**：它只覆盖你想到的词；没想到的词仍需要语义模型。
- 所以本轮能下的结论只有一句：**「同义词桥」是已证实缺口；「向量能补」是未测假设。**

## 八、与选型文档的不同意见（只写在报告里，不改选型文档）

选型文档的判断是「先补 rerank，再补向量」。**本轮支持这个大方向**，但补三条前置条件：

1. **2 字查询先做规范化，成本最低。**
   `无痛 → 疼痛缓解`、`防溢 → 溢乳`、`漏奶 → 溢乳`、`胀奶 → 乳房胀痛`、
   `温奶器 → 暖奶器` 这五组，一个受控同义词表就能把 top10 从 0–1 拉到全覆盖。
   它不是通用解，但它是**零外呼、零模型**的第一刀；先做它，再评估 rerank 的增量，
   否则你会把「同义词表能修的」算成「rerank 的功劳」。
2. **候选池要先对，再谈 rerank。**
   本轮 top10 里规则迁移条目经常压过业务台账（#1、#9、#15）。如果正确文档不在 topK 里，
   rerank 无法把它变出来。建议先做**分源路由/字段加权**（业务台账 vs 治理规则），
   再在同一候选池上比较「字面 vs rerank」。
3. **标题-only 的台账记录是语料缺口，不是排序缺口。**
   `taskid_19885.docx 婴儿背带` 这条记录没有正文；髋关节/IHDI 不在语料里。
   任何 embedding/rerank 都救不了「内容没入库」。在评估向量之前，先补台账正文/描述字段。

**因此建议的顺序**（供 05 改选型文档时参考，不由本报告直接改）：

```
① 2 字查询规范化（同义词表，零外呼）
② 业务台账正文/字段补齐 + 分源路由/字段加权
③ rerank（先在 ② 的候选池上做 A/B）
④ 向量召回（bge-m3 / Qwen3-Embedding，等 ③ 的读数）
```

如果 05 坚持「rerank 先于向量」，本报告不反对；但请把 ①/② 作为 rerank 评测的**前置**，
否则测出来的「rerank 没提升」很可能是在测语料缺口。

def term_score(term):
    scores={}
    s=norm(term)
    if len(s)>=3:
        q=set(trigrams(s))
        for i,d in enumerate(docs):
            sc=0.0
            for t in q:
                f=d['tf'].get(t,0)
                if f:
                    sc += idf(t)*f*(K1+1)/(f+K1*(1-B+B*d['dl']/avgdl))
            if sc: scores[i]=sc
    else:
        for i,d in enumerate(docs):
            c=d['text'].lower().count(term.lower())
            if c:
                title_hit=d['title'].lower().count(term.lower())
                scores[i]=c + 3*title_hit + 1.0/(1+len(d['text'])/800)
    return scores

def search(query, topk=10, expand=None):
    terms=[t for t in re.split(r'\s+',query.strip()) if t]
    if expand:
        terms=terms+[expand]
    per=[term_score(t) for t in terms]
    maxes=[max(x.values()) if x else 1.0 for x in per]
    agg=defaultdict(float)
    for sc,mx in zip(per,maxes):
        if mx<=0: continue
        for i,v in sc.items(): agg[i]+=v/mx
    ranked=sorted(agg.items(), key=lambda kv:(-kv[1], len(docs[kv[0]]['text']), docs[kv[0]]['id']))[:topk]
    return [(i,round(s,3),docs[i]) for i,s in ranked]

    return {i for i,d in enumerate(docs) if t in d['text'].lower()}
