## 1 · 备份（阶段 0）

### 1.1 第一次备份：★ 一个被自己吞掉的失败

第一次打包的命令是这样写的：

```bash
sudo tar czf .../backup-$TS.tar.gz -C /opt/momcozy-audit-platform data config .env.production 2>/dev/null
```

结果：包生成了、36 KB、`tar tzf` 能列出 31 项 `data/` —— **看起来成功**。

但 `config/` 一项都没有：

```
$ sudo tar tzf backup-...tar.gz | grep -c "^config/"
0
```

**真因**：`2>/dev/null` 把错误吞了。单独重跑一次（不吞 stderr）就看见：

```
$ sudo tar czf /tmp/test.tar.gz -C /opt/... config
（无输出）
$ sudo tar tzf /tmp/test.tar.gz
config/
config/principals.json          ← 单独打就好好的
```

也就是说第一次那份包里 `config/` 与 `.env.production` **都没进去** ——
而 `principals.json` 是权限源、`.env.production` 是全部凭据。
**一份缺这两样的备份，在需要它的时候等于没有备份。**

> 这与 AGENTS.md §2.2 第 5 条（`timeout` 不在时输出为空、`rc=127`，
> 与「扫完了没命中」长得一样）是同一个形状：
> **把 stderr 吞掉 → 失败与成功长得一样。**

### 1.2 重做，并逐项核对

```bash
sudo tar czf .../backup-$TS-full.tar.gz -C /opt/momcozy-audit-platform data config .env.production
# tar_rc=0（这次不吞 stderr）

$ sudo tar tzf ...-full.tar.gz | grep -cE "^data/authority/events/cmd"   → 4
$ ... | grep -cE "^data/projection/"                                     → 1
$ ... | grep -cE "^data/db/"                                             → 7
$ ... | grep -cE "^config/principals.json"                               → 1
$ ... | grep -cE "^\.env\.production$"                                   → 1
```

**五项逐个非零**才算备份成立 —— 不是「文件存在」，是「里面真的有东西」。

产物（均在 `/opt/`）：

| 文件 | 权限 | 内容 |
|---|---|---|
| `momcozy-audit-platform-backup-20261026-164224-full.tar.gz` | 644 root | data/ + config/ + .env.production |
| `...-164224-principals.json` | 600 root | 权限源单存一份 |
| `...-164224.env.production` | 600 root | 凭据单存一份 |

## 3 · report_root 的 bind mount（阶段 2）

代码更新到 `346d57b` 后，**P0-D 的修法自动到位**（它就在这个提交里）：

```
$ grep -n "reports-root" repo/docker-compose.yml
67:      - /opt/momcozy-audit-platform/data/reports-root:/data/reports-root

$ grep -n "mkdir -p /data" repo/Dockerfile
117: && mkdir -p /data/authority /data/projection /data/logs /data/reports-root \
```

所以**不需要手工改 compose** —— 这是「先更新代码再动手」带来的好处。
只需在宿主机建目录，并设对属主：

```bash
$ sudo mkdir -p /opt/momcozy-audit-platform/data/reports-root
$ sudo chown 10001:10001 /opt/momcozy-audit-platform/data/reports-root
$ sudo chmod 700 /opt/momcozy-audit-platform/data/reports-root
$ ls -ld → drwx------ 2 10001 10001
```

判据（`docker compose config` 的 source 数）：

```
改前 6 项（含 reports-root？—— 见下）
改后 6 项：
  data/authority · data/projection · data/logs · config/principals.json
  data/db · data/reports-root        ← 最后这项是新的
```

> ⚠️ 记账更正：方案 §三阶段 2 写「`grep -c reports-root` 从 0 变 1」，
> 实际代码更新后它已经是 1（因为修法在 `346d57b` 里）。
> 那个「从 0 变 1」只适用于**不更新代码、只手工改 compose** 的路径。
> 两条路径殊途同归，但判据的起点不同 —— 这里如实记下。

★ 属主必须是 `10001:10001`：容器以 uid 10001 运行，
而 `/readyz` 的 `data_permissions` 会检查 `mode & 0o077`。
属主错 → 容器写不进去，但**报错不会直接说「属主错」**，表现为权限检查 false。

## 5 · 替换（阶段 4）★ 这里出过一次事故

### 5.1 第一次替换失败：`missing_config:REVIEW_REPORT_ROOT`

```
 Container momcozy-audit-api  Started
 try1 readyz=502  try2 readyz=502  …  try6 readyz=502
```

容器反复 `Restarting (1)`。日志尾部：

```
File "/app/api/production_app.py", line 294, in from_env
    raise SettingsError("missing_config:" + ",".join(missing))
api.production_app.SettingsError: missing_config:REVIEW_REPORT_ROOT
```

**根因**：`REVIEW_REPORT_ROOT` 是新版才变成**必需**的配置项。

```
$ git merge-base --is-ancestor a91aa1b 6ad7a34 && echo 在旧版里 || echo 不在旧版里
★ 不在旧版里（旧版之后才加的）
```

线上 `.env.production` 是 10-22 建的，12 个键里没有它；
`.env.production.example` 里有（`:34 REVIEW_REPORT_ROOT=/data/reports-root`），
但**没人把 example 的变更同步到生产 env** —— 这正是「example 与真 env 漂移」的典型后果。

**为什么以前没暴露**：旧代码根本不读这个键（`6ad7a34` 里 `grep REVIEW_REPORT_ROOT` 为空），
所以缺了也能起。新版把它列进 `required`，缺了就在构造期抛 —— **报错很明确，这是对的**。

### 5.2 修法：只补这一个键

```bash
sudo cp .env.production .env.production.bak-$(date +%Y%m%d-%H%M%S)
printf "\nREVIEW_REPORT_ROOT=/data/reports-root\n" | sudo tee -a .env.production
sudo chown ubuntu:ubuntu .env.production && sudo chmod 600 .env.production
```

★ 顺手的一个隐患：`tee -a` 以 `sudo` 跑会把文件属主改成 root，
而 compose 是 `sudo -u ubuntu` 跑的 —— 属主一错就 `permission denied`（今早记过这个坑）。
所以追加之后**必须** `chown` 回来。

### 5.3 第二次替换：成功，中断约 7 秒

```
=== 重启 16:49:21
 Container momcozy-audit-api  Started
 try1 readyz=502 | Up Less than a second (health: starting)
 try2 readyz=200 | Up 3 seconds (health: starting)
```

**不可用窗口 ≈ 7 秒**（16:49:21 → 16:49:28）。
