### 2.2 ★ SSH 端口不是 22，是 22222

```
nc -z -G 8 43.163.92.244 22    → rc=1（超时，不是拒绝）
nc -z -G 3 43.163.92.244 22222 → OPEN
```

22 被安全组过滤（连 ping 都不通），22222 才是实际端口。
**任何照 22 写的脚本在这里都会超时，而超时看起来像「服务器挂了」。**

```bash
ssh -i zhoujian_pachong.pem -p 22222 ubuntu@43.163.92.244
```

| 项 | 值 |

| 容器 | `momcozy-audit-api` · `momcozy-audit:local` · **Up 3 days (healthy)** |

| 代码版本 | `HEAD=6ad7a34`（2026-10-22）· 工作区干净 |
| 镜像构建于 | `2026-10-22T18:41:08+08:00` |

**入口是共享反代，不是独立的 nginx**：

```
ai_video_nginx（持有宿主 80/443，40+ 站点共用）
  └─ server_name ca.luteos.com
       ├─ location /review-api/ → rewrite → proxy_pass 172.20.0.1:18000
       └─ location /            → proxy_pass 172.20.0.1:18000
```

★ 那个 `rewrite /review-api/ → /api/v1/` 是**为了兜住 P0-B**：旧前端包里 API 前缀写的是
`/review-api`（dev 的 vite 代理前缀）。它现在是**必需的**，去掉就会全线 404。

### 2.4 线上现状与今天 HEAD 的差距

线上 `6ad7a34` 落后 `346d57b` **17 个提交**，其中带着今天修掉的 P0-B：

```
线上前端包 assets/index-iDwmVd1k.js : "/review-api"   ← 靠 nginx rewrite 撑着
本地 dist  assets/index-B7zSRZt7.js : "/api/v1"       ← 已修
```

升级后必须**同时**去掉 nginx 那条 rewrite，否则前端打 `/api/v1/...`
会先被 `location /review-api/` 之外规则忽略、正常走 `location /` —— 其实无害，
但**留着 rewrite 等于留一条死代码**，且会让「P0-B 到底修没修」永远说不清。

### 2.5 ★ 匿名卷里 0 个报告

```
$ docker exec momcozy-audit-api sh -c 'ls /data/reports-root; find /data/reports-root -name "*.md" | wc -l'
（ls 无输出）
0
```

容器没有设 `REVIEW_REPORT_ROOT`，用代码默认值；该目录里**没有任何报告正文**。
所以 D3 的「抢救」步骤**必然是空的** —— 这件事本身要留证（证明不是「忘了拷」）。

### 2.6 `.env.production` 缺 `REVIEW_REPORT_LINK_SECRET`

线上 13 个键里没有它。代码里它是 `required=False`（`_link_secrets_from_env(env)`），
所以 `/readyz` 全绿 —— 但 `/api/v1/reports/{id}/resign` 会恒 503。

**本次不改这个**：它需要一个新的密钥值，而那是「谁有权决定这份密钥」的问题。
列为上线后的待办，不夹带在升级里。

### 2.7 依赖连通性

```
$ sudo -u ubuntu git -C .../repo ls-remote origin refs/heads/main
346d57ba33713ec3201db14beff80b1a348c6902   ← 与本地 HEAD 一致
```

服务器能以 `ubuntu` 身份 fetch（`sudo` 身份则 `Host key verification failed`）。
**必须用 `sudo -u ubuntu`**，不能用 `sudo`。

## 三 · 部署方案

### 阶段 0 · 备份（不可跳过）

| 动作 | 命令 | 判据 |
|---|---|---|
| 备份 data/ | `sudo tar czf /opt/momcozy-audit-platform-backup-$(date +%Y%m%d-%H%M%S).tar.gz -C /opt/momcozy-audit-platform data config .env.production` | 包内 `tar tzf` 能看到 `data/authority` 与 `config/principals.json` |
| 记当前状态 | 容器 id、镜像 id、`/readyz` body | 三样都存成文件 |
| 报告抢救（D3） | 见 §2.5 —— 0 个文件 | 打印 `find ... \| wc -l` 的输出并存证 |

**回滚点 = 这个 tar + 旧镜像 id。** 两者都要在动手前确认可读。

### 阶段 1 · 代码更新（线上不受影响）

```bash
sudo -u ubuntu git -C /opt/momcozy-audit-platform/repo fetch --all
sudo -u ubuntu git -C /opt/momcozy-audit-platform/repo reset --hard 346d57b
```

★ 为什么用 `reset --hard` 而不是 `pull`：工作区已确认干净，`reset` 对「远端被 force push 过」
（本仓今天 force push 过）是唯一可靠的方式。

### 阶段 2 · 加 `reports-root` 的 bind mount（修 P0-D）

```yaml
# docker-compose.yml，在 data/db 那行之后
- /opt/momcozy-audit-platform/data/reports-root:/data/reports-root
```

宿主机侧（属主必须是容器里的 10001，否则 `/readyz` 的 `data_permissions` 会 false）：

```bash
sudo mkdir -p /opt/momcozy-audit-platform/data/reports-root
sudo chown 10001:10001 /opt/momcozy-audit-platform/data/reports-root
sudo chmod 700 /opt/momcozy-audit-platform/data/reports-root
```

判据：`docker compose config | grep -c 'reports-root'` 从 0 变 1。

### 阶段 3 · 离线构建（线上仍跑旧版）

```bash
sudo -u ubuntu docker build -t momcozy-audit:346d57b -t momcozy-audit:local \
  /opt/momcozy-audit-platform/repo
```

★ 先用**版本号 tag** 构建，成功后才覆盖 `:local`。
这样「构建坏了」与「部署坏了」是两件事 —— 前者线上零影响。

### 阶段 4 · 替换（唯一的不可用窗口）

```bash
sudo -u ubuntu docker compose -f /opt/momcozy-audit-platform/repo/docker-compose.yml up -d
```

预期 5–15 秒。**这是整个方案里唯一会中断服务的动作。**

### 阶段 5 · 验收（D4：只读）

见 §四。

### 阶段 6 · 收尾：清掉那条 `rewrite`

新前端包打 `/api/v1`，`location /review-api/` 已无消费者。
**但这一步要放在验收全绿之后**，且改的是共享 nginx（40+ 站点共用）——
`nginx -s reload` 前必须 `nginx -t`。

## 四 · 验收清单

### 4.1 只读探测（可自动，零副作用）

| # | 检查 | 期望 | 失败说明什么 |
|---|---|---|---|
| A1 | `GET /healthz` | 200 JSON | 进程没起来 |
| A2 | `GET /readyz` | 200，**七项全 true** | 逐项看是哪一项 |
| A3 | `GET /` | 200 HTML，含 `<title>内容审查工作台` | 前端产物没进镜像 |
| A4 | `GET /cases/x`（SPA 深链） | 200 `text/html` | SPA 兜底没配 |
| A5 | `GET /api/v1/me` 未登录 | **401 JSON**（不是 200 HTML） | ★ 拿到 HTML = 路由被兜底吃了 |
| A6 | `GET /static/reports/x.md` 未登录 | 401 JSON | 同 A5 |
| A7 | `GET /api/v1/nonexistent` | 200 HTML（SPA 兜底，已知行为） | 这是**当前设计**，不是缺陷 |
| A8 | 前端包前缀 | `"/api/v1"`，**不含裸 `"/review-api"`** | P0-B 没修上 |
| A9 | `container.RestartCount` | 连续两次采样不变 | 反复重启 |
| A10 | 报告目录 | 容器内 `/data/reports-root` 是 bind mount 且权限 700 | P0-D 没修上 |

### 4.2 数据持久化（★ P0-D 的真判据）

```bash
# 替换后：restart 与 down/up 两种都要
docker compose restart && <A1–A6 重跑>
docker compose down && docker compose up -d && <A1–A6 重跑>
```

**判据不是「readyz 绿」**（它绿了不代表报告没丢），而是：
`GET /api/v1/reports` 里出现的每一个 report_id，`GET /static/reports/{id}.md` 登录后都 200。

## 五 · 回滚

**触发条件（任一条成立即回滚，不讨论）：**

| 读数 | 阈值 |
|---|---|
| `/readyz` 任一项 false 持续 | > 3 分钟 |
| 容器 `RestartCount` | 10 分钟内 ≥ 1 |
| `/api/v1/me` 未登录返回 200 | 出现即回滚（安全边界） |
| 写端点 5xx | 5 分钟内 ≥ 1 条 |
| 报告「列表有、点开 404」 | 出现即回滚 |

**回滚动作：**

```bash
# 1) 代码回旧版
sudo -u ubuntu git -C /opt/momcozy-audit-platform/repo reset --hard 6ad7a34
# 2) 镜像回旧版（构建阶段保留的版本号 tag 让它还在）
sudo -u ubuntu docker tag <旧镜像id> momcozy-audit:local
# 3) 重起
sudo -u ubuntu docker compose -f .../docker-compose.yml up -d
```

★ **回滚不是撤销**（今早那条硬边界）：旧镜像的投影层遇到不认识的 `aggregate_type`
会 `ProjectionError`。只要升级后产生了 **notifications 批次**，旧镜像就起不来。
判据：`docker logs` 里出现 `unknown_aggregate_type` → 回滚已不可行，
只能「换镜像 + 从 §三阶段 0 的 tar 恢复数据」，那会丢掉备份点之后的写入。
