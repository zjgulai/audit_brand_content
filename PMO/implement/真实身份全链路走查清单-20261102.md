# 真实身份全链路走查清单（2026-11-02）

> **目的**：让委托方（或指定的人）用**真实飞书账号**走一遍
> 「登录 → 提交 → 判定 → 复核 → 报告 → 放行」，每一步记下**实际看到的**与**应该看到的**。
>
> **这是上线前最后一道人工闸**。机器侧的 141 个自证检查器都已绿
> （见 `reports/守衡-项目成果总结-20261101.md` §五），但「真实身份的每一跳」
> 没有任何机器能替你走 —— 它涉及飞书扫码、真实权限、真实案件。
>
> 依据：`PMO/implement/生产部署执行记录-20261026.md` §8 D4。

## 一、登录（飞书扫码）

| 步 | 动作 | 应该看到 | 实际（打勾/记录） |
|---|---|---|---|
| 1.1 | 浏览器开 `https://ca.luteos.com/` | 跳 `/login`，**只有飞书扫码**一种方式（**没有**账号密码框 —— 2026-10-30 已撤） | ☐ |
| 1.2 | 用飞书 App 扫码 | 飞书内确认登录 → 跳回工作台首页 `/queue` 或 `/` | ☐ |
| 1.3 | `curl -b cookie.txt https://ca.luteos.com/api/v1/me` | 返回走查人真实姓名、`product_lines`、`capabilities` | ☐ |
| 1.4 | 右上角头像 / 设置页 | 显示走查人姓名，**不是**「未知用户」 | ☐ |

**1.3 的判据**：`product_lines` 必须**非空**且与走查人的业务品线一致。
如果是空数组 → 主体目录没登记上，记下截图，**停止走查**，联系我们。

## 二、提交（三种形态各一单）

### 2.A 广告文案（应该 PASS）

| 步 | 动作 | 应该看到 |
|---|---|---|
| 2.A.1 | 工作台首页 → 「提交审核」→ 选「文本」→ 粘贴一段正常广告文案 → 选品线 → 提交 | 跳 `/cases/<id>`，状态 `PENDING` 短暂后转终态 |
| 2.A.2 | 等 10 秒刷新 | 终态 `PASS`；「工作流耗时」一行显示总耗时（毫秒级）；「判定详情」展开看到命中规则（或「未命中」） |
| 2.A.3 | 案件详情页 | 案件 ID、品线、提交人（**真实姓名**）、提交时间、内容正文、四维字段（`content_type`/`content_stage`/`entry_channel`）都显示 |

### 2.B 违规文案（应该 BLOCK）

| 步 | 动作 | 应该看到 |
|---|---|---|
| 2.B.1 | 同上，但粘贴一段明显违规文案（含「最便宜」「100% 有效」类绝对化用语） | 终态 `BLOCK` |
| 2.B.2 | 「判定详情」 | 至少一条命中规则，每条带 `rule_key` 与命中片段 |

### 2.C 图片（应该 REVIEW，触发 OCR）

| 步 | 动作 | 应该看到 |
|---|---|---|
| 2.C.1 | 「提交审核」→ 选「图片」→ 上传一张**含文案**的图（广告截图最佳） | 案件详情显示媒体类型 image；判定详情显示 OCR 观察（至少 1 条） |
| 2.C.2 | OCR 观察条数 | **大于 0**；如果是 0 → `multimodal_client` 没接进来，记下截图停止 |

### 2.D 视频（可选；只验「未审查」路径）

| 步 | 动作 | 应该看到 |
|---|---|---|
| 2.D.1 | 上传短视频（< 30s） | 终态 `未审查` 或 `REVIEW`；**不应该出现 `PASS`** —— 视频无 ASR，按设计永不 PASS |

## 三、判定链复核（看「依据是什么」）

任选一个上面的案件，点进详情页：

| 步 | 应该看到 |
|---|---|
| 3.1 | 「判定链」分四段：normalize → judge → dispose → output |
| 3.2 | 每段带 `duration_ms`；五步求和 = 顶部「总耗时」 |
| 3.3 | 如果有命中规则：每条规则的 `rule_key` 都能在「规则词典」页搜到原文 |
| 3.4 | 「证据」一节：列出观察条目；媒体件至少有 OCR 结果 |

## 六、放行（**先确认走查人有 `release.sign` 能力**）

| 步 | 动作 | 应该看到 |
|---|---|---|
| 6.1 | 队列页 → 选中一个 `PASS` 案件 → 「放行」 | 弹确认框 |
| 6.2 | 确认 | 案件状态转 `RELEASED`；队列条目消失或换分组 |
| 6.3 | `curl -b cookie.txt https://ca.luteos.com/api/v1/release/pending` | 该案件**不在** pending 列表里 |
| 6.4 | 如果走查人没有 `release.sign` 能力 | 按钮置灰或 API 返 403；**不应该**装作能点 |

WBPM-0150 P3），**但其他真实用户可能还没配**。如果走查人没有这能力，
记下截图，**走完前五步即算通过**，放行这一步留给我们配置后再补测。
