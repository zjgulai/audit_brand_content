# UI/UX 深度审计与逐页模块化设计方案（2026-10-27）

> 性质：**纯方案，本轮不修改代码。**
> 方法：`design-taste-frontend`（taste-skill v2）app-screens 流程 —— 12 条路由 × 3 视口
> 机器审计（`inspect.mjs --app`）+ 代码级统计 + harness 数据态截图 + 生产登录页截图。
> 参考：www.beautifului.dev（AI 原生界面的 21 个组件模式）；
> 该技能对 23 个真实产品屏幕的实测研究（下称「研究」）。
> 证据：`.taste-skill/before-*/`（每页 report.json + 1440/768/390 截图）。

## 二、六个病灶（按修复收益排序）

### 病灶 1：字号层级塌陷（最重）

三条读数互相印证：12px 占 58 处、18px 只有 4 处、inspect 报 89% 文字 <13px。
**界面不是「字太小」，是「什么都一样小」**——18px 标题与 14px 正文只差 1.29 倍，
研究与 beautifului 的共同规律是层级靠**跳跃**（正文→标题 ≥2 倍）而不是靠档位多。

**修订：四档字阶，比例拉开**

| Token | 值 | 用途（唯一） | 现状 |
|---|---|---|---|
| `--text-title` | 12→**28px** | 每页唯一 h1（页面标题） | 18px，与正文拉不开 |
| `--text-section` | 新 **20px** | 区块标题、KPI 数值 | 无此档 |
| `--text-base` | 14px 不变 | **一切正文**：单元格、列表、表单、按钮 | 只有 14 处用它 |
| `--text-sm` | 12px | **仅三种**：徽标、表头、时间戳/来源行 | 58 处滥用为正文 |

硬规则（写进门禁）：`--text-sm` 出现处必须是 badge/th/时间戳三者之一；
正文段落、列表项、表格单元格、按钮文字一律 14px。28:14 = 2 倍跳跃，一眼分层。

字重三档：400（正文）/ 500（次强调：表头、按钮）/ 600（仅 h1、KPI 值、选中项）。
字重不再承担「把 12px 变重要」的任务。

行高收敛两档：14px→20px（1.43）、12px→16px（1.33）。删 1.5/1.65 裸值。

### 病灶 2：间距失控，光学对齐无从谈起

13 种 gap、杂值 padding——**对齐不是靠「对」，是靠「同一套节奏」**。
相邻模块一个 gap 0.5rem 一个 0.75rem，视线就会在读到内容前先绊一下。

**修订：4px 网格，六值封顶**

| Token | 值 | 用途 |
|---|---|---|
| `--space-1` | 4px | 图标与文字、徽标内距 |
| `--space-2` | 8px | 相关元素间（label→field 用 8–10） |
| `--space-3` | 12px | 卡内元素组间、行内松散分隔 |
| `--space-4` | 16px | **唯一卡间距**（全站 gap 只有这一个值） |
| `--space-5` | 24px | 卡 padding、页 gutter、标题→内容 |
| `--space-6` | 32px | 区块之间 |

规则：CSS 里禁止出现这六个之外的间距值（`0.35rem` 这类全部清除）；
卡与卡之间永远 16px；一行的卡**底边必须齐**（研究：ragged-row 每次都被扣分）。
嵌套同心圆角已有（6/4）保留；卡 radius 统一 8px（研究 tight 档中位）、控件 6px、徽标 4px。

### 病灶 3：首屏真空 + 空态贫穷

9/12 页首屏 28–61% 空白。两处来源：
①「左列表 + 右详情」页在未选中时右侧整块空白（61%）；
②统计条在无数据时渲染「趋势摘要：未测」「样本状态：未测」占位符。

**修订**：
- **空态必须有内容设计**：详情面板空态改为「三行引导」——这段面板是干什么的（一句话）、
  现在为什么是空的（一句话）、「去看什么」（一个真实链接去队列第一条）。
  研究：empty section 保留框架 + 一句话横跨整块，禁止一行灰字配 600px 白地。
- **「未测」占位符不渲染**：统计条三个槽位里凡是无数据的整槽不渲染，
  有数据时输出一句话真实摘要（beautifului Insight Card 模式：
  「10 条待办，最早一条等了 3 小时」>「待办 10 条（待人工判定 8 / 待品牌自决 2）」）。
- 左列表加载态：骨架条（真实行高的灰条）代替「加载中…」一行字。

### 病灶 4：研发视图当业务界面（用户第 2、3 条的主病灶）

实锤清单（全部截图可指认）：

| 位置 | 内容 | 该是什么 |
|---|---|---|
| 案件详情·覆盖证明 | `{"fingerprint": "ffffffffffffffff", "version": "rs-fixture"}` 原始 JSON | 「规则指纹 已登记」+ 悬停/展开看值 |
| 案件详情·证据链 | 「Finding.control_code 与 rule_id 不是同一个键…」两段键值不匹配的调试说明 | 删。这是 bug 记录不是界面；审核员需要的是「为什么关联不上」的一句话 |
| taxonomy | `web/src/data/taxonomy.json`、`spec_version: v1.1.4a96880b0cf8`、markdown `*`/`#` 痕迹 | 路径与 commit 删除；条目解析后再渲染 |
| 全站 footer | 「判定由后端唯一产出，本页不重算；人工动作只经写 API…」 | 整行删除（内部架构承诺不是界面文案） |
| 案件详情 | 「未评估（不是 0，是没跑）」 | 「未查部分」；空时整块不渲染 |
| 队列行 | `DP3 wearable shopify u_dp4` 内部术语连排 | 「穿戴 · 独立站」业务词（研究：words of the trade） |
| 案件详情 | 「变 前往签发台 G-1 →」（行首单字「变」） | 「放行」标签 + 「前往合规签发」按钮 |

**文案三规则**（落实用户第 1、2、3 条）：
1. 每句话回答审核员会问的问题；回答不了的不写。
2. 面向审核员的词：「检查/处置/签发/下架」；禁「双指针、欠定边界、主草稿、回执」直出。
3. 中点「·」已清零，**防止回潮**：lint 规则禁止 JSX 文本节点出现「·」。

### 病灶 5：色彩纪律——暖白底 + 紫徽标

- **sand-1 #fdfdfc 判 cream（12/12 页）**：色相偏黄虽仅 2% 色度，但整界面没有一处
  纯白/纯中性锚点，品牌酒红成了唯一的「颜色」，暖调淹没了它。
  修订：`--surface: #ffffff`（卡面纯白）、`--bg` 保留 sand-2（层次靠中性差）；
  暖调只允许出现在品牌元素（logo、主 CTA、选中态）。按钮底同步纯白。
- **紫 #8145b5 FAIL**：「未测」是中性状态（无结论），不该拿彩色信号。
  修订：未测徽标改**灰 chip**（sand-3 底 + sand-11 字 + 虚线边 0.5px），
  符合研究 §7.6「neutral states are monochrome chips」。A6 断言不受影响（灰不是品牌色）。
- **状态徽标改「淡底 + 同相深字」对**（研究 §7.6 的 pale pair）：
  现在是单色文字（`color: var(--bad)`），改 `--bad-surface` 底 + `--bad-text` 字，
  12px/500，高度 20px，`flex: none`——一行多徽标时不再互相挤压。
- **finding 卡 3px 左红条**（用户第 10 条漏网）：删。改卡片 0.5px 边 + 徽标表达严重度。

### 病灶 6：信息优先级——需要判断的交互太多（用户第 9 条）

- 队列筛选两行五枚 chips 全部带计数，数据态下「全部待办(10)/待人工复核(8)/品牌自决(2)」
  与页面实际内容（只显示 REVIEW 件）**口径不一**——用户要自己发现「为什么点 8 只出来 8 里的一部分」。
  修订：筛选 chips 与列表口径合一；计数为 0 的 chip 隐藏；保留单一默认视图，
  排序切换（紧迫度/最新）降为次要控件。
- 案件详情页的动作（确认违规/取回候选）沉底。修订：**判定卡置顶**
  （beautifului Approval Card 形态）：「这条内容查出了什么」一句话 + 证据折叠 +
  两个动作按钮（主：确认违规，副：取回候选）。审核员打开页面第一眼就是待决的事。
- 一行多徽标（待人工复核 + 高危×2 + 样例）改**一个状态徽标 + 一个严重度徽标**封顶
  （研究：one status mark per row）。

现状 12/12 页命中 edge-text FAIL + 侧边栏 logo 副标被裁。

| 模块 | 规格 |
|---|---|
| 侧边栏宽 | 224px（研究中位 230；现 240 偏宽但保留现值亦可，重点是内距） |
| 侧边栏内距 | 左右 **16px**（现 14px < 16px FAIL）；行高 34px / 行距 pitch 34px |
| 分组标题 | 12px/500 灰 sentence case（现符合），上下留白 20px/12px |
| 导航行 | 14px/400，图标 16px、1.5px 描边、与文字间 10px；选中态：灰底 pill（`--surface-muted`）+600 字重，**去掉品牌粉底**（研究：active nav 是中性灰 pill，0/23 用彩色；品牌色留给内容与主行动） |
| logo 区 | 高 40px；**logo 只用心形+字标段**（裁掉「Global No.1…」电商标语——20px 高时标语糊成一团且语境错误）；副标「内容审核工作台」12px 放 logo 下方，不再并排（并排被 240px 栏宽裁切，实测） |

| 页脚 | **整行删除**（两句内部说明）。浏览器支持范围只在 /login 页脚保留一行 |
| 画布 | gutter 24px、内容最大 1200px、title→首块 24px |

## 四、逐页模块化方案

> 每页格式：**该页唯一问题**（研究 §2.2：一屏一问）→ 模块拆解 → 关键规格。
> 共用组件不再重复（徽标=20px 淡底对、按钮=32px 高 6px 圆角、表格=规则与对齐）。

### 1. /login 登录页
唯一问题：「这是什么，怎么进去」。
- 现状已收敛（生产截图：logo + 标题 + 一句话 + 二维码并排按钮）。保持。
- 微调：标题升 20px；面板 padding 24px；按钮改灰底描边次级 + 说明改为「使用飞书扫码或点击登录」一体；页脚一行保留。

### 2. /queue 待人工复核（首屏页）
唯一问题：「现在该处理哪一条」。
- **模块 A 标题行**：h1「待人工复核」20px + 副标一句 + 右侧「+ 提交送审」。删双行统计条（三个「未测」占位）。
- **模块 B 队列列表**（主体，占首屏 60%+）：行高 64px 双行制——
  行 1：案件标题（14px/500 ink，截断省略）+ 严重度徽标（至多 1 个）；
  行 2：业务元信息 12px 灰（「穿戴 · 独立站 · 等 3 小时」）+ 右侧「开始复核」文字动作。
  删「样例数据」工具行到列表头部右侧一个次级按钮；删行内 3–4 枚徽标堆叠。
- **模块 C 详情面板**（选中态）：判定卡置顶（见病灶 6）；未选中态用三行引导空态。
- 选中行：`--surface-muted` 底（研究：驱动详情面板的列表选中不用 hover 色混淆）。

### 3. /cases 审核全景
唯一问题：「全部内容各自到了哪一步」。
- 删内容区重复大标题（顶栏已有「审核全景」）；h1 唯一。
- 删 50 字解释句；筛选项与计数口径合一；0 计数 chip 隐藏。
- 表格：identity 列（案件标题）占 40%；状态列徽标 1 枚；「共 N 条」右上角 12px。
  数字列右对齐 tabular；行规则 1px 比表面深 3–7%；无斑马纹。
- 分页保留（真列表页允许），显示「1–50 / N」。

### 4. /cases/:id 案件详情（改动最大）
唯一问题：「这条内容有什么问题，我要怎么裁」。
- **模块 A 判定卡**（首屏顶部，beautifului Approval Card）：
  「查出 1 处问题（L4 极高危），命中 BRD4 极限措辞控制」一句话 +
  两个按钮（确认违规=主、取回候选=次）+ 折叠的依据列表。
- **模块 B 原文面板**：删内部 ID 行与四枚 tab 按钮（改为面板头部两个文字切换：
  原文 / 结构化）；黄色高亮 → `--warn-surface` 淡底 + 2px 下划线；
  补充声明句删（第 2 条）。
- **模块 C 覆盖证明**：键值对只留四行（覆盖状态/适用控制点/规则版本/分类规范版本）；
  JSON 与指纹哈希折叠进「技术详情」details；空块不渲染。
- **模块 D 证据链**：调试说明两段删除；finding 卡去左色条、去内部 ID 前缀
  （保留截断短 ID 供对账，12px 等宽灰）。
- 未查区块：空时不渲染。

### 5. /reports 报告索引
唯一问题：「哪些报告已出、是否可对外」。
- 表格化（同 /cases 规格）；「区块一…六」编号词删（页内 h2 直接用内容名）。

### 6. /reports/:id 报告详情
唯一问题：「这份结论的依据链完整吗」。
- 六区块保留但标题去编号；区块 h2 20px/600；键值 dl 两列（label 12px 灰 / 值 14px ink）。
- 「重签」按钮唯一主行动。

### 7. /release 合规签发
唯一问题：「哪些结论在等正式放行」。
- 待签列表 + 行内「签发」动作（ghost 按钮，研究 §7.8）；危险操作（撤回）独立区红字。

### 8. /takedown 违规下架
唯一问题：「下架任务卡在哪一步」。
- 任务行：名称 + 状态徽标 + 持续天数右对齐；「提醒」「改派」收进行尾 kebab。
- 标题 h2 去内部票号（TD-4 等已在上一轮清了，保持）。

### 9. /appeals 申诉复议
唯一问题：「有哪些异议在等答复」。
- SLA 表述改业务词（「2 个工作日内答复」）；超时行才用 warn 淡底。

### 10. /taxonomy 分类规范（改动第二大）
唯一问题：「每条规则怎么判」。
- **七轴卡改主从结构**：默认只显示「轴名 + 一句定义 + 条目数」，
  判定条件/证据要点/复核入口收进展开区；同屏最多两列，禁止七卡同屏流水。
- 删 markdown 痕迹、代码路径、commit 指纹。
- below-fold 修复：首屏 = 版本行（一行）+ 七轴索引 + 第一轴卡展开。

### 11. /submit 提交送审
唯一问题：「把要审的内容交进来」。
- 表单两字段 + 品线选择；label 14px/500 在上，输入 38px；提交主按钮 44px 触控高。
- 说明句删（placeholder 已表意）。

### 12. /inbox 待办收件箱
唯一问题：「有什么要我知道的」。
- 已读/未读两态：未读行 600 字重 + 品牌色 6px 点，已读 400 灰；「已确认」时间戳 12px。

### 13. /admin/grants 授权治理
唯一问题：「谁能签发、谁能撤权」。
- 表格同全局规格；「release.revoke（撤回，需二次审批）」徽标化；
- 唯一主行动「新增授权」。

### 14. /admin/sessions 安全审计
