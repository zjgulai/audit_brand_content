# 阶段 3 · gold 试点标注指南（10 张 OCR + 5 段 ASR）

> **状态**：试点规格，**不是交付承诺**。
> 本指南服务的第一步是「**把流程跑通**」，不是「得出准确率结论」。
> 10 + 5 跑通之后，再按 [`阶段3-gold样本需求.md`](./阶段3-gold样本需求.md) 扩到 50 + 30。
>
> 消费方：`tools/gold_sample_check.py`（先验样本齐不齐）→ `tools/benchmark_media.py`（再算 CER/WER）。

---

## 0. 一条不能破的规矩

> **gold 不得由模型生成，必须人工确认。**

具体说，下面这些**都不算 gold**：

| 做法 | 为什么不算 |
|---|---|
| 用 OCR/ASR 工具跑一遍，把输出当 gold | 那是「模型自己对自己的答案」，CER/WER 会是 0，而真实错误一个都测不出来 |
| 用大模型「辅助生成」后没逐字核对 | 大模型的输出读起来完全像真的，**错了不会有任何东西变红** |
| 拿另一家模型的结果交叉验证后直接采用 | 两家都错的地方会被当成标准答案 |

**允许**的做法：用工具先跑一版草稿，然后**逐字、逐行**对着原图/原音频核对，每一个字都由人确认过。核对完要在 manifest 里写 `annotator`（谁核的）与 `reviewed_at`（哪天核的）。

这条为什么写在这里：本项目的坑点台账里有一整类「**未测被报成已过**」。gold 是整条评测链的地基 —— 地基如果是模型生成的，上面所有读数都是自己证明自己。

## 1. 目录布局

```text
stage3-samples/                    # ★ 放在**仓外**，目录权限 0700
  ocr/
    ocr_clear_001.png
    ocr_clear_001.gold.txt
    ocr_clear_002.png
    ocr_clear_002.gold.txt
    ...
  asr/
    asr_clean_001.wav
    asr_clean_001.gold.txt
    ...
  manifest.csv                     # 建议提供；不是必需
```

硬要求：

- **`<id>` 只用 ASCII 字母、数字、下划线、短横线** —— 不要空格、中文、斜杠。
- 同一目录内 `<id>` **唯一**；一个 id 只对应一个媒体文件。
- 每个媒体文件必须有一个同名 `<id>.gold.txt`，**放在同一目录**。
- 媒体扩展名（与 `benchmark_media.py` 一致，两边不一致会分裂）：
  - OCR：`.png` `.jpg` `.jpeg` `.webp`
  - ASR：`.wav` `.mp3` `.mp4` `.mov`
- gold 是**纯文本 UTF-8、无 BOM、非空**。不要写 JSON。

> ★ 目录必须在仓外。本仓库是**公开**的，样本与逐字稿可能含客户素材、个人信息。
> 执行点：`tools/gold_sample_check.py` 的 manifest 校验会拒掉仓内路径。

## 2. OCR：10 张，怎么挑

目标是**覆盖四种难度**，不是「找 10 张好看的图」。

| 层 | 张数 | 挑什么 | 不要什么 |
|---|---:|---|---|
| 清晰 | 3 | 白底或纯色底、正面拍摄、文字占画面比例大、无倾斜 | 完美到「和渲染出来的文本一样」——那种测不出东西 |
| 低清 | 3 | 真实退化：压缩噪声、轻微模糊、轻微倾斜、低对比度（如深底白字） | 不要用工具先超分/锐化修复 —— 要测的就是真实条件 |
| 多语言 | 2 | 中英混排、或含少量其他语种；含小字/艺术字更好 | 不要翻译；确认自己能逐字辨认 |
| 复杂背景 | 2 | 图文混排：产品图叠文案、价签、角标、UI 截图、渐变底上的字 | 不要挑**关键区域完全无法辨认**的图 |

**挑选时的三个否决项**（命中任一条就换一张）：

1. 关键文字你自己都看不出来 —— harness 没有「跳过这张」的字段，放进去只会把不可读算成模型错误。
2. 图片里有未脱敏的个人信息且你没法脱敏。
3. 同一张图你已经用在别的层里了（id 唯一，但内容重复会让分层失去意义）。

## 3. OCR gold 怎么写

**规则：写图里可见的全部文字，按自然阅读顺序。**

| 项 | 规则 |
|---|---|
| **顺序** | 从上到下、从左到右；多栏时**按栏读完再读下一栏**，不要横跨 |
| **原始字符** | 不翻译、不纠错、不补全品牌名、不把 `¥199` 改写成 `199 元` |
| **标点** | **保留**（标点计入 CER） |
| **空白** | 空格与换行**不计分**，所以可以按行写，不必复刻排版 |
| **看不清的局部** | **不要猜**。能绕开就绕开；影响关键判定就换图 |
| **同一行的分隔** | 用空格或直接连写都行 —— CER 忽略空白 |

一个最小例子：

```text
买一送一
仅限今日 ¥199
```

如果有竖排文字或艺术字变形，仍按人眼识读顺序写；如果顺序本身有歧义，在 manifest 的 `notes` 里写一句。

## 4. ASR：5 段，怎么挑

| 层 | 段数 | 挑什么 | 长度建议 |
|---|---:|---|---|
| 干净 | 3 | 单人、近场、安静环境、普通话清楚 | 10–40 秒 |
| 噪声 | 2 | 背景音（咖啡厅/街道/机器声）、远场、或带口音 | 10–40 秒 |

试点阶段**不选**：多人重叠说话、长视频（>5 分钟）。这两类留给扩量阶段 —— 阶段一不做说话人分离，试点阶段引入同类样本只会让失败原因变复杂。

**音频格式**：`.wav` 最省事；`.mp3` / `.mp4` / `.mov` 也可以（harness 需 ffmpeg）。不要说「随便导出一个格式」——先确认文件能被正常播放。

---

## 5. ASR gold 怎么写

**规则：逐字转写，不要概括、不要润色。**

| 项 | 规则 |
|---|---|
| **口语填充词** | **保留**（「嗯」「那个」「就是说」），不要删 |
| **标点/大小写/空白** | 不计分（WER tokenizer 会忽略），**可以**适度加标点方便阅读 |
| **数字与专有名词** | 按听感原样写；听不出就标注 `[听不清]`，**不要编造** |
| **噪声段的取舍** | 只写**能辨认**的内容；辨认不了的段落写 `[噪声]` |
| **不要概括** | 「他介绍了产品特点」这种写法是错的 —— 要写他说了什么 |

例子：

```text
嗯，这个其实我们上个月就已经，就是说已经推过一轮了。
[噪声] 然后那个数据大概是涨了百分之三十左右。
```

## 6. manifest（建议提供）

CSV，UTF-8，每行一个样本：

```csv
id,modality,layer,source,authorization,pii_redacted,annotator,reviewed_at,path,sha256,notes
ocr_clear_001,ocr,clear,catalog,业务提供,yes,张三,2026-10-19,ocr/ocr_clear_001.png,<sha256>,
asr_noise_001,asr,noise,业务提供,已授权录制,yes,张三,2026-10-19,asr/asr_noise_001.wav,<sha256>,咖啡厅背景
```

| 字段 | 说明 |
|---|---|
| `path` | 相对 manifest 所在目录，或绝对路径。**必须在仓外** |
| `sha256` | 该媒体文件的真实 sha256（`gold_sample_check.py` 会核对，写错会报） |
| `authorization` | 「业务提供」「已授权录制」等，不要留空 |
| `pii_redacted` | `yes` / `no`；写 `no` 时在 `notes` 说明为什么必须保留 |
| `annotator` / `reviewed_at` | **谁核的、哪天核的** —— §0 那条规矩的落点 |

manifest 是辅助材料，没有也能跑 benchmark；但**有了它，`gold_sample_check.py` 才会去核对 sha256 与仓外路径**。

## 7. 脱敏

- 人脸、姓名、手机号、地址、订单号、身份证号、内部链接 —— 能脱就先脱。
- **脱敏会改变 OCR 文本**：如果你把图上的手机号打了码，gold 里也必须打码，并在 `notes` 写 `pii_redacted: 手机号已打码`。
- ★ **不要把「脱敏后的 gold」配「未脱敏的图」** —— 那样算出来的 CER 全是错的，而且看不出错在哪。
- 来自飞书附件的样本，按现行下载治理登记来源与落盘路径；**下载来的东西不许进公开仓**。

## 8. 交付前自检

```bash
python3 tools/gold_sample_check.py --samples /path/to/stage3-samples
```

退出码：

| rc | 含义 | 下一步 |
|---:|---|---|
| `0` | 全部配对且可读 | 可以交给 benchmark |
| `1` | 有缺失 / 坏 gold / manifest 不合格 | 按它逐条列出的问题修 |
| `2` | 目录不存在或读不出 | **没测到**，不是「样本没问题」 |

带 manifest 时：

```bash
python3 tools/gold_sample_check.py --samples /path/to/stage3-samples \
  --manifest /path/to/stage3-samples/manifest.csv
```

它会逐条核对：每条有 `path` 与 `sha256`、路径在仓外、实际 sha256 与声明一致。

### 人工清单（工具查不了的）

- [ ] **每个 gold 都由人逐字核对过**，不是模型输出直接拿来用（§0）。
- [ ] OCR gold 按阅读顺序写全可见文字；标点保留；没有翻译或纠错。
- [ ] ASR gold 是逐字稿；没有概括或润色；听不清处标了 `[听不清]` / `[噪声]`。
- [ ] 已脱敏；或已在 `notes` 说明为什么保留。
- [ ] 10 张 OCR 覆盖 3/3/2/2；5 段 ASR 覆盖 3/2。

## 9. 跑通之后

试点阶段**只回答一个问题**：「这套流程能不能从样本走到读数」。

所以试点结束后要报的是：

1. 样本配对了多少、`gold_sample_check.py` 的退出码；
2. benchmark 有多少条 `tested`、多少条 `untested`（**逐条看 reason**）；
3. 过程中发现了哪些标注规则说不清的地方 —— 这些要回头改本指南。

**不报**：准确率结论、NFR 承诺、候选工具排名。10 + 5 的样本量支撑不了这些，报了就是拿小样本冒充结论。
