## 3. Benchmark 设计（建议稿，待产品/评估确认）

### 3.1 OB（OCR）— 对应 OB-1…OB-7

**样本分层（最低建议 50 张）**

| 层 | 数量 | 来源 | 要求 |
|---|---:|---|---|
| 清晰产品图/白底 | 15 | 94 张 catalog 图 | 人工逐字转写 + 关键 bbox |
| 低清 / 旋转 / 压缩 | 10 | catalog + landing 证据图 | 故意保留真实退化，不做超分 |
| 多语言 / 小字 / 艺术字 | 10 | catalog + 风险图 | 中文/英文混合，记录每图语种 |
| 复杂背景 / 图文混排 | 10 | landing 证据图 | 含 UI、价签、角标 |
| 构造对照（可选） | 5 | 渲染已知文本 | 只做解析/位置 sanity，不计入主准确率 |

**指标（逐图 + 汇总）**

- 字符准确率 `CA = 1 - edit_distance(ref, hyp) / len(ref)`（按 Unicode 字符；中英分别报）。
- 整图 exact match 率（可选，严格）。
- bbox：与人工框算 IoU；同时断言输出能映射到 `image_region{bbox{x,y,w,h}}`（OB-4）。
- 时延：单图 p50 / p95（CPU、固定容器配额、冷/热启动分开报）。
- 版本/许可证：exact 版本、模型名、LICENSE 路径（OB-5/OB-6）。
- **禁止**引用旧 macOS 基线外推（OB-7）。

**最低样本量**：50 张（按上表分层）；少于该数**不出结论**，只算 smoke。

### 3.2 AB（ASR）— 对应 AB-1…AB-7

**样本分层（最低建议 30 段）**

| 层 | 数量 | 来源 | 要求 |
|---|---:|---|---|
| 干净单人语音 | 10 | 业务方提供 / 有授权录制 | 人工逐字稿 + 句级时间码 |
| 噪声/远场/口音 | 10 | 业务方提供 | 记录噪声类型，不后期降噪 |
| 多人/重叠说话 | 5 | 业务方提供 | 阶段一不做 diarization，只要求不崩 |
| 长视频（>5 分钟） | 5 | 业务方提供 | 验证分段策略（AB-6） |

**指标**

- 英文 `WER = (S+D+I)/N`；中文 `CER`（按字符）。
- segment timestamp：与人工句级时间码的偏差（建议报 p50/p95，绝对偏差）。
- 时延：音频时长 / 处理时长（RTF）与 p50/p95；CPU 配额固定。
- 模型：model size + exact 版本必须锁（AB-5）；长视频分段参数必须记录（AB-6）。
- **禁止**引用旧基线外推（AB-7）。

**样本来源与缺口**

- 盘上**没有音频/视频**；ASR benchmark 目前**无样本可跑**。
- 合成 TTS 只能做格式/时间码冒烟，**不能替代**真实噪声/多人/长视频分层；
  业务方不提供时，AB-2 直接不成立，不得用合成样本凑绿。
- 飞书附件下载红线已于 2026-10-17 改线，但本评估**不下载**任何新内容；
  样本应由业务方提供或按治理登记后取。

### 4.3 容器化对现有 Compose 的影响

- 产品 Compose 尚未落盘，当前没有「现有 Compose」可改；UIUX §9.3 的 DC-1…DC-8 全是门。
- 建议 OCR/ASR 作为**独立 media worker 服务**，不要塞进 API 进程：
  - 独立镜像、固定 digest（DC-8）；
  - 模型/缓存目录放卷，不写仓内；bind mount 0700 + UID/GID（DC-3）；
  - CPU limits/healthcheck/日志轮转（DC-5/DC-6）；
  - SQLite 仍单写者（DC-4）。
- 镜像会显著变大；先测单一 OCR 服务，别同时把四套候选都装进同一镜像。

1. **只做 OCR、只做 CPU、只做容器**：
   - 在 Linux 容器内装 Tesseract（基线）与 PaddleOCR（候选）；

3. 在 benchmark 结论出来前，阶段 3 的 NFR、镜像预算、Compose 服务拆分都保持「待测」，
   不写死 20s/60s。
