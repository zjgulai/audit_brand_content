# 阶段 3 · 审查结论 gold 评测工具说明

> **状态**：试点工具说明，**不是准确率结论**。
> 工具：`tools/eval_review_gold.py`。
> 数据集：0e 正在建 10 条试点，约定位置 `~/audit-data/gold/pilot/`（**仓外**）。
> 本文件与 0e 的 `阶段3-gold试点-标注指南.md` 分开维护：那份讲**怎么标 OCR/ASR 样本**，
> 这份讲**怎么拿真人审核意见评审查结论**。

---

## 1. 它回答什么问题

给定：

- **gold**：真人审核对每条记录的结论（问题类型 + 原因文本 + 建议 + 图片名 + 图片 sha256）；
- **pred**：模型产出的 findings（字段与 `base/semantic_judge.py` 对齐）。

输出：每条记录的 **hit / miss / false_positive**，以及准确率、召回率、分类一致率。

它**不做**：不调模型、不判模型能不能用、不把没有 pred 的运行写成「0 错误」。

---

## 2. 输入格式

### 2.1 gold.json（真人结论，仓外）

```json
[
  {
    "record_id": "pilot-001",
    "品线": "pump",
    "分类": "H01",
    "原因文本": "宝宝存在窒息风险",
    "建议": "删除",
    "图片名": "pilot-001.png",
    "sha256": "<64 位十六进制>"
  }
]
```

硬要求：

- `record_id` 非空且唯一；
- `品线` / `分类` / `原因文本` / `图片名` 非空字符串；
- `建议` 必须是字符串（可以为空串，但字段要在）；
- `sha256` 必须是 64 位十六进制 —— 用来把结论钉到具体那张图，**不是**模型指纹；
- 顶层可以是数组、单个对象，或 `{"records": [...]}`；
- 一条记录多个结论时，加 `findings: [{control_code|分类, quote|原因文本, 建议?}, ...]`；
  没有 `findings` 时，`分类 + 原因文本` 就是这一条结论。

### 2.2 pred.json（模型输出）

字段与 `semantic_judge` 的 finding 对齐：`control_code / severity / quote / location`。
支持三种顶层形状：

```json
[
  {"record_id": "pilot-001", "control_code": "H01",
   "severity": "L5", "quote": "宝宝存在窒息风险",
   "location": {"kind": "image_region"}}
]
```

```json
{"records": {"pilot-001": [{"control_code": "H01", "quote": "..."}]}}
```

```json
{"records": [{"record_id": "pilot-001", "findings": [
  {"control_code": "H01", "quote": "..."}
]}]}
```

也接受 `{"findings": [...]}`，但每条 finding 必须自带 `record_id`。

## 3. 匹配规则（写死，可复核）

同一 `record_id` 下，一条模型 finding 与一条 gold 结论算 **hit**，当且仅当：

1. **问题类型一致**：两边 `control_code`/`分类` 归一化（去首尾空白、转小写）后完全相同；
2. **关键文本片段匹配**：两边 `quote`/`原因文本` 归一化（NFKC、转小写、去掉所有空白）后：
   - 一方是另一方的子串，**或**
   - 字符二元组 Jaccard 相似度 `>= 0.5`（常量 `TEXT_MATCH_THRESHOLD`）。

匹配是**一对一贪心**：每条 gold 结论最多认领一条模型 finding；剩下的模型 finding
全部记 **false_positive**。gold 结论没被认领记 **miss**（即 false_negative）。
gold 里完全没有的 `record_id`，模型只要产出 finding，也全部记 false_positive。

> ★ 这是**词面匹配**，不是语义匹配。模型换个说法、但意思相同的，会被记为 miss；
> 这是刻意选择：第一版宁可比真实效果更保守，也不要让「读起来像」冒充命中。
> 要改规则，先改本文和工具里的常量，再用 `--self-test` 跑一遍。

---

## 4. 指标公式

设 `H = hit`、`M = miss`、`FP = false_positive`：

| 指标 | 公式 | 说明 |
|---|---|---|
| accuracy | `H / (H + M + FP)` | 把漏报和多报都算错 |
| recall | `H / (H + M)` | gold 结论被找回的比例 |
| precision | `H / (H + FP)` | 模型 finding 中命中的比例 |
| classification_consistency | 至少有一条 finding 类型匹配的记录数 / 有 gold 的记录数 | 只看「类型对不对」，不看文本 |

分母为 0 时输出 `null`，**不写 0**。`hit / miss / false_positive` 同时按记录输出。

---

## 5. 三态退出码

| 退出码 | 含义 |
|---:|---|
| `0` | 评测完成（指标好坏不影响退出码） |
| `1` | 输入存在但不可用：JSON 坏、缺必填字段、sha256 不是 64 位、写盘失败 |
| `2` | **未测**：缺 `--gold` 或 `--pred` 文件（真实模型未接入时不伪造读数） |

`--pred` 缺失 → **rc=2**，输出「未测不是通过」，不会给出 0 条/100% 的假读数。

## 6. 用法

```bash
# 自证：只用合成样本，不依赖真实模型
python3 tools/eval_review_gold.py --self-test
# 当前读数：14/14，rc=0

# 真实评测
python3 tools/eval_review_gold.py \
  --gold ~/audit-data/gold/pilot/gold.json \
  --pred /path/to/model_findings.json \
  --out /tmp/review-gold-eval.json
```

没有 `--pred` 时：

```bash
python3 tools/eval_review_gold.py --gold ~/audit-data/gold/pilot/gold.json
# 未测：缺 --pred（真实模型未接入）；未测不是通过
# rc=2
```

## 7. 红线与边界

- **gold / 图片 / 逐字稿不进公开仓。** 放 `~/audit-data/gold/pilot/`，目录 `0700`；
  本仓库是公开的，真人审核原因和客户素材可能含个人信息。
- gold **不得由模型生成**；必须人工确认（与 0e 标注指南同一条规矩）。
- 工具的 `--self-test` 只用合成数据，**不证明**真实模型效果。
- `分类` 必须与模型 `control_code`/`category` 同口径；口径不同时类型匹配会全灭，
  读数会直接暴露，不会静默变成「模型很差」。
- 第一版词面匹配对同义改写不友好；这是已知边界，不用它下「模型可用/不可用」的结论。
