## 与 SOP 的两处刻意偏差（记为什么）

1. **`NMEM_AGENT_ID` 不注入**（SOP §6.1 要求注两个变量）。
   全仓 grep：唯一 nmem 环境读取点是 `tools/agent/nmem_recall.mjs:31` 的
   `NMEM_SPACE`，没有任何一行读 `NMEM_AGENT_ID` —— 写了就是 §2.4 的
   「常量定义了没人用」。本 CLI 的身份选择走 `--agent-context` 机制，与 SOP
   设想的环境变量是两套。已注入的只有 `NMEM_SPACE`（`settings.local.json`）。
2. **不设蒸馏自动 watcher**（SOP §四 允许脚本化，未强制自动化）。
   触发时机已显式写进 `tools/mem/distill_to_nmem.py` 头注释：
   L1/L2 真源实质变更后、每票收尾时手跑。蒸馏要判断力，watcher 只会灌低质条目。

## 超出 SOP 基线的部分（本仓自有，SOP 没有的）

| 项 | 是什么 |
|---|---|
| 来源分流契约 | 四层映射只对蒸馏语料成立；抽取类 / 其他 agent 写入的各走各的尺子（`verify_nmem.py` `_classify()`）—— 2026-10-28 实测另一会话写 6 条 `source=agent`，不分流会全部误报红 |
| 15 项反向对照 | `--controls` 喂坏样本必红、好样本必闭嘴（SOP 无反向对照概念） |
| source_pointer 逐条可解析 | 每条记忆的「依据：」尾注必须解析到仓内已跟踪文件的字面量锚点（SOP 只要求内容，不要求可复核） |
| 退码三态 | nmem 不可达退 2（未测），与通过 0 / 红 1 区分 |
| 图谱事件史 | 10-27「不适用」裁定 → 当晚作废 → 9/9 播种，全程留痕于裁定文件 |
