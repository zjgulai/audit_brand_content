## 3. 现状实测：三条硬结论

### 3.1 规则表是「文档」，不是「可执行规则库」

```
判断方式：21/21 全部填「自动可检测」
正则表达式：12/21 有   豁免词：7/21 有
```

**用规则自带的正则去匹配它自己声明的关键词：**

| 规则 | 关键词 | 被自己的正则覆盖 |
|---|---:|---:|
| H05 | 33 | **0** |
| H08 | 11 | **0** |
| H07 | 46 | **3** |
| M01 | 8 | 3（且正则命中自己的豁免词 `silent mode`） |

H07 是现网命中最多的一条规则（51 次），它的正则层 46 个关键词只看得见 3 个。

**「自动可检测」这五个字，当前是声明，不是事实。**

### 3.2 ★ 现网 291 条里藏着一张现成的多语种词表

这是本次复盘最重要的发现。

从 `命中片段` 字段解析（240 条命中、去重后 **60 个不同片段**）：

| | 数量 |
|---|---:|
| 现网真实出现过的不同片段 | **60** |
| 其中**规则表从未写过**的 | **35（58%）** |
| 规则表声明但现网**从未出现**的 | **395（94%）** |

规则表声明了 **424 个关键词**，但现网真正在触发判定的，是另外 **60 个片段** —— 而且
**58% 是规则表里没有的**（`cicha` 波兰语、`krankenhaus` 德语、`qualité hospitalière` 法语、
`sans douleur`、`schmerzfrei`、`sin dolor`、`más leche`、`plus de lait`、`leakage`…）。

> **这意味着**：「措辞表达库」不需要从零向各品线索要。
> 它已经以**真实命中 + 人工判定 + 多语种覆盖**的形态存在于 291 条记录里，
> 只是没有被提取成结构化词表。

## 6. 下一步应该怎么做

### 6.1 核心判断：把「数据资产」变成「可执行规则」

我们现在的处境是：**有最好的原材料（291 条真人判定），却没有生产线。**

```
现在：  291 条记录（人看过、人判过） → 停在表格里
应该：  291 条记录 → 提取真实词表 → 回填规则库 → 生成可执行规则 → Agent 判定 → 比对人工判定
```

这条链路走通一次，就能回答会议最关心的问题：**Agent 能不能复现人工判定的 90%？**

### 6.2 建议的三阶段路径

**阶段一（1–2 周）：证据闭环，不碰生成**

- 修复 §4 的 6 个数据问题（P1–P6）
- 从 291 条提取真实词表（60 片段 + 35 个规则表没有的）
- 用规则表自带的 424 关键词 + 提取的 60 片段，跑一次**离线复现**
- 产出：**「现有规则能复现多少人工判定」的准确数字**

> 这一步不产生新能力，但产生**唯一能证明方向对不对的数字**。
> 昨天的审计说「只能复现 13.8%」——那个数字是用规则自带正则算的，
> 换成提取出的真实词表后会是多少，**没人知道**。这正是要测的。

**阶段二（2–4 周）：最小可跑审查 Agent**

- 守衡接上内容审查工具（只读 → 输出分流建议）
- 跑通「送审 → Agent 判定 → 人工复核 → 留痕」的完整闭环
- 一开始只做**文字**，图片/视频后置

**阶段三（1–2 月）：接入真实业务流**

- 飞书多维表格成为审核工作台
- 错题本机制与规则迭代管道接通
- 度量上线（精确率/召回率/人机一致率）
