## 三、要你修的东西（按优先级，别跳）

每一项都在审计报告里有 `文件:行号`，这里只给要点。

### P0-a · 主模型 failover（先做这个）

**现状**：`llm.mjs:208` 只读 `config.llm.model` 一个值，`config.mjs:133-150` 没有候选列表。

**要做的**：加一条跨模型回退链。环境里已经有 `VOD_API_KEY`，
`config.mjs:113-118` 已经有一套「有 VOD key 就切 `gemini-3.1-flash-lite`」的现成分支，复用它。

**注意**：
- 402 / 401 / 403 是**不可重试**的（`llm.mjs:19` 的 `RETRYABLE_STATUS` 不含它们）——
  failover 要接在**不可重试**分支上，不是接在重试循环里。
- 现有 `attempts` 结构要保留（`llm.mjs:216-262`），失败体 `{ok:false, error, layer, chain, attempts, retryable}`
  被 `ws_daemon.mjs:194-201` 和 `retry_queue.mjs` 消费者，**改字段会连带改坏补发队列**。

### P0-b · `runtimeContext` 跨会话串台

**现状**：`tools.mjs:39` 是模块级单例，`agent.mjs:327` 在锁内 `Object.assign` 覆盖，
`tools.mjs` 里 **18 处**读它。实测同时最多 3 个会话在处理。

**后果的准确边界**（别说大）：回复**不会**发错群（`chatId` 是局部变量）。
出错的是**工具侧读到的上下文**，尤其是 `judge_copy` 回执上的 `--message-id`（`tools.mjs:730-732`）。
而 ADR-0005 说「没有 receipt 的判定不算发生过」—— **指向错误消息的回执比没有回执更糟。**

**要做的**：改成显式传参 `executeTool(name, args, ctx)`，删掉模块级单例。

**注意**：`judge_evidence.mjs` 也可能读它，改之前先 grep 全仓 `runtimeContext`。

### P0-c · 飞书调用无超时

**现状**：`feishu.mjs:20-31` 构造 `Lark.Client` 时**未传 `httpInstance`**，
走 SDK 的 `axios` 默认 `timeout: 0`。附件下载、`getUserName`、`getChatInfo`、
`getMessage`、**全部发送函数**都无超时。

**要做的**：传一个带 timeout 的 http 实例。约半天。

**验收标准**：不能只看「改了没报错」，要造一个能证明超时真的触发的读数。

### P1 · 知识库三处（改完 P0 再动）

1. **图片/视频完全不查知识库**：`agent.mjs:464-469` 提前给 `reply` 赋值，
   而工具循环条件是 `reply === null` → 循环一次不进 → 一次检索都不发。
2. **只传 URL / 文档链接时检索拿到空串**：`tools.mjs:709` 的 `body` 是空串，
   `:746` 传给 `gatherEvidence(body, ...)` 的**也是空串**，不是 python 侧抓到的正文。
3. **`200 + HTML` 被读成「库里没有」**（这条最危险）：`kb_client.mjs:383-390}` 对
   ngrok 过期页返回 `{_raw}` 而不抛错 → `hits=[]` → `judge_evidence.mjs:494` 判 `status:'none'`
   → **授权模型说「知识库里查不到」**。这是假阴性。

### P1 · `run_readonly_command` 的 15 秒超时形同虚设

**实测有一条跑了 975 秒**（日志 `[+166020.064s]`）。
根因：Node `execFile` 的 timeout 只杀**直接子进程**，杀不掉抱着 stdout 的孙进程；
`promisify(execFile)` 等管道关闭，promise 永不 resolve。

**要做的**：`{detached:true}` + 进程组 kill（`process.kill(-pid)`），或改用不带 shell 的实现。

### P2 · 提示词与代码不一致（5 处）

最硬的一条：`persona.mjs:86-87` 说图片/音视频解析「**这条链路还没接上**」，
而代码已接、今天还审了三张图。模型会照着说「我读不了图片」。

其余四处见审计报告 §5.4。

**这条是硬约束。绿着往下走等于把「改坏了」留给下一个人发现。**

| 你动了什么 | 必须跑 |
|---|---|
| 判定引擎 | `python3 tools/verify_engine_contract.py` |

**三态不可互代**：

```
未测 (exit 2)  ≠  通过 (exit 0)  ≠  红 (exit 1)
```

`exit 2` 不是绿。**未测的文案里不许写「没问题」。**
「有红」时也必须同时报出「有未测」——否则只看最后一行的人会以为其余都验过了。

> 一个真实教训：`prd_baseline.mjs` 第一次运行打印了「✅ 16 项全过（含 L3：上游与指纹一致）」，
> 而那一轮是 `--offline`，**一次网络都没发**。

## 五、这家仓库的规矩（违反会被回滚，不是建议）

### 5.1 并行会话共用工作区

- **绝不 `git add -A`**。提交前逐项归属，只 add 你确认是自己产出的具体路径。
- 动共享文件（`AGENTS.md`、`verifier-coverage.json`）前先看 `git status`。
- **`git reset HEAD~1` 会清空整个 index，包括别人暂存的文件。** 重做提交用 `git commit --amend`。

### 5.2 凭据文件一律不许读

```
~/.dsh/credentials  ~/.dsh/.credentials.yaml  ~/.ssh  ~/.aws  ~/.config/gh
按文件名拦：.env  id_rsa  .netrc  .git-credentials
```

执行点 `tools/agent/tools.mjs` 的 `secretGuard()`。**不要为了调试去 cat 任何凭据。**

### 5.3 重启守衡必须走闸门，闸门默认拒绝

```bash
bash tools/restart_shouheng.sh                     # 只报告影响面，退 3（拒绝）
bash tools/restart_shouheng.sh --check             # 同上，退 0（纯查看）
bash tools/restart_shouheng.sh --yes --why="<理由>" # 真重启，必须留痕
```

**不要用 `kill -TERM`** —— 它的 `shutdown()` 是 `process.exit(0)`，
launchd 按 `KeepAlive{SuccessfulExit:false}` 认定「正常停机」，**永不拉起**，
而日志看起来一切正常。

**重启前必须先问委托方。** 重启窗口里群里发的消息不会被回答，而且不会有任何东西记下来。

### 5.4 数字必须跑出来，不许写进去

凡是文档里出现的数字，要么带复现命令，要么标明是某时某刻的读数。
**复现不出来的数字不许写进文档。**

### 5.5 写盘纪律

生成物写完必须做**字节级校验**（环境 +4096 填充会让 `read` 工具打不开文件）。用一个能验证的读数：

```bash
python3 -c "
import os
p='<你的文件>'
print('stat',os.stat(p).st_size,'真实',len(open(p,'rb').read()))"
```

两个数相等才算写完。

## 七、你最容易踩的五个坑

1. **把 402 当成自己改坏了。** 端到端跑不通先看 `PMO/logs/llm_failures.jsonl`。
2. **以为消息是串行处理的。** 不是。SDK 是 `ws.on('message', async ...)`，EventEmitter 不 await，
   多会话**真并发**（实测最多 3 个）。只有同一 `sessionKey` 内才是串行的。
3. **以为 `verify_cards.mjs` 绿了就说明提示词没超长。** 它量的是无 `extra` 的形态（7950），
   真实群聊路径 8014，**已越线 14 字符**，断言看不到。
4. **改了 `code` 但没改 `mtime` 就重跑自证。** 本机 `sys.pycache_prefix` 指向
   `~/Library/Caches/com.apple.python`，**不在仓库里**。判据是「源码有、pyc 有没有」，
   不是比 `(mtime, size)`。改完被 import 的 `.py` 后如果结果和源码对不上，先清缓存：
   ```bash
   rm -rf ~/Library/Caches/com.apple.python/Users/lute/Project/audit_multi_content
   ```
5. **在 macOS 上写 `timeout 5 cmd`。** 没有这个命令，`rc=127`、输出为空 ——
   **和「扫完了没命中」长得一模一样**，用它得出的否定结论是假的。

## 八、明确定义「做完了」

| 级别 | 判据 |
|---|---|
| 单条修完 | 该子系统的 `verify_*` 绿；**并且**你能指出哪一行代码在拦它（不是「名字出现过」） |
| 一组修完 | 反向对照：喂一个已知坏样本，检查器**必须红**；喂好样本**必须绿** |
| 交付 | 自证读数 + 改动行号 + 未测项清单，三项齐全 |

**「改完了」不等于「验过了」。** 一个只查标识符是否出现的断言，在有 import / re-export 的地方恒真 ——
本项目踩过：`MAX_SECTIONS` 常量定义了，J1 断言也是绿的，但全仓没有一行拿它做比较。

```
事实 > 可复核 > 边界诚实 > 覆盖完整 > 速度 > 好看
```

说不清的明说「未测」，**不许空着，也不许当成 0 或当成通过**。

如果你觉得审计报告里有哪条判断错了 —— **先把读数跑出来再反驳**，
不要用「我觉得」推翻一个带 `文件:行号` 的结论。
反过来，如果你跑出的读数和我写的不一致，以**你的读数**为准，并在报告里更正我。
