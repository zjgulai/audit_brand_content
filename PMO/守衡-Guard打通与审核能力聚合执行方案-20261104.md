## 二、当前内容审核能力深度梳理与聚合矩阵

### 2.1 四维入口契约与五步固定编排（`base/contract.py` · `base/orchestrator.py`）

1. **入口四维正交模型（`base/submission_router.py`）**：
   - `content_type`：`文本` · `图片` · `视频` · `文档` · `结构化记录`
   - `content_stage`：`brief`（提纲/初稿） · `final_content`（成稿）—— 群内缺失时由 `apply_stage_inference()` 在算幂等哈希前推断并随案留痕 `intent_inference`
   - `entry_channel`：`群消息` · `飞书文档链接` · `落地页 URL` · `多维表批量` · `上传文件`（`NAS` 显式 `rejected_unsupported`）
   - `source.kind`：`free_text` · `ad_text` · `structured_json` · `landing_page` · `image` · `video`（`文档` 显式 `rejected_unsupported`）
2. **五步固定编排流水线（`base/orchestrator.py`）**：
   - 固定顺序：`normalize → judge → dispose → output → evaluate`（每步恰好一次，无回边、不跳步，`receipt.skipped` 恒为 `[]`）。
   - 双指纹锁定（`ContentUnit`）：`raw_sha256`（原件字节指纹）+ `text_sha256`（`text-v1` 归一化后正文指纹）。
3. **规则、控制点与双层依据基座**（复现命令：`python3 -c 'import json; cp=json.load(open("research/governance/control-points-v1.json")); r=json.load(open("research/governance/skeleton/rules-v1.json")); print(len(cp["control_points"]), sum(1 for x in cp["control_points"] if x["status"]=="active"), len(r["rules"]), sum(1 for x in r["rules"] if x.get("enabled",True)))'`）：
   - **控制点主表（`control-points-v1.json`）**：共 24 个控制点，其中 **19 个 `active`**。
   - **字面规则库（`rules-v1.json`）**：共 36 条规则，其中 **25 条 `enabled`**（`RuleJudge` 产出 `P0` 级精确 `start/end/quote` 命中，支持 `require_context` 与 `exclude_patterns` 语境守卫）。
   - **外部标准库（`external-standards-v1.json`）**：**62 条**外部法源引文（由 `ExternalStandardsAuthority` 注入 `judge_unit`；研究稿状态原样保留于 `ratification`）。
   - **远端治理知识库（`tools/agent/judge_evidence.mjs`）**：按引擎命中的关键表述检索 `docId` / `requestId`，严格区分 `found / none / probe_empty / partial / untested / disabled` 六档状态。
4. **五标签与五层处置（`base/decision_table.py`）**：
   - 五标签：`BLOCK`（违规拦截） · `REVIEW`（待人工复核） · `PASS`（未见拦截理由） · `待自决` · `未审查`。
   - 处置层：`DP0`（未入审） · `DP1`（退回提交人） · `DP2`（机器拦截） · `DP3`（人工复核） · `DP4`（法务终审）。
   - 权责边界（ADR-0005）：所有机器判定产出的 `release_status` 恒为 `"待放行"`，禁止输出「已通过 / 无需处理 / 审批完成」等回执禁词（由 `base/send_gateway.py` 强制拦截）。

### 2.2 多载体聚合审核映射表（`base/feishu_guard_ingest.py`）

| 群内输入类型 | 飞书事件与识别规则 | 映射四维 (`content_type` / `entry_channel` / `source.kind`) | 提取与审核链路 | 覆盖边界 (`covers` / `does_not_cover`) |
|---|---|---|---|---|
| **纯文本 / 富文本** | `message_type=text` 或 `post` | `文本` / `群消息` / `free_text`（或 `ad_text`） | `text-v1` 归一化 → 阶段推断 → `SubmissionIngestor` + `ReviewCommandService` → 知识库 `evidence_chain` | 覆盖提交文本；不含未附带的图片/视频 |
| **结构化商品 JSON** | JSON 含 `title` / `description_text` | `结构化记录` / `群消息` / `structured_json` | `fields-pipe-v1`（` \| ` 跨字段屏障）拼装 → 生产判定 + 建案 | 覆盖商品标题与描述文本 |
| **飞书云文档链接** | 文本含 `feishu.cn/(docx\|wiki)/<token>` | `文档` / `飞书文档链接` / `free_text` (`doc_type=docx`) | 调飞书开放接口拉取文档 `raw_content` → 生产判定 + 建案（并触发 `baselineWatch`） | 覆盖文档纯文本；文档内嵌图片需单走媒体审查 |
| **落地页 URL** | 文本含 `http(s)://` 外部商品/落地页链接 | `文本` / `落地页 URL` / ` free_text`（带 `landing_page` 提取摘要） | 抓取 HTML 并经 `lp_extract` 提取正文与 6 类营销声明 → 生产判定 + 建案 | 覆盖页面提取文本；页内位图需单走图片审查 |
| **图片消息** | `message_type=image` | `图片` / `群消息` / `image` | 下载至 `~/.shouheng/attachments`（`0700`）→ OCR（图内文字）+ `media_analyze`（`scene_semantics` + `mark_symbol`）+ `candidates_from_observations` → 生产判定 + 建案 → 删临时文件并记生命周期台账 | 覆盖图内 OCR 文字与 L1 多模态观察（未配多模态网关时显式报 `untested`） |
| **视频消息** | `message_type=media` | `视频` / `群消息` / `video` | 下载至 `~/.shouheng/attachments`（`0700`）→ `multimodal-direct-v1`（`scene_semantics` + `mark_symbol` + `av_alignment`）→ `parse_status=partial` 生产判定 + 建案 → 删临时文件 | 显式声明 `does_not_cover`：口播文案（无本地 ASR）、逐帧 OCR；`partial` 永不 `PASS` |
| **文件附件** | `message_type=file` | 文本扩展名转 `free_text`；二进制 Office 文档显式拒收 | 文本类（`txt/md/csv/json`）UTF-8 读入（NUL 检测）送审建案；二进制未接解析类记 `Attempt` 并回 `cannot-read` 卡 | 二进制文档明说「内容解析未接上」，提供转云文档替代路径 |

## 三、飞书长连接事件回调与建案全链路设计

1. **长连接层（`tools/ws_daemon.mjs`）**：
   - 使用 `@larksuiteoapi/node-sdk` 的 `Lark.WSClient` 建立 WebSocket 长连接，监听 `im.message.receive_v1`、`im.chat.member.bot.added_v1`、`im.chat.member.bot.deleted_v1`、`card.action.trigger`。
   - 入站先写 `PMO/logs/ws_events.jsonl` 原始事件台账，经 `alreadyHandled(message_id)` 去重、`withLock(sessionKey)` 会话串行化，再进推理内核 `handleMessage`。
2. **工具与附件入站层（`tools/agent/agent.mjs` · `feishu.mjs` · `tools.mjs` · `image_judgment.mjs`）**：
   - **文本/链接/云文档**：通过升级后的 `judge_copy` 工具，既产出兼容 `judge_evidence.mjs` 的 `hits` 与 `evidence_chain`，又调起 `base/feishu_guard_ingest.py` 完成生产五标签判定与工作台建案（返回 `case_id`、`production_judgment`）。
   - **图片/视频附件**：`ingestAttachment` 下载到仓外 `~/.shouheng/attachments` 后，调 `base/feishu_guard_ingest.py`（在 `REVIEW_MEDIA_INGEST=1` 与受控 `media_roots` 下完成图片/视频生产进件与建案），随后立即清理临时目录并写入 `attachment_lifecycle.jsonl`。
3. **工作台账本同源与并行隔离（`base/feishu_guard_ingest.py`）**：
   - 账本根目录由环境变量 `SHOUHENG_WORKBENCH_DATA_ROOT`（或 `REVIEW_AUTHORITY_ROOT`）指定，默认落在仓外 `~/.shouheng/workbench-data`（权限 `0700`），绝不落入公开仓。
   - 每次群内送审以发送者 `senderOpenId`（或回落 `feishu:guard`）在租户下构造合法提交主体，通过 `WriterLease` 单写锁执行 `ReviewCommandService.execute_submission()` + `Projector.catch_up()`，确保权威事件流与 SQLite 投影实时一致。
4. **形态决策与卡片输出层（`tools/ws_daemon.mjs :: replyTo` · `tools/reply-cards/`）**：
   - 唯一形态决策在 `replyTo` 执行，模型通过 `[[card:evidence]]` / `[[card:query-answer]]` 输出结构化卡片，展示：`case_id`、五标签结论、处置层（`DP0–DP4`）、命中控制点与原文切片、外部法源与知识库 `docId/requestId`（折叠区）、品线/阶段推断说明及覆盖边界。
