## 一 · 为什么是「蓝本」不是「底座」

这一节的每一条都是**实测**，不是判断。六条里有三条是**它自己写的**。

| # | 实测 | 复现 | 对我们意味着什么 |
|---|---|---|---|
| **1** | **没有飞书连接器。** `grep -rn "feishu\|lark" --include=*.rs --include=*.sql crates/ migrations/` → **0 命中**；命中的全是文档，且都写 not started（`0013:3` *Feishu and Confluence not started*；`README.md:114` 路线图） | 报告 §1.5 | 我们的全部知识源都在飞书。第一步就得自己写连接器 |
| **2** | **它没有任何对外产生副作用的能力。** `0034`「an action is a declared call」状态行逐字 *cut 1 · this record. **No code yet***；`grep -rn "CREATE TABLE actions\|action_runs\|action_grants" migrations/` → **0**；告警只到浏览器 SSE | 报告 §4.5 | PRD §8.1「REVIEW → 转对应团队」在它那侧没有落点，集成只能是拉模式 |
| **3** | **抽取既不读本体也不读先例**（`crates/utopia-extract/src/lib.rs:3-5`：*不读本体、不算日期*）。人的理由只拼进消歧裁决器的提示词，`docs/design/governance.md:130` 自认 *nothing computes it*；`resolution_reviews.rationale` **生产代码从不读** | 报告 §5.2 | PRD §9「人工复核结论回流，更新规则权重和正负样本」——**这是被设计排除的，不是没做** |
| **4** | **「每个队列都被治理」是 ADR 不是代码。** `0043` 状态行逐字 *no code on `dev` … PR #699 … **closed on 2026-09-17***；`migrations/0035:20` 的 `target_kind` CHECK 仍只允许 `'review'` | 报告 §5.3 | 12 个队列里只有重复对有 agent，其余纯人工 |
| **5** | **取回检索结果时不带出处。** `ChunkView`（`models.rs:436-442`）只有 `id/document_id/seq/text/filename` —— **没有 `origin`/`anchor`**。`docs/design/chat-and-mcp.md:23-25` 说的「MCP 结果带证据出处」**只对 `changes` 成立** | 报告 §2.4 | 走检索的调用方分不清引的是原文、OCR 还是模型转述 —— 而 ADR-0040 的立论正是「这四种不是同等证据」 |
| **6** | **没有 `chunk → 条款原文` 的一跳。** `chat-and-mcp.md:72` 的 not-built 明写 *The read-contract gaps: conflict and review state, **chunk identity behind a quote***；它不认识「第 12 条第 3 款」，只有 `seq` 与字符偏移 | 报告 §2.4 / §8(d) | **条款编号必须在外面对齐** —— 而这正是我们 A1 公理要的东西 |

> ★ **最有力的一条是它自己写的。** `docs/decisions/0046-*.md:37-40`：
>
> > *"**The layer an app would read is in motion.** Extraction writes only the open graph (#736), and typed facts come from alignment, whose cuts are landing as this is written (#751, #752, #753, #754). **The first applications would be written against a model being replaced underneath them, and the cost of that lands on whoever wrote them.**"*

### 2.3 明确没有、而恰好是我们最需要的三条

| 我们 PRD 要的 | Utopia 的现状 | 证据 |
|---|---|---|
| **一票否决**（「不得 / 必须 / 至多一个」） | **没有否定、没有义务、没有基数限制**（`owl:maxCardinality` 零实现）。只有 `functional` / `disjointWith` / `irreflexive` / `asymmetric` 四种**事后**违规检查，规则只能推 `typing\|attribute\|computed`，**永远不能推「违规」** | 报告 §5.2 |
| **封闭世界缺省** | `0029` 明文：*The base is open-world. A missing reading means nobody wrote it down, not that the value is false.* 而法规判定常需「没有许可证 ⇒ 不得经营」 | 报告 §11 |
| **条款级结构与依据链** | **没有章-节-条-款模型，没有稳定条款 id**。证明树的前提是 `facts`，**不是「《XX 办法》第 12 条」**；`0070` 还主动禁止跨库引用 | 报告 §11 |

**第三条是决定性的**：我们 A1 公理（每条判定都能指回一条人类可读的依据）要的正是它，而 Utopia 不覆盖。
**而第一条同样要命**：我们 26 条规则里 **11 条是 `prohibit`**（`modality` 分布：prohibit 11 / review 14 / permit 1，`python3 tools/verify_kb.py`）。

## 三 · 本仓已独立收敛的七个不变量（互为印证，不重复建设）

本次剖析最反直觉的结论：**本仓在没看过 Utopia 的情况下，独立到达了它大约一半的设计不变量。**
所以这不是「引进一套外来架构」，是**「补上我们自己也认的那套架构里缺的三块」**。

| 我们的既有物 | Utopia 的对应物 | 两边说的是同一句话 |
|---|---|---|
| ADR-0002「知识单元必须记录级溯源 + 内容指纹」 | `fact_evidence` + `recorded_at` | 证据要落到记录级 |
| ADR-0005「Agent 只补证据，不替人过门」 | `0015` *a nod belongs to the person who said it* | 机器不得替人终结 |
| ADR-0008 / 0009「机制分离，白名单与语境守卫各自独立成表」 | 「派生事实住自己的表」；`0015` 「待定事实住自己的表」 | **一条状态列会往错的方向失败**（漏一个 `AND` 就泄漏），独立成表则失败方向是「隐形」 |
| `disposition-layers` 的 `can_finalize` + **机器的终结权是单向的** | 影响闸门 `execution_gate.rs`（*keeps are not gated*） | 机器可以拦、不可以放 |
| `evaluability: auto / auto_then_manual / manual_only`（12 / 9 / 5） | 自动 / 影响闸门 / 只在人 | 三级分流 |
| `evidence_required`（V21a「所需材料」） | 举证责任 | 结论要声明它需要什么证据 |
| `detection_layer: native / codified / added`（19 / 3 / 4） | `extraction_drops` 的留痕纪律 | 词表来源必须可审计 |
| `qualifier_axes`（修饰性极端词不占主题节点） | `relation_type_qualifiers`（`0037`：*a qualifier is not part of the edge's identity*） | 修饰词不是边的一部分 |
| ADR-0012「版本由制品内容指纹派生，不由人填写」「`source_text[start:end] == matched_text` 可断言」 | 「制品变了版本没变在结构上不可能」「引文必须在 chunk 里、偏移服务端算」 | 版本与引文都必须可复算 |

> **这张表的作用不是自夸，是一条排期判据**：凡是这张表里的东西，**本轮不重做**。
> 重复建设一个我们已经有的不变量，是这份方案最可能犯的错。

## 四 · 移植清单：三条（进验收，按依赖排）

三条的共同形态是**「把一条原来靠人记住的纪律，变成一条会红的断言」**。
每条都写四件事：**移植什么形状 → 落在哪个文件 → 判据（哪一行会红）→ 排期**。

### 移植-1 · C6 逐条缺口账（最便宜，先做）

| 项 | 内容 |
|---|---|
| **形状** | 每一次「知识没能落地」都要**留下一行**，而且带**原因码**。不是「没进库就算了」，是「没进库，因为 X，第 N 次」 |
| **落在哪** | 新增 `research/kb/缺口账-v1.jsonl`（只增不删），一行一个事件：`{库, 条目ID, 通道, 原因码, 首次出现, 次数, 最近一次}`。原因码先按我们自己的口径定，**照 `extraction_drops` 的形状**（枚举、不许自由字符串） |
| **它解决什么** | **G-11b**：62 条外部标准今天「一条判定也没支撑过」这件事，现在只能靠全仓 grep `EXT-0` 才发现。有了这本账，它会是 **62 行 `unused`** |
| **判据（哪一行会红）** | ① 恒等式：`Σ(各原因码计数) == 总行数`；② **每条外部标准条目要么有一条 `cited_by`，要么有一行 `unused`** —— 二者必有其一，缺一即红；③ 反向对照：塞一条不存在的条目 ID 必须红 |
| **排期** | W1（与 T2 同期，不占关键路径） |
| **状态** | ✅ **2026-09-23 落地**。`research/kb/缺口账-v1.jsonl` 62 行 + `tools/kb_gap_ledger.py`；判据 `T17a–T17d`（`python3 tools/verify_kb.py \| grep T17`），四条反向对照**各自点名**。★ 本方案 §四 预言「它会是 **62 行 unused**」—— T3 落地前实测**逐字吻合**；T3 落地后翻成 **48 cited_by / 14 unused**。<br>★★ 但 `cited_by` 只说明**规则层认账**，不说明判定用过它们（那是 `engine` 通道，仍未接线）—— 所以 `KB-GAP-11b` 那句话**今天仍然成立** |

> **为什么它排第一**：`AGENTS.md` §2.4 说「写进文档的每一个上限，必须能指出是哪一行代码在拦它」。
> 这三条里只有它能立刻兑现这句话，而且它**不依赖任何未完成的东西**。

### 移植-2 · C1 三层结构（本方案的主干）

| 项 | 内容 |
|---|---|
| **形状** | 把「四类知识库 = 四个并列的库」改成**一条链**：<br>**① 原文层**（上游条款原话 + 链接 + 指纹）→ **② 条款层**（可寻址的条目：库名 + 条文号 + 适用范围）→ **③ 规则层**（可执行的判定条件 + 它引的条款） |
| **落在哪** | 不新建目录。**`clause_no`（T2）是条款层的地址，`external_ref[]`（T3）是规则层指向条款层的边，`evidence_ref`（T4）是回执指向条款层的边** —— 三条本来就在既有方案里，本方案只是**给它们一个共同的名字与方向** |
| **它解决什么** | **G-11 / G-11c / G-12**：62 条没有条文号、26 条规则没有任何字段指向外部法规、规则键与《库名》第 N 条对不上。三面合起来是一句话：**双向都没有一条边** |
| **关键约束（照搬 Utopia 的教训）** | ★ **一个条目要有两套标识**：**身份**（`EXT-001`，稳定、不随改名变）与 **token**（`clause_no`，API 与引用用）。Utopia 的 `UNIQUE (kb_id, iri)` + `key` 就是这个分工，理由是**从标签派生的 key 会在改名时断，而 IRI 是名字不是地址**（`ontology.md:173`）<br>★ **绑定要能失效**：条款改了 → 引用它的规则标记 `stale`。Utopia 的做法是给决策存一份「**我考虑了什么的指纹**」（`0053`），输入变了才算 stale —— 这比时间戳准，因为时间戳看不见「父边被加了一条」 |
| **判据（哪一行会红）** | ① `clause_no` 唯一率 100%、无空值（T2 已有）；② **每条 `rule_key` 至少一条 `external_ref`，或显式写 `no_external_basis` + 理由**（空着不算，T3 已有）；③ **新增**：每条 `external_ref` 指向的 `clause_no` 必须存在，且**该条款被改动时 `external_ref` 要标记 stale** —— 这条今天**没有任何执行点**，是 C1 移植的实质工作量 |
| **排期** | W1–W2（T2 → T3 → T4 这条路径上加一环，**不加新路径**） |
| **状态** | ✅ **2026-09-23 落地**（W1 部分）。`tools/kb_clause.py` 是条款层词汇的唯一定义处；62 条各带 `clause_no`+`变更指纹`，24 条规则各带 `external_ref`（T2/T3 同批完成）；判据 `T18a–T18c`，**改条款正文一个字节必红**。<br>★ **指纹刻意不含 `条款位置`**（描述不是内容）—— 否则整理一次措辞会让 26 条规则全部变 stale，而一个天天响的信号会被学会忽略 |

> ⚠️ **C1 里唯一真正的「新东西」是第 ③ 条**：条款变更 → 引用失效。
> 其余两条（条文号、external_ref）T2/T3 已经在做。**别把这条写成「重建知识库」** —— 它是给已有字段之间补一条**失效判据**。

### 移植-3 · C2 溯源链与 origin 分级（跟 W3）

| 项 | 内容 |
|---|---|
| **形状** | 每一条证据都要声明**它是怎么来的**，四档：`stated`（原文照读）/ `ocr`（图片文字）/ `transcribed`（音视频转写）/ `described`（模型对画面的转述）。**这四种不是同等证据**，而且**第四种不能单独改结论** |

不写这一节，「不移植」就会变成「还没来得及做」。

| # | 不移植什么 | 为什么 | 什么条件下才重新考虑 |
|---|---|---|---|
| **N1** | **C3/C4/C5 双时态**（世界轴 / 记录轴 / 精度显式状态 / 单据式纠正） | 它**不是 PRD 要求的**。PRD §10 要的是「规则、知识库、模型版本绑定审查记录」，而**我们已经有**：`engine-manifest.json` 记四个判定制品的 `sha256`，`engine_version` 是它们的确定性折叠，回执里带 `rule_version` / `vocab_version` / `topic_tree_version`（ADR-0012 决定 3）。<br>代价侧却是我们最贵的一种：知识单元 schema 要重写一轮，62 条外部标准、26 条规则、回执三处全部跟着改，而到 W4 只剩 **28 天** | 出现一个**真的问得出口**的问题：「这条判定当时依据的是哪一版条款？」—— 而版本号答不了它。今天没有任何人问过 |
| **N2** | **C7 派生证明树 + 保险丝** | 我们的判定**不是从公理派生出来的**，是关键词 + 降级带 + 语境守卫。移植一个「证明树」等于给一个不存在的推理层配解释器。<br>保险丝（7 天两次撤回 → 关闸）同理：我们没有「agent 自动合并」这种动作，只有「机器单向拦截」——**而单向拦截错了的代价是少发一条广告，不需要保险丝** | 我们真的建起 P1/P2 语义层、且它有自动放行动作的那一天 |
| **N3** | **审核队列 + 先例 + 影响闸门** | ① 它的先例机制依赖「**只有人的决策算先例**」这个前提，而我们的「人的决策」今天**根本没有落点**（G-20：`检查人` 填充率 **0/291**；G-22：回流通道不存在）；**先给不存在的决策建队列，是给空库装引擎**。<br>② 它的影响闸门管的是「合并会不会把东西送出图外」，而**我们不做合并** | `检查人` / 复判字段填起来之后（T8），队列才有东西可排 |
| **N4** | **本体包冷启动**（schema.org 等五个包） | 它自己的实测结论是**反直觉的**：包给的是**类型**不是**谓词**。带 schema.org 时 98% 实体有类型，但 **81% 的事实仍然没有谓词**；空库最后长出 13 个类、175 个关系，**全是用语料自己的话**（`0008` §2026-09-10 修订）。而且**五个包里没有一个法律/合规向的**。<br>对我们的意义是**正向**的：**不要先建一个大的九大场景域本体** —— 让 §7.2 那九个域从真实语料里长出来，这正是 D4「四条通道各跑通 1 条真素材」的更深一层理由 | 出现「同一个概念在不同文档里被叫成两个名字」的真实冲突，且它挡了判定 |

## 六 · 本次顺带查出来的两个缺陷

两个都是**同一个病**：**「手动看一眼」改掉了「将来要发生的事」**（`AGENTS.md` §2.4.4 的形状，第三个与第四个实例）。

### 1 · `--check` 会吞掉一次告警（✅ 本轮已修）

**事故**（2026-09-23，本轮实测）：

| 北京时刻 | 事件 |
|---|---|
| 14:16:42 | 上游改 PRD，指纹 `a336500862…` → `8df44f86…` |
| 18:05:46 | 按文档跑 `node tools/agent/prd_baseline.mjs --check` —— **它不带 `dryRun`**，于是 `enter()` 算出的那句话被 `saveState` **记成「已说过」**（`saidDriftFp` = 新指纹），而 CLI 只 `console.log`，**一个字都没发出去** |
| 18:06:03 | 重拉基线、记新指纹、`verify_prd_baseline` 23/23 复绿 |

**两个对外后果方向相反、同时发生**：① 群里**永远收不到**那条告警（daemon 的发送条件是 `if (!r.say) return`，而下次它自己跑到同一漂移时 `enter()` 会回「同一个漂移指纹已经说过」，`say` 是 null）；② 状态里 `lastState` 停在 `drift`，等基线复绿后 daemon 会走「从红/未测恢复」那一支，发一句「✅ 上游基线检查恢复了」—— **一个从没收到过告警的群，凭空收到收尾**。这正是 §2.4.7 在 09-22 刚修过的形状从另一条路回来：CLI 不传 `chatId`，`alertChat` 记成 null，收尾只能退回 `resolveChat()` 去猜一个群。

**已落的三件事**：

1. CLI 那一支加 `dryRun: true`（`tools/agent/prd_baseline.mjs`）；
2. **一对新断言**（自证 78 → **80**）：行为级那条**真起一次子进程**、`SHOUHENG_STATE_DIR` 指向临时目录、断言那个状态文件**一字节未变**；
3. **反向对照**：把 `dryRun` 拿掉 → 79 号**红**、退 1，80 号仍绿 —— 证明它不是恒真。

**状态改正走的是真检查路径**（不是手改 JSON）：`lastState` drift→ok、`saidDriftFp` 清空、`lastCode` 1→0。
那句「✅ 上游基线检查恢复了」**刻意不发** —— 它的前提（有人看到过告警）不成立。
**不需要重启**：只动了 CLI 段，daemon 走的是 `checkNow` 本身。

**一处副作用要说清楚**：`PMO/守衡-内容推送与被at登记-20260915至0922.md:151` 的配方写着「`--check` → 退 1，`lastState: drift`」。现在 `--check` 不再写状态，那条**从「配方」降为「历史读数」**（它记的是 09-22 那天的事实，仍然成立）。要看状态请用 `--state`。

### 2 · `--pending` 是同一个病的另一半（**未修，待决**）

`runCheckPending` 只在**注入了 `--today=`** 时不落盘（那是 09-22 为「提前看一眼」加的），**不带 `--today=` 的裸 `--pending` 照样写状态**。而 `enterPending` 会写 `p_saidDueKey` / `p_saidBrokenDay` / `p_saidUntestedDay`，daemon 又正是用这几个键判「今天已经说过一次」→ `say: null` → **不发**。

**今天无害**（`python3 tools/verify_pending.py` 退 0，最近一个到期日 **2026-10-02**）。
**但 10-02 那天谁手动跑一次裸 `--pending`，那条到期提醒就永远不会到群里。**

修法与 `--check` **完全同形**（一处 `dryRun`），已登记进 `$decision_queue`（见 §八）。
