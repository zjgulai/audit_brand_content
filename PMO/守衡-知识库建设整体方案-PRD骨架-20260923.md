## 一 · PRD v1.2 的骨架（五层）

把 PRD 拆成「一次判定要经过的五个环节」，每一层有**独立的失败模式**，且**下层不能补救上层**。

| 层 | 环节 | PRD v1.2 出处 | 输入 → 输出 |
|---|---|---|---|
| **S1** | **判定对象** | §2.1 范围内 / §5.1 输入方式 / §5.2 审查能力 | 发布前完整内容 → 可判定的内容单元（文字 / 图片 / 视频，**带版本**） |
| **S2** | **判定依据** | **§7 知识库与规则体系**（7.1 四类 / 7.2 九域 / 7.3 一票否决） | 原始资料 → **可寻址的条款** → **可执行的规则** |
| **S3** | **判定机制** | **§6 规则优先级与分层审查机制**（6.1–6.6） | 内容 + 规则 → 分层命中 |
| **S4** | **判定输出** | §5.3 三态结论 / §5.4 结构化 JSON / §8.3 报告链接 | 命中 → 三态结论 + 维度 + 位置 + 原因 + **依据链接** |
| **S5** | **判定之后** | §9 人工复核与 sign-off / §10 记录与统计 / §11 准确性要求与评估 | 结论 → 人工复核 → **回流** → 准确率读数 |

**为什么是这五层而不是按 PRD 的章节顺序**：PRD 的章节顺序是**写作顺序**（背景→范围→角色→流程→功能…），不是**依赖顺序**。
按依赖切的好处是每一层都能独立说「我今天能不能跑通」—— 这正是 D4 定的交付口径（四条通道各支撑 1 条真素材）需要的坐标系。

**本方案覆盖 PRD 的哪些章**：§2.1、§5.1–5.4、§6、§7、§8.3、§9、§10、§11、§14、§15。
**不覆盖**：§3 角色（组织问题）、§12 非功能需求（性能/并发，属工程实现）、§13 权限与安全、§16 风险。

## 三 · S2 展开：四类知识库 × 九大场景域（本方案的主干）

### 3.1 一条链，不是四个库

**GAP 分析 §4.1 推论三已经判过：四类知识库不是「四个库」，是四条可寻址的证据通道。**
本方案按 U4 的 C1 把它写成**一条链上的三段**：

```
① 原文层  ──►  ② 条款层  ──►  ③ 规则层
（上游原话+链接+指纹）  （库名+条文号+适用范围）   （判定条件 + 它引的条款）
        ▲                                              │
        └────────────  ④ 证据回链（回执 → 条款 → 原文） ◄┘
```

**为什么这个形状是对的**：PRD §5.3 的三个示例，**每一个都以「依据《文档名》第 X 条」结尾**。
一个存了 62 条外部标准、但**没有条文号**的库，对这条要求的贡献是 **0** —— 不是「少一点」，是**一条判定都支撑不了**。

> ★ 2026-09-23 补：条文号（T2）与引用边（T3）已补上，规则层现在指得到其中 48 条。
> **但上面这句话仍然成立** —— 「指得到」不是「判定用过」。见 §五 T17 的边界声明。

### 3.3 九大场景域（PRD §7.2）：**不先建本体，让它从语料里长出来**

PRD §7.2 列了九个域（车内场景 / 功效宣称与广告用语 / 喂养场景 / 人物肖像与 AI / 睡眠场景 / 洗护与沐浴 / 出行与户外 / 居家与用电 / 玩具与玩乐），每个带风险等级、审核优先级、主要规则归属。

**本方案不把它当「先写一本词典」的任务** —— 依据是蓝本的一条实测（`PMO/守衡-Utopia结合方案-20260923.md` §五 N4）：
**先建一个大的本体，给的是「类型」不是「谓词」。** 实测读数：带 schema.org 时 98% 实体有类型，但 **81% 的事实仍然没有谓词**；而空库最后长出 13 个类、175 个关系，**全是用语料自己的话**。

**所以九域的建法是**：

| 步骤 | 做什么 | 判据 |
|---|---|---|
| 1 | 先把九个域的名字与 §7.2 的优先级**登记成一张空表**（只登记，不填内容） | 九个域都有行；**空的显式写空**，不许写「进行中」 |
| 2 | 每跑通一条真素材（T15），把落到的域**加一个计数** | 计数是算出来的，不是填的 |
| 3 | 某个说法在**两份以上真实素材**里出现过，才成为「域内候选规则」 | 单份素材不产生候选（照搬 `MIN_DOCS = 2` 的教训：一份文档里的一个动词曾被误采纳） |

### 3.4 一票否决（PRD §7.3）

PRD §7.3 列了七类 P0 命中即 BLOCK 的项（车内未用安全座椅 / 医疗功效宣称 / 绝对化用语 / 无依据销量排名 / 危险行为示范 / 未成年人未授权出镜 / AI 深度合成未标识）。

**本方案对它的立场（一句话）**：**这一层我们今天只能覆盖一部分，而覆盖率是一个必须被算出来的数，不是一个可以被声明的判断题。**

- 我们已有的落点：`disposition: auto_reject` 的规则 **11** 条（`python3` 读 `rules-v1.json` 的 `modality`/`disposition` 分布）。
- **没有落点的部分要显式写「未覆盖」** —— 这正是既有的 `CATCH-ALL-01` 兜底通道在做的事，它的 `reason` 逐字写着：
  > *「未命中 ≠ 合规。不拆 `未覆盖` 与 `合规`，盲区率在数学上不可观测。」*
- **蓝本在这里帮不上忙**：Utopia **没有否定、没有义务、没有基数限制**，规则永远不能推「违规」（见结合方案 §2.3）。**这一层只能自建。**
