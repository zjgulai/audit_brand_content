## 十三 · ★ 真 bug：**落在冷却窗口里的一次重启，会把那次检查推迟到换日**（最多约 24 小时）

### 13.1 怎么发现的

§10.9 我预测「17:29:32 前后基线检查会自己跑一次」。**到 17:34 没跑。**
不是没到点 —— 是**没有任何东西会在到点后触发它**。

### 13.2 判据（三条触发路径，逐条排除）

`baselineWatch()` 在全仓只有**三个**调用点（`grep -n "baselineWatch(" tools/ws_daemon.mjs`）：

| 行 | 触发条件 | 这次会不会响 |

| `136` | `LARK_DOC_RE.test(preview)` —— 群里收到飞书文档链接 | ❌ 她没有发新链接 |
| `604` | 启动即核 `void baselineWatch('startup')` | ✅ **响了，但被冷却跳过** |
| `621` | 心跳里 `if (loadState().lastDay !== bjDate())` —— **只在换日** | ❌ 今天还没换日 |

而冷却那一行（`prd_baseline.mjs:360`）只做一件事：

```js
if (!force && Date.now() - last < COOLDOWN_MS) {
  return { skipped: `冷却中（上次 ${prev.lastRunAt}，不足 ${COOLDOWN_MS / 60000} 分钟）` };

```

调用方（`ws_daemon.mjs`）接住 `skipped` 之后：`log(...)` → `return`。
**没有定时器，没有待办，没有下一次**。

心跳（每 5 分钟一拍，`ws_daemon.mjs:615`）里确实有四个 `Watch`，
但三个 `Watch` 的条件都是**换日**（`lastDay !== bjDate()`），只有补发队列是每拍都跑。

### 13.3 后果（两条，第二条更坏）

**时间线（全是本次的活读数）：**

**后果一：漂移的发现窗口被一次重启撑到约 24 小时。**
这与已登记的「换日兜底时效上界是一整天」**不是同一条** ——
那条说的是「只在收到链接时跑会漏掉改已推过的文档」；

也就是说 `lastState` 停在 `drift`，**不是因为它还是 drift，而是因为没有东西去更新它**。
任何人此刻读这个文件，都会得到「基线仍然是漂移的」这个错误结论 ——
**而这正是这个文件存在的唯一用途。**

> 于是一件已经做完的事被当成待办又提了一遍）**是同一个病**：

### 13.4 这是设计意图的副作用，不是谁写错了

`ws_daemon.mjs:256` / `607` 的注释写得很清楚：「带 3 小时冷却 —— **重启不重抓**」。
