## 二、★ 2026-10-21 更正：`skill/` 与 `skills/` 是两个目录

由 `fa` 实测发现，我（05）先前写错，一并更正：

```
.gitignore:39      skills/          ← 复数，被忽略
盘上的目录          skill/   (39 项)  ← 单数，git check-ignore → rc=1，**没被忽略**
                   skills/  (第三方) ← 复数，被忽略
git ls-files skill                  → 0 行
git add -n skill                    → 220 个文件
```

**后果**：`skill/` 现在处于**第三种状态** —— 既未跟踪、也未忽略。
任何人一次 `git add -A` 就会把 220 个文件（含 27 个 Proprietary 内部件、
10 个第三方、以及 `skill/kb-l0-feishu/scripts/preflight.sh:18` 的硬编码
`BASE_TOKEN="${KB_BASE_TOKEN:-GnRZbIuXraCzf0sGr2UcmZ62nfc}"`）带进**公开仓**。

> ★ 这条的危险不在「会不会忘」，在**它长得像已经安全**：
> 大家一直以为 `skills/` 那行挡住了它，而单复数差一个字母。

## 三、跨会话的三条硬约束**1. 汇报前必须回读现场，不只看日志。**

但两个检查共写一份状态文件，把对方的 `p_*` 抹掉了。抓到它的是**回读状态**，不是日志。

**2. 自证跑绿 ≠ 生产可用。**
阶段计划 `:312-320` 逐字：「验证器绿 ≠ 真实路径通」。凡涉及写链的验证器，
跑的都是本地内存台账。汇报时要分开写「自证通过」与「生产可用」。

**3. 不确定归属时，先问、别写。**
在共享工作区里，「我以为是空的」是最贵的一句判断。
