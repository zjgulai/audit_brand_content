2. 人工验收：登录后逐页过一遍

自动探针在无凭据的情况下到此为止。下面这部分必须有人登录后操作， 因为「页面能挂载」和「业务数据正确」是两件事。

第 1 步 · 登录

  1. 用 桌面 Chrome（版本 155 或 156）打开 https://ca.luteos.com/login —— 页脚写明支持范围；其他浏览器会看到「不支持」横幅，但**不阻断**访问。
  2. 用手机飞书扫页面上的二维码。扫码后手机会弹出确认，点确认即可。
  3. 回到浏览器，应自动跳进工作台。若停在登录页，刷新一次。

第 2 步 · 逐页走一遍（12 个业务页）

每一页只用做四件事，任一不满足就记一条：① 有没有内容 ② 数字对不对 ③ 点得动吗 ④ 报错吗。

顺序页面入口具体看什么
1复核队列/queue列表有没有行；点一条能否进详情；「待自决 / 最新」排序切换是否生效
2案件详情从队列点进去IR / 回执 / 双指纹是否并列显示；未评部分是否写明「未评原因」而不是空着
3认领与草稿详情页点「认领」后按钮变「释放草稿」；保存草稿后刷新页面，草稿还在
4案件总览/cases筛选条件叠加后结果数量随之变化；点「重置」能清空
5收件箱/inbox未读有几条；标已读后数字减少且刷新不回退
6提交内容审查/submit空内容应被拦；提交后能看到回执与案件号
7申诉中心/appeals列表与详情能对上；受理 / 驳回按钮有理由输入
8签发中心/release四个前置条件是否显示；不满足时签发按钮应禁用并说明原因
9下线任务台/takedown任务状态推进（开始 / 重试）后刷新是否保持
10报告索引/reports点报告能打开详情；链接带 exp 与 sig 两个参数
11分类规范与规则/taxonomy七轴筛选能用；规则详情只读（不应出现编辑框）
12授权名单 / 会话审计/admin/grants、/admin/sessions能列出条目；撤权 / 续期按钮的二次确认会弹出

第 3 步 · 键盘与缩放（这 4 项机器测不了）

  1. 纯键盘走一遍：只用 Tab / Enter / 方向键，从队列进详情再回到队列，全程不碰鼠标。
  2. 焦点可见：每按一次 Tab，当前元素必须有明显的焦点框（不能靠鼠标才知道在哪）。
  3. 200% 缩放：Chrome 里 Cmd + 按两次，文字不重叠、不截断。
  4. 400% 缩放：按到 400%，页面变成单列且不出现横向滚动条。

★ 动效这一项已有一半自动化了（a11y_check.mjs 在模拟 prefers-reduced-motion: reduce 下读真实渲染样式，确认零动画零过渡）。 剩下那一半仍需人看：系统开启「减少动态效果」后，页面用起来是否仍然顺畅。

3. 发现问题时怎么记录

按这个格式记，别人才能复现：

页面：/queue
操作：点了列表第 3 条
期望：进入案件详情
实际：页面停在原地，控制台报 TypeError
视口：1280×720（或 320px / 200%）
能否稳定复现：刷新后仍能

控制台错误在 Chrome 里按 Cmd + Option + J 打开，把红色那几行一起贴上。
