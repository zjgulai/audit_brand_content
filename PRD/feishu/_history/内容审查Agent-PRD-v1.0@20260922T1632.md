1. 背景与目标
1.1 背景
美国市场内容产出量大、审核机制不统一：
广告二创月均约 500 条，高峰约 3000 条，当前无固定审核机制，是最高风险端口。
吸奶器品线红人内容月均 100-200 条，已有两轮审核，但规则未完全统一。
品牌设计部 AI 平面素材每日产出，核心痛点是通识常识错误。
品牌社媒、PR、专家、独立站内容分散在 NAS、GD、飞书 Drive、Figma 等多处。
法务仅固定覆盖 listing、TVC、上市物料包、EDM，高频内容无固定介入通道。

1.2 目标
建立统一的内容发布前审查 Agent，实现：
排雷：识别消费者安全、品牌信任、合规、经营风险。
分流：PASS / REVIEW / BLOCK 三态结论，自动转交对应负责人。
提效：降低人工逐条审核负担，优先处理 REVIEW / BLOCK。
留痕：审核记录绑定版本，支持统计、复盘、知识库回流。
准确：预审结论争取达到 90% 以上准确性，避免给人工复核增加麻烦。

5. 功能需求

5.1 输入方式

方式一：飞书群 @Agent 预审
内容提交方在飞书群直接 @Agent，发送文字、图片、视频、链接或文件。
Agent 自动识别内容类型，调用对应审查能力。
输出三态结论：
PASS：一句话总结，转 sign-off 负责人。
REVIEW：列明需再审查点、原因、依据文档链接，转对应人工。
BLOCK：列明需修改点、原因、依据文档链接，返回内容方。
支持 @ 指定下一步审核人，或由 Agent 按规则自动 @。

方式二：批量上传 + 批量扫描
内容批量上传到指定位置：飞书多维表、NAS 共享盘、结构化 URL 列表。
Agent 批量扫描后：
输出整体结论摘要；
在飞书多维表中批量生成每条内容的审查结论；
支持按 PASS / REVIEW / BLOCK 筛选、导出、统计。
独立站、广告可提供结构化 URL，Agent 批量扫描排雷。

5.2 审查能力



内容类型

第一阶段能力

说明

文字

全文审查

caption、listing、PDP、落地页、社媒文案、图片文字

图片文字、产品使用、人物行为、场景风险

审查维度：
消费者安全：错误示范、危险使用、误导性操作。
品牌信任：专业性受质疑、公开点名、达人争议。
合规：法规、平台政策、医学宣称、广告用语、绝对化用语。
经营风险：投诉、下架、返工、投放损失。
产品准确性：功能边界、型号差异、允许/禁止描述。

5.3 三态结论规范

PASS
结论：一句话总结，说明未发现已知底线风险。
动作：转交对应 sign-off 负责人。
示例：
> 未发现已知底线风险，可转交 @陈静姝 进行 sign-off。

REVIEW
结论：明确哪个地方需要再审查，依据是什么（原因 + 对应文档链接）。
动作：转交对应法务、医学、专家、北美本地同事复核。
示例：
> 发现 2 处需人工确认：
> 1. 视频 00:12 字幕“治疗堵奶”涉嫌医疗宣称，依据《合规措辞库 v1》第 3.2 条；
> 2. 图片中吸奶器使用姿势可能误导，依据《产品描述库-吸奶器》第 2.1 条。
> 建议转 @法务 @医学顾问 复核。

BLOCK
结论：总结需要修改的地方是哪些，返回内容方修改。
依据：原因 + 对应文档链接。
示例：
> 发现 3 处必须修改：
> 1. 图片文字“最安全”为绝对化用语，依据《广告法禁用语》第 1 条；
> 2. 视频 00:08 奶液流速夸张，依据《负面样本库-吸奶器》案例 07；
> 3. caption 中“治疗乳腺炎”为医疗宣称，依据《外部标准库-FDA》第 X 条。
> 请修改后重新提交。

5.4 输出方式

人类可读结论
飞书群消息：简洁、清晰、接近人审查反馈。
飞书多维表：每条内容一行，字段包括结论、风险点、依据、责任人、状态。
批量扫描摘要：总数、PASS/REVIEW/BLOCK 数量、高风险项 Top 列表。

结构化 JSON
用于系统记录、流转、统计。每条审查生成一份 JSON。

5.5 飞书群交互
支持 @Agent 触发。
支持文字、图片、视频、链接、文件。
Agent 回复三态结论，并 @ 下一步负责人。
支持内容方回复“已修改，重新提交”，Agent 重新预审。
支持人工复核结论回流，更新记录。

5.6 批量扫描与多维表
批量上传入口：飞书多维表、结构化 URL、NAS 路径。
多维表字段：
内容 ID、产品线、渠道、内容类型、送审版本
Agent 结论、置信度、风险点、依据链接
人工复核人、复核结论、sign-off 人、发布时间
状态：待审 / PASS / REVIEW / BLOCK / 已修改 / 已发布
支持按品线、渠道、风险类型统计。

5.7 人工复核与 sign-off
REVIEW 自动转对应专业团队。
BLOCK 返回内容方修改，修改后重新提交。
PASS 转 sign-off 负责人，负责人确认：
Agent 审查记录完整；
REVIEW 已有人工结论；
BLOCK 已修改并重新提交；
发布版本与送审版本一致。

5.8 知识库与规则
Agent 判断依据四类知识库：
内容治理-知识库
外部标准库：美国法规、平台政策、行业标准、医学共识、本地常识。
内部正面与负面样本库：合规优秀内容 + 投诉、下架、警告、返工、达人争议、审核争议。
措辞表达库：Do not say / Say this instead、禁用/慎用/推荐表达、中英对照。
产品描述库：功能边界、型号差异、允许/禁止描述、认证参数、常见误解。

5.9 记录与统计
审核记录绑定内容版本。
支持统计：
审查覆盖率
PASS / REVIEW / BLOCK 比例
人工复核负担
误报 / 漏报
规则命中率
知识库回流数量

7. 准确性要求与评估

7.1 目标
整体三态准确率 ≥ 90%。
BLOCK 精确率 ≥ 95%，避免误伤。
PASS 误放率 ≤ 5%，避免漏放。
REVIEW 召回率 ≥ 95%，不确定内容优先转人工。
人工复核负担降低 ≥ 50%。

7.2 保障机制
证据链：每条结论必须附原因 + 文档链接。
置信度阈值：
高置信度：直接 PASS / BLOCK。
中置信度：输出 REVIEW。
低置信度：输出 REVIEW，并标注“不确定，建议人工重点看”。
多模型测试：选型阶段测试多个模型，比较误报/漏报。
人工反馈回流：人工复核结论回流知识库，持续优化规则。
每周抽检：每周人工抽检 100 条，评估准确率。
规则版本管理：规则、知识库、模型版本绑定审查记录。

7.3 评估方式
以人工复核为金标准，计算：
准确率 = 三态结论一致数 / 总审查数
BLOCK 精确率 = 正确 BLOCK / 全部 BLOCK
PASS 误放率 = 人工复核为 REVIEW/BLOCK 的 PASS / 全部 PASS
REVIEW 召回率 = 人工复核为 REVIEW/BLOCK 且 Agent 输出 REVIEW / 全部人工 REVIEW/BLOCK
