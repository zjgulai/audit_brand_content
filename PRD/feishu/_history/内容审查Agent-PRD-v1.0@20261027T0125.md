1. 背景与目标
1.1 背景
美国市场内容产出量大、审核机制不统一：
广告二创月均约 500 条，高峰约 3000 条，当前无固定审核机制，是最高风险端口。
吸奶器品线红人内容月均 100-200 条，已有两轮审核，但规则未完全统一。
品牌设计部 AI 平面素材每日产出，核心痛点是通识常识错误。
品牌社媒、PR、专家、独立站内容分散在 NAS、GD、飞书 Drive、Figma 等多处。
法务仅固定覆盖 listing、TVC、上市物料包、EDM，高频内容无固定介入通道。

1.2 目标
建立统一的内容发布前审查 Agent，实现：
排雷：识别消费者安全、品牌信任、合规、经营风险。
分流：PASS / REVIEW / BLOCK 三态结论，自动转交对应负责人。
提效：降低人工逐条审核负担，优先处理 REVIEW / BLOCK。
留痕：审核记录绑定版本，支持统计、复盘、知识库回流。
准确：预审结论争取达到 90% 以上准确性，避免给人工复核增加麻烦。

5. 功能需求

5.1 输入方式

方式一：飞书群 @Agent 预审
内容提交方在飞书群直接 @Agent，发送文字、图片、视频、链接或文件。
Agent 自动识别内容类型，调用对应审查能力。
输出三态结论（详见 5.3 输出规范）。
支持 @ 指定下一步审核人，或由 Agent 按规则自动 @。

方式二：批量上传 + 批量扫描
内容批量上传到指定位置：飞书多维表、NAS 共享盘、结构化 URL 列表。
Agent 批量扫描后：
输出整体结论摘要；
在飞书多维表中批量生成每条内容的审查结论；
支持按 PASS / REVIEW / BLOCK 筛选、导出、统计。

5.3 三态结论输出规范

Agent 输出三态结论时，必须先标注问题所属维度，再给出总结和建议。以下为三种状态在不同问题数量下的输出格式。

5.3.1 PASS
一句话总结，说明未发现已知底线风险。
动作：转交对应 sign-off 负责人。
示例：
> 【审查结论：PASS】未发现已知底线风险，可转交 @陈静姝 进行 sign-off。

1.【合规-医疗宣称】视频 00:12 字幕“治疗堵奶”涉嫌医疗宣称。

  依据：《合规措辞库 v1》第 3.2 条（链接：https://...）

2.【消费者安全-使用姿势】图片 1 中吸奶器使用姿势可能误导。
  原因：吸奶器使用姿势可能误导消费者。
  依据：《产品描述库-吸奶器》第 2.1 条（链接：https://...）

建议转 @法务 @医学顾问 复核。

问题数量 ≥ 3 个时，只输出分类汇总 + 报告链接：

【审查结论：REVIEW】共发现 5 处需人工确认。

→ 查看完整问题清单与修改建议：https://feishu.cn/review/xxx

5.3.3 BLOCK

问题数量 1-2 个时，逐条输出：

【审查结论：BLOCK】共发现 2 处必须修改。

1.【合规-绝对化用语】图片文字“最安全”为绝对化用语。
  原因：广告法禁止使用“最、第一、最佳”等绝对化用语。
  依据：《广告法禁用语》第 1 条（链接：https://...）

2.【消费者安全-车内场景】视频 00:08 宝宝未坐安全座椅。
  原因：内容不得呈现未使用安全座椅的画面。
  依据：《车内场景审查规则》第 1 条（链接：https://...）
  建议：替换为宝宝坐在安全座椅内的画面。

请修改后重新提交。

【审查结论：BLOCK】共发现 4 处必须修改。

· 合规类问题：2 个
· 消费者安全类问题：1 个
· 产品描述类问题：1 个

→ 查看完整问题清单与修改建议：https://feishu.cn/block/xxx

5.3.4 输出格式设计说明

问题数量阈值设定为 3 的依据：
根据行业内容审核实践，单次审查中 3 个及以上问题已超出用户可快速浏览和记忆的范围，逐条展开会显著增加认知负担。
审核报告最佳实践采用“摘要 + 钻取报告”模式：主报告提供摘要级别信息，用户通过链接查看详细问题清单。
阈值支持配置，后续可根据用户反馈调整（建议保留 3 作为默认值）。

报告链接内容要求：
完整问题清单，每条包含：维度、位置、问题描述、原因、依据文档链接、修改建议。
按维度分组展示，便于按类别处理。
支持导出为飞书文档或 PDF。
报告链接有效期 ≥ 30 天，存于飞书云文档。

6. 规则优先级与分层审查机制

6.1 设计背景

不同规则类型对模型推理的需求、响应速度和审查准确率要求差异显著。法务合规类规则命中即需拦截，常识性错误需要语义理解，措辞规范相对可容忍。如果不做分层，所有规则走同一推理链路，会导致两个问题：一是法务红线规则被模型“过度推理”后误判为不违规，二是大量低风险内容消耗模型算力、降低整体吞吐效率。

行业内容审核的通行做法是采用漏斗式分级过滤：第一层快速拦截（关键词、规则引擎），第二层深度推理（大模型语义理解），第三层人工复核。轻量规则先跑，大模型算力只用于真正需要深度理解的少数内容。

6.2 规则优先级分层设计

将审查规则按业务紧要性、监管要求和风险严重程度分为四个优先级层级，不同层级使用不同的审查策略和模型能力：

执行规则：
P0 命中即停止后续审查，直接输出 BLOCK，确保法务红线零延迟拦截。
P1 与 P2 可并行执行，按最高风险等级输出结论。
P3 仅输出建议，不改变 PASS/BLOCK 结论。
当多条规则同时命中时，按最高优先级输出；例如同时命中 P0 和 P2，结论为 BLOCK，报告中列出全部问题供参考。

6.4 行业实践依据

内容审核行业的核心做法是“规则优先级分层 + 分级匹配”：

权重分配：将规则分为硬性规则（违法违规内容）和软性规则（低质量文本），硬性规则权重最高（例如权重 10），软性规则次之（例如权重 5）。

分级匹配：第一层高频硬性规则快速匹配（关键词黑名单），匹配成功立即处理；第二层低频软性规则异步检测（语义分析），降低延迟。先用正则匹配敏感词（毫秒级响应），再调用 NLP 模型分析语义（秒级响应）。

冲突解决：当多条规则同时命中时，采用“最高权重优先 + 人工复核兜底”模式。例如，一条内容同时命中广告规则（权重 50%）和涉政规则（权重 90%），系统优先拦截涉政内容。

漏斗式三层架构：第一层快速拦截（关键词、规则引擎和轻量模型），第二层深度推理（中高风险内容进入大模型审核层），第三层人工复核（边界模糊、高敏感度内容）。

本 PRD 的 P0-P3 四层设计即基于上述行业实践，结合母婴品类审查场景做了适配。

绝对化用语（最、第一、最佳、100%、纯天然等）
无依据的销量/排名宣称

状态：待审 / PASS / REVIEW / BLOCK / 已修改 / 已发布

8.3 报告链接
问题数量 ≥ 3 时，生成完整报告并返回链接。
报告内容：完整问题清单（维度、位置、问题描述、原因、依据链接、修改建议），按维度分组展示。

支持导出为飞书文档或 PDF。


9. 人工复核与 sign-off

REVIEW 自动转对应专业团队（法务、医学、专家、北美）。

发布版本与送审版本一致。
人工复核结论回流知识库，更新规则权重和正负样本。

11. 准确性要求与评估

11.1 目标
整体三态准确率 ≥ 90%。
BLOCK 精确率 ≥ 95%，避免误伤。
PASS 误放率 ≤ 5%，避免漏放。
REVIEW 召回率 ≥ 95%，不确定内容优先转人工。
人工复核负担降低 ≥ 50%。

11.2 保障机制
分层审查：P0 规则引擎保障红线零漏放，P1-P3 大模型保障语义理解准确性。
证据链：每条结论必须附原因 + 文档链接。
置信度阈值：按 6.6 策略分流。
多模型测试：选型阶段测试多个模型，比较误报/漏报。
人工反馈回流：人工复核结论回流知识库，持续优化规则和权重。
每周抽检：每周人工抽检 100 条，评估准确率。
规则版本管理：规则、知识库、模型版本绑定审查记录。

11.3 评估方式
以人工复核为金标准，计算：
准确率 = 三态结论一致数 / 总审查数
BLOCK 精确率 = 正确 BLOCK / 全部 BLOCK
PASS 误放率 = 人工复核为 REVIEW/BLOCK 的 PASS / 全部 PASS
REVIEW 召回率 = 人工复核为 REVIEW/BLOCK 且 Agent 输出 REVIEW / 全部人工 REVIEW/BLOCK
P0 层漏报率 = P0 规则应命中但未命中的数量 / P0 规则应命中总数（目标为 0）
