# Playbook v1 修订清单 · 2026-10-17

> **这份文件为什么存在**：v1 交出去后收到 13 条审阅意见（10 条承重 + 3 条证据）。
> 逐条核实后**全部成立**。这份清单记录：哪条成立、改成什么、改在哪一行。
>
> **它的用法**：改完一条划掉一条。**没有「考虑一下」这一档** —— 要么改，要么写明不改的理由。

## 一、承重问题（10 条）

### R1 · 规范权威声明过大

| 项 | 内容 |
|---|---|
| **问题** | 文件头写「任何技术决策冲突以本文件为准」，但本文件自身有 U1–U6 未定项、有我的派生判断、有待法务项。**一个自己没定完的文件，不能当最高权威。** |
| **改法** | 加**规范元数据**（draft/ratified 状态、Owner、审批人、基线指纹、生效日）；<br>加**优先级链**：法律 / 法务裁定 / 上游批准需求 **>** 本文件；<br>加**冲突处理**：冲突触发评审，**不自动覆盖**。 |
| **状态** | ✅ 已改 |

### R2 · 输入分类混层

| 项 | 内容 |
|---|---|
| **问题** | 「五种形态」里 `brief` 是**内容阶段**，`链接` 是**入口载体**；§3 又列了 7 项（文档链接 / URL / 广告记录）。三套口径混在一个「形态」概念下，**「5 种全覆盖」无法验收**。 |
| **改法** | 拆成四个**互不重叠**的维度：`content_type`（内容形态）/ `content_stage`（内容阶段）/ `entry_channel`（入口通道）/ `source.kind`（来源种类）。验收表按四维分别断言。 |
| **状态** | ✅ 已改 |

### R3 · 二级分类没交付

| 项 | 内容 |
|---|---|
| **问题** | 只写了「七个控制族 + 子类数」，**没有 58 个控制点的全集、稳定码、版本、唯一归属**。用户最初点名「没有二级分类」，写「必须有」不算规格。 |
| **盘上实测** | `rules-v1.json` 有 **26 条规则 / 21 个 `parent_rule` 码**（H01–H09 / M01–M07 / U01–U04 / 安全词）；<br>`rulelib-live.json` 有 **21 条**。<br>**「58 个子类」是 `分类确认` 那张汇报表的数，不是控制点全集。** |
| **改法** | 写清「控制点」的三件事：**稳定码格式**、**唯一归属规则**、**版本化引用**；<br>并**明确交付物**：一张控制点主表（码 / 名称 / 所属控制族 / 判据类型 / 依据来源 / 版本），**当前 21 个不等于最终数**。 |
| **状态** | ✅ 已改 |

### R4 · P0 候选与 BLOCK 下限冲突

| 项 | 内容 |
|---|---|
| **问题** | 原则三写「有 P0 就是 BLOCK 下限」，但浅档 / 语义档产出的**只是候选**、必须转人工。**候选不该先被命名为终局 P0。** |
| **改法** | 引入 `finding` 的**确认状态**：只有 `confirmed` 的 P0 才给 BLOCK 下限；`candidate` 的 P0 **不参与状态计算**，只进 REVIEW 的证据。 |
| **状态** | ✅ 已改 |

### R5 · pipeline 仍用「轮」且缺唯一运行契约

| 项 | 内容 |
|---|---|
| **问题** | 五步已定，但：skill 选择规则、唯一编排器的输入/输出、回执 schema（skill id / version / hash、规则与知识快照、跳过原因）**全都没定义**。`L2-7` 只说「有回执」，无法开发验收。 |
| **改法** | 把「轮」改成「步」（pipeline 无回边时没有「轮」的概念）；<br>补三张契约：**编排器输入**、**编排器输出**、**执行回执 schema**（逐字段）。 |
| **状态** | ✅ 已改 |

### R6 · 知识库失败路径缺失

| 项 | 内容 |
|---|---|
| **问题** | `authority_ref` 查不到 / 过期 / 冲突时怎么办没写。后果：**规则命中可以在拿不到依据的情况下继续 BLOCK**，违背「每个结论可指依据」。 |
| **改法** | 补三条失败路径，且**默认动作是降级不是放行**：<br>查不到 → 结论降为 `REVIEW` + 标「依据缺失」；<br>过期 → 同上 + 标「依据过期」；<br>冲突 → 强制转人工 + 标「依据冲突」。 |
| **状态** | ✅ 已改 |

### R7 · Markdown 没进入工作流

| 项 | 内容 |
|---|---|
| **问题** | 已定「IR 为源、md 为渲染视图」，但五段图、归一化、输出**都没有 IR→md 的步骤**，只有 U1 说格式未定。 |
| **改法** | 在五段里加**显式的 md 渲染时点**；写清**输入是 IR、输出是 md**、**必带区块**、**与结构化记录的一致性判据**（md 里每个结论都要能指回 IR 的 id）。 |
| **状态** | ✅ 已改 |

### R8 · 输出契约远不够

| 项 | 内容 |
|---|---|
| **问题** | 没有五标签→文字/卡片模板映射、BLOCK/REVIEW 必带字段、报告章节与 schema、coverage receipt 位置。七条去 AI 味只列名称，**没有定义适用范围与阻断策略**。 |
| **改法** | 补三张契约：**群里消息模板**（按标签分）、**报告章节与必带字段**、**去 AI 味七条的适用范围与阻断等级**（阻断 / 警告 / 只记录）。 |
| **状态** | ✅ 已改 |

### R9 · 验收条件有不可执行/错误目标

| 项 | 内容 |
|---|---|
| **问题** | ① `L1-4` 要求两次解析正文指纹必相同 —— 对 OCR/VLM **不成立**（模型非确定性）；<br>② `L4-2` 要求链接 TTL ≥ 记录期 —— 与「结构记录可重建报告」冲突；<br>③ `L4-3` 「坏样本全部拦下」与实际的 warn / 搬折叠策略不一致。 |
| **改法** | ① 限定为「**同输入 + 同解析器版本 + 同模型版本 + 确定性配置**」下的指纹一致；非确定性档改为「**同输入多次解析，结论集合的差集为空**」；<br>② 改成「**保存期内报告可稳定重建**」；<br>③ 七条各自标明**阻断 / 警告 / 仅记录**，验收只断言「阻断级的必须拦住」。 |
| **状态** | ✅ 已改 |

### R10 · 指标未成合同

| 项 | 内容 |
|---|---|
| **问题** | 四个指标只有名字，**没有分子/分母/窗口/抽样层/最低 n/未测状态/目标线**。不能据此做看板或验收。 |
| **改法** | 每个指标补七要素：定义式（分子/分母）、统计窗口、抽样层、最低样本量、未测时的显示、目标线、数据来源。 |
| **状态** | ✅ 已改 |

## 三、额外一条（委托方本轮直接决定）

### D1 · 机器可以下任何状态，人做最后放行

| 项 | 内容 |
|---|---|
| **原话** | 「**机器人可以下任何状态，但最终都会由人做最后的放行**」（2026-10-17） |
| **推翻了什么** | v1 原写「机器唯一能自行下的是 BLOCK，其余四档都是退出或转人」—— **那个写法把「判断」和「放行」压成了一件事**。 |
| **改法** | 原则一重写：机器下判断不设限，**放行权锁在人手里**；<br>判据从「搜不到机器产出的 PASS」改成「**搜不到从审查标签直连发布状态的路径**」。 |
| **状态** | ✅ 已改 |

> ★ **这条值得单独记**：我原先的设计用「限制机器能说什么」来达成「限制机器能放行」，
> 方向反了。正确做法是**放开判断、锁死放行** —— 前者让人省事，后者才是可控。
