# 三态读数 · 写报告/登记状态时的纪律（skill v1）

> 用途：**任何 agent 写报告、登记表格同步 JSON、或给检查器下结论时**，按这一页办。
> 它管的是「**未测 / 通过 / 红**」三个词的写法 —— 不许互相代替。

自证：本文件是文档，没有 bash 命令可跑；它的执行点在每个调用它的报告里 ——
你写出来的「未测」/「通过」/「红」要能被这一页的判据反问到。

---

## 一、三态不可互代（本项目最容易犯的错）

```
未测 (exit 2)  ≠  通过 (exit 0)  ≠  红 (exit 1)
```

| 状态 | 含义 | 文案里不许出现 |
|---|---|---|
| **通过** | 跑过了，断言全绿 | — |
| **红** | 跑过了，有断言不绿 | — |
| **未测** | **没跑** / 跑不起来 / 读数采不到 | 「没问题」「OK」「✅」「通过」「正常」 |

本项目栽过的三次（每次都把「没测」写成了「通过」）：

1. `prd_baseline.mjs` 第一次运行：`--offline` 一次网络都没发，
   却打印「✅ 16 项全过（含 L3：上游与指纹一致）」。
2. `verify_shouheng_ops.py` 的 `ps` 被受限环境拦：
   读数采不到时整块跳过，读起来像「没什么会生效」，实际是「我读不到」。
3. 守衡停机 21 天：没被 pgrep 核的会话以为它在跑，
   以为「随时能重启它让改动生效」。

---

## 二、写「未测」的五种合法场景

只有这五种可以写「未测」。其他都该是「通过」或「红」。

| 场景 | 怎么写 |
|---|---|
| 工具/服务不在盘上（`~/.cache/magpie` 清单、`.vendor/`、被停的守衡） | 「未测：X 不在盘上」 |
| 外部依赖读不出（`ps` 被拦、网络超时、权限不够） | 「未测：X 读不出（原因）」 |
| 这一跳**该跑但本轮没跑**（「其余 135 个检查器本轮未跑」） | 「未测：X 本轮未跑」 |
| 读数是**声明**不是**证据**（开关显示开着 ≠ 数据真的读到了） | 「未测：仅见声明，未见读数」 |
| 注入的查看改掉了将来要发生的事（`--today=YYYY-MM-DD` 落了状态） | 「未测：这次是 dry-run 查看，不是真实运行」 |

---

## 三、写「未测」时必须同时写出来的三件事

缺一件就等于把「未测」写成了「通过」的伪装。

1. **范围**：哪些东西没测 —— 「其余 135 个检查器」/「视频 ASR」/「生产镜像 tag」
2. **原因**：为什么没测 —— 「不在盘上」/「读不出」/「本轮未跑」
3. **怎么补测**：什么命令能补上 —— 指不出来的「未测」就是一句**安慰**（§2.4.2）

---

## 四、写「通过」前必问的三个问题

一个答不上来就不许写「通过」。

1. **这句话比我的输入大吗？**（§2.4.1）
   输入是「我采的那条通道里没有」，说出去的却是「所有通道都没有」→ 不许。
2. **判据拦过吗？**（§2.4 反向对照）
   一个断言从来没在某次真实事故里红过，就不算验证过它 —— 写「通过」时
   你赌的是「它真拦得住」。
3. **「本地能跑」是不是被当成了「生产能跑」？**（2026-10-30 三连 ImportError）
   本地 verifier 全绿、上生产就 ImportError —— 同一个检查器的两种形状。

---

## 五、写「红」时不许做的事

| 不许 | 为什么 |
|---|---|
| 红与未测混在一起只报一个数 | 只看最后一行的人会以为「其余都验过了」（H1–H7 的存在理由） |
| 红了但不给**怎么修** | 读者只能干瞪眼 |
| 把红写成「告警」「⚠」 | 告警是能被忽略的；红是要么修要么明说不修 |

## 六、常见反模式（都是本项目栽过的）

### 6.1 「我读不到」被当成「没什么会生效」

`restart_shouheng.sh` 第一版：`ps` 取空后 `if [ -n "${START_EPOCH:-}" ]` 整块跳过 ——
读起来像「重启会让 0 个改动生效」，实际是「我读不到启动时刻」。
**修法：取不到时显式说「未测」，不许空着。**

### 6.2 「自证全绿」被当成「跑起来也对」

`prd_baseline.mjs` 上线前 38 项反向对照全过，重启后状态文件被**两个检查共写**抹掉。
**修法：上线后第一件事是回读一次现场，不是看日志有没有报错。**

### 6.3 「查看」改掉了「将来要发生的事」

`--today=YYYY-MM-DD` 第一版落了状态，于是真正的 10-03 到了反而闭嘴。
**修法：注入的查看一律 dry-run，不落状态。**

### 6.4 「字段名出现过」被当成「拦得住」

`VERDICT_MAX` 与 `BOUNDARY_MAX` 真的接上了比较，`MAX_SECTIONS` 只出现在 import 行
与 `ENFORCED` 台账里 —— J1 源码文本存在性测试对它**恒真**。
**修法：判据必须比「到达比较」，不能比「名字出现」。**

### 6.5 「本地能跑」被当成「镜像里有」（2026-10-30 三连）

`lp_extract` / `lp_fetch` / `multimodal_client` 三次同源：本地 import 闭包
与镜像 import 闭包是两个数，没有任何一行代码在拦。
**修法：`python3 tools/verify_image_completeness.py` 现在是执行点。**

### 6.6 「扫得出来」被当成「扫得对」

`verify_field_contract.py` 第一版扫同根单复数字段名 ——
`path/paths`、`job/jobs`、`event/events` 全是合法的，误报爆炸。
**修法：静态扫描判不出「合法 vs 事故」时，宁可不做这个检查器。**
（2026-11-02 删掉了它，不是留个一直红的摆设。）

## 七、最简模板（写报告时抄这个）

```markdown
| 检查 | 范围 | 结果 |
|---|---|---|
| `verify_X.py` | X 的 Y 断言 | ✅ 通过（N/N） |
| `verify_Z.py` | Z 的 W 断言 | ❌ 红：W2 失败，见 PMO/xxx.md §N |
| 其余 M 个 | — | ⚠ 未测：本轮未跑 |
```

退出码与文案对齐：`0=全过` / `1=有红` / `2=有未测`。

**不许出现的话**：「✅ 全过（含 X）」当 X 其实没测的时候。
