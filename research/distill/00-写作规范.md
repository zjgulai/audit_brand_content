# 蒸馏写作规范（唯一标准，派活只用这一份）

> 本规范适用于 `research/distill/shards/` 下所有分片。**每一处技术论断都必须可回溯到源码的具体行。**
> 违反「零幻觉铁律」的稿件直接作废，不是修改，是作废。

---

## 一、零幻觉铁律（作废级，逐条遵守）

1. **每一处引用、每一个行号、每一个类型名与函数名，动笔前用读文件工具实读核实。**
   禁止凭印象写、禁止根据文件名推测、禁止照抄大纲里的候选行号。
   大纲里的行号一律视为**候选**，即使旁边标了 ✓ 也要重读——✓ 的含义是「曾经核实过」，不是「现在还对」。
2. **代码块必须与源文件逐字节一致。** 保留原始缩进、注释、空行。
   禁止转译、禁止美化、禁止写「示意代码」「简化版」、禁止补一个源文件里没有的 `# 注释`。
3. **中间跳过内容必须显式写省略标记**，格式为整行注释且 `...` 紧跟注释符号：
   ```
   // ... 中间省略 ...
   ```
   静默删行是最危险的失败模式（曾有一章悄悄删掉六行，删掉的恰好是「有意保留什么」那半段，结论因此不完整却看不出破绽）。
   `// 处理 bash -lc "..." 的情况` 这种正常注释**不是**省略标记，校验器不会放过它。
4. **找不到某个机制的实现，明确写出来**：`未找到对应实现，检索关键词为 X、Y、Z`。
   不许编一个看起来合理的实现。这条同样适用于「README 声称有但代码里没有」的情况——
   这本身就是重要发现，要写进卡片并标注 **README 与代码不符**。
5. **由推断得出的结论，显式标注为推断。** 卡片里用 `【推断】` 开头。
6. **引用注释原文时说明这是注释**，不要把注释内容当成代码行为陈述。
7. **数字（行数、文件数、规则条数、枚举变体个数）必须实际统计过**，统一用 `splitlines()` 口径。
8. **README / 文档 / 注释的声明不是证据。** 只有当代码真的那样做时才算证据。
   本项目已四次踩到这个坑（README 重复、低估、张冠李戴、clone 地址写错另一个仓库名）。
   **凡是「文档说 X」而「代码里查不到 X」，必须在卡片里写明，这是高价值发现。**

## 二、引用格式（三部分必填）

路径**相对 `research/repos/` 的仓库根**，即 `<repo目录名>/<仓库内相对路径>`。

````
```153:160:ad-review-agent/src/decision/engine.py
<逐字节原文>
```
````

- 起止行、仓库内路径，三者缺一不可。
- **要引用的源文件自身含 ``` 代码栅栏时（Markdown 类语料，如 `sceneforge/SKILL.md`、`soe-legal/skill.md`、各仓库 README），
  外层栅栏必须加长到 4 个反引号**，否则外层会被内层提前闭合，校验器报出假的 `RANGE_MISMATCH`：

  ````
  ````12:34:repo/path/file.md
  （含 ``` 的原文，栅栏行也要逐字节引进去）
  ````
  ````

- 语料根：`/Users/lute/Project/audit_multi_content/research/repos/`
- 可用的仓库目录名：`ad-review-agent`、`ad-compliance-agent`、`cbi`、`sinyard`、`invoice`、`sceneforge`、`soe-legal`、`contract_audit`、`PolySafe`、`omniguard`、`source-reading-methodology`
- **正文里**引用位置时，用行内代码写成 `ad-review-agent/harness/constraints.yaml:42-58`。

## 三、卡片固定结构（每张卡照此填写，不要自由发挥）

每张卡一个二级标题，编号见大纲。

```markdown
### S1-03 双轨置信度聚合

- **出处**：`ad-review-agent/src/decision/engine.py:88-121`（已实读核实）
- **一句话**：有违规时取违规维度的 max，无违规时取核心维度的 min，并排除 non_drag 维度。
- **原文**：
  ```
  <逐字节引用，带起止行>
  ```
- **为什么这样做 / 不这样做会出什么事**：…
- **代价与局限**：…（这个方案付出了什么代价、什么场景下会失效）
- **Momcozy 迁移形态**：…（具体到字段名/维度名，不要写「可以参考」）
- **证据强度**：已实读核实 / 仅注释说明 / 【推断】/ README 声称但代码中未找到
```

**「证据强度」字段必填。** 这是本知识库区别于前一份报告的核心——前一份报告是论断级的，本份是证据级的。

## 四、文风禁忌（交付前必须清零，可正则化）

交付前跑：

```bash
python3 /Users/lute/Project/audit_multi_content/research/distill/style_scan.py <你的分片路径>
```

禁止：

1. 破折号 `——`
2. 省略号 `……`
3. 「不是…而是…」句式（包括「而不是」「而非」变体）
4. 评价式转述：「非常巧妙」「很简单」「设计得很好」
5. 解读前置：「这背后其实有一个深层判断」「值得注意的是」（后面才说是什么）
6. 情绪词：「震撼」「细思极恐」「惊艳」「完美」
7. 过程性语言：「大纲写…」「按规范要求」「本次任务」「我负责的这一章」、本机绝对路径出现在正文
8. 中文本地化里的英文引号混用（代码块内不受限）

**不要用同义替换绕过正则**（把「而不是」换成「而非」正则过了，问题一点没解决）。禁的是靠否定制造对比这件事。
**禁忌只管正文**，代码块、行内代码、`「」`直接引用内的字符不判违规，扫描器会先剥掉。

## 六、四种典型偏差，提前堵死

1. **删引用让校验变绿**。曾有一章初稿 56 处引用、交付时只剩 22 处且全部通过——作者把报错的引用删掉了。
   校验器的 `DENSITY` 项就是堵这个的。**报错要修，不要删。**
2. **滥用省略标记凑字数**。省略只用于确实无关的样板代码（import 段、重复的 CRUD 分支）。
   单块省略超过 8 处会被判 `OMISSION_DENSITY`。
3. **把检查糊弄过去**。为了让校验通过而改写引用内容、或把找不到的代码块整段删掉，都算作弊。
4. **误报上游文档写错**。真实命中率约两成。上报「报告写错了」时必须带证据，格式固定：
   **被质疑的原话 → 源码文件与行号 → 那几行的原文 → 为什么对不上**。
   三种常见误判要先自己排除：引用区间含文档注释不算错；顺着继承/别名再查一层再下结论；约数按约数判。

## 七、本项目的特殊要求（区别于通用源码精读）

- **读者是 Momcozy 品牌内容审计系统的设计者，不是来学这几个仓库的。**
  每张卡必须回答「这个资产能不能迁移到美国市场 + 母婴/吸乳器品类 + 发布前一次性把关」。
- **所有仓库的规则库都是中国《广告法》语境。** 凡涉及具体法条，必须写明是哪个法域，
  并明确指出迁移到美国市场（FTC / FDA）时哪一条不能直接搬。
- **横向对比是必填项**：至少每张 P0 卡给一组「另一个仓库怎么解同一个问题、代价是什么」。
  禁止写成功能清单对照（「A 有 B 没有」），要说清另一侧为什么可以没有、或用别的东西补上了。
- **不要复述前一份报告**（`research/star-lists-audit-report.md`）已有的论断。
  前一份是论断级的；本份的价值在于**把论断落到行**，并给出可直接复用的原文。
  如果实读后发现前一份报告某条论断有误，**明确写出来并给出证据**——这是高价值交付。
