## 二、三件必须说清楚的事

### 1. 「能看见」远大于「它自己的」

守衡云盘里只有 **2 个**文件，但搜索接口能命中 **455 条**。可达面是后者。
**只看云盘会漏掉 99%。**

### 2. 「能看见」又远大于「是我们的」—— 这是本轮最大的修正

上一版把 455 条当成「守衡能拿到的资源」，业务读到的意思会是「我们手握 455 份家底」。
**那是假账。**

`drive/v1/metas/batch_query` 对每条资源回一个 `url`，**域名就是它挂在哪个租户下**，
服务端给的：

| 域名 | 条数 | 是什么 |
|---|---|---|
| **`momcozy-in.feishu.cn`** | **25** | **本公司租户** —— 真正的家底 |
| `www.feishu.cn` | 387 | 飞书官方模板/帮助内容 |
| `fcna6swh3rtl.feishu.cn` | 43 | 飞书模板库租户，**43 条全是模板**，一条不漏 |

抽验不是靠域名猜的，是读了正文：`www` 域的《团队 OKR 周会（飞阅会方式）》正文是
飞书官方的 OKR 教学稿；同域《SWOT 分析看板》的表名就叫「示例：企业 SWOT 分析」。

### 3. 「读得到正文」这件事，分形态

委托方说「无法下载那就阅读，原文提取」。实测下来要分成三类，**不能混报**：

| 形态 | 能不能抽正文 | 原因 |
|---|---|---|
| 云文档 / 多维表格 / 电子表格 | ✅ 能 | 有**只读内容接口**（`raw_content` / `records` / `values`）—— 这是**阅读**，不是下载 |
| 幻灯片 / 思维笔记 | ❌ 不能 | 接口 **http_404** —— **能力边界**，申请也没用 |
| 附件（file） | ⛔ **不取** | 只有下载通道，而**飞书内容禁止下载**（`AGENTS.md` §2.6）—— **策略边界**，不该下 |

本租户 25 条里 **24 条抽到了原文**，剩下 1 条是附件 —— 它**不是失败，是不取**。
这三类必须分开报：混在一起，会让人以为还差一个开关没打开。

## 三、分级口径 —— 本轮改过一次，这是改的理由

**只有一条判据**：这条资源挂在哪个租户下（`drive/v1/metas/batch_query` 回的 url 域名）。

| 档 | 判据 | 含义 |
|---|---|---|
| `core` | 域 = `momcozy-in.feishu.cn` | **本公司租户**，全部抽正文 |
| `reference` | 非本租户，但命中业务词 | 可能相关，只记元数据 |
| `noise` | 其余 | 非本租户且无业务信号 |

### 旧判据错在哪（两个方向都错，而且都很安静）

旧规则是「命中业务词 **且** (revision>0 **或** 标题命中项目词)」。

**漏** —— 本租户的《全球吸奶器品牌型号库》（62 条竞品型号、30+ 技术字段）、
《全球产品小百科》（9 张品类表）、《W1美国故事TVC项目看板》、《BW04 新品上市社媒
宣传设计需求》、《Lumi 1 红光科普视频项目看板》全被判进 **noise** —— 只因为标题里的
词不在我写死的词表里。**词表漏一个词，一个真资产就消失。** 而这五条恰恰是内容合规
最需要的东西：产品事实依据、待审的营销内容。

**误报** —— 同样本租户但业务无关的《行政-差旅常见Q&A》《飞书帮助中心常见问题》，
因为标题里凑够两个弱领域词，被抬进「核心层（业务真正要用的）」。

合起来说明：**「跟我们业务相不相关」是判断题，分级器判不了。**
我把它当成能用关键词算出来的东西，算出来的就是**假精度** —— 而假精度比没有分级更糟，
因为它看着像读过。现在分级器只做它确实能确定的事，相关性写在 `可达清单.md` 里人工判。

## 四、文件地图与怎么用

```bash
cd /Users/lute/Project/audit_multi_content

python3 tools/feishu_index.py              # 重扫全量，重写索引
python3 tools/feishu_index.py --check      # 只比对：哪条新增/消失/改了（退出码非 0 = 过期）
python3 tools/feishu_index.py --no-extent  # 跳正文抽取，快（回归用）
python3 tools/verify_feishu_index.py       # 验收 28 项
python3 tools/verify_feishu_index.py -v    # 逐条明细
```

**环境注意（2026-09-18 实测）**：本环境里**子进程写出的文件**，`stat` 报的大小会比
真实内容多 **4096 字节**，DSH 的 `read` 工具据此把文件判成 `binary file` —— 正文一个字
都读不出来。内容本身是对的（`python open().read()` 与 `shasum -a 256` 一致），是**视图
不一致**。全仓库扫出 **308 个**文件处于这个状态，包括本项目的 `AGENTS.md`。
索引器写完生成物后会自己做一次 `cp → mv` 往返（`depad()`，带 sha256 断言「内容未变」），
所以本目录的生成物一直打得开。`verify_feishu_index.py` 的 E9 项盯着这件事。

**`--check` 的两套口径**：`core`（≡ 本租户）按 token 严判 —— 它是域名判据给的硬事实；
`reference + noise` 按标题集合比 —— 它们的成员随搜索索引抖动，按 token 比会持续报
**假差异**，而假差异会淹没真差异，然后人开始不看报告。
