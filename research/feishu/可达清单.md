> 委托原话：「我要看到你最终给到我的你能够访问到的链接列表，以及它是讲什么的，
> 你会怎么处理它。」

---

## 0. 先说清楚「25」是怎么来的

搜索矩阵 40 个词扫出 **455 条**。但 `drive/v1/metas/batch_query` 对每条回一个
`url`，**域名就是它挂在哪个租户下** —— 这是飞书服务端给的，不是我按标题猜的：

| 域名 | 条数 | 抽验结论 |
|---|---|---|
| **`momcozy-in.feishu.cn`** | **25** | **本公司租户。公司里真有人在用** |
| `www.feishu.cn` | 387 | 飞书官方模板/帮助内容 |
| `fcna6swh3rtl.feishu.cn` | 43 | 飞书模板库租户，**43 条全是模板**（CRM/OKR/报销/考勤…），一条不漏 |

抽验不是靠域名猜的 —— 我读了正文：`www` 域的《团队 OKR 周会（飞阅会方式）》
正文是飞书官方的 OKR 教学稿；同域《SWOT 分析看板》的表名就叫「示例：企业 SWOT 分析」。

**所以：455 条里，430 条根本不在我们租户里。** 把 455 报成「守衡能拿到的资源」，
业务会以为我们手握 455 份家底 —— 那是假账。真正的家底是这 25 条。

**原文抽取：24/25 成功**，但那 1 条没抽到的**不是失败**。委托方说「无法下载那就阅读，
原文提取」—— 阅读这条路对云文档/多维表格/电子表格走得通（已全部抽出），
对**幻灯片、思维笔记**走不通，因为**飞书没有这两种形态的正文接口（http_404，申请也没用）**。
**附件**则属于第三类：它不是「读不到」，而是**按红线不取** —— 附件只有下载这一条通道，
而飞书内容禁止下载（`AGENTS.md` §2.6，见 §8.2）。三者不能混报：
一个是「接口不存在」，一个是「策略不允许」，混在一起会让人再去点一遍开关。

## 1. 处理方式口径

| 记号 | 含义 | 动作 |
|---|---|---|
| 🟢 **接入** | 直接进守衡的知识库/规则库，作为**运行输入** | 抽正文 → 结构化 → 入 `需求知识库`/`内容治理-知识库` |
| 🟡 **订阅** | 登记为**发布后监测/变更检测**对象 | 记 token + 定期复扫，不进知识库 |
| 🔵 **登记** | 只记录存在与用途，暂不接 | 留在本清单 |
| ⚪ **不接** | 本公司资产但与内容合规项目无关 | 只登记，避免误接 |
| ⛔ **红线不取** | 附件形态（xlsx/pdf/图片/视频）—— 飞书内容禁止下载（`AGENTS.md` §2.6） | **不做**，且**不是缺口**：不申请权限、不找 owner、不催任何人 |
| 🔴 **待解** | 读不到 / 缺权限 / 形态不支持 | 见 §6 缺口表（**本轮 0 条**，唯一那条已改判为 ⛔） |

### 8.2 附件 403：**两次归因都是错的** —— 真因是「红线不让下」

这一段留档，不是为了记住 `403` 怎么解（它不用解），而是为了记住**这个错是怎么犯的**：
我把一条**策略问题**（公司不让下）当成了**能力问题**（权限没给够），于是连着归因两轮，
每轮都更精细、也都更偏。

**第一次判断**：「403 = 缺 `drive:drive:download`，申请即可」→ **错**，因为那两个 scope
早在册（424 个里就有），**根本没有可申请的东西**。

**第二次判断**：「403 = 文档级授权，不是 scope；找 owner 把守衡加为该文件的协作者」
→ **仍然错**，而且错得更像对的 —— 它有 7 条对照撑着。以下是那 7 条读数，
它们本身都是真的，只是**回答错了问题**：

| # | 做法 | 结果 | 说明 |
|---|---|---|---|
| ① | 查应用 scope 清单 | `drive:file:download` ✅、`drive:drive:readonly` ✅ **都在册** | **没有可申请的链接**。缺 scope 时飞书回 `99991672` 并在 msg 里附申请链接；这次没有 |
| ② | `drive/v1/metas/batch_query` 读它 | `code=0` | 应用**够得着**这个文件 |
| ③ | `drive/v1/files/{t}/statistics` | `code=0` | 不是「看不见这份文件」 |
| ④ | `drive/v1/files/{t}/download` | `403`、**空 body** | 对照：同接口换**假 token** → `404`、空 body。接口存在且可达，403 是**针对这份文件**的 |
| ⑤ | `drive/v1/permissions/{t}/members` | `403` `1063004 User has no share permission` | 应用不是这份文件的协作者（**这个读数是真的，但它不该被读**） |
| ⑥ | `drive/v1/permissions/{t}/public` | `code=0`，`link_share_entity: tenant_readable` | 文件是「租户内可阅读」—— 但**可阅读 ≠ API 可下载** |
| ⑦ | 旁证 `medias/batch_get_tmp_download_url` | `code=0` 但 `tmp_download_urls: []` | **静默返回空列表**，连原因都不给 |

**第三次判断（正确，2026-09-18 委托方指出）**：

> 飞书上的内容**禁止下载**。

一句话把上面 7 条全变成**多余动作**：`file` 形态在飞书 OpenAPI 里**没有原文读取接口**，
`download` 是它唯一的内容通道（`medias/batch_get_tmp_download_url` 同样是下载通道）。
于是「下得下来吗、403 还是 200」**根本不是要问的问题** —— 不该下。

**能读的是文档形态，走的是只读接口、不是下载**：
`docx` → `raw_content`、`sheet` → `values`、`bitable` → `records`。
本清单 §2–§5 里那些「抽到了多少字」（TK 周报 40,185 字等）全是这么来的 —— 是**阅读**，
不是下载。**附件没有对应的东西**，它只有下载，所以附件一律不取。

**已落实的处理**（不是只写进这段文字）：

- `tools/feishu_index.py` 的 `fetch_file()` 现在**不调 download、不调 medias、连权限探测都不做** ——
  因为探一次就等于摆出了要下的姿态，而探测结果不会改变结论。
- 红线写进 `AGENTS.md` **§2.6**（此前那一节一直是空的「待补」）。
- 执行点在 `tools/verify_feishu_index.py` 的 **M 段**（5 项）：M1 AST 级扫全仓下载调用、
  M2 喂已知坏样本证明检测器真会红、M3 飞书产物里不许有附件二进制、
  M4 文档与代码互锁、M5 `fetch_file` 一次网络调用都不许有。
- **2026-09-18 复核：一件附件都没下载过** —— `research/feishu/` 里只有 4 个文本文件
  （README / 可达清单 / 资源索引.md / 资源索引-v1.json），零附件二进制。

> 教训跟 §8.1 是同一个形状的**第三次**，但这次更深一层：
> 前两次是「把读数读错」，这次是「**把问题问错**」。
> `99991672` + 申请链接 = 应用级缺 scope；`403` + 空 body + `1063004` = 文档级没授权 ——
> 这个区分本身没错，但它只回答了「**为什么下不下来**」，
> 而正确的问题是「**我为什么要下**」。**问错了问题，越严谨越偏。**
