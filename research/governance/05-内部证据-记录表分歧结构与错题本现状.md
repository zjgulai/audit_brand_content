### 5.4 一个已确认的误报

命中片段中出现：

```
| H07:say goodbye to cold | 2 |
```

**[判断]** H07 的语义是**疼痛**功效承诺。`say goodbye to cold` 说的是「告别冰冷」，**句中不含任何疼痛词**。

而 H07 的正则是：

```
(say )?goodbye to [^.!?|]*pain\w*
```

这个正则要求 `goodbye to` 之后必须以 `pain` 开头结尾的词收尾，**不可能匹配 `say goodbye to cold`**。

**[判断]** 因此：**这 2 条是误报，且误报来源是 §5.3 描述的同一个未记录通道。**

> 关联证据：R5 §7.7 记录了 Momcozy 官网 W1 页的原文 `No more cold, mechanical suction. Just warmth, comfort, and care.`，以及 R5 的改写建议 SUG-21 处理的是 `Say goodbye to cold, painful pumping`。**该句同时含 `cold`（合规）与 `painful`（H07 命中）**，两个词在同一个句子里。
> **[判断]** 如果执行器把整句交给 H07 并记录了 `say goodbye to cold` 作为片段，那么这是**片段截取错位**，不是规则本身的误报。**这一点决定了修法完全不同**：前者要修正则，后者要修片段提取。**需要向团队确认**（见 §7 Q3）。

| 关联规则 | 建议条数 | | 关联规则 | 建议条数 |
|---|---:|---|---|---:|
| H02 | 12 | | M01 | 3 |
| M07 | 5 | | H04 | 2 |
| H09 | 4 | | M03 | 2 |
| H01 | 4 | | M04 | 2 |
| M02 | 4 | | M05 | 2 |
| H07 | 3 | | H03 / H06 / H08 | 各 1 |
| H05 | 3 | | M06 / U03 / U04 | 各 1 |

**没有改写建议的规则（3 条）：U01、U02、安全词。**

**[判断] 关键洞察：这张 52 条的表按「实际发生过的违规表达」沉淀，不是按规则编号铺满的。**

证据是它给 H02 配了 12 条、H07 只配 3 条——**这与 §4.1 的生产触发频次（H07 命中 51 条、H02 命中 34 条）不一致**。如果它是按规则铺设的，比例应当接近触发频次；它不接近，说明它的排序依据是**别的什么东西**（很可能是「改写难度」或「实际被问到的次数」）。

**[判断]** 这意味着：**改写建议库天然就是错题本的一个视图，而不是规则库的分支。** 它记录的是「出过错的地方」和「正确的写法」，而不是「规则是什么」。

### 6.3 所以错题本缺的不是数据，是三个连接

已经存在的东西：

| 已有资产 | 条数 | 它记录什么 |
|---|---:|---|
| 记录表 | 291 | 机器判了什么（等级 + 命中规则 + 命中片段） |
| 规则表 | 21 | 规则是什么 |
| W1 卖点表达边界 | 19 | 人工判过的「卖点 → 三档 + 替换表达」 |
| 改写建议库 | 52 | 「出过的错 → 合规写法」的映射 |

缺的连接：

| 缺口 | 后果 |
|---|---|
| **记录表 → 人工结论**（没有任何列） | 无法知道某条判得对不对 |
| **人工结论 → 规则修订**（没有字段记录"这条结论导致哪条规则被改"） | 复核结论无法回流成规则改进 |
| **漏报的记录位置**（记录表只有"命中"，没有"应当命中但未命中"） | **假阴性完全没有存储位置** |

**[判断] 第三个缺口是最严重的。** 记录表的结构天然只能记录假阳性（机器判了），假阴性（机器没判但人发现了）**在数据模型里没有位置**。而小语种漏检（§5）恰恰全部表现为假阴性——**这就是 §0 说的因果链**。

## 9. 规则库交叉一致性检验（`audit_rule_consistency.py`）

对 21 条规则做四类交叉检验。**本节含一次判据修正，原样记录。**

### 9.1 T1｜规则间关键词重叠

| 规则 A | 规则 B | 交集关键词 | 交集大小 |
|---|---|---|---:|
| **H07** | **安全词** | `less pain`, `reduces pain` | 2 |
| H01 | H02 | `prevent mastitis` | 1 |
| H02 | M07 | `improve pumping efficiency` | 1 |

**[判断]** 三对重叠，其中注意：
- `prevent mastitis` 同属 H01（医疗功效）与 H02（催乳/增产）—— 一个词触发两条红线，**若两条的 `disposition` 不同，DMN 语义下会产生冲突**（当前两条都是「严格限制红线」，恰好一致，但这是巧合而非设计）；
- `improve pumping efficiency` 同属 H02（红线）与 M07（审慎）—— **严重度不同（红 vs 黄）**，这是真正需要 `hit_policy` 裁决的情形。

### 9.2 T2｜豁免词 vs 检测词 —— **一次判据错误的修正记录**

**v1 的错误结论**：脚本初版报告了 **4 组**「豁免词↔检测词」冲突：

| 豁免方 | 「检测方」 | 冲突词 |
|---|---|---|
| H06 | 安全词 | `fda cleared`, `fda registered`, `fda-cleared` |
| M01 | 安全词 | `low noise`, `low-decibel`, `quiet mode` |
| H07 | 安全词 | `comfort`, `gentle` |
| M02 | 安全词 | `adjustable suction`, `suction level` |

**为什么这是错的**：`安全词` 行的 `边界类型` = `安全词白名单`，其 `边界内容` 列逐字写着：

> 客观功能/真实认证关键词（**正面提示，不参与降级**）

它是一个**白名单，不做判险**。把它当 T2 的「检测方」，等于把「规则明确宣告这些词是安全的」误报成「规则自相矛盾」。

**修正方式**：`检测方` 只取真正的判险规则（`边界类型 ≠ 安全词白名单`）。

**修正后的结论**：

> **判险规则（20 条）之间的 豁免词↔检测词 冲突为 0 组。**

**[判断]** 这是一个**反直觉但重要**的结果：**这套规则库的内部一致性比它的表面质量问题要好。** 12 字段的位置错、语义重叠、粒度过粗（R3 §11.1 的诊断）都是**建模**问题，不是**逻辑**问题——规则之间没有打架。

**[判断]** 同时，R5 曾指出的「安全词表 `reduces pain`/`less pain` 与 H07 矛盾」，经本次检验**成立但需精确表述**：

- 它存在于 **H07 ↔ 安全词** 之间（见 T1），**不在两条判险规则之间**；
- 按白名单「不参与降级」的定义，它**不会造成运行时的双重结论**；
- 但它仍是一个**语义问题**：同一个词同时出现在「判险列表」与「安全列表」里，**对维护者是陷阱**——下一个人改 H07 时会认为 `less pain` 是禁用的（因为它在检测关键词列），改安全词表时会认为它是安全的。

> **这正是「豁免词」这个字段名本身有问题的第三个证据**（R3 §11.5 给的两个是 LegalRuleML 的 weak/strong permission 区分）。当白名单与判险词表存在交集时，**读者无法从表结构判断谁优先**。

### 9.3 T3｜检测通道完整性 —— **第二次口径修正**

**v1 的错误口径**：初版统计出 **413 个关键词「正则匹配不到」**。

**为什么这个数字没有用**：正则本来就不需要逐字覆盖关键词——它用 `\w*`、`[^.!?|]*` 覆盖词形变化与语序。例如 H01 的正则 `\bunclog\w*\b` 覆盖 `unclog`/`unclogs`/`unclogging`，而关键词列只写了 `unclog`，这**不是缺陷**。

**修正后的口径**——只报两类真正会漏的：

**(i) 无正则的判险规则：8 条 / 75 个关键词只有单通道**

| 规则 | 边界类型 | 关键词数 |
|---|---|---:|
| H03 | 严格限制红线 | 9 |
| H04 | 严格限制红线 | 12 |
| M02 | 审慎关注 | 8 |
| M04 | 审慎关注 | 11 |
| U01 | 人工复核 | 14 |
| U02 | 人工复核 | 6 |
| U03 | 人工复核 | 5 |
| U04 | 人工复核 | 10 |
| **合计** | | **75** |

**[判断]** 这 8 条里 **H03、H04 是红线**（临床背书、专家推荐背书）—— 两条最重的规则之一只有关键词通道，没有任何模式匹配。这意味着它们**只能命中逐字相同的写法**：`clinically proven` 会被命中，`proven in clinical trials`、`clinical studies demonstrate` 不会。

> R5 §9.6 已实测到这一点：竞品在用 `FDA approved`（3 品牌）、`FDA compliant`（1 品牌），而 H06 的正则是 `\bFDA\s+(approved|certified)\b` —— **`compliant` 变体会漏**。

**(ii) 有正则，但中文关键词不可能被英文正则匹配：140 个**

| 规则 | 中文关键词数 |
|---|---:|
| H01 | 30 |
| H02 | 32 |
| H05 | 15 |
| H07 | 15 |
| M07 | 14 |
| H09 | 13 |
| H08 | 4 |
| M01 | 4 |
| M03 | 4 |
| H06 | 3 |
| M05 | 3 |
| M06 | 3 |
| **合计** | **140** |

**[判断]** 所有 13 条有正则的规则，其正则**全部是英文的**（正则列中无一个中文字符）。它们的中文关键词共 140 个，**在正则通道上永远不会被匹配**。

**[判断]** 这本身**不一定是缺陷**——如果投放文案没有中文，中文关键词就是给人工看的。但结合 §5.2 的实际语种分布（英语 199 / 德语 42 / 法语 20 / 西语 11 / 意语 9），**中文投放不在样本内**（`文案语种` 列无中文），所以这 140 个中文关键词当前是**未被使用的资产**。

### 9.4 T3b｜关键检验：「会漏」的词真的出现过吗

**[判断]** 光说「正则匹配不到」不等于会漏，要看词有没有真的出现。用 291 条广告文案的全文语料（Primary Text + Headline + 广告名称 + 广告系列 + 命中片段）实测：

| 规则 | 在语料中出现过的关键词 | 该规则有正则? |
|---|---|---|
| H04 | `ibclc-recommended` | **否** |
| H04 | `ob-gyn recommended` | **否** |
| H04 | `recommended by 100+ experts` | **否** |
| M04 | `limited time` | **否** |
| M04 | `don't miss` | **否** |
| U01 | `ibclc` | **否** |
| U01 | `泌乳顾问` | **否** |
| U02 | `hsa` | **否** |
| U02 | `fsa` | **否** |
| U03 | `hospital` | **否** |
| U04 | `painful pumping` | **否** |
| **H08** | **`秒杀`** | **是（但匹配不到）** |

**共 12 个「会漏且真的出现过」的关键词。**

**[判断]** 这张表把 §9.3 的抽象缺口变成了具体的风险清单：

- 11 个来自**无正则的规则**——它们在真实文案中出现了，而规则只有关键词通道，**任何词形变化都会漏**；
- **1 个是 `秒杀`（H08）**：H08 的正则是 `\b\d+x\s+(better|more)\s+than\b`，只能匹配 `10x better than` 这样的数字倍数对比，**中文的「秒杀/碾压/完胜」形态完全匹配不到**。而 `秒杀` 确实出现在语料里。

> **但这条需要与 §4.2 交叉读**：H08 在生产中命中 0 次。而语料里出现了 `秒杀`。**这意味着 H08 曾经面对过它本该命中的文案，却没有命中** —— 这是一条**已发生的假阴性**（而非潜在风险）。
>
> **这是全文唯一的、有直接证据的漏报实例。** 虽然只有 1 个词，但它证明了 §6.3 的论断：**假阴性在现有数据模型里没有存储位置，所以它只能靠这种交叉比对偶然发现。**

### 9.5 T4｜边界类型 vs 风险等级

| 边界类型 | 对应的风险等级 |
|---|---|
| 严格限制红线 | 高危 |
| 审慎关注 | 审慎 |
| **人工复核** | **审慎, 待复核** |
| 安全词白名单 | 合规 |

| 风险等级 | 对应的边界类型 |
|---|---|
| 高危 | 严格限制红线 |
| **审慎** | **人工复核, 审慎关注** |
| 待复核 | 人工复核 |
| 合规 | 安全词白名单 |

**[判断]** 两列**接近**双射但有 2 处例外，且例外都出在 `人工复核` 上：

- `边界类型 = 人工复核` 对应 **两种**风险等级（审慎 M05、待复核 U01/U03/U04）；
- `风险等级 = 审慎` 对应 **两种**边界类型（审慎关注 M02、人工复核 M05）。

**这修正了 R3 §11.1 的判断。** R3 写「`风险等级` 与 `边界类型` 一一对应（高危↔红线、审慎↔审慎关注、待复核↔人工复核、合规↔白名单），是同一信息的两次编码」。

**[判断]** 实测结果是：**4 组映射中 3 组确实一一对应，第 4 组（人工复核）是 1 对 2。** 所以：

- R3 的核心结论（**两列存在大量冗余编码**）**成立**——3/4 的取值可以互相推出；
- 但「一一对应」这个说法**不精确**。`人工复核` 这一档实际上承载了两种语义：**「这一档本身就是最终处置」（M05，判为审慎即止）** 与 **「这一档需要人来看」（U01/U03/U04，判为待复核）**。

**[判断]** 这恰恰说明 `边界类型` 这一列**混合了两个不同的概念**——R3 已经指出它混了 `modality` 与 `severity`，本次检验补充第三个：它还混了 **`disposition`（命中后处置）**。M05 与 U01 的差别不在严重度，而在**下一步做什么**。

### 9.6 检验汇总

| 检验 | 发现数 | 性质 |
|---|---:|---|
| T1 规则间关键词重叠 | 3 对 | 需要 `hit_policy` 裁决（H02↔M07 的严重度不同） |
| T2 判险规则间 豁免词↔检测词 冲突 | **0 组** | **规则库内部逻辑一致** |
| T2b 同规则内 豁免词↔检测词 冲突 | 0 条 | — |
| T3(i) 无正则的判险规则 | **8 条**（75 关键词单通道） | 通道缺口，含 2 条红线 |
| T3(ii) 中文关键词无法被英文正则匹配 | 140 个 | 当前样本无中文投放，属未使用资产 |
| **T3b 「会漏且真的出现过」** | **12 个**（含 1 条已发生的假阴性） | **可直接行动的风险清单** |
| T4 边界类型↔风险等级 | 非严格双射（3/4 冗余） | 修正 R3 的「一一对应」表述 |

**[判断] 本节的总判断：这套规则库的问题不在「规则打架」，而在「表达力不足 + 通道不完整 + 元数据冗余」。**

- 规则之间**不矛盾**（T2 = 0）—— 这是好消息，说明规则是人写的、有判断的，不是机器批量生成的；
- 但 **8 条规则只有单通道、140 个中文词在正则里够不着、12 个会漏的词已经出现** —— 这解释了为什么 291 条里只有 132 条被命中（45.4%），而 §4.2 的 6 条规则零命中；
- **`边界类型` 一列混了三个概念**（modality / severity / disposition）—— 这是 R3 诊断的加强版，也是「规则库该如何定义」这个问题的直接证据。
