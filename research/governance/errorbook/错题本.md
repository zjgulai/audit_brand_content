## 这是什么

**它不是一份新的设计文档，是一份可以打开就填的表。**

用户原话问过：「是否需要给我们提供『错题本』？还是规则库？严重等级？要是没有呢？怎么处理？」
这份文件回答的是**错题本长什么样、由谁产生、填完之后去哪里**。

## 两类错题的区别（重要）

| | A 类：内容错题（`EB-NNNN`） | B 类：规则错题（`EB-RNNN`） |
|---|---|---|
| 记的是 | 某一条具体内容判得对不对 | 某条规则本身有没有缺陷 |
| 谁产生 | 自动导出 + 人工复判 | 静态检查，自动产生 |
| 谁来填 | **复核人**（填 `人工复判结论`）+ **规则维护人**（填 `处置码`） | **规则维护人** |
| `内容ID` | 有 | 空（它不针对具体内容） |
| 复判结论的意义 | 决定这是 FP 还是 FN | 不适用 |

**B 类是这个错题本里最容易被人忽略、但价值最高的一类。** 它不需要等任何一条文案出错就能发现规则的问题。

### B 类里的第三个发现路径：迁移对账（`来源 = 迁移对账-*`）

原有 B 类全部来自 `audit_rule_consistency.py` 的**静态检查** —— 它看的是规则**今天**长什么样。
但规则不是长出来的，是**从旧的规则库翻译过来的**；翻译会出错，而**翻译错了之后，
每一条规则单看都是自洽的**，静态检查永远看不见。

这类错题只能靠**把新旧两份规则放在一起对账**才能发现。本批来自
`audit_migration_fidelity.py`：旧规则集（21 条，H/M/U 编号）→ 骨架 v1。

判据不靠任何分类字段，而是**实测**：旧规则的 94 个豁免词里，只有
「**自身就会命中本规则**」的 36 个词，豁免才真正生效过。把这 36 个词逐个喂给引擎，
看它拿到什么带：

| 实测带 | 条数 | 是什么 | 处置 |
|---|---:|---|---|
| 无带（**满档判险**） | **21** | 词在守卫表里但 `已接线=False` → 对引擎零影响，规则按 `L4 auto_reject` 判险。含 8 个中文否定式（`不能治疗`…） | **决定接线与否**；中文 8 个优先 —— 免责声明被自动拒绝 |
| `downgrade`（降级） | 13 | 已接线，但落点从「放行」被改成「降级」。含 `treat yourself`（已翻掉 3 条记录） | 逐词定性：词义消歧 → 应放行；否定式免责声明 → 交法务 |
| `pass`（仍放行） | **2** | `silent mode` / `静音模式` —— 旧语义**唯一活下来的两个** | 不用动（D3 法务定案的成果） |

★ 三桶之和必须等于 36，守恒成门（`V45c`）。

★ **语种不对称**：`not intended to treat` 是降级，`不能治疗` 却是满档判险。
同一个意思，语种不同、结局不同。

> （词条自带「机器推导 · 语义归属待法务确认」）这个未确认的启发式上，
> 并把源表写明的三层设计压成了两层。撤回记录见

## 怎么用（三步）

### 第一步：填 A 类的 `人工复判结论`（132 条）

这是唯一需要人力投入的动作，也是**目前完全没有在做的事**（`检查人` 列非空率 0.0%）。

- 高危（L4）**全部**要复判，审慎（L3）抽 20%
- 填写 `维持原判` / `推翻-应判违规` / `推翻-应判合规` / `无法判定`
- 同时填 `复判人` 与 `复判时间`

**为什么要做这一步**：现在这 132 条在表里只有「待人工复核」一个状态，**没有出口**。规则判了红/黄/灰，但没有任何地方记录人看了之后怎么想。这一步做完，`误拦 (FP)` 与 `漏放 (FN)` 才第一次变得可计算。

### 第二步：填 B 类的 `处置码`（45 条）

B 类不需要复判，直接进入规则维护流程。填 `直接改规则` / `部分改规则` / `评估中` / `不改（附理由）`。

**注意**：`不改（附理由）` 也是一个合法答案，但**理由必须写**。允许不改，不允许不说明。

### 第三步：每周新增「随机抽样」批次

A 类是**按风险优先**导出的（来自投放金额排序的表），它**只适合用来发现错误，不能用来估计错误率**（R4 §7.2.2）。

要算比率，必须另建随机批次：**每周从 `合规·绿` 里随机抽 30 条复判**，并且**按语种分层**（德/法/西/意 每语种每两周至少 5–10 条）。

> 原因：这套规则库的检测关键词里，**小语种词占比 0%**（424 个关键词，0 个小语种），而实际投放的非英语文案占 28.2%。**不按语种分层抽样，小语种的漏检永远不会被发现。**

## 这份文件没有做什么

为了不误导，明确列出**没有**做的事：

| 没有做 | 原因 |
|---|---|
| 没有生成假的内容 ID 或复判结论 | 不臆造数据。所有需要人工判断的字段一律留空 |
| 没有把'合规·绿'的 157 条纳入 A 类 | 它们是自动放行的，不是"待复核"。要采集它们的错误需要**另建随机批次**（第三步） |
| 没有包括官网产品页 / Amazon listing | 现有 291 条全部来自 Google(262) 和 Meta(27)。**官网与 listing 尚未进入审查范围** —— 这是需要确认的问题，不是本文能解决的 |
| 没有计算任何"准确率" | 没有随机样本 + 没有复判结论，**任何比率都是假的** |
| 没有臆造"小语种命中"的归因 | 32 条被标注出来了，但**为什么会被命中**（是否存在第二套检测逻辑）需要向团队确认，见 `05-内部证据` §7 Q3 |
