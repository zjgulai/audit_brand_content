## 3. ★ 本次跑出来的五处设计文档更正

设计文档 §2/§4 有四处判断，**跑过之后需要改**。第五处是数据层面的发现。

### 更正 1：「绝对化表述」不能与「医疗功效」并列为主题（§0.3）

设计文档 §2.2.1 把 T5「绝对化表述」列为与 T1「医疗功效」并列的主题。
实测冲突：`the best breast pump for pain relief` 必须同时归 T1 和 T5；
`clinically proven to double milk supply` 要归 T3 + T2 + T5。

**「绝对化」修饰的是另一条声明，它自己不构成主题。** 已改为正交轴
`qualifier_axis ∈ {safety, performance, quantity, time, exclusivity, comparison, none}`。
T5 只保留能独立成立的安全性主张（`safe` / `no side effects`）。

### 更正 2：`安全词` 既不是规则，也不是白名单 —— 它是「主题 + 常量表」（§2.2.1）

设计文档说「T9 是一个主题，不是一张白名单」——**这句对，但只说了一半**。
第一版把安全词当普通规则跑，**142 次误报，Precision 从 1.00 掉到 0.478**。
因为每一条含 `hands-free` / `wearable` 的文案都会「命中一条规则」。

已加 `is_modifier: true`。三者的区别是：
```
主题   = 分类节点（用于挂载与盲区统计）
白名单 = 一组字符串常量（用于豁免判定）
规则   = 可产生命中的判定逻辑
```

### 更正 3：跨主题规则是 7 条，不是设计文档映射表里的 0 条（§2.2.1）

设计文档给的映射是**一对一**（H01→T1、H02→T2、H07→T1…）。实测：

| 原规则 | 实际横跨 | 直接证据 |
|---|---|---|
| H02 | T1.2 疾病预防 + T2.1.1 奶量提升 | 它的 `边界内容` 字段用分号列了三段不同边界 |
| H07 | T1.4 症状缓解 + T2.1.2 人体结果 | 同一个 `pain relief` 两种主题 |
| U03 | T3.3 等级背书 + T7.1 医疗场景 | `hospital grade`（要认证文件）≠ `hospital` 场景（要使用真实性） |
| U04 | T1.5 疏通 + T7.2 痛点场景 | 场景名词 + 消除性动词 = 功效承诺 |
| H05 | T5.1 安全 + T2.2 适体性 | 「适合所有胸型」是性能主张，不是安全主张 |
| M03/M04/M05/M07 | 各自跨两叶 | — |

**这不是分类错误，是现行规则表把多个主题压进了一条规则。** 后果是
**规则无法按主题重组**（P2-2），因为拆之前得先知道拆成几条。
本骨架拆出 26 条，`parent_rule` 字段保留可追溯性。

### 更正 4：NIST 矩阵证伪乘法的力度比文档说的更强（§4.3.1）

设计文档列了 **3 处**乘法与查表的结论差异。实测**25 格里有 13 格不同**：

```
likelihood=Very Low  impact=Very High  → 查表=Low       乘法≈Moderate
likelihood=High      impact=Very Low   → 查表=Very Low  乘法≈Moderate
likelihood=Very High impact=Moderate   → 查表=Moderate  乘法≈High
... 共 13/25
```

封顶效应已复现：`Low likelihood` 行最高只到 `Moderate`，`Very Low` 行最高只到 `Low`。
**乘法不是这张矩阵的近似，是一个不同的模型。**

### 更正 5 ★：43% 的命中记录从未投放 —— `exposure` 的结构问题比文档说的更严重

设计文档 §4.3.2 说 exposure 缺 `irreversibility` 与 `remediability` 两维。**这是对的，但漏了更基本的一层：**

```
132 条有命中的记录中，展示量 = 0 的有 57 条（43%）
```

这 57 条**不是「低暴露」，是「从未真正投放」**。查表会把它们判成 `Very Low`，
而 `Very Low` 的含义是「低风险」——**语义错误**。它们应当是一个独立类别。

**另一个必须显式声明的选择：分箱阈值完全改变结论。**

| 分箱方式 | High | Moderate | Low | Very Low |
|---|---:|---:|---:|---:|
| 固定阈值（10k / 50k / 150k） | **2** | 10 | 104 | 16 |
| 分位阈值（p20/p40/p60/p80） | **53** | 0 | 63 | 16 |

同一份数据，High 档从 2 条变成 53 条。**所以 `likelihood_bin` 的阈值是业务决策，不是技术参数** ——
本骨架采用**固定绝对阈值**（理由：分位阈值让「高暴露」变成相对概念，
一条 500 次展示的测试广告在有它自己的分位里也会变成「高暴露」，这没有业务含义）。
**这个选择必须写进规则库的元数据，不能藏在代码里。**

## 4. ★ Q3 的答案：不是「谁判的不知道」，是「人类在替规则补小语种」

设计文档把 Q3 列为待确认问题（「`schmerzfrei` 等 31 次命中来源不明」）。**本骨架给出了答案：**

```
现行 238 次命中片段中，规则的关键词/正则能复现的 200 次（84.0%）
规则完全无法复现的                          38 次（16.0%）
```

**无法复现的部分不是随机的，是语种性的。** 人工复核记录里写着规则表里没有的词：

| 规则 | 规则外片段 | 语种 |
|---|---|---|
| H02 | `augmente la production de lait` / `plus de lait` / `mehr milch` / `más leche` / `producción de leche` | fr / de / es |
| H07 | `schmerzfrei` / `sans douleur` / `indolore` / `sin dolor` | de / fr / it / es |
| M01 | `cicha` / `silencieux` / `silenciosa` / `silencioso` | pl / fr / es |
| M05 | `qualité hospitalière` | fr |
| U02 | `krankenhaus` | de |

**判据**：这些记录的 `修改建议` 字段里，31/31 条显式写着这几个词。
**改规则的人知道这些词，但没有把它们写进规则表。**

**反证**：U01 是唯一 15/15 全部可机械复现的规则 ——
因为它的关键词全是**英文头衔**（`ibclc` / `lactation consultant`），**没有小语种暴露**。

→ **结论：语种缺口 = 规则缺口。** 不是「检测通道不明」，是「规则表缺了 5 个语种的词，
由人工在补」。修法明确：把这批词 codify 进规则库（已在 `rules-v1.json` 中以
`detection_layer: "codified"` 标注，与 `native` / `added` 区分）。

## 5. 我们自己的缺陷（记在案，不推给数据）

跑这个骨架的过程中，**我们犯了 4 个错误**，其中 2 个正是设计文档警告过的类型：

| # | 错误 | 后果 | 怎么发现的 |
|---|---|---|---|
| **E1** | 改写 H05 正则时把 `\s+` 放进了可选组，`\bthe\s+(only\|safest)\b` 退化成 `\b(only\|safest)\b` | **32 次误报**：`weighs only 230g`、`Only $225.24 CAD`、`Only 4 parts to clean` 全被判成虚假安全承诺 | 逐条打印命中词，发现 32 次全来自同一条正则 |
| **E2** | 转录 H05 关键词时**漏抄 `perfect pump`** | 12 次漏报 | 漏报归因把它标成 A 类（片段在正文里） |
| **E3** | 第一版把 `安全词` 当普通规则 | 142 次误报，P 从 1.00 掉到 0.478 | 看到「安全词 FP=142, TP=0」 |
| **E4** | 一次 `python3 - <<PY` 脚本在 `write_text` **之前**抛 KeyError | 补的 4 组关键词**全部丢失**，但我的下一步以为已生效 | 重跑后 M07/M02/H05 仍是 0，回读 JSON 才发现 |

**E4 的教训最值得记**：脚本崩溃时文件未改动，而**没有回读校验就无法察觉**。
后续所有写盘都加了回读校验（`json.loads(p.read_text())` 后再打印实际变化），
并加了「`rule_key` 主题段必须与 `topic` 一致」的漂移校验 —— 因为改名时确实漂移了 3 条。

## 6. 剩余 16 处的最终归因

**9 次漏报：**

| 类 | 数量 | 说明 |
|---|---:|---|
| C 不可验证 | 5 | 片段在整条记录里都找不到（含 `GG-479814e83bf0` 一条占 4 个）。**现行判定依据的文本不在表内** —— 最可能是落地页内容或完整创意。需要 Q2/G0 回答 |
| **规则归属不一致** | **2** | `improve pumping efficiency` 被现行表**同时挂在 H02 和 M07 两条规则下**（见 §6.1） |
| D 模糊匹配 | 2 | `augmente la production de lait` / `smoother milk flow` —— 正文有近似表述、无逐字片段 |

### 6.1 ★ 新发现：同一片段被挂在两条规则下，且现行表内部不一致

记录 `GG-f810ceaf2420` 与 `GG-5d9c3ac7ee11`（同一文案的两条广告）：

```
现行命中规则: H02, H05, M07
现行命中片段: H02:improve pumping efficiency / H05:perfect pump / M07:improve milk flow,improve pumping…

同一片段 `improve pumping efficiency` 出现在 H02 段**也**出现在 M07 段。
```

**这是规则边界重叠，不是判定结果的规则冲突。**

设计文档 §2.5.1 记录「规则交叉一致性检验 T2 = 冲突 0 组」，并据此写「规则库内部一致」。
**这个结论需要限定范围**：T2 检验的是**规则两两之间对同一内容的判定是否矛盾**
（即「A 说放行、B 说拦截」）。而这里的问题是另一类 ——
**同一条文案的命中片段被重复计入两条概念不同的规则**：

| 规则 | 概念 | 是否合适 |
|---|---|---|
| H02 | 奶量产出承诺（**生理结果**） | ✗ `pumping efficiency` 是机器/过程侧 |
| M07 | 效率/奶流/移除量（**过程**） | ✓ 正确归属 |

**后果**：命中计数被虚增，且**规则的触发频次统计不可信** ——
而设计文档 §4.4 的等级校准与 P1-5 的 golden set 都建立在触发频次上。

**已修**：本骨架把 `improve pumping efficiency` 只归 `T2.1.3.milk-flow`（M07）。
`H02` 的 31 次 TP 中不含这 2 次，故 Recall 记 0.91 而非 0.97。

**7 次误报：**

| 类 | 数量 | 说明 |
|---|---:|---|
| **真阳性，现行表漏了** | **3** | `Treat yourself to total comfort!` —— `treat yourself` **本来就在 H01 的 44 个豁免词里**，但现行判定没记录这三条。**建议升级为现行表的疑似漏报** |
| 多语言词汇 | 2 | 波兰语 `bestsellery`、法语 `Recommended by IBCLCs and OB-GYNs`（H04 正则未含 IBCLC 缩写） |
| 边界 | 2 | 见下 |

> ⚠️ **本报告的比较基准是 `命中规则` 字段，而它是「人工判定」，不是「规则执行结果」。**
> 所以这里算出的 P/R 是「新引擎 vs 人工」，**不是「新引擎 vs 现行规则」**。
> 设计文档 §2.5 记录的「现行正则只能复现 13.8% 人工判定、且从不多报一条」
> 说明现行正则与人工判定是两套东西 —— 这个差别必须在引用 P/R 时说清。

## 7. 这套骨架证明了什么、没证明什么

**证明了：**

1. 三层结构（主题 × 正交属性 × 风险级）**在真实数据上可执行** —— F1 0.966；
2. 严重等级查表**可以零采集成本落地** —— 用的就是表里已有的 `近7天展示`；
3. `CATCH-ALL` 让**盲区第一次可数** —— 159 条 / 54.6%；
4. Q3 有确切答案（§4）。

**没有证明：**

1. **Precision 0.970 不等于「规则准」** —— 基准是人工判定，不是独立标注（见 §6 警告）；
2. `exposure` 的**分箱阈值是业务决策**，本骨架只给了一个有理由的选择（§3 更正 5），不是校准；
3. `irreversibility` / `remediability` **仍然没有数据**，代码留了接口但没执行；
4. **CATCH-ALL 的 159 条从未被复判** —— 54.6% 这个数字是「命中数」，不是「盲区率」。
   要变成盲区率，需要 P0-6 的人工复判；
5. **α 一致性仍然算不出来** —— 标注指南（G-ANNO-1，特别是 T1.4 ↔ T2.1.2 的边界）还没写。
