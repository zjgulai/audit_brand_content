## 四之二、飞书同步：两条必须记住的规矩（2026-09-16 实测追加）

```bash
python3 tools/migrate_vocab_to_lark.py                 # 预演（不写）
python3 tools/migrate_vocab_to_lark.py --apply --force # 重建：非空表**必须**显式 --force
python3 tools/verify_vocab_lark.py                     # 回读逐词比对 + 重复行检查
```

1. **非空表拒绝写入。** `migrate_vocab_to_lark.py` 用的是 `batch_create`，
   那是**追加**不是替换。原先它无条件追加，所以**跑一次是对的、跑两次整表翻倍**，
   而两次的输出一模一样全是 ✅。现在写入侧加了闸门：表非空即拒绝，重建必须 `--force`。
   实测踩到的后果：守卫表 174 行（85 词）、白名单表 56 行（30 词）。
2. **行数 ≠ 唯一词数，两个都要看。** `verify_vocab_lark.py` 原先按词建索引，
   同一个词的第二行被静默覆盖 —— 它当时报「飞书 89 条 / 字段不符 0」，
   而真实行数是 174。**集合式比对看不见重复**，而业务看的就是行数。
   现在它数行数、列重复词、并让重复导致验证失败。

> ★ 这两条合起来的教训：**一个工具说「已同步」，还需要问它比的是集合还是行数。**
> 「跑一次对、跑两次错」是最难发现的一类缺陷，因为两次的输出都是绿的。

## 四之三、逐词落点覆盖（D9 · 2026-09-16）

`rules-v1.json` 的 `downgrade_band` 现在支持逐词覆盖：

```json
"effect": "auto_reject → auto_pass",
"keyword_effect_overrides": {
  "FDA registered": "auto_reject → manual_review",
  "FDA 注册":       "auto_reject → manual_review"
}
```

- **为什么需要它**：同一个带里的词强度可以不同。`FDA cleared` 是**器械层** 510(k) 状态；
  `FDA registered` 是**企业/设施层**注册，FDA 明确「注册不表示批准、许可或授权」。
  两者同为放行词，等于用一个关于工厂的事实为一个关于器械的主张背书。
- **两个带同现时降级优先**（保守）：`FDA approved. FDA cleared. FDA registered.` 判 `manual_review`，
  宁可多一次人工，不赌一次放行。
- **词的门禁没变**：`FDA registered` 仍在白名单表（注册号可查，可独立复核为真），
  只是它的**通道**是降级。这正是 W3 写明的边界 ——「放行与降级是两个通道，不是一件事」。
- **机检**：`lint_whitelist.py` 的 **W6**（W6a 死覆盖 / W6b 空改动 / W6c 非法落点）。
  ★ 与 W5 同一个病：**声明了但取不到**，行为与「没声明」完全一样 ——
  而 W6b 那种（落点与默认相同的「空改动」）更坏，因为评审时看得见一行新配置，
  会以为行为变了。
