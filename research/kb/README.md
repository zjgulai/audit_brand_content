## 三、怎么用

```bash
cd /Users/lute/Project/audit_multi_content

# 全流程（只读源系统，写飞书需显式 --apply）
python3 tools/kb_snapshot.py                  # ① 拉快照
python3 tools/kb_analyze.py                   # ② 结构分析
python3 tools/kb_build.py                     # ③ 生成台账
python3 tools/kb_index.py                     # ④ 索引本地资产
python3 tools/kb_evidence.py                  # ⑤ 需求→证据
python3 tools/kb_query.py --md                # ⑥ 查询手册
python3 tools/verify_kb.py                    # ⑦ 验收

# 落飞书（有副作用，需显式确认）
python3 tools/migrate_kb_to_lark.py --apply
python3 tools/migrate_kb_to_lark.py --roundtrip   # 回读比对
python3 tools/kb_materials_lark.py --apply

# 直接问问题
python3 tools/kb_query.py 2      # 哪些需求逾期了
python3 tools/kb_query.py 8      # 哪些需求有证据、哪些零证据
```

**改口径的正确姿势**：改 `schema-v1.json` → 重跑 `kb_build.py` → 重跑 `verify_kb.py`。
不要直接改台账 JSON，那会让指纹失配，`load.py` 会当场拒绝装载。

## 四、这份知识库**做不到**的事（显式声明，不是遗漏）

1. **算不出「卡在同一状态超过 N 天」。** 源系统只有当前状态，没有状态变更时间戳。
   用「提交日期至今」代替会把「一直没开始」和「做到一半停住」混为一谈。
   → 已登记为对源系统的数据需求：**状态变更需留痕**。

2. **逾期率不能外推。** 1160 条里只有 189 条有计划完成日期（16%）。
   「30 条逾期」是这 189 条里的事实，不是全部需求的事实。

3. **「产出物为空」≠「没有产出物」。** 可能只是没填。这张表回答的是**可追溯性**。

4. **10 条材料读不到。** 材料收集表 15 条里只有 5 条能以程序方式读取，
   其余 10 条是权限错误或 token 失效。**「收集了 15 条」是个错觉，实际可用 5 条。**

5. **353 条需求的品线未识别**（PSEO 的 `品类` 字段 283 条写的是
   「翼果未分类，后续文章已进行分类」—— 把一句话写进了分类字段）。

6. **不判断需求该不该做。** 知识库只呈现事实与缺口（ADR-0005）。
