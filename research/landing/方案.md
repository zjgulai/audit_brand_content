## 一、北极星

**回答法务自己写下的验证表第二层：「工具能否稳定获取并处理目标内容」。**

法务原文（逐字）：

> **可用性及覆盖能力** ｜ 验证目标：工具能否稳定获取并处理目标内容
> 指标：内容获取成功率 / 页面/素材识别完整度 / 处理耗时等
> 标准：满足初步验证范围内的基本覆盖和稳定运行要求

这三个指标今天**一个数字都没有**。本批次把它们变成可复算的数字。

一句话检验：法务问「你们抓得下来吗」，我们能给一个带分母的成功率，
而不是「应该没问题」。

## 二、为什么是这 92 个 URL

来源：`research/live/snapshot-20260916T050845Z.json` 的 `ad_copy` 表（291 条广告）。

| 事实 | 读数 |
|---|---|
| 带落地页 URL 的广告 | **204 条** |
| 去重后唯一页面 | **92 个**（204 条广告平均 1 个页面被 2.2 条广告引用） |
| 域名 | 10 个（`momcozy.com` 41 + 9 个地区站 + `www.amazon.de` 1） |
| 页面类型 | 产品页 48 · 博客 23 · 集合页 13 · 营销页 7 · 其他 1 |
| 同一产品跨 locale | **10 个产品分布在 2–10 个地区站** |

**这组 URL 不是随手挑的**，它同时满足三件事：

1. 它们是**真实投放中的广告**的落地页 —— 法务关心的「公司实际对外发布了什么」的最直接样本；
2. 10 个产品跨 2–10 个地区站 —— 直接构成法务「跨页面、跨版本整改闭环」的测试集
   （A 页面整改后，B/C 地区站是否同步）；
3. 23 篇 SEO 博客在样本里 —— 这是**没有进入任何人工审核流程**的内容类型，
   正好检验「上线后持续监测」面对的对象。

## 三、三个指标的操作化定义

法务的指标名逐字沿用，不改词。每个指标给出**可复算的定义**与**分母**。

### 3.1 内容获取成功率

分四档，**分母是全部 92 个 URL**，不剔除任何一条：

| 档 | 定义 | 判定 |
|---|---|---|
| `ok` | HTTP 200 且取得**可提取正文**（≥ 200 字符可见文本） | 成功 |
| `ok_structured` | 在上述基础上另有结构化数据（Shopify 商品 JSON 或 JSON-LD） | 成功（升级） |
| `empty` | HTTP 200 但可提取正文 < 200 字符（JS 渲染壳 / 空页） | 失败 |
| `blocked` | HTTP 401/403/429（被反爬或需登录） | 失败 |
| `error` | 网络错误 / 超时 / 5xx / DNS | 失败 |

**成功率 = (ok + ok_structured) / 92**，并**按域名与页面类型分别给出**
（因为「平均 95%」会掩盖「博客全挂」这类结构性事实）。

### 3.2 页面 / 素材识别完整度

对每个成功页面，检查**六类要素**是否提取到。这是「完整度」的分母：

| 要素 | 为什么它是要素 |
|---|---|
| `title` | 页面标题（含产品名与主张） |
| `body_text` | 可见正文（合规风险的主要载体） |
| `images` | 图片清单及 `alt` 文本（法务 PRD 明确要求跑图片素材） |
| `claims` | 认证/参数类声明（`FDA`/`mmHg`/`dB`/`hospital grade` 等） |
| `links` | 站内链接（跨页面关联与整改闭环的边） |
| `locale_signals` | hreflang / 货币 / 语言信号（跨版本对照的锚点） |

**完整度 = 该页提取到的要素数 / 6**，报告给出均值与逐要素覆盖率。

> 注意：完整度**只对获取成功的页面计算**，并显式声明这一点。
> 把失败页面算作「完整度 0」会让两个指标互相污染。

### 3.3 处理耗时

每页 wall time（含重定向）。报告 **P50 / P90 / P95 / max**，
并按「结构化端点」与「HTML」两条路径分列 —— 两者差一个数量级时，
这个差本身就是可执行结论。

## 四、范围与边界（明确不做的）

1. **只读**。不登录、不提交表单、不抓取 `robots.txt` 中 `Disallow` 的路径。
   实测前逐域名核对 `robots.txt`（本项目已核对 `momcozy.com`：本批 URL 均不在禁止列表）。
2. **限速礼貌抓取**。同域名串行、请求间隔 ≥ 1.2s、带真实 UA、遵守 429/Retry-After。
3. **不做判定**。本批次只回答「拿不拿得到、拿得全不全、快不快」。
   「拿到之后判得对不对」是批次 B（规则识别能力验证）的事，**本批次不越界**（ADR-0005）。
4. **不存全量 HTML 原文到报告里**。原始响应 gzip 落 `_evidence/`，
   报告只引用可复核的片段 + 内容指纹（ADR-0002）。
5. **Amazon 那 1 条照抓照报**。反爬失败会如实计入失败档并单列说明 ——
   它的失败是结论的一部分（Amazon 需要另一套获取策略），不是要抹掉的噪声。
6. **不做定时监测**。本批次是一次快照式实测；「持续监测」需要明确消费者后再评估。

## 六、验收（机器可判定）

| # | 检验 | 判据 |
|---|---|---|
| V1 | URL 清单完整 | `urls.json` 的 `total_ad_refs` = 204，唯一 URL 数 = 实际 |
| V2 | 分母诚实 | 成功率的分母 = URL 总数，**失败项没有被静默剔除** |
| V3 | 可复算 | 从 `_evidence/` 重跑 `lp_metrics.py` 得到同一组数字 |
| V4 | 指纹稳定 | 每个成功页面有内容指纹；同 URL 重抓指纹一致（或差异被记录） |
| V5 | 边界显式 | 报告必须包含「本批次做不到的事」一节；缺失即验收失败 |
| V6 | 无越界判定 | 产物中不得出现「该内容合规/不合规」的结论 |

**V5 与 V6 是硬门**：本项目已确立「声明 GAP 算通过，静默略过算失败」的验收风格。
