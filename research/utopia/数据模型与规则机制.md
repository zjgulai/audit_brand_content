## 1. 架构骨架：三层，而「ontology」只指中间那一层

> **evidence** `docs/design/ontology.md:12-17`：
> "**Three layers, and "ontology" names one of them.** The open graph holds what documents say… The ontology holds object types, link types and properties… The typed graph holds facts expressed in the ontology, computed from the open graph and marked with the ontology version it was computed under"
> "Since 2026-09-16 extraction writes the open graph and nothing else (#731, #736); the ontology enters no extraction prompt; typed facts will come only from alignment (0044 cut 2, not built)."
> "A base extracted today holds open statements and name facts and no typed facts, so signature checks, timelines and proposals have nothing to read until alignment lands."

这三句是理解整个仓库的钥匙，也是它当前最大的落地缺口：**抽取不再产类型化事实**。类型化图谱改由「对齐（alignment）」从开放陈述算出来，而对齐本身只做到一半（见 §7、§10）。

## 3. 双时态建模：**两条时间轴 + 第三条证据轴**

### 3.1 两条轴的名字与语义

| 轴 | 列 | 语义 |
|---|---|---|
| **世界轴（valid time）** | `valid_from` / `valid_to` + `valid_from_precision` / `valid_to_precision` + `valid_from_grade` | 这条事实在世界上何时成立 |
| **记录轴（transaction/record time）** | `recorded_at` / `invalidated_at` | 我们何时知道、何时推翻 |
| **证据轴（attestation）** | `attested_from` / `attested_to` | 最早那份说出它的文档的日期 / 说出它结束的那份文档的日期 |

> **evidence** `docs/design/time.md:9-13`：
> "**Two clocks, never one control.** `valid_from` / `valid_to` say when a fact held in the world; `recorded_at` / `invalidated_at` say when the base held it. Every graph read takes `at` (world) and `as_of` (record) separately; `at` absent means every moment, `as_of` absent means now"
> `migrations/0030_an_unknown_date_is_not_an_open_one.sql:8-11`：
> `-- attested_at：这一行的各次观察里，**最早那份文档的日期**。没有起点的事实从它起成立；结束了不知哪天的事实到它为止。它是世界轴上的时刻（文档的日期），不是 recorded_at（我们何时写下——另一根轴，0019）`

### 3.2 有效性怎么编码（三个最锋利的设计）

**(a) 精度是一条梯子，且「没日期就没精度」**，用 `date_trunc` 把「存的值 == 声称的精度」写成 CHECK：

> **evidence** `migrations/0033_the_world_axis_reaches_the_second.sql:8-11`：
> `-- 存的值截到自己的精度：date_trunc(precision, value, 'UTC') = value。精度的名字就是 date_trunc 的字段名，一条表达式说完`
> `migrations/0033:27-38`：`facts_from_precision_matches_date` / `facts_to_precision_matches_date`，梯子 `IN ('year','month','day','hour','minute','second')`，结束端多一个 `'unknown'`。
> 三值逻辑的坑被显式记下：`migrations/0033:13-14` `-- precision IN (…) 在 precision 为 NULL 时是 NULL，与 TRUE 相与仍是 NULL，而 CHECK 遇 NULL 判通过。所以每个分支都先写 IS NOT NULL。`

**(b) 「结束了，但不知道哪天」是一个显式状态，不是 NULL**：

> **evidence** `migrations/0003_graph.sql:256-258`：
> `--   仍在持续          valid_to IS NULL   valid_to_precision IS NULL`
> `--   结束了，不知哪天   valid_to IS NULL   valid_to_precision = 'unknown'`
> `--   2023 年结束       valid_to = …       valid_to_precision = 'year'`

**(c) 「日期是怎么得来的」决定它能不能改写历史**：迁移 0069 把时间解析等级从 `time_mentions.grade` 带到 `facts.valid_from_grade`，引擎据此决定后任能否关闭前任。

> **evidence** `migrations/0069_a_timeline_closes_on_how_a_date_was_got.sql:9-15`：
> `-- 起点是 A 或 B 的后任照常关上前任，起点是 C 的不许改写历史（它的位置本来就是猜的），跳过它、这一对交给人。数字从引擎里出去`
> `crates/utopia-store/src/temporal.rs:157`：`self.valid_from_grade.as_deref() == Some("C")`

### 3.3 「append-only」的准确含义（别被手册误导）

手册说 "A fact is a row that is never updated in place"（`docs/design/ledger.md:9`），**代码里 `facts` 行会被 UPDATE**：作废写 `invalidated_at`、闭合写 `valid_to`、确认改 `confidence`、时间解析写 `valid_*`。

> **evidence** `migrations/0051_a_conflict_that_evaporated_was_not_decided.sql:27-28`：
> `--   2. 退场发生在**作废的那一刻**…置 invalidated_at 的地方有十二处，撤销作废还有四处`
> `migrations/0030:27-28` `ALTER TABLE facts ALTER COLUMN attested_at SET NOT NULL`；`crates/utopia-store/src/graph.rs:1014` `UPDATE facts SET … valid_to = $4, valid_to_precision = $5, valid_from_grade = $6 …`

**准确说法**：可变的是**状态位**（有效/作废/闭合/置信度），不可变的是**断言的语义**——纠正一条事实必须插新行 + `supersedes`，而不是改旧的 `object`/`valid_from`。`docs/decisions/0006` 的注释把违反这条的旧写法点名了：`concept_mappings` 从前借 `UPDATE facts SET confidence = 1.0` 表达「确认」，`-- 而账本是 append-only 的…一个需要原地改状态的东西住在一张不许原地改的表里，本身就是它不合身的证据`（`migrations/0006_semantic_layer.sql:39-43`）。

### 3.4 回放（rewind）的实现

- 世界轴 + 记录轴**永远是两个参数**：`at`（世界）与 `as_of`（记录）。
- 单一谓词：`held_at(T)` = `recorded_at <= T AND (invalidated_at IS NULL OR invalidated_at > T)`。

> **evidence** `docs/decisions/0019-the-second-clock-can-be-rewound.md:19`：
> "`held_at(T)` — `recorded_at <= T AND (invalidated_at IS NULL OR invalidated_at > T)`, where `None` means now. Every **read** that hard-codes `invalidated_at IS NULL` takes it instead."
> 同文 `:13`：`That hard-coded filter appears 26 times in graph.rs and 54 times across the store.`
> 同文 `:23-25`：`-- **Two parameters, never one control**… Folded into one slider they would answer "the world in March, as we understand it now" with "the world in March as we understood it then", or the reverse, and both look plausible on screen.`

## 4. Provenance：一条事实怎么系回一句原文

### 4.1 链条

```
facts row ──fact_evidence(fact_id, chunk_id, quote, quote_start/end, proposed_predicate)
          ──chunks(id, text, origin, origin_model, anchor, document_id, superseded_at)
          ──documents(id, sha256, doc_time, doc_time_source, deleted_at/purged_at)
          ──document_versions(version, sha256)   ← blob 内容寻址，不删
```

### 4.2 五个可引用的硬事实

1. **引文偏移是字符，服务端算，模型报的数字不算数。**
   `migrations/0061:47-50`：`-- 引文在 chunks.text 里的字符偏移（不是字节）；NULL = 没定位到`；`crates/utopia-server/src/extraction_open.rs:45-47` 注释同上。
2. **模型原话落在证据行而不是事实行。** 因为事实按 (kb,主,谓,宾) 去重，甲块说 "runs on"、乙块说 "optimized for" 会并成同一行。
   `migrations/0003_graph.sql:306-309`：`-- 模型原话。**落在证据上而不是事实上**：…放事实上就是先写者胜、其余静默丢弃。`
3. **证据行记 doc_version**，用于「证据过期」判定：`migrations/0003_graph.sql:303-305` `-- 证据出处版本：出自哪份文档的第几版（版本对账与"证据过期"展示的判定依据）`。
4. **一段文字的来源记在分块上，而不是证据行上**：`stated / ocr / transcribed / described`，且 `described`（模型对图表的转述）**不能单独改写账本**。
   `migrations/0058:2-4`：`-- 一块文字从哪来（0040）：原文写的、扫描页上认出来的、录音里转出来的、模型看图说的。`
   `docs/decisions/0040-a-chunk-says-where-its-words-came-from.md:49`：`described | a chart, a photo, a diagram | **a model's paraphrase of a picture — nobody wrote or said it** | cannot be checked word for word`
   实现：`docs/design/ledger.md:29-31`：`A fact from a described chunk closes nothing by itself: the temporal engine reads the chunk's origin and opens a described_evidence conflict instead of closing a correct fact… Its confidence is also capped below the review threshold`
5. **原文读得回来，而且是契约**（ADR 0052，状态 proposed）：`GET /api/v1/documents/{id}/content[?version=N]` + `/versions`，purge 后 `410 Gone`，账有 blob 缺失 `500`。
   `docs/decisions/0052-document-content-is-a-read-contract.md:21-25`、`:41-44`。

### 4.3 「记录一句话不等于断言一个事实」（ADR 0015）

`remember` 抽出的三元组先进 `pending_facts`，人点头才写 `facts`。

> **evidence** `docs/decisions/0015-recording-a-sentence-is-not-asserting-a-fact.md:9-14`（实测起因）：
> The user said "Please remember this: Acme moved its headquarters to Shenzhen on 2026-03-15."… The graph got `Acme --(empty predicate)--> Shenzhen`, confidence 0.9, live… and what was said and what went in differed with no way to notice.
> `migrations/0018_a_fact_awaiting_a_nod.sql:20-22`：`-- **只拦交互式的单条写入，不拦批量摄入。** 灌 500 篇文档抽出一万条事实，让人逐条确认是不可能的；那条路仍旧乐观写入 + 事后审阅。`

## 5. 基数/函数性属性与公理存储；「X 必须不发生」怎么表示

### 5.1 公理存在哪

全部落在 `relation_types` 一行上（8 个布尔/引用列）+ 两张 domain/range 关联表 + 一张类互斥表：

| 公理 | 列/表 | 消费者 |
|---|---|---|
| functional（主语侧唯一） | `relation_types.functional` | 时态引擎（自动闭合）、R0 `functional` 违规、0027 合并闸门 |
| inverse_functional（宾语侧唯一） | `relation_types.inverse_functional` | 同上（0053 起与 functional **分开报**） |
| transitive | `is_transitive` | R1 编译成规则 + R0 `cycle` 检查 |
| symmetric | `is_symmetric` | R1 编译成规则 |
| asymmetric | `is_asymmetric` | R0 `asymmetry` |
| irreflexive | `is_irreflexive` | R0 `self_loop` |
| inverseOf | `inverse_of` | R1 `inverse` 规则 |
| subPropertyOf | `sub_property_of` | R1 `sub_property` 规则 |
| domain / range | `relation_type_domains` / `_ranges` | 写入时方向判定 + R0 `signature` 违规（SQL 算） |
| disjointWith | `entity_type_disjoint` | **只被本体自检消费**；身份消解里作为 cannot-link |

> **evidence** `migrations/0003_graph.sql:72-79`：
> `-- 其余属性公理，跟 functional / inverse_functional 同族…**默认 false 而不是 NULL**：OWL 是开放世界，但一致性检查只能按写下来的判，「没声明」与「声明为否」后果相同`
> `0003_graph.sql:77-79` 还记了一个工程细节：`-- **列名带 is_ 前缀不是风格洁癖**：symmetric 与 asymmetric 都是 Postgres 保留字（BETWEEN SYMMETRIC）`

### 5.2 「一条规则说 X 必须不发生」

**今天有三种可用的表达，全部是「事后查出违规 + 人裁决」，没有一种是「事前拒绝写入」：**

| 想表达 | 落到哪 | 代码位置 |
|---|---|---|
| 「同一主语同一时刻只能有一个值」 | `functional=true` → R0 报 `functional`，或时态引擎自动闭合 | `crates/utopia-reason/src/lib.rs:74-101`（`Kind::Functional`） |
| 「一个类不可能同时属于两个互斥类」 | `entity_type_disjoint` → 目前**只有本体自检 + 消解不能链** | `docs/decisions/0001:193-196`：`disjointWith is consumed only by R0's ontology self-check` |
| 「这条边不可能指向自己 / 不可能双向 / 不可能成环」 | `irreflexive` / `asymmetric` / `transitive` → R0 报 `self_loop` / `asymmetry` / `cycle` | 同上 |
| 「条件满足则**推出**结论」 | `attribute_rules`（正向蕴含） | `migrations/0028`、`crates/utopia-reason/src/rules.rs` |

**表达不了的东西（都有明文决定，不是遗漏）：**

- **否定即失败 / 缺失条件**：「这个实体压根没有某属性」不是条件。
  `crates/utopia-reason/src/rules.rs:36-37`：`/// 反过来的 In。**它判的仍然是一条存在的事实**，所以照样有前提、有区间；「压根没有这个属性」是另一件事，不在这套里（0029 末节）`
  `docs/decisions/0029-a-rule-may-say-or-once.md:31-36`：`**"This entity has no such attribute at all" is not in this record, and not by oversight.** Two reasons, either one sufficient: It has no premise… The base is open-world.`
- **聚合（sum/count/avg）**：
  `docs/decisions/0032-a-rule-computes-what-it-concludes.md:46-52`：`**It asserts completeness, which this base cannot.**… The honest statement is "the wells we know about total 300", and that is not what the row would say.`
- **基数限制**（`owl:maxCardinality`/`minCardinality`）：仓库里**没有任何实现**，只有 functional / inverse_functional 两个 0/1 布尔近似。
- **义务 / 必须发生**：没有模态、没有 deontic 算子。`attribute_rules.conclusion` 只有 `typing|attribute|computed`（`migrations/0041:38-41`）。

**结论**：「X 必须不发生」在 Utopia 里只能写成 **公理 + 事后一致性检查 + 人工裁决队列**，不能写成一条会在写入时拒绝的约束。这条界线在 ADR 里是自觉的：`docs/decisions/0001:48-54`：`A declaration can be wrong (part_of was), so the ontology shapes the prompt and candidate ranking and **drives no discard, overwrite or rewrite**: a wrong guide is overridden by the text, a wrong gate destroys data systematically.`

## 6. 本体：pack 是什么、怎么长出来、是不是契约

### 6.1 pack

**五个内嵌包**（gzip 后 316 KB，源码里就是文件）：

> **evidence** `ls crates/utopia-server/packs/` → `schema-org.ttl.gz`、`w3c-org.ttl.gz`、`prov-o.ttl.gz`、`foaf.rdf.gz`、`iof-core.rdf.gz`
> `docs/decisions/0008-ontology-packs-as-cold-start.md:3-6`：`five packs embedded in the binary (gzip, 1.7 MB → 316 KB), multi-select at KB creation, 22-row static alignment table · a new KB seeds no relations: the packs are the whole ontology · **no pack is checked by default**`

包间冲突靠**手写 22 行静态对齐表**，不做任何相似度推理：
`docs/decisions/0008:66-71`：`**Static alignment table, no runtime inference.** About 20 rows by hand (22 built, SameAs and Rename, e.g. org:Role → org_role)… No label similarity or embedding matching — the packs are ours, five or six of them, and the overlaps can be enumerated.`

**空本体是合法的、而且是默认**（#580）：
`docs/decisions/0008:106-113`（实测）：schema.org 让 98% 实体有类型（对 Wikidata 答案卷 90% 准），但 **81% 的事实仍然没有谓词**（bootstrap 后 65%），342 条因 `domain_mismatch` 被丢；空库最后长出 13 类 175 关系、80% 实体有类型（77% 准），**带谓词的实体间边反而更多**（56% vs 49%）。每次抽取调用 ~2k token 而不是 ~18k。

### 6.2 本体怎么被写出来

三条来路：**（a）导入 OWL 文件**（Turtle / RDF/XML，`oxttl` + `oxrdfxml`）、**（b）在 Ontology 页手工建/改**、**（c）从开放图谱的建议里采纳**。

- 原文**按内容寻址存 blob**，投影只是「今天有消费者」的那部分；读不懂的不是错误，是「暂未投影」（`migrations/0004_ontology.sql:22-27`）。
- 映射规则（`docs/decisions/0001:97-104`）：`owl:Class → entity_type`、`rdfs:subClassOf → entity_type_parents`、`owl:ObjectProperty → relation`、`owl:DatatypeProperty → attribute`、`rdfs:domain/range → 关联表「stored as signals, never as gates」`。
- **个体（ABox）永不导入成事实**：`docs/decisions/0001:124-125`：`**Individuals (ABox) are never imported as facts.** Every fact needs an evidence chain`。
- IRI 是身份、key 是给模型的 token：`migrations/0003_graph.sql:29-32`、`docs/decisions/0001:105-110`。

### 6.3 本体是契约吗？——分两个时代回答

**时代一（0012 之后）：类型是引导，论证顺序是强制的。**
`docs/decisions/0012-the-ontology-is-a-contract-not-a-suggestion.md:28-33`：
1. `**Which types may participate stays guidance; argument order is enforced by the signature.**`
2. `**Correct direction at write time.** When the subject violates the domain and the object satisfies it, swap them by signature`
3. `**Never silently.** Every swap leaves a direction_corrected trace.`
4. `**A relation that does not apply falls silent.**`（主语宾语都不合 → 丢掉谓词，保留主宾与证据）

实测效果（`0012:1-3`）：五次受控运行把违反率从 **57% 降到 4%**，真反向从 **39 降到 0**。

**时代二（0044 之后）：本体干脆不进抽取提示词，改由「对齐」事后按签名绑定。**
`docs/decisions/0044-the-ontology-is-a-view-over-what-documents-say.md:58-67`：
- `**Alignment produces the typed graph: bindings and implication rules**`（按签名，不按事实）
- `This is how the facts a reader draws without the text stating them … reach the typed graph without a second extraction pass bound to the ontology.`

也就是说：**「本体是契约」在 2026-09-16 之后已经退化为「本体是事后的绑定目标」**——抽取阶段不约束，绑定阶段才约束，而且绑定是按签名缓存的一次判定。

### 6.4 「no-relation-is-no-relation」的具体含义

字面含义：**抽取器发现一条边但本体里没有对应的关系时，事实照落，谓词留空（NULL）**，绝不填一个叫 `related_to` 的兜底词。

> **evidence** `migrations/0003_graph.sql:229-231`：
> `-- 删掉它一个字的信息都不丢：原意一直存在证据的 proposed_predicate 里，被那行假词汇盖着而已。删掉之后信息反而更多`
> `docs/decisions/0010:29-32`：`**facts.predicate_id becomes nullable and related_to is deleted.** The reader sees more: on a real corpus (14,706 facts, 5,934 on related_to), 93 graph edges that all read "related" now read placed_pressure_on / agreed_to_resign / countersued / revived_legal_action / license_from.`
> 代价被如实记下：`docs/decisions/0010:71-74`：`Of 5,934 fallback facts, 420 have no source wording… They now display empty; they used to display "related" — zero information either way.`
> 同一逻辑在类型侧（0009）、映射侧（0011）、以及 Metric/Dimension 两个类上（0036）**重复了四次**，ADR 自己承认：`docs/design/ontology.md:176-178`：`**A placeholder in the ontology is control flow written as vocabulary.** concept, related_to, mapped_to and then Metric / Dimension were removed on the same argument`

## 8. 规则与推理引擎

### 8.1 语言：**不是 Datalog，也没有任何规则语言**

这是最容易被 README 误导的地方。

> **evidence** `README.zh-CN.md:65`：`| **知识派生与推理** | 时态 Datalog · 前向链 · 本体公理编译 · 派生路径追溯 · 基于 Rust 自建轻量推理引擎 |`
> **代码里没有任何 Datalog**：仓库级 `grep -rni "datalog\|semi-naive" crates/ --include=*.rs` → **0 命中**；`crates/utopia-reason/Cargo.toml` 依赖只有 `uuid` 与 `serde_json`（没有 pest/nom/lalrpop/chumsky），无 `build.rs`。

规则以**两种完全不同的形态**存在：

**(A) 公理编译出来的规则**——一个 4 变体 Rust enum，落成一行 `rules`：

```rust
// crates/utopia-reason/src/derive.rs:34-45
pub enum Rule {
    /// `A p B` ∧ `B p C` ⟹ `A p C`
    Transitive,
    /// `A p B` ⟹ `B p A`
    Symmetric,
    /// `A p B` ∧ `p⁻¹ = q` ⟹ `B q A`。**主宾对调且换谓词**
    Inverse,
    /// `A p B` ∧ `p ⊑ q` ⟹ `A q B`。主宾不动，只升谓词
    SubProperty,
}
```

生成者是 `crates/utopia-store/src/reasoning.rs:1243-1290 compile_rules()`，只按 `relation_types` 的 8 个声明列产规则；`rules.kind` 的 CHECK 在迁移 0016 扩到四个值：`CHECK (kind IN ('transitive','symmetric','inverse','sub_property'))`（`migrations/0016_a_relation_can_name_its_inverse.sql:41-42`）。

**(B) 人写的业务规则**——`attribute_rules` + `attribute_rule_conditions`，结构化列：

```rust
// crates/utopia-reason/src/rules.rs:196-209
pub enum Conclusion {
    /// 派生归类：结论是一个类，落成 `is_a` 上的字面值
    Typing { class: String },
    /// 派生属性：算出来的数（0032）
    Computed { predicate: Uuid, expr: Expr },
    /// 派生属性：某个属性谓词上的一个字面值
    Attribute { predicate: Uuid, value: serde_json::Value },
}
```

条件的算子只有 8 个：`gt/gte/lt/lte/between/in/not_in/present`（`rules.rs:29-40`）；算式只有四则：`Add/Sub/Mul/Div`（`rules.rs:85-93`，注释：`**只有这四个**：再多一个就得回答它对缺读数、对除零、对单位各是什么语义，而那是一门语言的开头（0002 / 0032）`）。

**没有 `body`/`head`/`premise`/`conclusion` 之类的列**；规则身份就是 `(kb, predicate, kind)`（`docs/decisions/0002:49`：`no user DSL. Rule identity is (kb, predicate, kind)`）。

**一条真实规则的形状**（DB 里就是这几行）：

```sql
-- crates/utopia-store/tests/a_rule_concludes_a_type.rs:124-155
INSERT INTO attribute_rules (id, kb_id, name, subject_type_id, conclusion, conclude_type_id)
VALUES ($1, $2, 'gas-bearing', $3, 'typing', $4);
INSERT INTO attribute_rule_conditions (id, rule_id, seq, predicate_id, op, operand)
VALUES ($1, $2, 0, $3, 'gt', $4), ($5, $2, 1, $6, 'in', $7);
-- $4 = 阈值数字，$7 = ["气测异常", "气测异常后效"]
```

「或」是加一个 `group_seq`（迁移 0039）：**组内与、组间或，只一层，不做任意嵌套**——`migrations/0039_a_rule_can_say_or.sql:10-14`：`-- 加一列 group_seq：同组的条件用「与」连，组与组之间用「或」连。一层，不做任意嵌套——**因为求值器的形状就是一组「与」**`

### 8.3 求值策略

**两趟推理，两种策略，同一个 `materialize()`：**

1. **公理闭包 `derive()`：真正的半朴素（semi-naive）前向不动点。**
   `crates/utopia-reason/src/derive.rs:145-157`：`**全局不动点，不再按谓词分组。** 三条规则会串起来…各谓词各算各的话，这条链在第一步就断了。所以改成半朴素求值扫全集：每一轮拿上一轮的新边（frontier）再推一遍，没有新增就停。` 循环 `for _ in 0..MAX_DEPTH`（`derive.rs:204`），每轮只 drain frontier，且**不推自环**（`derive.rs:259-263`）。
2. **业务规则：朴素全量重跑的不动点，明确拒绝半朴素。**
   `crates/utopia-store/src/reasoning.rs:1775-1789`：`**全量重跑而不是半朴素**：链通常只有一两环，收敛靠「这一轮没产出新键」那一下……半朴素要维护每条规则读哪些谓词，为一个两三轮的循环换一份索引，不划算。`

**没有分层（stratification）**，没有规则依赖图；终止只靠三件事：每轮去重（`reached`/provisional key）、`MAX_DEPTH` 上限、每谓词产出上限，**且超限一律回报而不是静默**（`derive.rs:80-87`、`rules.rs:234-243`：`少推几条与「这个实体不满足」在结果里长得一模一样`）。

### 8.4 解释与追溯

- 证明存成**树**：`fact_derivations(derived_fact_id, premise_fact_id | premise_derived_id, seq)`，`CHECK` 恰好一支（迁移 0040）；视图 `derivation_premises` 让六处读者不用各写一遍 UNION。
- 读出：`utopia-store::reasoning::proof()`（`reasoning.rs:2218`），按 `seq` 递归展开，深度由 `MAX_DEPTH` 封顶。
- **前提变了但结论没变时，证明会被重写**，计数是报告里的 `reproved`（`docs/decisions/0030:63`）。
- MCP 暴露只读工具 `list_rules` / `rule_matches`；**写规则不进 MCP**（`docs/decisions/0021:66-75`）。
- 前端：实体面板把结论连同前提逐条指回原文；派生边画成金色、被挡住的派生画成 ghost edge、被争议的边用 `#ff6a3d`（`docs/decisions/0017:124-143`，颜色值给到 `rgba(255,106,61,0.55)`）。

### 8.5 本体公理怎么编译进推理机

1. 一趟 SQL 只捞**声明过公理的行**（`crates/utopia-store/src/reasoning.rs:74-81`）：
   `SELECT id, is_transitive, is_symmetric, is_asymmetric, is_irreflexive, functional, inverse_functional, inverse_of, sub_property_of FROM relation_types WHERE kb_id = $1 AND (… OR inverse_of IS NOT NULL OR sub_property_of IS NOT NULL)`
2. 归一化逆：`-- 已经声明了自己的逆就不动它——**人写的优先于推出来的**，两边指得不一样是本体自己的矛盾，交给 R0 报，不在这里悄悄改`（`reasoning.rs:127-134`）。
3. 结构体 `Axioms`（`crates/utopia-reason/src/lib.rs:34-47`）只有 8 个字段——**domain/range 不在里面**，它们由 SQL 的 `signature_breaks` 单独算（`lib.rs:88-96` 注释：`**这一类不由本 crate 算出**`）。

## 9. 冲突检测与 rewind

### 9.1 两张表、两种问题的分工

> **evidence** `migrations/0012_axiom_violations.sql:5-11`：
> `--   fact_conflicts    时态冲突，问的是「哪条对」 → closed / kept_both / rejected_new，三个答案都在改事实`
> `--   axiom_violations  公理违规，问的是「错在数据还是错在定义」 → 撤事实，或者去改本体那条公理`

| 表 | 回答的问题 | 出路 |
|---|---|---|
| `fact_conflicts` | 两条事实在时间上打架（functional/inverse_functional 的状态关系） | `closed` / `kept_both` / `rejected_new` / （自动）`withdrawn` |
| `axiom_violations` | 账本违反本体声明 | `fact_retracted` / `fact_closed` / `axiom_relaxed` / `accepted` |
| `ontology_defects` | **定义自己站不住** | `fixed` / `accepted` |

> **evidence** `migrations/0013_reasoning.sql:5-8`：
> `-- axiom_violations 说的是「事实与定义抵触」，这张说的是「定义自己站不住」。分开不是分类癖：一个自相矛盾的本体会让事实层的结论**全部可疑**`

### 9.2 冲突的键必须规范（否则「人的裁决会悄悄失效」）

这是仓库里被修过三次的真实 bug 类，值得单列：

> **evidence** `migrations/0052_a_cycle_is_keyed_by_the_cycle.sql:5-11`：
> `-- 量过：一个三元环、同一份输入，check() 跑 200 次给出三种 (left, right, path)——三个旋转都来过。`
> `-- axiom_violations 按 (kb_id, kind, left_fact, right_fact) 唯一，所以换个旋转就是换一行。真正的后果不是多一行，是**人的裁决会悄悄失效**`
> 修法演进：0052 环转到最小事实起头 → 0053 互斥组按整组事实定键、`inverse_functional` 独立成类 → 0054 环**按整条 path 定键**（`CREATE UNIQUE INDEX axiom_violations_cycle_key ON axiom_violations (kb_id, path) WHERE kind = 'cycle'`），实测数据：`400 个单位的组织重组库上形状环 572 个，落库 165 行`。
> `migrations/0051_a_conflict_that_evaporated_was_not_decided.sql:1-33`：冲突「蒸发」曾由**读路径跑 UPDATE** 实现，于是 `resolved_at` 记的是「有人打开了审核页的时刻」，而「T 时刻这条冲突开着吗」取决于此后谁开过那一页。修法：新增 `withdrawn` 状态 + **由 `facts` 上的触发器在作废那一刻退场**（`migrations/0051:87-91 CREATE TRIGGER facts_invalidation_follows_through_to_conflicts AFTER UPDATE OF invalidated_at ON facts`），并把存量 `stale` 行的 `resolved_at` 改成先作废的那一刻——`不是抹成 NULL：抹掉会让 record_axis 把这些冲突当成「从来没开过」，那是另一种假话`。

### 9.3 「矛盾指向上游」（ADR 0017）

一致性检查不只报「这里矛盾」，而是给出**四条上游成因 + 相应修复按钮**：

> **evidence** `docs/decisions/0017-a-contradiction-points-upstream.md:28-31`：
> `The error is in one of four places: stale knowledge (most common), a misread extraction, a wrong merge, an over-strict ontology. The interface's job is to lay out the clues and offer the repairs.`
> 五个修复动作全部落在既有端点上（`0017:90-96`）：关掉断言（`POST /facts/{id}/close`）、撤回断言（`reject_fact`）、去重复队列、改本体、`accepted`（两边都对）。
> 派生撞断言**不落地**，只留一行 `derived_contradiction`，每谓词上限 50（`crates/utopia-store/src/reasoning.rs:55 MAX_CLASHES_PER_PREDICATE: usize = 50`，`docs/decisions/0017:195` 自认：`**The per-predicate cap of 50 is a guess**`）；派生撞派生**按规则对聚合**进 `ontology_defects.rules_disagree`，两边都不落地。

### 9.4 rewind（ADR 0019）

见 §3.4。补两条边界：

- **检索的半边**：向量检索与分块读取接受 `as_of`（superseded chunk 保留向量），**全文检索只有「现在」**（`docs/decisions/0019:38`）。

> **evidence** `README.md:118-120`：

## 11. 对「外部法规条目 + 内部规则 + 正负样本 → 可判定知识库」的适配度

先把这件事拆成四个能力：**表示（能不能说清）**、**获取（能不能从文件里抽出来）**、**判定（能不能自动算结论/查出违规）**、**治理（错了能不能收回来、能不能向人解释）**。Utopia 在这四项上强弱差别极大。

### 11.1 直接可用（拿过来就能承载）

| 能力 | Utopia 的现成件 | 为什么够用 |
|---|---|---|
| **法规/规则条目的出处必须回到原文** | `fact_evidence(fact_id, chunk_id, quote, quote_start/end, document_id, doc_version)` + `chunks.origin/anchor` + DOC_CONTENT 读契约 | 引文偏移、版本、来源（原文/OCR/转写/模型转述）四件都在，且**偏移由服务端算**。合规审计要的「这句话出自哪一版文件的哪一段」是被 schema 强制的，不是附加功能 |
| **「某时刻我的判断是什么」与「我何时知道」分开** | 两条时间轴 + `held_at(T)` + `record_axis`/`world_axis` | 法规有生效日期（世界轴），我方有修订与回溯（记录轴），证据有发文日期（attestation）。三轴分开正是合规场景的刚需，且已实现到「精度梯子 + CHECK 钉住」的粒度 |
| **结论必须能解释** | `derived_facts` + `fact_derivations`(树) + `derivation_premises` 视图 + `proof()` | 「这条判定凭什么」可逐级展开到前提再展开到原文 |
| **人工裁决与留痕** | `audit_events`（触发器不可变 + 应用权限被 REVOKE）+ `agent_decisions.trace/precedents/question` + 各队列表的 `decided_by/decided_at/rationale` | 审计台账是**真的改不动**（连 TRUNCATE 都单挡一道），不是约定 |
| **知识库隔离** | 迁移 0070 的跨库出处不变式（26 条复合外键 + 13 条触发器 + kb 不可过户） | 多法域/多客户场景可以直接依赖 |
| **抽取出处与丢弃可见** | `extraction_drops`（13 个原因码，按文档清）+ 服务端逐条检查（引文必须在块里、名字必须在引文里、时间词必须在这条陈述自己的引文里） | 「抽取器有没有静默丢东西」这件事有账 |

### 11.2 需要改造（能用，但要动它的核心假设）

| 缺口 | 具体障碍（引证据） | 改造方向 |
|---|---|---|
| **① 没有否定、没有义务、没有基数** —— 法规大量是「不得」「必须」「至多一个」 | `attribute_rules.conclusion` 只有 `typing\|attribute\|computed`（`migrations/0041:38-41`）；缺失条件被明确拒绝（`rules.rs:36-37`、0029）；聚合被拒（0032:44-54）；未支持 `maxCardinality` 等任何 OWL 基数 | 只能把「不得」写成 (a) OWL 公理 + R0 事后违规，或 (b) **正向规则推出一个 `violation`/`non_compliant` 类**（typing 结论落到 `is_a` 上），再由人裁决。要真做 deontic 判定，得在 `attribute_rules` 上加**否定结论**与**缺省条件**——那等于改 0029/0032 两条 ADR，属于**产品级改造** |
| **② 规则不能跨实体取数** | `rules.rs:277`（按实体分组）、0032 把跨关系取值列为未建 | 需要单跳边加载器（0032 已设计但未写）。法规条目常需要「A 的 X 与 B 的 Y」 |
| **③ 规则之间不能推边** | 0021 明确「conclusions are types or attributes, never edges」；0047 提案未建 | 若法规链需要「A 控制 B、B 控制 C ⇒ A 控制 C 且有阈值」，今天只能靠公理的传递闭包（无阈值）或拆成多条规则 |
| **④ 抽取阶段不设约束，绑定阶段才约束** | `docs/design/ontology.md:17`：抽取不写类型化事实；0044 决定 2 | 现在**新库抽完是空的（无类型化事实）**：时间线、冲突、签名检查在你跑完对齐之前都读不到东西。要对齐真正可用，必须先跑通 parity（#880 尚未用模型跑过） |
| **⑤ 术语对齐靠「签名 + 两票 + 短语缓存」** | `phrase_bindings` / `type_bindings`、`phrase_alignment.rs`、迁移 0072 的 `basis` 指纹 | 法规术语量级大、同义/上下位关系密，两票一致制对**长尾短语**的覆盖率是未验证的（实测覆盖率**跟随类别词绑定与本体规模，不跟随 binder**：`docs/design/ontology.md:126-127`）。且 `in`/`not_in` 是**逐字匹配**（`rules.rs:77-78`），法规多语种会漏 |
| **⑥ 正负样本没有一等公民** | 全仓没有「样本/用例」表；最接近的是 `ontology_imports.summary`、`ontology_proposals`、`errata_actions` 与 bench 脚本（`scripts/bench/*.mjs`），都是**开发期**产物 | 「正负样本」要成为可判定知识库的一部分，需要新建表（样本 ↔ 结论 ↔ 依据 ↔ 版本），并让 `attribute_rules` 的回归跑挂在它上面。0021 的 open question 提到「为每条已批准元素带回归用例」，那是**本体工作台**（未建）的一部分 |
| **⑦ 单位/量纲不校验** | `docs/decisions/0032:60`：`Units and datatypes have to be checked when the expression is written, and today nothing checks them.` 0049 仍在 proposed | 阈值型法规（金额、期限、浓度）今天可以 `revenue(USD) − cost(EUR)` 静默算出数 |
| **⑧ 「判定」只有物化，没有查询期求值** | 0002 开放问题：`Materialize or evaluate at query time` 未决；R3 增量维护未建；每次全库重算 | 法规库大、变更频繁时，全量重算的代价与延迟未测量 |
| **⑨ 治理 agent 只覆盖同名消解队列** | `docs/decisions/0043:3`、`docs/design/governance.md:109-110` | 「每个队列都被治理」未落地，法规场景下违规队列会堆 |

### 11.3 不覆盖（要另建，不要指望改造它）

1. **法规版本的「生效/失效/替代」关系语义**：`documents` 有 `doc_time` 与 `version`，但**没有「法规 A 被 B 取代」「B 修订了 A 的第 5 条」这类关系模型**。`supersedes` 是**事实级**的（同一三元组的新旧），不是文档级/条款级的替代链。
2. **条款/条目的层级结构**：`chunks` 有 `heading`、`seq`、`char_start/end`，但没有「章-节-条-款」的显式模型，也没有条款 id 的稳定身份。要按条引用法规，得自建（并且要处理重排版/重新编号）。
3. **判定结论的「依据链」对法规条款的形式化**：Utopia 的证明树前提是 **facts**（事实行），不是「法规条款」。也就是说它能解释「乙烷浓度 > 阈值 ⇒ 该井为气测异常」，但**解释不了「依据《XX 办法》第 12 条」**——除非把条款本身建成实体并让规则引用它（可以用 `derived_facts` + `fact_derivations` 拼，但要自己设计）。
4. **时间/期限的日历推理**：`time_mentions` 有 `shape/reference/granularity` 与 `resolved_*`，但没有工作日/节假日、没有期间运算（`duration` 只是 shape 之一），也没有「自 X 日起 N 个工作日内」的求解。
5. **否定性一致性（open-world 语义的代价）**：这是最根本的一条。0029 明说：`The base is open-world. A missing reading means nobody wrote it down, not that the value is false.` 而法规判定常常需要「没有许可证 ⇒ 不得经营」这种**封闭世界**推理。今天必须显式地先物化一条 `has_license = false` 的事实，规则才能用——**这一步没有任何自动化**，而且违反 open-world 假设会让「没抽到」变成「不存在」的静默错误。
6. **多法域/多版本的并用与冲突消解**：跨库引用被迁移 0070 **主动禁止**（`出处链不许跨库`），所以「一个国家一个库、法域之间要交叉引用」在这套 schema 下是**做不到的**，只能同库建模。
7. **不可否认性与签名**：`audit_events` 是防篡改（触发器 + 权限），注释也承认挡不住 superuser、并说「要让蓄意篡改也无所遁形，得靠后续的哈希链」（`migrations/0007:40-43`）——**哈希链没有实现**。

### 11.4 一句话结论

**Utopia 是一台做得很扎实的「带证据链与时态的双时态事实账本 + 人工裁决队列 + 轻量前向推理机」，而不是一台「规则引擎」。** 它最成熟、也最值得直接搬的三样东西是：**(1) 事实→证据→文档版本→原文偏移的溯源链**（`fact_evidence` + `chunks.origin/anchor` + ADR 0052 的读契约）；**(2) 世界/记录/证据三轴分离 + 精度梯子 + `held_at(T)` 回放**；**(3) 审计台账的不可变实现与「派生优先让位于断言」的硬规矩**。

反过来，**「法规 → 可判定」这条路上最关键的三个能力它明确没有**：**否定/义务/基数的表达**（0029/0032/0021 三条 ADR 是主动拒绝的）、**封闭世界下的缺省判定**、以及**条款级的法规结构模型与依据链**。另外有一条容易被忽略的落地事实：**自 2026-09-16 起抽取只写开放图谱，类型化图谱要靠对齐（alignment）算出来，而对齐尚未在模型上跑过 parity 基准（#880）**——也就是说，**今天从零建一个库，抽完之后时间线、冲突检测、签名检查、规则推导全部读不到东西**，必须先跑通对齐链（`align_types → align_phrases → materialize_typed`）并在人审队列里把 `undecided` 的签名处理掉。这一点如果不提前算进工期，会是最容易踩空的地方。
