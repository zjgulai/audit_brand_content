# 守衡群回复卡片 · 名片

> 跟业务沟通时用这一页。想看细节再看 `contract.md`，想看代码看 `cards.mjs`。

---

## 一句话

守衡在群里回答问题，今天发出去的是**一整段纯文本**（中位 786 字），
表格显示成竖线、结论埋在开头、边界声明重复五遍。
这套模版把它改成**十一种卡片**：结论在标题栏，证据默认收起，边界只占一行。

---

## 三个数字

| | 今天 | 用了模版之后 |
|---|---|---|
| 一眼能看到的 | 第一句（在那之前还有铺垫） | **标题栏 = 结论本身** |
| 表格 | 一堆 `\|` | 原生表格（探针实测可用） |
| 边界声明 | 一段话，重复 3–5 遍，占全文三分之一 | **一行，≤90 字，没有就不写** |
| 内部记录（工具名、栈） | 出现过两次（一次连列 27 次工具名） | **只允许进折叠区**，正文出现即故障 |

---

## 十一种卡片，什么时候用哪张

| 类型 | 什么时候用 | 标题栏配色 |
|---|---|---|
| `query-answer` **问答** | 问的是事实或结论，三句话能说完 | 蓝 |
| `data-table` **数据** | 回答是 ≥3 行记录，每行字段相同 | 蓝 |
| `correction` **更正** | 发现自己前面说错了 | **红**（唯一必须停下看的） |
| `capability-boundary` **能力** | 被问「你能做什么」 | 灰 |
| `find-nothing` **没找到** | 查了但一条都没有（**必须说清查了哪里**） | 橙 |
| `cannot-read` **读不了** | 图片/文件/语音/**已撤回**/窗口外 | 浅蓝 |
| `receipt` **回执** | 对方只需要知道「收到了」 | 灰 |
| `turn-diff` **改口** | 同一问题两次答得不一样（**不说明会被读成改口**） | 紫 |
| `evidence` **证据** | 结论短、证据长 —— 证据全收起 | 绿 |
| `alert` **告警** | 我这侧坏了（**内部详情只进折叠区**） | **深红** |
| `decision` **征询** | 要对方拍板（**一次只问一件**） | 紫 |

判据写在 `contract.md` 第三节，每条都带**反例**。
判据分不开的类型形同不存在 —— 模型会全用同一个模版，模版就白做了。

---

## 为什么是这十一种，不是别的

不是拍脑袋列的。是从守衡**真实答错的那几条**反推的：

| 真实事件 | 对应的模版 |
|---|---|
| 连列 27 次工具名发进群（2026-09-17） | `alert` + 「内部记录只进折叠区」这条硬约束 |
| 「10 次」→「11 次」，对方连问四遍 | `turn-diff`（今天没有任何模版处理这个） |
| 说「找不到」但不说找了哪里 | `find-nothing` 强制填 `paths` |
| 把「内容没有了」和「内容在我范围外」混成一句「我读不了」 | `cannot-read` 把三类拆开 |
| 边界声明重复五遍 | 「一个格，一行，没有就不写」 |

## 现在能不能用

**已经在用了。** 说清楚四件事：

1. **模版与自证已完成** —— 十一个类型建得出、白名单与探针实测一致、降级可读、文档同步。
   跑 `node tools/verify_cards.mjs` 看，239 项全过。
2. **守衡的回复已经会走卡片** —— 它每次回答可以选一段纯文本，或一张卡片。
   选择权在它手里；写坏了会退成纯文本发出去，**不会丢话，只会丢格式**。
3. **还有一件事只能你确认：卡片在群里长什么样。** 我们的探针只验到「接口收下了」，
   验不到「渲染出来对不对」。跑一次 `node tools/reply-cards/cli.mjs send-all --confirm`
   往测试群发 11 张样例卡，看一眼就行。没有 `--confirm` 不会发任何东西。
4. **按钮点不动** —— `ws_daemon` 收到 `card.action.trigger` 只记日志。模版里的按钮位置留了，
   但**没有假装它能交互**。

### 怎么知道它没有乱来

每一条群回复在日志里都留了这几行，出问题不用重跑猜：

```
   🃏 卡片 alert · markdown · collapsible(收起)
   ↪ verdict → boundary（结论超过 60 字）
   ❌ 语域 internalLeak ×1 tool_calls / ...
   💬 回复 434 字，耗时 16696ms
   ✓ 已发送 om_xxx [reply-card]
```

四行分别回答：**它选了哪种形态**、**有没有被搬迁**、**有没有踩到语域规则**、**发出去没有**。

## 一件要提前说的事：这套模版治的不是「用词」

我们把「去 AI 味」的七条机械检查跑在守衡**真实发出去的 8 条群回复**上（共 5,544 字）：

| 命中 | 次数 |
|---|---|
| 内部记录泄漏 | **1 次**（那条连列 27 次工具名的） |
| 模糊限定堆叠 | 8 次 |
| 客服腔 / 结尾总结段 / 双音节填充 / 连词串珠 / 排比三连 | **0 次** |

**守衡说话并不「像 AI」——它没有客服腔，也没有套话。** 它的问题是三件结构上的事：

1. 边界声明重复五遍，占全文三分之一
2. 内部记录被当成内容发到群里
3. 结论埋在 786 字里的某处

这三件正是这十一种模版在治的。**模版是主药，去 AI 味的词表是安全网。**

## 附：本次实测否掉了两个元素

`note`（注脚）和 `action`（按钮容器）在卡片 schema V2 里**已被移除**。
写了不是降级，是**整张卡被服务端拒绝** —— 守衡的回复会在群里凭空消失。
替代写法已测通：注脚用 `column_set` + 灰底，按钮裸放。
