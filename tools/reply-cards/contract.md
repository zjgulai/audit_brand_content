# 守衡群回复卡片 · 模版契约（v1）

> **这是什么**：守衡在飞书群里回答问题时用的卡片格式。十一个类型，每个类型一张模版。
> **给谁看**：跟业务对接时用它说明「守衡的回答长什么样、每一格是什么、什么时候用哪张」。
> **状态**：模版已定稿并通过自证（`node tools/verify_cards.mjs`）。**发送层尚未接入**
> —— 守衡现在仍然走纯文本发消息，见 §六。
>
> 不是设计稿。下面每个元素都是 2026-09-18 往测试群真发卡片测出来的，
> 原始读数在 `PMO/logs/card_probe.jsonl`，被否掉的两项写在 §三。

## 一 · 为什么要有模版

先看守衡今天在群里的实际输出（本项目会话记录，原文摘录）：

| 现象 | 实测 |
|---|---|
| 回复中位长度 | **786 字**（8 条群回复：423 / 434 / 704 / 779 / 793 / 1045 / 1057 / 1312） |
| 含数据表的比例 | **42%** —— 而发送走的 `msg_type=text`，表格在群里是一堆 `\|` |
| 同一条回答里重复的「边界声明」 | **5 条**，约占全文三分之一 |
| 「等于没答」的回复 | **2 条**：一条连列 27 次工具名发进群；一条把工具调用记录当内容列了二十多个 |

四件事其实是同一个原因：**提示词里写了「结论先行」「不确定性显式」，但每次都要模型自己重新解释一遍。**
解释就变成复读，复读就变成篇幅，篇幅挤掉结论。

模版的作用是把这些变成**槽位**：

- 结论有且只有一个格（`verdict`），超 60 字就是没提炼出来
- 边界有且只有一个格（`boundary`），一行，≤90 字，**没有就不填**
- 内部记录只能进折叠区（`collapsible_panel`），正文里出现就是故障

**不靠模型自觉，靠模版逼。**

## 二 · 卡片长什么样

飞书卡片 schema `2.0`，四层结构：

```
{ schema: "2.0",
  config: { update_multi: true },        ← 允许后续原地更新同一条卡片
  header: { title, subtitle?, template } ← 标题栏 + 配色
  body:   { elements: [...] }            ← 正文，V2 的正文在 body 下（不在顶层）
}
```

### ✅ 实测可用的 tag（白名单，共 10 个）

| tag | 用途 | 探针读数 |
|---|---|---|
| `markdown` | 正文。标题/粗体/列表/引用/代码块 | 2/7 通过 |
| `plain_text` | 只用于 `header.title`、`header.subtitle`、`button.text` | 1/7、10/10 通过 |
| `hr` | 分割线（把边界声明和正文隔开） | 2/7 通过 |
| `table` | **原生表格** | 3/7 通过 |
| `column_set` + `column` | 分栏、字段排、注脚区 | 4/7、8/10 通过 |
| `collapsible_panel` | 折叠面板（长证据默认收起） | 5/7 通过 |
| `button` | 按钮，**裸放**在 elements 里 | 10/10 通过 |
| `code_block` | 代码块（`markdown` 里的 ``` 也可） | 2/7 通过 |
| `standard_icon` | 仅用于折叠面板的箭头 | 5/7 通过 |

### ❌ V2 已移除，写了就整卡被拒

| tag | 服务端原话 | 替代 |
|---|---|---|
| `note` | `cards of schema V2 no longer support this capability` | `column_set` + `background_style: grey`，或一行斜体 markdown |
| `action` | 同上 | 按钮**裸放** elements 里 |
| `div` / `fields` / `img` / `image` | 同上（V2 同批移除） | `markdown` / `column_set` / markdown 图片语法 |

> ⚠️ **这不是「降级」，是「整卡被服务端整体拒绝」。** 判错一个 tag，守衡的回复会在群里凭空消失。
> 所以 `cards.mjs` 里有一份白名单，`validateCard()` 在发之前拦一遍，被拦下的会抛异常而不是发出去。

### header 配色 → 语义

颜色不是装饰，是「这条要不要停下看」的信号。

| 类型 | 配色 | 读作 |
|---|---|---|
| `query-answer` | blue | 常规问答，可以略过 |
| `correction` | **red** | 我说错了，必须看 |
| `capability-boundary` | grey | 能力边界，存档性质 |
| `find-nothing` | orange | 没找到，需要你补信息 |
| `cannot-read` | wathet | 输入我读不了 |
| `receipt` | grey | 只确认收到 |
| `turn-diff` | violet | 同一问题的两次回答不一样 |
| `evidence` | green | 证据陈列 |
| `alert` | **carmine** | 我这侧坏了 |
| `decision` | purple | 要你做决定 |

## 三 · 十一个类型

每个类型给：**什么时候用**（判据，不是描述）、字段、样例形状。

> 判据必须能区分。写不出判据的类型不该存在 —— 模型在两条模糊描述之间选不出来，
> 最后会全用同一个模版，模版就白做了。

### 1. `query-answer` · 问答

**用**：问的是一个**事实或结论**，一到三句话能说完。
**不用**：要罗列多条记录 → `data-table`；回答本身就长 → `evidence`。

字段：`title`（**写结论本身**，不写「关于 X 的答复」）· `verdict`（≤60 字）· `reasoning`（可选）· `fields`（≤4 个）· `evidence`（收起）· `boundary`（一行，没有就不填）

形状：`markdown · markdown · column_set(3栏) · collapsible(收起) · hr · markdown`

---

### 2. `data-table` · 数据

**用**：回答的实体是**一堆记录**（≥3 行），每行字段相同。
**不用**：2 行以内用 `query-answer` 的 `fields` 就够，开表格是浪费一屏。

字段：`title`（写「共 N 条」比写「明细」有用）· `columns` · `rows` · `note` · `fields` · `subtitle`（给表加限定：「窗口：最近 50 条」）

形状：`markdown · table(5行) · markdown · column_set(3栏)`

> ★ 这是本次最大收益：**42% 含表格的回复终于真的是表格了。**
> 注意 `rows` 的每一项是**对象** `{列名: 值}`，不是数组。传数组会被服务端拒绝。

---

### 3. `correction` · 更正

**用**：**发现自己前面说错了**。唯一必须红头的类型 —— 群里上一句还挂着，更正不显眼等于没更正。
**不用**：只是补充信息，不是改口 → `query-answer`。

字段：`wrong`（错在哪，**引自己原话**）· `right` · `cause`（错在哪个环节，**是归因不是道歉**）· `boundary`

形状：`markdown · markdown · markdown · column_set(1栏) · hr · markdown`

---

### 4. `capability-boundary` · 能力

**用**：被问「你能做什么 / 你能不能做 X」。**三栏一次说完，不分段解释** —— 这类问题的价值在清单，不在论证。

字段：`can`（每条带一句边界）· `limited`（有硬上限的）· `cannot`（**直接说做不到**，不用「暂时」软化，除非真有计划）· `evidence`（收起）· `boundary`

形状：`markdown · column_set(3栏) · collapsible(收起) · hr · markdown`

---

### 5. `find-nothing` · 没找到

**用**：查了但**一条都没有**。
**必须说清查了哪里** —— 「没找到」不带检索范围，对方无法判断该补信息还是该换个地方找。

字段：`paths`（`{where, how, result}`，**每一处都要写**，漏写等于谎报覆盖）· `tried`（收起）· `nextStep` · `boundary`

形状：`markdown · markdown · table(3行) · collapsible(收起) · markdown · hr · markdown`

---

### 6. `cannot-read` · 读不了

**用**：输入是图片/文件/语音/卡片，或**已撤回**，或掉出可见窗口。
**这几件事的信息量完全不同，别混成一句「我读不了」**：「内容没有」「内容在我范围外」
「**按规矩不取**」是三回事。

> ★ **附件（file/image/media/audio）单独说**：飞书内容禁止下载（`AGENTS.md` §2.6），
> 附件只有下载这一条通道 —— 所以不是「读不到」，是**不取**。
> 写成「没权限」「能力还没做」，对方就会去申请权限、去找文件主人，**全是白跑**。
> 并且必须给一条走得通的路（把文字贴过来 / 存成飞书云文档发我）。

字段：`verdict`（写准是哪一类）· `item`（`{kind, from, at, content}`）· `why` · `alternative`

形状：`markdown · table(4行) · markdown · markdown`

---

### 7. `receipt` · 回执

**用**：对方**只需要知道「收到了」**。也可以在一次长回答已发出后补一条确认链路通。

> ★ 判断错了代价不对称：多一条回执是噪音，少一条回执对方会以为你没收到。
> **所以不确定时用回执，但一次对话里不要连发两条。**

字段：`verdict`（一句话）· `fields`（≤3 个）· `note`

形状：`markdown · column_set(2栏) · markdown`

---

### 8. `turn-diff` · 改口

**用**：**同一个问题，这次答得跟上一次不一样**。不说明就会被读成「在改口」。

> 这是守衡真实踩过的坑：「10 次」→「11 次」，对方连问四遍。
> 三种原因（窗口滑动 / 新证据 / 上次算错）的处置完全不同，必须分开写。

字段：`verdict` · `before` · `after` · `cause` · `fields`

形状：`markdown · table(2行) · markdown · column_set(2栏)`

---

### 9. `evidence` · 证据

**用**：**结论很短、证据很长**。结论放正文，证据全塞折叠区默认收起。

> ★ 这是「中位数 786 字」的直接解法：想一眼看完的人看标题和结论，想核对的人点开。

字段：`verdict` · `groups`（`{title, content, count, expanded}`，**默认 `expanded: false`**）· `fields` · `boundary`

形状：`markdown · collapsible(收起) · collapsible(收起) · column_set(2栏) · hr · markdown`

---

### 10. `alert` · 告警

**用**：**我这侧坏了** —— 模型调用失败、工具循环用尽、内部异常。

> ★ 这个类型的首要职责是**拦住内部记录**。守衡真的往群里发过一条连列 27 次工具名的回复
> （2026-09-17）。内部详情只允许出现在折叠区，且要写「排查用」。

字段：`what`（**不要贴栈、不要列工具名**）· `impact` · `internal`（**只能进折叠区**）· `retry`

形状：`markdown · markdown · collapsible(收起) · column_set(2栏) · markdown`

---

### 11. `decision` · 征询

**用**：**要对方拍板**。一次只问一件 —— 这不是模版的约定，是 `AGENTS.md` 第一节的硬约束。

字段：`ask` · `options`（`{label, cost}`，**每条必须写代价**；只给选项不给代价等于把选择又推回去）· `recommend`（没有建议就别写这行，不要用「供参考」占位）· `fields`

形状：`markdown · table(3行) · markdown · column_set(1栏)`

## 四 · 边界声明怎么写

守衡今天的边界声明是**一段话**，而且同一条回答里写五遍。契约把它压成：

1. **一个格**（`boundary`），一行，≤90 字
2. **没有就不填。** 不许写「本回答基于…」这种模板句充数
3. 只在三个条件之一成立时才写：
   - 结论**依赖一个会变的窗口**（「只覆盖最近 50 条」）
   - 结论**依赖一个我没查的地方**（「有权读的范围之外我无法判断」）
   - 结论**依赖一个我读不到的输入**（「撤回的原文取不回」）

合起来写，用分号断：`只覆盖本群；只覆盖最近 50 条；撤回的取不回。`

反过来：**「我不确定」这四个字不属于边界声明**。不确定是结论的一部分，写在 `verdict` 里
（「**11 条**（按 senderOpenId 过滤，见的都是能看到的窗口内）」），不是塞在脚注里。

## 五 · 模型怎么用卡片：卡片块

模型不写卡片 JSON —— 它只写一个**卡片块**，剩下的交给代码。这是刻意的分工：
`header.template` 白名单、「V2 移除了 note」这些知识属于代码，不属于每一次推理。
模型在这些细节上犯错，代价不是样式难看，而是**整条消息被服务端拒掉、回复凭空消失**。

```
先正常写你的回答。

[[card:receipt]]
{"title":"已收到","verdict":"收到。"}
```

标记后面必须紧跟一个 JSON 对象。三个容错是实测需要的：

| 容错 | 为什么 |
|---|---|
| 允许包在 ```json 围栏里 | 模型习惯性加围栏 |
| 块前后容许有文字 | 模型常先写一句再给块。**这些文字会被并进这张卡**，不会留在群里 |
| 括号配对扫描，不是 indexOf('}') | 卡片数据里几乎一定有 {...}（option / item / 表头对象），直接找第一个 } 会切在半路 |

解析器是 `tools/reply-cards/envelope.mjs`。它做四件事：

1. **切块** —— `extractCardBlock()`
2. **执行上限** —— `enforceLimits()`
3. **拦住内部记录** —— 公开格（`what`/`impact`/正文…）里出现 `tool_calls` 之类的标识时，
   整段搬进折叠区；公开格因此留空则由构造器的默认值兜住
4. **降级** —— 块不可用时剥掉整块，只发可读的话

### 三条硬约束是被**执行**的，不是写在校规里的

| 约束 | 执行点 | 违反时 |
|---|---|---|
| 结论（`verdict`）≤60 字符 | `enforceLimits` | 超出部分按句**搬**到 `boundary`，**一个字符不丢** |
| 边界（`boundary`）≤90 字符 | `enforceLimits` | 超出部分搬进该类型的折叠区 |
| 内部记录只进折叠区 | `scrubInternal` | 从公开格整段搬进折叠区 |

> **搬是搬，砍是砍。** 超长时搬走、不截断 —— 丢内容比格式难看严重得多。
> 搬完还有残留、或这个类型根本没有能承载的格子 → 降级为纯文本，理由写进正文。

> **上限此前没有执行点。** `cards.mjs` 里 `VERDICT_MAX` / `BOUNDARY_MAX` / `MAX_SECTIONS`
> 三个常量定义完之后，整个仓库没有一行代码引用它们（grep 只有定义行）。
> 也就是「结论 ≤60 字」原先是**一句注释**，模型写 300 字也照发。
> `envelope.mjs` 是它们现在唯一的执行点，自证 J1 段会断言这一点。

### ★ 一条不能靠人眼验的约束

`[[card:...]]` **一个字符都不许出现在群里**。标记被卡片渲染藏进折叠区时肉眼看不出，
但对方点开就看见了 —— 和泄漏 `tool_calls` 是同一类故障。

这条在自证里逐用例断言（J 段 13 个用例），因为它是唯一一条人眼不可靠的。
第一版这里真的漏了：JSON 被截断时，`[[card:receipt]]` 和半截 JSON 会**原样发进群**。

## 六 · 发不出去时怎么办：降级链

发送是**唯一**的格式决策点（`ws_daemon.mjs` 的 `replyTo`）。降级链只有一条：

```
有卡片 → reply 卡 ──失败──→ reply 纯文本（正文 = 卡的降级文本）
没有卡 → reply 纯文本 ──失败──→ sendMarkdown 补发
```

**为什么卡片失败后也是 `reply` 而不是新发一条**：新发会断开引用关系，
群里看到的是一段悬空的话，不知道在答谁。**守住引用比守住卡片重要。**

**兜底只能有一处。** `agent/feishu.mjs` 的 `replyCard()` 只尝试一次、不自己兜底；
两处叠加的表现是同一个回答在群里出现两次。（自证 L2 段会拦。）

**降级文本规则**：
- 标题变第一行
- 表格退化成 markdown 竖线表（在 text 里显示为竖线，但每行至少是独立一行）
- 折叠区**不展开**，改标「（已收起 N 条证据）」
- **必须注明原因** —— 对方看到格式变了，得知道为什么，而不是以为守衡改风格了

**不许发生的事**：卡片发不出去就「不答」，或者把卡片 JSON / 半截 JSON 吐进群。
后者是 2026-09-17 那条故障的同类错误。

### 一条诚实的读数：这套模版治的不是「用词」

把 7 条内容级检查跑在守衡**真实发出去的 8 条群回复**上（共 5,544 字）：

| 命中 | 次数 |
|---|---|
| `internalLeak`（内部记录泄漏） | **1 次** —— 那条连列 27 次工具名的故障输出 |
| `hedgeStack`（模糊限定堆叠） | 8 次 |
| 其余五条 | **0 次** |

**守衡的「AI 味」不在词汇层面。** 它没有客服腔、没有结尾总结段、没有双音节填充、没有连词串珠。

真正要治的是三件**结构**上的事，也正是这十一类模版在做的事：

1. 边界声明重复五遍（占全文三分之一）→ 压成一个 `boundary` 格，一行，没有就不写
2. 内部记录被当内容发出去 → 只允许进 `collapsible_panel`
3. 结论埋在 786 字的某处 → 提到 `header.title`

所以：**模版是主药，语域检查是安全网。**

**关于「发到测试群试一次」**：这是目前唯一能确认卡片真的渲染正确的手段，
因为离线校验 API 拿不到。命令是 `node tools/reply-cards/cli.mjs send-all --confirm`，
会往测试群发 11 张样例卡。**没有 `--confirm` 不会发任何东西。**

## 七 · 怎么用

```bash
# 看有哪十一个类型
node tools/reply-cards/cli.mjs list

# 看某个类型：字段、样例、它长什么样（纯文本形态）、形状摘要
node tools/reply-cards/cli.mjs show data-table

# 拿样例卡的原始 JSON（接发送层时用这个当输入格式参考）
node tools/reply-cards/cli.mjs sample data-table --json

# 校验一张卡（从 stdin 读 JSON）
echo '{"schema":"1.0"}' | node tools/reply-cards/cli.mjs validate -

# 自证：模版 / 登记表 / 文档三者一致
node tools/verify_cards.mjs
```
